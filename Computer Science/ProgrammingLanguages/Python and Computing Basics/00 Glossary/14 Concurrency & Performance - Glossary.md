# 14.24 Cumulative glossary additions

- **Absolute deadline:** expiry point represented on a specified clock rather than a duration newly started at each layer.
- **Acceleration kernel:** isolated computation selected for replacement by a faster specialised implementation.
- **Accuracy:** closeness of a measurement to the quantity or reference it is intended to represent.
- **Activity:** execution entity with its own progress state at the chosen abstraction level.
- **Actor:** scheduled entity that exclusively owns state and processes messages according to a defined protocol.
- **Adaptive batching:** forming a batch until either an item limit or time limit is reached.
- **Adaptive specialisation:** runtime replacement or refinement of generic operations using observed execution information while preserving language semantics.
- **Admission control:** policy deciding whether new work may enter a resource-bounded system.
- **Ahead-of-time compiler:** translator that produces target code before the translated program runs.
- **Amdahl’s law:** upper-bound model relating overall speedup to the accelerated fraction of a fixed workload.
- **Ambiguous outcome:** state in which a caller cannot know whether an external operation took effect.
- **Amortisation:** spreading a fixed or occasional cost over several operations.
- **Application binary interface (ABI):** binary-level contract governing calls, data representation, and symbol compatibility.
- **Async context manager:** object whose asynchronous enter and exit operations delimit a resource or transactional lifetime.
- **Async generator:** generator supporting asynchronous iteration and suspension.
- **Async iterator:** object whose next-item protocol returns awaitables.
- **Asyncio:** Python’s standard-library framework for event-loop-based asynchronous I/O.
- **Asynchrony:** control structure in which initiation and completion are separated and completion can be awaited or otherwise observed later.
- **Atomic operation:** operation whose intermediate states are not observable through the stated interface.
- **At-least-once delivery:** delivery contract permitting duplicates while attempting to avoid permanent omission.
- **Backoff:** deliberate delay before another attempt, commonly increased after repeated failure.
- **Backpressure:** control propagating downstream capacity limits towards producers.
- **Barrier:** synchronisation object that releases a group only after a specified number of participants arrive.
- **Batch:** group of items handled in one operation to amortise fixed cost.
- **Benchmark:** controlled measurement of one or more performance outcomes under a defined workload and environment.
- **Blocked:** unable to execute until an event or resource condition changes.
- **Borrowed reference:** native-interface reference whose user does not own an independent lifetime claim.
- **Bounded queue:** queue with a finite capacity whose full-state behaviour forms part of the protocol.
- **Buffer protocol:** Python interface through which objects expose memory regions and representation metadata to consumers.
- **Byte-weighted admission:** capacity policy charging work according to estimated retained bytes rather than item count alone.
- **Call graph:** graph whose edges represent calls among executable units.
- **Cancellation:** cooperative request for incomplete work to stop under a cleanup contract.
- **Cancellation latency:** elapsed time from cancellation request to the task’s completed termination.
- **Capacity:** maximum useful work rate or finite quantity available from a resource under stated conditions.
- **Checkpoint:** safe point at which progress or cancellation can be observed without exposing an invalid intermediate state.
- **Closed-loop load:** load in which a client generally waits for completion before generating its next request.
- **Coalescing:** overload policy combining several updates into one semantically representative update.
- **Coffman conditions:** mutual exclusion, hold-and-wait, no pre-emption, and circular wait conditions jointly necessary for classical resource deadlock.
- **Condition variable:** synchronisation object combining notification with a lock and state predicate.
- **Confidence interval:** interval generated by a procedure with a stated repeated-sampling coverage property under its assumptions.
- **Confinement:** restriction making mutable state reachable by only one designated execution context.
- **Concurrency:** overlap in activity lifetimes that admits more than one possible interleaving.
- **Concurrency limit:** bound on operations simultaneously in progress.
- **Contention:** competition among activities for a shared limited resource.
- **Context switch:** change in which execution context occupies a processing resource.
- **Context variable:** dynamically scoped context value designed to follow logical execution contexts such as asynchronous tasks.
- **Coordinated omission:** latency-measurement bias caused by failing to represent arrivals that should have occurred during stalls.
- **Copy-on-write:** memory-sharing technique in which inherited/shared pages are privately copied when written.
- **Coroutine function:** async function whose call constructs a coroutine object.
- **Coroutine object:** awaitable execution state created by calling a coroutine function.
- **CPU affinity:** restriction or preference associating an activity with specified processors.
- **CPU-bound workload:** workload whose progress is principally constrained by processor execution capacity in the observed environment.
- **CPU time:** processor execution time charged to a process or thread rather than elapsed wall time.
- **Critical path:** longest dependency chain whose duration bounds completion time below.
- **Critical section:** code region requiring controlled access to preserve a shared invariant.
- **Cumulative time:** profiler attribution including time in called descendants.
- **Cyclic garbage collection:** reclamation mechanism identifying certain unreachable reference cycles.
- **Cython:** language and compiler for generating CPython extensions from Python-like source with optional C-level declarations.
- **Data race:** language-memory-model category involving unsynchronised conflicting accesses under that model’s definition.
- **Deadline:** latest permitted completion point under a specified clock and policy.
- **Deadlock:** permanent waiting configuration in which required progress cannot occur.
- **Determinism:** property that admitted executions and inputs yield the same specified observation.
- **Deterministic profiler:** profiler instrumenting execution events such as calls and returns rather than periodically sampling.
- **Dispatch:** selection of the next instruction implementation, method, function, or operation.
- **Drop-newest:** overload policy discarding the arriving item when capacity is full.
- **Drop-oldest:** overload policy evicting an older waiting item to admit a new one.
- **Effect size:** magnitude of a measured or estimated difference in units relevant to the objective.
- **End-to-end latency:** elapsed time from the externally defined beginning of an operation to its contractually defined completion.
- **Event:** synchronisation object representing a boolean condition that can wake waiting activities.
- **Event loop:** scheduler that runs callbacks and coroutine tasks, waits for I/O readiness, and resumes eligible work.
- **Event-loop lag:** delay between a callback becoming eligible and being run by the event loop.
- **Exception group:** exception object retaining several failures as a structured aggregate.
- **Exclusive time:** profiler attribution to a function body excluding time in descendants.
- **Executor:** abstraction that accepts callable submissions and represents their later outcomes with futures.
- **Exponential backoff:** retry policy increasing delay multiplicatively across attempts.
- **Fairness:** progress policy governing how contending participants receive opportunities or resources.
- **Fan-out:** decomposition of one operation into several child operations whose outcomes are later combined.
- **Fast path:** specialised route handling a common case with less work while a general route preserves full semantics.
- **Fault isolation:** containment reducing the effects one component’s failure has on another.
- **Flame graph:** aggregate sampled-stack visual whose frame width represents sample proportion.
- **Foreign-function interface (FFI):** mechanism for calling code through another language or platform’s binary interface.
- **Fork:** process start mechanism creating a child from a snapshot-like inheritance of the current process.
- **Forkserver:** process start mechanism asking a dedicated server process to fork children.
- **Fragmentation:** unusable or unreleasable gaps caused by allocation sizes and lifetimes within managed memory regions.
- **Free-threaded build:** CPython configuration capable of operating without the traditional global interpreter lock.
- **Future:** object representing a result that may later succeed, fail, or be cancelled.
- **Generator:** resumable iterator whose execution suspends at yields.
- **GIL:** global interpreter lock conventionally limiting simultaneous Python-code execution within one CPython interpreter.
- **Graceful degradation:** intentional delivery of a reduced but explicitly valid service under resource pressure.
- **Graceful shutdown:** ordered cessation that stops admission, resolves owned work, and closes resources under a bounded policy.
- **Gustafson’s law:** scaled-workload model showing how parallel speedup can grow when parallel work increases with processor count.
- **Happens-before relation:** formal or protocol-defined ordering establishing which effects must be visible before another event.
- **Head-of-line blocking:** delay imposed on later work by an earlier slow item in an ordered queue or channel.
- **Idempotency:** property that repeating an operation has the same relevant effect as performing it once.
- **Idempotency key:** stable request identity enabling a receiver to deduplicate repeated logical operations.
- **Immutability:** inability to change an object’s value through its interface after construction.
- **Inclusive time:** time attributed to a unit together with its called descendants.
- **Independent variable:** experimental factor deliberately changed to study its effect.
- **Interleaving:** ordering formed by steps selected from several concurrent activities.
- **Inter-process communication (IPC):** transfer of data or signals across process boundaries.
- **I/O-bound workload:** workload whose progress is principally constrained by waiting for input/output in the observed environment.
- **Isolation:** separation limiting direct state sharing or failure propagation.
- **Jitter:** random variation added to retry or scheduling delay to reduce synchronised bursts.
- **Join:** operation waiting for an owned thread, process, task, or queue-accounting state to complete.
- **Just-in-time compiler (JIT):** compiler generating specialised code while the program is executing.
- **Latency:** elapsed duration from a defined operation start to a defined outcome.
- **Laziness:** postponement of computation until its result is demanded.
- **Linearisation point:** conceptual instant at which a linearizable operation appears to take effect.
- **Linearizability:** consistency property making each operation appear instantaneous between invocation and response while preserving real-time order.
- **Little’s law:** stable-system relation \(L=\lambda W\) among average population, arrival rate, and average residence time.
- **Live set:** storage occupied by data still needed for possible correct future execution.
- **Livelock:** continuing activity that repeatedly reacts but performs no required useful progress.
- **Load shedding:** deliberate rejection or loss of excess work to preserve bounded useful service.
- **Lock:** synchronisation object controlling entry to operations protected by a shared protocol.
- **Lock granularity:** amount of state or work governed by one lock acquisition.
- **Lock-free progress:** system-wide progress guarantee that some operation completes despite delay of individual participants.
- **Lock ordering:** protocol acquiring several locks according to a global acyclic order.
- **Logical time:** ordering model based on causal or program events rather than physical timestamps alone.
- **Memory-bound workload:** workload principally limited by memory latency or bandwidth in the observed environment.
- **Memory leak:** unintended retention whose lifetime exceeds the program’s need.
- **Memory view:** Python object exposing a view onto a buffer without necessarily copying its bytes.
- **Microbenchmark:** benchmark of a small isolated operation or code region.
- **Monotonic clock:** clock guaranteed not to move backwards within its specified domain.
- **Multiprocessing:** execution using several operating-system processes with isolated heaps by default.
- **Mutual exclusion:** property that at most one participant enters a protected region or owns a resource at a time.
- **Native extension:** compiled module integrating native machine code with a Python implementation.
- **Nondeterminism:** admission of more than one observable execution outcome or order under a contract.
- **Obstruction-free progress:** guarantee that an operation completes if it eventually runs in isolation long enough.
- **Open-loop load:** load whose arrivals are scheduled independently of prior request completion.
- **Operating-system thread:** schedulable execution stream within a process, sharing the process address space.
- **Oversubscription:** presence of materially more runnable computational activities than useful processing capacity.
- **Parallelism:** simultaneous execution on multiple processing resources.
- **Partial order:** ordering in which some pairs of events need not be comparable.
- **Percentile:** distribution value at or below which a stated proportion of observations falls under a specified estimator.
- **Pickling:** Python-specific object serialisation protocol, unsuitable for untrusted input.
- **Pipeline:** staged computation in which outputs from one stage feed a later stage.
- **Precision:** repeatability or fine distinction of measurements, not necessarily their accuracy.
- **Pre-emption:** suspension of an activity by a scheduler without an explicit cooperative yield.
- **Priority inversion:** delay of high-priority work because a lower-priority participant holds a needed resource.
- **Process:** operating-system execution and resource-isolation container with its own address space by default.
- **Process pool:** reusable bounded group of worker processes accepting submitted operations.
- **Profiler:** instrument attributing resource use or observed execution to program locations and call paths.
- **Progress property:** statement about whether and under what scheduling assumptions desired completion eventually occurs.
- **Queue utilisation:** offered demand relative to the service capacity of a queueing resource under a stated model.
- **Race condition:** violation of correctness under some uncontrolled relative timing of concurrent operations.
- **Rate limit:** bound on starts, completions, or other events per interval.
- **Ready:** eligible to execute once assigned a processing resource.
- **Re-entrancy:** entry into code again before an earlier invocation has finished, possibly through callbacks or recursive control.
- **Reference ownership:** protocol determining which component keeps an object or native resource alive and must release it.
- **Relative timeout:** duration budget beginning when a particular timeout is established.
- **Resident set size (RSS):** operating-system-accounted memory pages resident for a process under platform-specific rules.
- **Retry amplification:** ratio of physical attempts to original logical operations.
- **Running:** state in which an activity is currently executing instructions on a processor.
- **Safety property:** property stating that a prohibited state or event never occurs.
- **Sampling profiler:** profiler estimating execution-time attribution from periodic observations.
- **Schedule:** one permitted ordering and resource assignment of execution steps.
- **Scheduler:** mechanism selecting which eligible activity may advance.
- **Semaphore:** synchronisation counter admitting at most a configured number of simultaneous holders.
- **Sentinel:** distinguished message representing control information such as end-of-stream.
- **Serial fraction:** portion of a workload not accelerated by the parallel mechanism under analysis.
- **Serialisation:** conversion of state to a transferable or persistent representation under a schema.
- **Service demand:** resource time required by one unit of work at a specified resource.
- **Service-level indicator (SLI):** measured quantity representing a service property.
- **Service-level objective (SLO):** target range or threshold for an SLI over a stated interval.
- **Shared memory:** memory region deliberately addressable by more than one process or execution context.
- **Shielding:** preventing outer cancellation from automatically cancelling a particular inner awaitable while retaining ownership obligations.
- **Span:** total cost along the longest dependency chain in a parallel computation.
- **Spawn:** process start mechanism launching a fresh interpreter and importing required program state.
- **Speedup:** ratio of baseline time to changed-system time for equivalent work under specified conditions.
- **Spill:** transfer of waiting work to another storage tier, often durable storage.
- **Starvation:** indefinite failure of one participant to progress while others continue.
- **Statistical significance:** evidence, under a statistical model, against a null explanation; not a measure of practical value.
- **Structured concurrency:** organisation in which child lifetimes, results, and failures remain within an explicit owning scope.
- **Suspension point:** location at which an activity can pause and allow another to run.
- **Synchronisation:** mechanism establishing exclusion, ordering, notification, or visibility among activities.
- **Task:** scheduled coroutine execution whose outcome and cancellation state are retained.
- **Task confinement:** mutable-state ownership restricted to one logical task.
- **Task group:** asynchronous context owning a related set of child tasks through completion or failure.
- **Thread:** execution stream sharing its process’s address space and resources.
- **Thread confinement:** mutable-state ownership restricted to one thread.
- **Thread-local storage:** values separately associated with each operating-system thread.
- **Throughput:** completed work per unit time.
- **Timeout:** policy action triggered when incompletion exceeds a duration or deadline.
- **Time-of-check to time-of-use (TOCTOU):** race between testing a condition and acting under the assumption it remains true.
- **Token bucket:** rate-control model accumulating tokens at a rate up to a burst capacity and consuming one per admitted event.
- **Trace:** timestamped record linking operations or spans across an execution path.
- **Transactional store:** storage system providing stated atomicity, consistency, isolation, and durability behaviours for grouped operations.
- **Utilisation:** fraction of a resource’s available capacity occupied over an interval.
- **Vectorisation:** expression of operations over collections so a specialised implementation can process multiple elements in bulk.
- **Virtual memory size:** mapped address-space extent, not necessarily physically resident memory.
- **Wait-for graph:** directed graph whose edges represent participants waiting for resources held by others.
- **Wait-free progress:** per-operation guarantee of completion within a bounded number of its own steps under the model.
- **Wall-clock time:** elapsed real time between two observations, including execution and waiting.
- **Weak reference:** reference that does not by itself keep its target alive.
- **Work:** total operations performed across activities in a parallel-computation model.
- **Workload:** specified population and distribution of inputs, operations, arrival patterns, and system state used for analysis or measurement.
