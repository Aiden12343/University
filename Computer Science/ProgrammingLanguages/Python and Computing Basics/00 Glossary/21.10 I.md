# 21.10 I

- **IaC:** version-controlled machine-readable representation of infrastructure state. *(Introduced §20.38.)*
- **IaC state:** persistent mapping and attributes connecting infrastructure declarations to remote resource identities. *(Introduced §20.38.)*
- **IAM:** identity and access management mechanisms mapping principals to permitted actions on resources under conditions. *(Introduced §20.38.)*
- **Idempotency:** property that repeated application of the same logical operation has the same intended effect as one application under its contract. *(Introduced §20.38.)*
- **Idempotency key:** caller- or operation-scoped identifier used to recognise and reconcile duplicate logical requests. *(Introduced §20.38.)*
- **Idempotent operation:** operation whose intended effect after repetition equals its effect after one performance. *(Introduced §18.36.)*
- **Identifier:** source text usable as a name under lexical and grammatical rules. *(Introduced §5.22.)*
- **Identity:** the property distinguishing one object from every other object during its lifetime. *(Introduced §5.22.)*
- **Image:** immutable layered filesystem and metadata used to instantiate containers. *(Introduced §20.38.)*
- **Image index:** OCI object associating multiple platform-specific image manifests with operating-system and architecture descriptors. *(Introduced §20.38.)*
- **Immediate operand:** an operand value encoded within an instruction. *(Introduced §2.17.)*
- **Immortal object:** CPython implementation object whose lifetime bookkeeping is arranged not to reach ordinary deallocation. *(Introduced §15.23.)*
- **Immutable:** unable to change value after construction. *(Introduced §5.22.)*
- **Immutable artifact:** artifact whose accepted identity cannot be silently rebound to different bytes after publication. *(Introduced §20.38.)*
- **Implementation:** software realising the semantics of a language or abstract interface. *(Introduced §4.15.)*
- **Import package:** a Python module capable of containing submodules. *(Introduced §4.15.)*
- **Incident:** policy-threatening event requiring coordinated investigation and response. *(Introduced §19.34.)*
- **Incident commander:** role coordinating incident objectives, decisions, roles, cadence, and communication. *(Introduced §20.38.)*
- **Incremental backup:** backup containing changes since a preceding backup in a defined chain. *(Introduced §20.38.)*
- **Index:** ordered labels attached to a pandas axis and used in alignment. *(Introduced §16.31.)*
- **Index (Git):** staging state proposed for the next commit; distinct from a collection index or database index. *(Introduced §12.26.)*
- **Induction:** proof from base cases and preservation from one case to the next. *(Introduced §13.22.)*
- **Infinite loop:** repetition that does not reach an ordinary exit. *(Introduced §6.20.)*
- **Information state:** a distinguishable condition used to represent a possibility. *(Introduced §1.14.)*
- **Infrastructure as code:** version-controlled machine-readable declaration and controlled reconciliation of infrastructure resources. *(Introduced §20.38.)*
- **Ingress:** traffic entering a workload, network segment, or other defined boundary. *(Introduced §20.38.)*
- **Inheritance:** derivation of a class from one or more bases under Python’s type and lookup relations. *(Introduced §9.23.)*
- **Init system:** operating-system facility starting, supervising, ordering, and stopping system services. *(Introduced §20.38.)*
- **Injection:** unintended interpretation of untrusted data as code or command structure. *(Introduced §18.36.)*
- **Input/output (I/O):** exchange of represented information with external devices or systems. *(Introduced §1.14.)*
- **Instance:** an object whose type is a given class. *(Introduced §9.23.)*
- **Instance attribute:** attribute state owned by an individual instance. *(Introduced §9.23.)*
- **Instruction:** an encoded operation defined by a processor architecture. *(Introduced §1.14.)*
- **Instruction register:** processor storage holding the instruction currently being handled. *(Introduced §1.14.)*
- **Instruction set architecture (ISA):** the machine-level contract visible to software. *(Introduced §1.14.)*
- **Integration test:** test of cooperation across real component boundaries. *(Introduced §12.26.)*
- **Integrity:** prevention or detection of unauthorised alteration. *(Introduced §19.34.)*
- **Interface:** a boundary through which components exchange values, effects, or requests. *(Introduced §3.16.)*
- **Interpretation:** a rule assigning meaning to a representation. *(Introduced §1.14.)*
- **Interpreter:** a program carrying out behaviour described by another program representation. *(Introduced §2.17.)*
- **Interrupt:** an event causing processing to enter a designated handler. *(Introduced §1.14.)*
- **Introspection:** programmatic examination of runtime program objects and structure. *(Introduced §8.20.)*
- **Invariant:** a property preserved at designated points of an algorithm. *(Introduced §3.16.)*
- **Inventory drift:** existence of resources outside the declared management inventory or ownership model. *(Introduced §20.38.)*
- **IP address:** network-layer address used for packet routing. *(Introduced §18.36.)*
- **Isolation:** restriction of visibility, communication, authority, resource use, or failure propagation between subjects. *(Introduced §20.38.)*
- **Iterable:** an object from which an iterator can be requested. *(Introduced §6.20.)*
- **Iterator:** a stateful object producing successive values and signalling exhaustion. *(Introduced §6.20.)*
