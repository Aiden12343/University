# 21.13 L

- **Label cardinality:** count of distinct metric-series combinations created by label values. *(Introduced §20.38.)*
- **Lambda expression:** expression syntax creating a one-expression function. *(Introduced §8.20.)*
- **Last-known-good:** previously validated immutable configuration or policy version retained for bounded fallback. *(Introduced §20.38.)*
- **Late binding:** closure behaviour in which a retained binding is consulted when the function runs, not copied when created. *(Introduced §8.20.)*
- **Latency:** elapsed time from request to result. *(Introduced §1.14.)*
- **Layer-4 load balancer:** distributor operating primarily on network and transport connection information. *(Introduced §20.38.)*
- **Layer-7 load balancer:** distributor parsing an application protocol to make content-aware routing or policy decisions. *(Introduced §20.38.)*
- **Lazy evaluation:** delaying work until its result is requested. *(Introduced §6.20.)*
- **Learning rate:** scale applied to an optimisation update. *(Introduced §17.37.)*
- **Least privilege:** granting only the authority needed for a task, duration, and scope. *(Introduced §19.34.)*
- **LEGB:** summary of local, enclosing, global, and built-in name resolution. *(Introduced §8.20.)*
- **Lexicographic order:** sequence order determined by the first unequal corresponding elements, then length. *(Introduced §7.18.)*
- **Linked list:** nodes connected by references rather than contiguous positional storage. *(Introduced §13.22.)*
- **Linker:** a program combining translated units, resolving symbols, and applying relocations. *(Introduced §2.17.)*
- **Liskov substitution principle:** requirement that subtype objects preserve the behavioural expectations of their supertype interface. *(Introduced §9.23.)*
- **List:** Python’s mutable sequence type, implemented in CPython as a dynamic reference array. *(Introduced §7.18.)*
- **Literal:** source syntax denoting a value construction or retrieval. *(Introduced §5.22.)*
- **Livelock:** continuing concurrent activity without useful progress. *(Introduced §14.24.)*
- **Liveness:** health dimension asking whether local restart is an appropriate remedy for the component's present state. *(Introduced §20.38.)*
- **Load balancer:** component distributing connections or operations among eligible backends under an algorithm and health model. *(Introduced §20.38.)*
- **Load factor:** occupancy measure relating stored entries to hash-table capacity. *(Introduced §13.22.)*
- **Load shedding:** deliberate early rejection or deferral of selected work to preserve capacity for admitted work. *(Introduced §20.38.)*
- **Loader:** system machinery arranging a program’s executable representation into a process. *(Introduced §2.17, §10.18.)*
- **Locality:** tendency for access to recur in time or nearby addresses. *(Introduced §1.14.)*
- **Lock:** synchronisation object controlling entry to protected operations. *(Introduced §14.24.)*
- **Lock file:** a record of an exact or constrained dependency solution for reproducible reconstruction. *(Introduced §4.15.)*
- **Logic gate:** a component implementing a Boolean function. *(Introduced §1.14.)*
- **Logic level:** a permitted signal range interpreted as a logical value. *(Introduced §1.14.)*
- **Logical service:** stable service identity represented independently of its changing runtime endpoint set. *(Introduced §20.38.)*
- **Long-lived connection:** connection persisting across many operations or substantial time, complicating balancing, draining, and endpoint change. *(Introduced §20.38.)*
- **Loss function:** numerical penalty comparing prediction with target. *(Introduced §17.37.)*
