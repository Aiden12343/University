# 21.14 M

- **MAC:** secret-key tag providing message integrity and authentication among key holders. *(Introduced §19.34.)*
- **Machine code:** ISA-specific encoded instructions. *(Introduced §2.17.)*
- **Machine learning:** computational improvement on a defined task from data under a performance criterion. *(Introduced §17.37.)*
- **Main memory:** addressable working storage holding active instructions and data. *(Introduced §1.14.)*
- **Manifest digest:** content digest identifying an OCI or similar manifest that in turn identifies configuration and component objects. *(Introduced §20.38.)*
- **Mapping:** a collection associating keys with values. *(Introduced §7.18.)*
- **Marginal cost:** additional cost attributable to one more selected unit of demand or capacity. *(Introduced §20.38.)*
- **Materialisation:** constructing and retaining a complete concrete collection from an iterable. *(Introduced §6.20.)*
- **Measurement scale:** structure determining meaningful comparisons and operations on recorded values. *(Introduced §16.31.)*
- **Memoisation:** retention of results keyed by inputs to avoid repeated computation. *(Introduced §8.20.)*
- **Memory hierarchy:** storage levels organised by speed, capacity, cost, and persistence. *(Introduced §1.14.)*
- **Memory leak:** unintended retention beyond required lifetime. *(Introduced §14.24.)*
- **Memory limit:** enforced bound on memory use whose breach can cause reclamation, throttling under some systems, or abrupt termination. *(Introduced §20.38.)*
- **Metaclass:** the class of a class; an object controlling class construction. *(Introduced §9.23.)*
- **Metamorphic relation:** expected relationship between outputs under a defined input transformation. *(Introduced §12.26.)*
- **Method resolution order:** the linear order used to search classes for attributes and cooperative methods. *(Introduced §9.23.)*
- **Metric:** numeric observation or aggregation over time with defined name, unit, labels, and semantics. *(Introduced §20.38.)*
- **Microbenchmark:** measurement of a small isolated operation. *(Introduced §14.24.)*
- **Migration:** versioned transformation of database schema or managed data state. *(Introduced §18.36.)*
- **Mini-batch:** subset used to estimate an optimisation update. *(Introduced §17.37.)*
- **Missing value:** marker that an ordinary observed value is absent under a stated convention. *(Introduced §16.31.)*
- **Mnemonic:** a symbolic name for an operation, commonly used in assembly. *(Introduced §2.17.)*
- **Mock:** a test double configured with and verifying expected interactions. *(Introduced §12.26.)*
- **Model:** selected mapping from represented inputs to outputs. *(Introduced §17.37.)*
- **Module:** a runtime Python object serving as a loaded namespace. *(Introduced §10.18.)*
- **Monotonic transition:** state change that accumulates information or progress without requiring reversal of established facts. *(Introduced §20.38.)*
- **Multi-stage build:** container build using separate stages so build tools and intermediate material need not enter the final runtime image. *(Introduced §20.38.)*
- **Multi-window burn alert:** alert combining short and long observation windows to detect fast or sustained SLO-budget consumption. *(Introduced §20.38.)*
- **Mutable:** able to change value while retaining identity. *(Introduced §5.22.)*
- **Mutable tag:** readable artifact reference whose target digest is permitted to change. *(Introduced §20.38.)*
- **Mutation testing:** evaluation of a test suite by deliberate small program changes. *(Introduced §12.26.)*
