# 21.17 P

- **p99 latency:** 99th percentile of a precisely selected latency observation population under a named quantile method. *(Introduced §20.38.)*
- **Package:** a module capable of containing submodules. *(Introduced §10.18.)*
- **Package manager:** software automating acquisition and management of distributed software. *(Introduced §4.15.)*
- **Page:** a fixed-size virtual-memory mapping unit. *(Introduced §2.17.)*
- **Page table:** data describing virtual-memory mappings and permissions. *(Introduced §2.17.)*
- **Pagination:** division of a remote collection response into pages connected by continuation state or tokens. *(Introduced §20.38.)*
- **Parallelism:** simultaneous execution on multiple processing resources. *(Introduced §14.24.)*
- **Parameter:** a name in a callable definition bound during a call. *(Introduced §8.20, §16.31, §17.37.)*
- **Partial correctness:** the property that any terminating result satisfies the specification. *(Introduced §3.16.)*
- **Password hashing:** deliberately expensive salted transformation for storing password verifiers. *(Introduced §19.34.)*
- **Path:** a structured description used to resolve a filesystem location. *(Introduced §2.17.)*
- **Path traversal:** escape from an intended filesystem root through manipulated path semantics. *(Introduced §19.34.)*
- **Pattern matching:** structural selection and decomposition under `match`/`case` grammar. *(Introduced §6.20.)*
- **Persistent volume:** storage resource whose lifecycle and identity can outlive an individual scheduled Pod. *(Introduced §20.38.)*
- **Pickle:** Python-specific object serialisation protocol capable of invoking reconstruction code. *(Introduced §11.20.)*
- **Pipeline:** a composition connecting one process’s output stream to another’s input stream. *(Introduced §3.16, §17.37, §20.37.)*
- **Pipelining:** overlapping stages of multiple instructions. *(Introduced §1.14.)*
- **Plan:** proposed set of actions derived before mutation from desired state, recorded state, and observations. *(Introduced §20.38.)*
- **Platform manifest:** platform-specific artifact manifest selected from a multi-platform index. *(Introduced §20.38.)*
- **Pod:** Kubernetes scheduling and lifecycle unit containing one or more containers sharing selected namespaces and volumes. *(Introduced §20.38.)*
- **Pod disruption budget:** Kubernetes policy limiting selected voluntary concurrent Pod disruptions for a workload. *(Introduced §20.38.)*
- **Point-in-time recovery:** restoration of state to a selected recoverable point using a consistent base and compatible change-log sequence. *(Introduced §20.38.)*
- **Policy as code:** machine-evaluated representation of organisational or technical constraints applied to artifacts, plans, or runtime state. *(Introduced §20.38.)*
- **Polling:** repeatedly checking whether an event or device condition is present. *(Introduced §1.14.)*
- **Polymorphism:** use of one operation across differing types under a shared contract. *(Introduced §9.23.)*
- **Population:** complete collection defined by an inferential question. *(Introduced §16.31.)*
- **Port:** transport-layer number directing traffic to an application endpoint. *(Introduced §18.36.)*
- **Positional-only parameter:** a parameter that cannot receive an argument by keyword. *(Introduced §8.20.)*
- **Post-incident review:** evidence-based analysis of impact, timeline, contributing conditions, response, learning, and verified corrective action. *(Introduced §20.38.)*
- **Postcondition:** a property required after successful completion. *(Introduced §3.16.)*
- **Precedence:** grammar determining grouping among different operator classes. *(Introduced §5.22.)*
- **Precondition:** a property required before an operation begins. *(Introduced §3.16.)*
- **Predictive scaling:** allocation of capacity in advance based on forecast or known schedule rather than only current feedback. *(Introduced §20.38.)*
- **Principal:** identity recognised by an authentication and authorisation system. *(Introduced §18.36.)*
- **Priority queue:** collection removing an item by priority rather than insertion time. *(Introduced §13.22.)*
- **Probe:** periodic diagnostic whose result influences lifecycle or routing decisions for a workload. *(Introduced §20.38.)*
- **Problem instance:** one concrete admitted input to a computational problem. *(Introduced §3.16.)*
- **Process:** a protected running execution environment containing program state and resources. *(Introduced §2.17.)*
- **Process contract:** explicit agreement covering process start, identity, inputs, readiness, health, shutdown, state, output, resources, and failure. *(Introduced §20.38.)*
- **Process supervisor:** parent or service manager controlling process lifecycle, restart, environment, and selected resources. *(Introduced §20.38.)*
- **Profile:** sampled or measured attribution of CPU, allocation, lock, or wall time to code locations. *(Introduced §20.38.)*
- **Profiler:** tool attributing resource use to program locations or call paths. *(Introduced §14.24.)*
- **Program:** a representation of algorithms and associated data processable by a computational system. *(Introduced §3.16.)*
- **Program counter (PC):** processor state designating the next instruction address. *(Introduced §1.14.)*
- **Progressive delivery:** controlled expansion of a release's exposure according to evidence and guardrails. *(Introduced §20.38.)*
- **Project directory:** a chosen filesystem root for one coherent body of source, configuration, tests, and documentation. *(Introduced §4.15.)*
- **Promotion:** approval of an unchanged identified artifact for a broader environment or use. *(Introduced §20.38.)*
- **Prompt:** terminal text indicating readiness for command input. *(Introduced §3.16.)*
- **Propagation delay:** finite time between an input change and valid corresponding output. *(Introduced §1.14.)*
- **Property:** a descriptor exposing managed attribute syntax through getter, setter, or deleter functions. *(Introduced §9.23.)*
- **Property-based testing:** generated-input testing of general behavioural properties. *(Introduced §12.26.)*
- **Protocol:** a behavioural interface defined by supported operations. *(Introduced §9.23, §18.36.)*
- **Provenance:** evidence describing origin, identity, and transformations of source, artifact, data, or configuration. *(Introduced §20.38.)*
- **Provisioning:** creation or configuration of infrastructure resources to satisfy declared or requested state. *(Introduced §20.38.)*
- **Proxy-side discovery:** endpoint resolution and selection performed by a proxy rather than each application client. *(Introduced §20.38.)*
- **Pseudo-polynomial:** polynomial in a numeric value but potentially exponential in that value’s encoded bit length. *(Introduced §13.22.)*
- **Pseudorandom number generator:** deterministic state machine producing a statistically designed sequence. *(Introduced §16.31.)*
- **Public API:** the supported interface external callers may depend upon. *(Introduced §10.18.)*
- **Pure function:** a function whose specified result depends only on arguments and that has no intentional externally observable effects under a stated model. *(Introduced §8.20.)*
- **Python:** the programming language defined by its syntax and semantic documentation, distinct from any one implementation. *(Introduced §4.15.)*
