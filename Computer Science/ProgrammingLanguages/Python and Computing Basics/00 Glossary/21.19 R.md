# 21.19 R

- **Race condition:** correctness dependence on uncontrolled relative timing. *(Introduced §14.24.)*
- **Radix:** the base of a positional numeral system. *(Introduced §1.14.)*
- **Reachable:** designatable through a chain of live references from program roots. *(Introduced §5.22.)*
- **Readiness:** health dimension asking whether an instance should receive new work at the present time. *(Introduced §20.38.)*
- **README:** a durable document explaining a project’s purpose and operating contract. *(Introduced §4.15.)*
- **Reconciliation:** repeated comparison and action intended to converge observed state towards desired state. *(Introduced §20.38.)*
- **Reconciliation loop:** controller cycle of observation, difference calculation, bounded action, and renewed observation. *(Introduced §20.38.)*
- **Reconnection storm:** synchronised creation of replacement connections after many existing connections close or fail together. *(Introduced §20.38.)*
- **Recovery point objective:** targeted maximum data-loss interval measured backwards from a disruption. *(Introduced §20.38.)*
- **Recovery time objective:** targeted maximum time to restore a defined service capability after disruption. *(Introduced §20.38.)*
- **Recursion:** solution of a problem through calls on smaller or structurally simpler instances of the same operation. *(Introduced §8.20.)*
- **Reduction:** operation combining an array along one or more axes into fewer values. *(Introduced §16.31.)*
- **Reference:** a relationship by which program state designates an object. *(Introduced §5.22.)*
- **Reference counting:** lifetime mechanism tracking strong ownership and deallocating when it reaches zero. *(Introduced §15.23.)*
- **Register:** small, fast processor storage treated as a multi-bit unit. *(Introduced §1.14.)*
- **Regression test:** test preserving established behaviour after a change or defect repair. *(Introduced §12.26.)*
- **Regularisation:** constraint or penalty discouraging selected model complexity. *(Introduced §17.37.)*
- **Relative import:** import resolved from the current package using leading dots. *(Introduced §10.18.)*
- **Release:** act of making a capability available to its intended users or workload population. *(Introduced §20.38.)*
- **Relocation:** a recorded location requiring address adjustment after placement is known. *(Introduced §2.17.)*
- **REPL:** read–evaluate–print loop; an interactive program-evaluation session. *(Introduced §4.15.)*
- **Replica:** one runtime copy of a workload or data set under a replication and identity model. *(Introduced §20.38.)*
- **Representation:** a physical or symbolic arrangement interpreted as standing for something. *(Introduced §1.14, §18.36.)*
- **Reproducible build:** build capable of yielding bit-for-bit equivalent output from the same declared inputs under specified conditions. *(Introduced §20.38.)*
- **Request idempotency:** convergence of repeated attempts representing the same logical request to one intended effect and result policy. *(Introduced §20.38.)*
- **Requirement:** a capability, property, or constraint a system must satisfy. *(Introduced §12.26.)*
- **Residual risk:** risk remaining after selected controls. *(Introduced §19.34.)*
- **Resolver:** tool selecting dependency versions satisfying declared constraints. *(Introduced §10.18.)*
- **Resource exhaustion:** failure or degradation caused by consumption of a bounded computational, storage, network, or external quota resource. *(Introduced §20.38.)*
- **Resource limit:** enforced maximum or control on resource consumption, with resource-specific breach behaviour. *(Introduced §20.38.)*
- **Resource request:** capacity declaration used by an orchestrator for scheduling, reservation, or quality-of-service classification. *(Introduced §20.38.)*
- **REST:** architectural style defined by constraints on distributed hypermedia systems. *(Introduced §18.36.)*
- **Restart storm:** correlated rapid process restarts that add load and obscure a persistent failure. *(Introduced §20.38.)*
- **Resurrection:** making an otherwise finalising object reachable again. *(Introduced §15.23.)*
- **Retention:** policy governing how long artifacts, data, evidence, or backups remain available and when they are deleted. *(Introduced §20.38.)*
- **Retry:** new attempt of a logical operation after selected non-success or uncertainty. *(Introduced §20.38.)*
- **Retry budget:** bound on retry attempts or retry load relative to original work over a scope and period. *(Introduced §20.38.)*
- **Return value:** the object supplied when a call completes normally. *(Introduced §8.20.)*
- **Reverse proxy:** intermediary accepting client requests and forwarding them to upstream servers. *(Introduced §18.36.)*
- **Risk:** expected loss over a defined data-generating distribution. *(Introduced §17.37.)*
- **Roll-forward:** deployment of a newer corrective state when returning to an older state is unsafe or impossible. *(Introduced §20.38.)*
- **Rollback:** replacement of selected running artifact or configuration with a prior version under compatibility constraints. *(Introduced §20.38.)*
- **Rolling deployment:** gradual replacement of subsets of a workload while old and new versions coexist. *(Introduced §20.38.)*
- **Rootless container:** container runtime arrangement operating without host-root authority, commonly using user namespaces. *(Introduced §20.38.)*
- **Routing:** mapping request method and target pattern to application behaviour. *(Introduced §18.36.)*
- **Routing table:** ordered or prioritised mapping from destination prefixes to next-hop or interface decisions. *(Introduced §20.38.)*
- **RPO:** targeted maximum interval of data loss after disruption. *(Introduced §20.38.)*
- **RTO:** targeted maximum time to restore service after disruption. *(Introduced §20.38.)*
- **Runbook:** versioned human or executable procedure for a recurring operational condition, including evidence and stop rules. *(Introduced §20.38.)*
- **Runtime:** execution environment and mechanisms instantiating an artifact as processes with configured resources and authority. *(Introduced §20.38.)*
- **Runtime contract:** explicit combined specification of workload identity, filesystem, kernel, network, resources, lifecycle, and evidence. *(Introduced §20.38.)*
