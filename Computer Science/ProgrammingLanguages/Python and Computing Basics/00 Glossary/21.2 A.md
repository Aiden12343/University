# 21.2 A

- **ABI:** application binary interface; low-level binary calling and layout contract. *(Introduced §10.18.)*
- **Absolute import:** import naming a module from an import-system root. *(Introduced §10.18.)*
- **Abstraction:** a model exposing selected properties while hiding details under a stated contract. *(Introduced §1.14.)*
- **Acceptance criterion:** observable condition by which a requirement is judged. *(Introduced §12.26.)*
- **Accumulator:** a register retaining an intermediate arithmetic result. *(Introduced §1.14.)*
- **Activation:** modification of a shell environment so commands preferentially select a virtual environment. *(Introduced §4.15.)*
- **Activation function:** nonlinear function applied to a unit’s affine input. *(Introduced §17.37.)*
- **Adaptive specialisation:** runtime replacement or configuration of generic interpreter operations for observed conditions under guards. *(Introduced §15.23.)*
- **Address:** a numeric designation for a memory or device location. *(Introduced §1.14.)*
- **Addressable memory:** storage whose locations can be selected by address. *(Introduced §1.14.)*
- **Addressing mode:** an ISA rule for locating an instruction operand. *(Introduced §2.17.)*
- **Adjacency list:** graph representation mapping vertices to neighbours. *(Introduced §13.22.)*
- **Adjacency matrix:** graph representation using a vertex-by-vertex edge table. *(Introduced §13.22.)*
- **Admission control:** decision performed before expensive work to accept, defer, prioritise, or reject a request under capacity and policy. *(Introduced §20.38.)*
- **AEAD:** authenticated encryption construction protecting plaintext and associated data integrity under a secret key. *(Introduced §19.34.)*
- **Aggregation:** operation reducing multiple observations to fewer summary values. *(Introduced §16.31.)*
- **Ahead-of-time compilation:** translation performed substantially before execution. *(Introduced §2.17.)*
- **Alert:** notification produced when evidence satisfies a condition requiring timely human or automated action. *(Introduced §20.38.)*
- **Alert fatigue:** degradation of response caused by excessive, low-value, repetitive, or unactionable alerts. *(Introduced §20.38.)*
- **Algorithm:** a finite, unambiguous general method intended to satisfy a specification. *(Introduced §3.16.)*
- **Alias:** an additional reference or access path to the same object. *(Introduced §5.22.)*
- **Aliasing:** the condition in which several references designate one object. *(Introduced §5.22.)*
- **Allocation:** assignment of shared resource or cost to an owner, service, tenant, or business purpose under a stated rule. *(Introduced §20.38.)*
- **ALU:** arithmetic logic unit; processor circuitry performing arithmetic and logical operations. *(Introduced §1.14.)*
- **Ambient state:** inherited or globally available process state not expressed explicitly in the immediate interface. *(Introduced §20.38.)*
- **Amortised complexity:** a bound distributing occasional expensive work across a sequence of operations. *(Introduced §7.18.)*
- **Application consistency:** recoverable relationship among application-level records and systems at a defined logical boundary. *(Introduced §20.38.)*
- **Argument:** an object supplied by a caller to a callable. *(Introduced §8.20.)*
- **Artifact:** versioned output of a build process intended for distribution, verification, or deployment. *(Introduced §20.38.)*
- **Artifact digest:** cryptographic content identifier computed over the exact bytes of an artifact. *(Introduced §20.38.)*
- **ASGI:** asynchronous Python server–application event interface. *(Introduced §18.36.)*
- **Assembler:** a program translating assembly source into machine code or object code. *(Introduced §2.17.)*
- **Assembly language:** architecture-specific symbolic notation closely corresponding to machine instructions. *(Introduced §2.17.)*
- **Asset:** something of value or requiring protection. *(Introduced §19.34.)*
- **Associativity:** grammar determining grouping among selected operators of equal precedence. *(Introduced §5.22.)*
- **AST:** abstract syntax tree; a structural representation of parsed source. *(Introduced §2.17.)*
- **Asymptotic notation:** notation classifying resource growth for large input size. *(Introduced §13.22.)*
- **Asyncio:** Python’s standard-library framework for event-loop-based asynchronous I/O. *(Introduced §14.24.)*
- **Atomic:** appearing indivisible relative to specified observers and a concurrency model. *(Introduced §7.18.)*
- **Atomic operation:** operation observed under its contract as occurring wholly or not at all, without an exposed intermediate state. *(Introduced §20.38.)*
- **Attack surface:** reachable interfaces through which system behaviour can be influenced. *(Introduced §19.34.)*
- **Attribute:** a named value resolved through an object and its type’s access protocol. *(Introduced §9.23.)*
- **Authentication:** establishment of a principal’s identity under a confidence model. *(Introduced §18.36.)*
- **Authorisation:** decision that a principal may perform an operation on a resource. *(Introduced §18.36.)*
- **Automatic differentiation:** systematic derivative computation by composing local operation rules. *(Introduced §17.37.)*
- **Autoscaling:** feedback or predictive mechanism adjusting allocated capacity according to measured or forecast demand. *(Introduced §20.38.)*
- **Availability zone:** provider-defined failure and placement domain within a region, whose independence must be assessed rather than assumed. *(Introduced §20.38.)*
- **Average cost:** total selected cost divided by the number of selected units over a period. *(Introduced §20.38.)*
- **Axis:** one index direction of a multidimensional array. *(Introduced §16.31.)*
