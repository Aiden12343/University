# 21.20 S

- **Safety property:** property stating that a prohibited condition never occurs. *(Introduced §14.24.)*
- **Salt:** unique non-secret input used to separate password hashes and defeat precomputation. *(Introduced §19.34.)*
- **Sample:** observed subset used to learn about a defined population. *(Introduced §16.31.)*
- **Saturation:** condition in which a constrained resource approaches or reaches its usable capacity and queueing or rejection grows. *(Introduced §20.38.)*
- **SBOM:** inventory of software components and versions in an artifact or system. *(Introduced §19.34.)*
- **Scale-to-zero:** elasticity policy removing all warm instances during idle periods and accepting subsequent cold-start behaviour. *(Introduced §20.38.)*
- **Scheduler:** OS machinery choosing which runnable thread executes. *(Introduced §2.17.)*
- **Schema:** declared structure, representation, constraints, and meaning of data fields. *(Introduced §16.31.)*
- **Script:** a source file intended to be executed as an entry program. *(Introduced §4.15.)*
- **Secret:** information whose disclosure grants authority or defeats a security property. *(Introduced §19.34.)*
- **Secret zero:** initial credential or trust basis by which a workload obtains further secrets or service authority. *(Introduced §20.38.)*
- **Semantic drift:** behavioural divergence caused by changed provider or platform semantics despite apparently equal visible configuration. *(Introduced §20.38.)*
- **Semantics:** the meanings assigned to admitted forms. *(Introduced §5.22.)*
- **Sequential circuit:** a circuit whose output or future behaviour depends on retained state as well as current input. *(Introduced §1.14.)*
- **Serialisation:** transformation of state into a storable or transmissible representation. *(Introduced §11.20.)*
- **Series:** pandas one-dimensional labelled array-like object. *(Introduced §16.31.)*
- **Service:** continuously or conditionally delivered capability exposed through a defined interface and operational obligation. *(Introduced §20.38.)*
- **Service account:** non-human principal representing a workload or automation under lifecycle and policy. *(Introduced §20.38.)*
- **Service contract:** complete behavioural and operational agreement covering interface, identity, state, objectives, failure, and support. *(Introduced §20.38.)*
- **Service discovery:** mapping from logical service identity to a changing set of candidate endpoints and metadata. *(Introduced §20.38.)*
- **Service manager:** operating-system or platform facility starting, stopping, supervising, and constraining service processes. *(Introduced §20.38.)*
- **Service mesh:** infrastructure layer using proxies and a control plane to apply transport, routing, identity, and telemetry policy among services. *(Introduced §20.38.)*
- **Service-level agreement:** formal agreement defining service measures, obligations, exclusions, and possible consequences. *(Introduced §20.38.)*
- **Service-level indicator:** quantitative measure of selected user-relevant service behaviour over an explicit population. *(Introduced §20.38.)*
- **Service-level objective:** target range or proportion for an SLI over a defined window. *(Introduced §20.38.)*
- **Session:** association of requests with server-recognised application state. *(Introduced §18.36.)*
- **Session affinity:** policy attempting to route related client operations to the same backend. *(Introduced §20.38.)*
- **Set:** Python’s mutable unordered collection of unique hashable elements. *(Introduced §7.18.)*
- **Shallow copy:** a new outer container initially retaining references to the same elements. *(Introduced §5.22.)*
- **Shared library:** a separately managed linked binary usable by multiple loaded programs. *(Introduced §2.17.)*
- **Shell:** a program interpreting command language and coordinating program execution. *(Introduced §3.16.)*
- **Short-circuit evaluation:** omitting a later operand when an earlier result determines the operation. *(Introduced §6.20.)*
- **Showback:** reporting attributed shared cost to an owner without transferring the charge into that owner's budget. *(Introduced §20.38.)*
- **Side effect:** an observable state change beyond producing an expression value. *(Introduced §5.22.)*
- **Sidecar:** auxiliary container sharing a Pod or equivalent lifecycle and selected namespaces with a primary workload. *(Introduced §20.38.)*
- **Signal:** a varying physical quantity used to convey information. *(Introduced §1.14.)*
- **Singleton:** a distinguished role for which one object instance is exposed. *(Introduced §5.22.)*
- **SLA:** formal service agreement that may include consequences. *(Introduced §20.38.)*
- **SLI:** quantitative measure of user-relevant service behaviour. *(Introduced §20.38.)*
- **Slice:** a sequence selection described by start, stop, and optional step. *(Introduced §7.18.)*
- **SLO:** target for an SLI over a defined population and interval. *(Introduced §20.38.)*
- **Slot:** a declared instance-storage location that can replace or constrain an ordinary instance dictionary. *(Introduced §9.23.)*
- **Snapshot:** point-referenced storage copy or view whose consistency and independence depend on the underlying system. *(Introduced §20.38.)*
- **Socio-technical system:** system whose outcomes arise from interaction among software, hardware, people, organisations, and procedures. *(Introduced §20.38.)*
- **Socket:** operating-system communication-endpoint abstraction. *(Introduced §18.36.)*
- **Soft keyword:** text given keyword meaning only in specified grammatical contexts. *(Introduced §5.22.)*
- **Software engineering:** disciplined software construction and evolution under requirements and change. *(Introduced §12.26.)*
- **Source distribution:** source archive intended for standardised building. *(Introduced §10.18.)*
- **Source file:** persistent text containing program source. *(Introduced §4.15.)*
- **Specialisation:** creation of code or representation optimised for established conditions. *(Introduced §2.17.)*
- **Specification:** a precise statement of required behaviour for admitted conditions. *(Introduced §3.16.)*
- **Split-horizon DNS:** name service returning different answers according to requester or network context. *(Introduced §20.38.)*
- **Spot capacity:** discounted interruptible compute capacity requiring workload tolerance of provider-initiated removal. *(Introduced §20.38.)*
- **Spy:** a test double recording interactions for later assertion. *(Introduced §12.26.)*
- **SSRF:** attacker influence over server-originated requests to unintended destinations. *(Introduced §18.36.)*
- **Stable sort:** a sort preserving input order among elements with equal comparison keys. *(Introduced §7.18.)*
- **Standard error:** the conventional process stream for diagnostics. *(Introduced §3.16, §16.31.)*
- **Standard input:** the conventional process stream for ordinary input. *(Introduced §3.16.)*
- **Standard output:** the conventional process stream for ordinary results. *(Introduced §3.16.)*
- **Startup probe:** health probe granting a workload a separate initialisation interval before ordinary liveness evaluation. *(Introduced §20.38.)*
- **Starvation:** indefinite lack of progress because others repeatedly receive resources. *(Introduced §14.24.)*
- **State:** retained information capable of affecting later behaviour. *(Introduced §1.14.)*
- **State transition:** a change from one retained condition to another. *(Introduced §1.14.)*
- **StatefulSet:** Kubernetes controller supplying ordered workload identity and persistent-volume relationships to replicas. *(Introduced §20.38.)*
- **Statement:** a complete instruction in Python’s execution grammar. *(Introduced §5.22.)*
- **Static configuration:** configuration applied only through process or workload start and replacement. *(Introduced §20.38.)*
- **Static method:** a function descriptor that suppresses automatic instance or class binding. *(Introduced §9.23.)*
- **Static type checker:** tool approximating type flows without executing every program path. *(Introduced §12.26.)*
- **Static validation:** examination of declarations or code without provisioning or executing the complete target system. *(Introduced §20.38.)*
- **Statistic:** numerical function of a sample. *(Introduced §16.31.)*
- **StopIteration:** the exception used at the iterator protocol boundary to signal exhaustion. *(Introduced §6.20.)*
- **Stored-program computer:** a computer that holds instruction representations in addressable memory. *(Introduced §1.14.)*
- **Stream:** an ordered flow of data available over time. *(Introduced §3.16.)*
- **Stride:** byte displacement for moving one element along an array axis. *(Introduced §16.31.)*
- **Strong reference:** reference retaining an object’s lifetime. *(Introduced §15.23.)*
- **Structural induction:** proof following the constructors of a recursive structure. *(Introduced §13.22.)*
- **Structured concurrency:** organisation in which child task lifetimes and failures remain within an owning scope. *(Introduced §14.24.)*
- **Structured logging:** event emission as stable named and typed fields rather than unparsed prose. *(Introduced §20.38.)*
- **Stub:** a test double supplying predetermined responses. *(Introduced §12.26.)*
- **Substitutability:** ability to use one object wherever another interface is expected without violating its contract. *(Introduced §9.23.)*
- **Suite:** a group of statements controlled by a compound-statement clause. *(Introduced §5.22.)*
- **Supervised learning:** learning from paired inputs and target outputs. *(Introduced §17.37.)*
- **Supervisor:** component controlling another process's start, observation, restart, and stop lifecycle. *(Introduced §20.38.)*
- **Supply chain:** path of sources, dependencies, tools, identities, and systems producing executable software. *(Introduced §19.34.)*
- **Symbol:** a named code or data entity used during translation and linking. *(Introduced §2.17.)*
- **Syntax:** the forms admitted by a language. *(Introduced §5.22.)*
- **Synthetic transaction:** controlled operation generated to test an end-to-end service path independently of organic user traffic. *(Introduced §20.38.)*
- **System call:** a controlled request by user space for a kernel service. *(Introduced §2.17.)*
- **Systems engineering:** design and operation of interacting software, hardware, networks, people, and procedures as a coherent service. *(Introduced §20.38.)*
