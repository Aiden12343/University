# 21.21 T

- **Tail latency:** latency behaviour in the upper quantiles of an operation distribution. *(Introduced §20.38.)*
- **Tail sampling:** trace-sampling decision made after observing enough of a trace to use outcome or latency criteria. *(Introduced §20.38.)*
- **Tail-call optimisation:** reuse or elimination of a caller frame for a call in final result position; not required by Python. *(Introduced §8.20.)*
- **Target:** outcome a supervised model is trained to predict. *(Introduced §17.37.)*
- **Target utilisation:** resource-use level an autoscaling controller seeks to maintain under its model. *(Introduced §20.38.)*
- **Task:** scheduled coroutine execution with retained outcome in asyncio. *(Introduced §14.24.)*
- **TCP:** transport protocol providing an ordered reliable byte stream between endpoints. *(Introduced §18.36.)*
- **Telemetry:** remotely collected metrics, events, traces, profiles, and associated metadata describing system behaviour. *(Introduced §20.38.)*
- **Temporary state:** short-lived data whose loss is acceptable under a stated operation but whose security and capacity remain governed. *(Introduced §20.38.)*
- **Tensor:** multidimensional numerical object with dtype, shape, layout, device, and optional gradient metadata. *(Introduced §17.37.)*
- **Terminal:** a text-oriented interface conveying input and displaying output. *(Introduced §3.16.)*
- **Termination:** completion after finitely many steps for the inputs under consideration. *(Introduced §3.16.)*
- **Termination grace period:** maximum interval granted for graceful shutdown before forced termination. *(Introduced §20.38.)*
- **Test:** an executable experiment comparing observation with an expected claim. *(Introduced §12.26.)*
- **Test double:** controlled replacement for a collaborator in a test. *(Introduced §12.26.)*
- **Test oracle:** an independent rule or source determining an expected result. *(Introduced §3.16.)*
- **Text stream:** stream applying character encoding/decoding and possible newline translation above bytes. *(Introduced §11.20.)*
- **Thread:** an execution sequence within a process. *(Introduced §2.17.)*
- **Threat:** potential cause of harm to an asset. *(Introduced §19.34.)*
- **Threat model:** explicit account of assets, actors, capabilities, boundaries, objectives, controls, and assumptions. *(Introduced §19.34.)*
- **Throttling:** deliberate limitation or delay of work when a quota, rate, or resource policy is reached. *(Introduced §20.38.)*
- **Throughput:** completed work per unit time. *(Introduced §14.24.)*
- **Time complexity:** growth of work with a defined input size. *(Introduced §7.18.)*
- **Time to live:** caching lifetime attached to a record before it should be refreshed under protocol and implementation rules. *(Introduced §20.38.)*
- **Time-based availability:** SLI sampling whether service behaviour is good across time intervals rather than weighting individual events. *(Introduced §20.38.)*
- **Time-of-check to time-of-use:** race between observing external state and later acting on the assumption that it is unchanged. *(Introduced §11.20.)*
- **TLS:** protocol establishing authenticated, confidential, integrity-protected transport under configured trust. *(Introduced §18.36.)*
- **Toil:** recurring manual, tactical, automatable operational work whose volume tends to grow with service scale. *(Introduced §20.38.)*
- **Token:** a classified lexical unit of source text. *(Introduced §2.17.)*
- **Tombstone:** durable marker recording logical deletion or completion so older state cannot silently resurrect an object. *(Introduced §20.38.)*
- **Topological order:** ordering of a DAG placing every predecessor before its successor. *(Introduced §13.22.)*
- **Topology spread:** scheduling policy distributing replicas across named failure or placement domains. *(Introduced §20.38.)*
- **Total correctness:** partial correctness together with termination. *(Introduced §3.16.)*
- **Trace:** causally related collection of spans representing the path of an operation through components. *(Introduced §20.38.)*
- **Trace context:** identifiers and flags propagated to relate distributed work into a trace. *(Introduced §20.38.)*
- **Traffic shifting:** controlled movement of request or connection exposure among backend populations or versions. *(Introduced §20.38.)*
- **Transaction:** grouped database operations governed by atomicity and isolation semantics. *(Introduced §18.36.)*
- **Transactional outbox:** pattern recording an intended external message in the same transaction as authoritative state, then publishing it idempotently. *(Introduced §20.38.)*
- **Transformer:** estimator that learns and applies a representation change. *(Introduced §17.37.)*
- **Transistor:** a semiconductor device allowing one electrical signal to control another current path. *(Introduced §1.14.)*
- **Transitive dependency:** a dependency required by another dependency. *(Introduced §4.15.)*
- **Trust boundary:** point at which authority or validation assumptions change. *(Introduced §19.34.)*
- **Trust graph:** model of artifacts, identities, components, and authority relationships on which a process or pipeline relies. *(Introduced §20.38.)*
- **Truth table:** an exhaustive mapping from Boolean input combinations to outputs. *(Introduced §1.14.)*
- **Truth testing:** the protocol mapping an object to a Boolean condition. *(Introduced §5.22.)*
- **Tuple:** Python’s immutable sequence of object references. *(Introduced §7.18.)*
- **Turing-complete:** able, given sufficient abstract resources, to simulate universal Turing computation. *(Introduced §3.16.)*
- **Two’s complement:** a conventional fixed-width signed-binary interpretation. *(Introduced §1.14.)*
- **Type:** the object property determining supported operations and behaviour. *(Introduced §5.22.)*
