# 21.23 V

- **Value:** an object’s abstract content or state under its type’s semantics. *(Introduced §5.22.)*
- **Variable:** in this work, a name capable of being bound and rebound; not an object-containing box. *(Introduced §5.22.)*
- **Variance:** relationship between generic and parameter subtype relations. *(Introduced §12.26.)*
- **Variant:** a well-founded measure that moves strictly towards a termination boundary. *(Introduced §3.16.)*
- **Vectorcall:** CPython calling convention designed to reduce temporary argument-container overhead. *(Introduced §15.23.)*
- **Vectorisation:** expression of bulk operations for execution by compiled or specialised kernels. *(Introduced §16.31.)*
- **Version:** an identifier for a software release under a project’s versioning policy. *(Introduced §4.15.)*
- **Version control:** system recording and relating project states over time. *(Introduced §12.26.)*
- **Version precondition:** requirement that observed object or state version still matches before a mutation proceeds. *(Introduced §20.38.)*
- **Vertical scaling:** changing resources allocated to an existing or replaced workload instance. *(Introduced §20.38.)*
- **View:** array object sharing element storage with another array. *(Introduced §16.31.)*
- **View object:** a live iterable view over selected state of another object. *(Introduced §7.18.)*
- **Virtual address:** a process-visible address translated under a mapping context. *(Introduced §2.17.)*
- **Virtual address space:** the virtual addresses and mappings visible to a process. *(Introduced §2.17.)*
- **Virtual environment:** an isolated Python execution context with environment-specific entry points and installed distributions. *(Introduced §4.15.)*
- **Virtual machine:** a software-defined abstract execution machine. *(Introduced §2.17.)*
- **Volatile:** requiring continued power to retain state. *(Introduced §1.14.)*
- **Volume:** storage exposed to a workload under defined attachment, persistence, sharing, and lifecycle semantics. *(Introduced §20.38.)*
- **Voluntary disruption:** orchestrator- or administrator-initiated workload interruption distinguishable from an involuntary failure. *(Introduced §20.38.)*
- **Von Neumann architecture:** a stored-program model in which instructions and data occupy a common addressable memory organisation. *(Introduced §1.14.)*
- **Vulnerability:** weakness permitting a threat to violate a security objective. *(Introduced §19.34.)*
