# 21.24 W

- **Warm capacity:** already started and ready capacity available before new scaling actions complete. *(Introduced §20.38.)*
- **Watchdog:** mechanism expecting periodic evidence of progress and acting when that evidence is absent. *(Introduced §20.38.)*
- **Weak reference:** reference that can observe an object without retaining its lifetime. *(Introduced §15.23.)*
- **Weighted round robin:** load-balancing algorithm distributing assignments cyclically in proportions represented by backend weights. *(Introduced §20.38.)*
- **Wheel:** built Python distribution format intended for installation. *(Introduced §10.18.)*
- **Worker:** process or workload instance consuming and executing units of queued or assigned work. *(Introduced §20.38.)*
- **Workload:** application process set and resource requirements scheduled or operated as one unit. *(Introduced §20.38.)*
- **Workload identity:** platform-established non-human identity bound to a running workload and exchangeable for scoped authority. *(Introduced §20.38.)*
- **Workload model:** explicit statistical and semantic description of arrivals, operation mix, data, concurrency, and dependency behaviour used in testing or capacity analysis. *(Introduced §20.38.)*
- **Write-ahead log:** ordered durable record of intended state changes written before their main data structures, enabling recovery or replay. *(Introduced §20.38.)*
- **WSGI:** synchronous Python callable interface between web servers and applications. *(Introduced §18.36.)*
