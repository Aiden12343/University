# 21.3 B

- **Backfill:** controlled processing of existing data to populate or transform state required by a newer representation. *(Introduced §20.38.)*
- **Backoff:** policy increasing delay between repeated attempts to reduce contention or pressure. *(Introduced §20.38.)*
- **Backpressure:** control preventing producers from overwhelming downstream capacity. *(Introduced §14.24.)*
- **Backpropagation:** reverse-mode gradient accumulation through layered computations. *(Introduced §17.37.)*
- **Backup:** recoverable copy plus metadata, keys, artifacts, authority, and procedure required to restore intended state. *(Introduced §20.38.)*
- **Baggage:** application-defined contextual values propagated with distributed trace context. *(Introduced §20.38.)*
- **Bandwidth:** quantity transferable per unit time. *(Introduced §1.14.)*
- **Base case:** a recursive case answered without a further recursive call. *(Introduced §8.20.)*
- **Baseline:** simple reference procedure against which a model is evaluated. *(Introduced §17.37.)*
- **Binary:** having two alternatives; in notation, using radix two. *(Introduced §1.14.)*
- **Binary stream:** stream whose units are bytes. *(Introduced §11.20.)*
- **Binding:** an association between a name and an object in a namespace. *(Introduced §5.22.)*
- **Bit:** one binary digit. *(Introduced §1.14.)*
- **Blast radius:** maximum or observed scope of users, data, resources, or obligations affected by a change or failure. *(Introduced §20.38.)*
- **Blocked:** unable to proceed until a required event occurs. *(Introduced §2.17.)*
- **Blue–green deployment:** strategy preparing a parallel environment and switching traffic between old and new populations. *(Introduced §20.38.)*
- **Boolean algebra:** rules for values such as false and true and operations over them. *(Introduced §1.14.)*
- **Boolean context:** a language position that requests truth testing. *(Introduced §5.22.)*
- **Borrowed reference:** C API reference whose ownership remains elsewhere. *(Introduced §15.23.)*
- **Bottleneck:** resource or dependency whose usable capacity first constrains system throughput or latency. *(Introduced §20.38.)*
- **Bound method:** a callable retaining a function and its receiving instance or class. *(Introduced §9.23.)*
- **Breadth-first search:** queue-based graph traversal exploring non-decreasing unweighted distance. *(Introduced §13.22.)*
- **Break:** a statement exiting the nearest enclosing loop. *(Introduced §6.20.)*
- **Break-glass access:** exceptional, strongly controlled, short-lived authority used when ordinary administrative paths are insufficient or unavailable. *(Introduced §20.38.)*
- **Broadcasting:** compatibility rules for elementwise operations on unequal array shapes. *(Introduced §16.31.)*
- **Buffer:** storage temporarily retaining data to combine or defer transfers. *(Introduced §11.20.)*
- **Build backend:** tool implementing standard project build operations. *(Introduced §10.18.)*
- **Build cache:** reusable result of a build action addressed by an identity intended to commit to every correctness-relevant input. *(Introduced §20.38.)*
- **Build closure:** transitive set of source, dependency, tool, environment, and other inputs capable of affecting a build output. *(Introduced §20.38.)*
- **Build context:** set of files and metadata made visible to a container or other build operation. *(Introduced §20.38.)*
- **Build graph:** directed dependency graph whose nodes are build actions or products and whose edges convey prerequisites. *(Introduced §20.38.)*
- **Build provenance:** authenticated evidence describing source, builder, invocation, materials, and subjects of a build. *(Introduced §20.38.)*
- **Bulkhead:** resource partition intended to prevent one workload or dependency from exhausting capacity required by others. *(Introduced §20.38.)*
- **Burn rate:** observed bad-event fraction divided by the error-budget fraction for an SLO. *(Introduced §20.38.)*
- **Bus:** an interconnection carrying a related group of signals or transfers. *(Introduced §1.14.)*
- **Business continuity:** organisational ability to continue or restore essential functions through disruption, including technical and non-technical dependencies. *(Introduced §20.38.)*
- **Byte:** conventionally, a group of eight bits. *(Introduced §1.14.)*
- **Bytearray:** Python’s mutable sequence of byte values. *(Introduced §5.22.)*
- **Bytecode:** instructions for a software-defined abstract machine. *(Introduced §2.17.)*
- **Bytes:** Python’s immutable sequence of integers from 0 through 255. *(Introduced §5.22.)*
