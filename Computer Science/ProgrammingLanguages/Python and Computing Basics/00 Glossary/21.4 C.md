# 21.4 C

- **Cache:** small, fast storage retaining copies of data from a slower level. *(Introduced §1.14, §18.36.)*
- **Calibration:** agreement between predicted probabilities and observed frequencies under stated conditions. *(Introduced §17.37.)*
- **Call by sharing:** argument semantics in which parameters bind to supplied objects and shared mutation can be observed. *(Introduced §8.20.)*
- **Call stack:** ordered active function-call contexts under nested execution. *(Introduced §8.20.)*
- **Callable:** an object supporting call syntax. *(Introduced §5.22.)*
- **Canary:** deliberately limited population receiving a change before broader exposure so its consequences can be evaluated. *(Introduced §20.38.)*
- **Cancellation:** cooperative request for incomplete work to stop under a cleanup contract. *(Introduced §14.24.)*
- **Canonicalisation:** mapping equivalent representations to a selected standard form. *(Introduced §19.34.)*
- **Capability:** unforgeable reference or token carrying authority over a resource. *(Introduced §19.34.)*
- **Capacity:** sustainable workload a system can serve under stated latency, reliability, failure, and resource conditions. *(Introduced §20.38.)*
- **Cardinality:** number of distinct members in a set. *(Introduced §7.18.)*
- **Cell variable:** binding stored so nested functions can retain access. *(Introduced §15.23.)*
- **Cgroup:** Linux kernel mechanism for hierarchical resource accounting, control, and limits over groups of processes. *(Introduced §20.38.)*
- **Change fail rate:** proportion of deployments requiring immediate intervention such as rollback or urgent repair under the selected DORA definition. *(Introduced §20.38.)*
- **Change lead time:** elapsed time from a committed change to its production deployment under the selected DORA definition. *(Introduced §20.38.)*
- **Change record:** evidence linking change intent, immutable subjects, approval, execution, observation, and final outcome. *(Introduced §20.38.)*
- **Chaos engineering:** controlled experimentation intended to build justified confidence in behaviour under specified disturbances. *(Introduced §20.38.)*
- **Character encoding:** a rule representing text units as bytes. *(Introduced §4.15.)*
- **Chargeback:** accounting practice that transfers attributed shared technology cost to the responsible budget or unit. *(Introduced §20.38.)*
- **Checkpoint:** durable marker from which interrupted work can safely resume without repeating earlier completed effects incorrectly. *(Introduced §20.38.)*
- **CI:** frequent integration of changes with automated verification. *(Introduced §20.38.)*
- **Circuit breaker:** state machine that temporarily rejects calls after selected failures and probes for recovery under controlled admission. *(Introduced §20.38.)*
- **Circular import:** import dependency cycle exposing partially initialised modules. *(Introduced §10.18.)*
- **Class:** an object used to construct instances and define shared behaviour through attribute lookup. *(Introduced §9.23.)*
- **Class attribute:** an attribute stored in a class namespace and available through class or instance lookup. *(Introduced §9.23.)*
- **Class method:** a descriptor-wrapped function bound to a class on access. *(Introduced §9.23.)*
- **Classification:** prediction of discrete target categories. *(Introduced §17.37.)*
- **Clock:** a repeating signal coordinating synchronous state transitions. *(Introduced §1.14.)*
- **Clock cycle:** one repetition of a clock signal. *(Introduced §1.14.)*
- **Closure:** a function retaining access to bindings from a lexical environment. *(Introduced §8.20.)*
- **Cloud SDK:** language library wrapping remote provider APIs, authentication, pagination, retries, and data representations. *(Introduced §20.38.)*
- **Code coverage:** measurement of program structures executed by a test suite. *(Introduced §12.26.)*
- **Code object:** immutable CPython object containing bytecode and execution metadata. *(Introduced §15.23.)*
- **Code point:** a number assigned by Unicode to a textual element. *(Introduced §5.22.)*
- **Collection:** an object organising references or values under a behavioural contract. *(Introduced §7.18.)*
- **Collision:** competition between distinct hashed keys for a candidate table location or hash value. *(Introduced §7.18.)*
- **Combinational circuit:** a circuit whose settled outputs depend on current inputs alone. *(Introduced §1.14.)*
- **Command line:** one textual command submission interpreted by a shell. *(Introduced §3.16.)*
- **Comparison sort:** sorting algorithm whose ordering information comes from comparisons. *(Introduced §13.22.)*
- **Compiler:** a program translating one program representation into another while preserving specified meaning. *(Introduced §2.17.)*
- **Composition:** construction of behaviour from cooperating component objects. *(Introduced §9.23.)*
- **Comprehension:** syntax constructing a collection through iteration, transformation, and optional filtering. *(Introduced §6.20.)*
- **Computation graph:** dependency graph of primitive operations and intermediate values. *(Introduced §17.37.)*
- **Computational dossier:** organised claims and evidence defending a program and its execution contract. *(Introduced §3.16.)*
- **Computational problem:** a family of questions defined by admitted inputs and required answers. *(Introduced §3.16.)*
- **Computer:** a physical system arranged to represent and transform information according to rules. *(Introduced §1.14.)*
- **Confidence interval:** output of an interval-producing procedure with a stated repeated-sampling coverage property under assumptions. *(Introduced §16.31.)*
- **Confidentiality:** prevention of unauthorised information disclosure. *(Introduced §19.34.)*
- **Configuration:** externally selected, validated information that changes program behaviour without changing its source. *(Introduced §20.38.)*
- **Configuration drift:** divergence between intended or declared configuration and effective system state. *(Introduced §20.38.)*
- **Confounder:** variable capable of distorting an exposure–outcome causal comparison through its relations to both. *(Introduced §16.31.)*
- **Consistency point:** boundary at which a set of captured state satisfies a specified relationship suitable for recovery. *(Introduced §20.38.)*
- **Container:** isolated process set instantiated with filesystem and runtime metadata, ordinarily sharing a host kernel. *(Introduced §20.38.)*
- **Container image:** content-addressed configuration and ordered filesystem layers from which a container root filesystem and defaults are constructed. *(Introduced §20.38.)*
- **Contention:** competition among tasks for a shared limited resource. *(Introduced §14.24.)*
- **Context manager:** an object governing entry to and exit from a runtime context. *(Introduced §11.20.)*
- **Context switch:** saving one execution context and restoring another. *(Introduced §2.17.)*
- **Contiguous array:** array whose elements occupy an uninterrupted supported memory layout. *(Introduced §16.31.)*
- **Continue:** a statement transferring control to the next loop test or item request. *(Introduced §6.20.)*
- **Continuous delivery:** practice of keeping software releasable and automating verified movement towards production while retaining an explicit release decision. *(Introduced §20.38.)*
- **Continuous deployment:** automatic production release of every change satisfying an enforced delivery policy. *(Introduced §20.38.)*
- **Continuous integration:** frequent combination of changes with automated reproducible verification. *(Introduced §12.26.)*
- **Contract:** stated obligations governing an interface. *(Introduced §3.16.)*
- **Control flow:** the rule determining which operation executes next. *(Introduced §6.20.)*
- **Control plane:** interfaces and components that configure, schedule, authorise, or observe resources performing service work. *(Introduced §20.38.)*
- **Controller:** process repeatedly observing actual state and acting to reduce divergence from desired state. *(Introduced §20.38.)*
- **Cookie:** browser-managed state attached to matching HTTP requests under scope rules. *(Introduced §18.36.)*
- **Coordinated omission:** latency-measurement bias caused when a generator waits during slowness and therefore omits arrivals that would otherwise have queued. *(Introduced §20.38.)*
- **Correlation:** dimensionless measure of specified association, commonly linear association. *(Introduced §16.31.)*
- **Cost allocation:** rule and process assigning shared technology expenditure to services, owners, tenants, or outcomes. *(Introduced §20.38.)*
- **Cost anomaly:** spending or usage behaviour materially inconsistent with an expected baseline or forecast. *(Introduced §20.38.)*
- **Cost model:** definition of input size and charged elementary operations. *(Introduced §13.22.)*
- **Counter:** cumulative metric that normally increases with events and resets only under a defined lifecycle. *(Introduced §20.38.)*
- **CPU:** central processing unit; the subsystem that obtains and carries out instructions. *(Introduced §1.14.)*
- **CPython:** the reference Python implementation, written principally in C. *(Introduced §4.15.)*
- **Crash consistency:** state recoverable as though components stopped abruptly, without necessarily preserving cross-system application invariants. *(Introduced §20.38.)*
- **Credential federation:** acceptance of identity assertions from another trusted issuer in exchange for scoped local credentials or sessions. *(Introduced §20.38.)*
- **Critical section:** code region requiring controlled access to preserve a shared invariant. *(Introduced §14.24.)*
- **CronJob:** controller or scheduled definition that creates finite jobs according to a time schedule and explicit overlap and missed-run semantics. *(Introduced §20.38.)*
- **Cross-validation:** repeated fitting and evaluation over prescribed development-data partitions. *(Introduced §17.37.)*
- **Cryptographic hash:** fixed-length digest function designed for adversarial preimage and collision resistance. *(Introduced §19.34.)*
- **CSRF:** abuse of automatically attached credentials to induce an unwanted cross-site request. *(Introduced §18.36.)*
- **CSV:** a family of delimited tabular text formats with quoting and framing rules. *(Introduced §11.20.)*
- **Current working directory:** the ordinary base used to resolve relative paths for a process. *(Introduced §3.16.)*
- **Cybersecurity:** management of risks to information systems and those dependent upon them. *(Introduced §19.34.)*
- **Cyclic garbage collection:** detection and reclamation of selected unreachable reference cycles. *(Introduced §15.23.)*
