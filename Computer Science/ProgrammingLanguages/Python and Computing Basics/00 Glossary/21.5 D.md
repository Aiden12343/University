# 21.5 D

- **Daemon:** background service process, historically detached from an interactive terminal. *(Introduced §20.38.)*
- **Data:** represented information available to computation. *(Introduced §3.16, §16.31.)*
- **Data descriptor:** a descriptor defining setting or deletion and taking precedence over ordinary instance entries. *(Introduced §9.23.)*
- **Data durability:** preservation of accepted data across a stated class of failures. *(Introduced §20.38.)*
- **Data leakage:** improper information flow into model fitting or evaluation. *(Introduced §17.37.)*
- **Data plane:** components and paths that perform the service's intended user or business operations. *(Introduced §20.38.)*
- **Data structure:** an organised representation with operations and invariants. *(Introduced §3.16.)*
- **Dataclass:** a class transformed to generate selected record-like methods from declared fields. *(Introduced §9.23.)*
- **DataFrame:** pandas two-dimensional labelled table with potentially heterogeneous columns. *(Introduced §16.31.)*
- **Deadline:** latest time by which an operation remains useful, commonly propagated across dependency calls. *(Introduced §20.38.)*
- **Deadlock:** cyclic waiting in which no participant can progress. *(Introduced §14.24.)*
- **Debugging:** localisation and explanation of divergence between expected and observed behaviour. *(Introduced §12.26.)*
- **Decision threshold:** rule converting a continuous score into a discrete action or label. *(Introduced §17.37.)*
- **Declarative configuration:** representation specifying desired outcome rather than a complete imperative sequence of mutations. *(Introduced §20.38.)*
- **Decode:** interpret an instruction pattern according to an ISA. *(Introduced §1.14.)*
- **Decorator:** a callable receiving a defined object and returning the object to bind under its name. *(Introduced §8.20.)*
- **Decorator factory:** a callable producing a decorator from configuration. *(Introduced §8.20.)*
- **Deep copy:** an attempted recursive copy of a reachable object graph under type-specific rules. *(Introduced §5.22.)*
- **Defence in depth:** independent or partially independent controls across multiple boundaries. *(Introduced §19.34.)*
- **Defensive programming:** validation and protection placed at owned trust or responsibility boundaries. *(Introduced §8.20.)*
- **Degraded mode:** explicitly reduced service behaviour preserving selected essential properties during constrained conditions. *(Introduced §20.38.)*
- **Delegation:** forwarding responsibility to another object. *(Introduced §9.23.)*
- **Deoptimisation:** withdrawal from specialised compiled execution when its assumptions cease to hold. *(Introduced §2.17.)*
- **Dependency:** an external project required for operation, build, testing, or development. *(Introduced §4.15.)*
- **Dependency closure:** full transitive set of systems, artifacts, identities, keys, and information required for an operation or recovery. *(Introduced §20.38.)*
- **Dependency injection:** supplying collaborators from outside a component rather than locating them invisibly. *(Introduced §10.18.)*
- **Deployment:** controlled change to installed or running artifacts, configuration, infrastructure, or policy. *(Introduced §20.38.)*
- **Deployment frequency:** number of deployments per period or interval between deployments under the selected DORA definition. *(Introduced §20.38.)*
- **Deployment rework rate:** proportion of deployments that are unplanned responses to production incidents under the current DORA definition. *(Introduced §20.38.)*
- **Depth-first search:** graph traversal exploring a path before backtracking. *(Introduced §13.22.)*
- **Deque:** a double-ended queue supporting efficient operations at both ends. *(Introduced §7.18.)*
- **Descriptor:** a class-owned object controlling attribute access through `__get__`, `__set__`, or `__delete__`. *(Introduced §9.23.)*
- **Deserialisation:** reconstruction of state from an external representation. *(Introduced §11.20.)*
- **Design matrix:** matrix whose rows are instances and columns are represented features. *(Introduced §17.37.)*
- **Desired state:** versioned description of the system state a controller is intended to establish or preserve. *(Introduced §20.38.)*
- **Device driver:** software exposing controlled operations for a hardware device to an operating system. *(Introduced §2.17.)*
- **Dictionary:** Python’s mutable insertion-ordered mapping from unique hashable keys to values. *(Introduced §7.18.)*
- **Differential backup:** backup containing changes since a selected full backup. *(Introduced §20.38.)*
- **Digital signature:** private-key operation producing publicly verifiable message authenticity and integrity evidence. *(Introduced §19.34.)*
- **Directed acyclic graph:** directed graph containing no directed cycle. *(Introduced §13.22.)*
- **Discovery:** process of obtaining candidate endpoints or resources corresponding to a logical identity. *(Introduced §20.38.)*
- **Disruption budget:** policy constraining selected voluntary concurrent workload disruptions without preventing involuntary failure. *(Introduced §20.38.)*
- **Distribution package:** an installable project unit managed by Python packaging tools. *(Introduced §4.15.)*
- **Distribution project:** a versioned unit of software that can be built and installed. *(Introduced §10.18.)*
- **Distribution shift:** change between development and application data-generating conditions. *(Introduced §17.37.)*
- **DMA:** direct memory access; block transfer between a device and memory with limited per-unit CPU work. *(Introduced §1.14.)*
- **DNS:** distributed system mapping domain names to records such as network addresses. *(Introduced §18.36.)*
- **Drain:** transition that stops admitting new work while bounded existing work completes or reaches a safe checkpoint. *(Introduced §20.38.)*
- **Drift:** divergence among declared configuration, recorded state, remote observation, effective semantics, or intended ownership. *(Introduced §20.38.)*
- **Dtype:** array element representation and operation contract. *(Introduced §16.31.)*
- **Duck typing:** structural use of objects according to supported behaviour rather than demanded concrete type. *(Introduced §9.23.)*
- **Dunder method:** conventional name for a double-underscore special method used by Python protocols. *(Introduced §9.23.)*
- **Durability:** persistence of an accepted update across a named failure model. *(Introduced §11.20.)*
- **Durable state:** state required to survive a specified process, host, zone, regional, or organisational failure. *(Introduced §20.38.)*
- **Dynamic array:** a contiguous indexable array with separately tracked logical length and capacity. *(Introduced §7.18.)*
- **Dynamic configuration:** configuration capable of changing within a running process or deployment without replacing the artifact. *(Introduced §20.38.)*
- **Dynamic programming:** retained evaluation of overlapping subproblems defined by states and recurrences. *(Introduced §13.22.)*
- **Dynamically typed:** having runtime values carry types without permanently fixing ordinary name bindings to one type. *(Introduced §5.22.)*
