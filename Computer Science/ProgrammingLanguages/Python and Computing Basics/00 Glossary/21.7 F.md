# 21.7 F

- **Failback:** controlled transition from a recovery location or mode back to a sustainable primary arrangement. *(Introduced §20.38.)*
- **Failover:** transfer of service responsibility to an alternate component, zone, region, or system after failure or planned exercise. *(Introduced §20.38.)*
- **Failure domain:** set of components liable to fail together under a specified disturbance. *(Introduced §20.38.)*
- **Fake:** a simplified working implementation used as a test collaborator. *(Introduced §12.26.)*
- **Feature:** represented input component supplied to a model. *(Introduced §17.37.)*
- **Feature flag:** governed dynamic configuration selecting behaviour independently from deployment. *(Introduced §20.38.)*
- **Federation:** trust arrangement in which one system accepts bounded identity claims issued by another. *(Introduced §20.38.)*
- **Fetch:** obtain the next instruction designated by the program counter. *(Introduced §1.14.)*
- **File:** an OS-managed resource presenting stored data and metadata. *(Introduced §2.17.)*
- **File descriptor:** a process-local integer handle for an open resource in POSIX-style interfaces. *(Introduced §2.17.)*
- **File offset:** position used by sequential file operations. *(Introduced §11.20.)*
- **Filesystem:** structures and rules organising persistent data, names, directories, and metadata. *(Introduced §2.17.)*
- **Finder:** import-system component locating a module specification. *(Introduced §10.18.)*
- **FinOps:** organisational and engineering practice connecting technology usage and cost to accountable business value and decisions. *(Introduced §20.38.)*
- **Firewall:** mechanism admitting or rejecting network traffic under rules over addresses, ports, protocols, state, and sometimes application information. *(Introduced §20.38.)*
- **First-class object:** an object that can be bound, passed, returned, and stored through ordinary language mechanisms. *(Introduced §8.20.)*
- **Fixture:** controlled state or resource supplied to tests. *(Introduced §12.26.)*
- **Fleet percentile:** quantile calculated over the complete selected event population across service instances rather than averaged instance quantiles. *(Introduced §20.38.)*
- **Flip-flop:** a storage element designed to capture state in relation to a clock transition. *(Introduced §1.14.)*
- **Foreground process:** process remaining attached to supervisor-controlled lifecycle and streams rather than self-daemonising. *(Introduced §20.38.)*
- **Forward compatibility:** ability of an older consumer to handle, ignore, or safely reject information produced by a newer version under a stated contract. *(Introduced §20.38.)*
- **Frame:** an execution context retaining local state and resumption information for code. *(Introduced §8.20.)*
- **Framing:** division of a stream into meaningful records or messages. *(Introduced §11.20.)*
- **Free variable:** name resolved through an enclosing lexical function binding. *(Introduced §15.23.)*
- **Free-threaded build:** CPython configuration capable of running without the traditional global interpreter lock. *(Introduced §14.24.)*
- **Frozenset:** Python’s immutable set type. *(Introduced §7.18.)*
- **Full backup:** backup containing the complete selected dataset at a specified consistency point. *(Introduced §20.38.)*
- **Full jitter:** retry policy selecting a random delay from zero to the current capped backoff ceiling. *(Introduced §20.38.)*
- **Function:** a callable object packaging parameterised behaviour. *(Introduced §8.20.)*
- **Functional completeness:** the ability of a set of logical operations to express every Boolean function. *(Introduced §1.14.)*
- **Functional requirement:** required system behaviour or result. *(Introduced §12.26.)*
- **Future:** object representing a result that may complete, fail, or be cancelled later. *(Introduced §14.24.)*
- **Fuzz testing:** automated generation or mutation of inputs to discover unexpected behaviour. *(Introduced §19.34.)*
