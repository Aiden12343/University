# 1.5 From combinational logic to memory

A combinational circuit reacts to current inputs but cannot, by that fact alone, remember a past input. General computation requires **state**: information retained from one step and made available to a later step. A **state transition** is a change from one retained condition to another.

Digital storage can be constructed through **feedback**, in which part of a circuit’s output influences its later input. Cross-coupled gates can form a latch with two stable logical conditions. A **latch** is a storage element whose state may respond while an enabling condition is active. A **flip-flop** is a storage element commonly designed to capture an input at a particular transition of a coordinating clock signal. Terminology varies across circuit contexts, but both devices make prior logical state available to later behaviour.

A **register** is a small group of storage elements treated as one multi-bit unit. If a register contains 64 flip-flops, it can retain a 64-bit pattern. Registers reside close to the processor’s arithmetic and control circuits and are generally much faster and scarcer than main memory.

A **clock** is a repeating coordination signal. A **clock cycle** is one repetition of that signal, commonly measured from one corresponding edge to the next. A **clock edge** is a transition from low to high or high to low. In a synchronous circuit, state elements are designed to capture new values in relation to specified edges, after combinational logic has had sufficient time to settle.

Clock frequency is the number of cycles per second. One **hertz** means one cycle per second; one gigahertz means one billion cycles per second. A 3 GHz clock has a nominal cycle duration of one third of a nanosecond, approximately 0.333 nanoseconds. This does not mean the processor completes three billion program instructions per second. An instruction may require several cycles; several instructions may overlap; some processors may retire multiple instructions per cycle; memory stalls, branch errors, power limits, and instruction differences all affect completed work.

### Worked example 1.6 — A clocked accumulator

An **accumulator** is a register used to retain an intermediate arithmetic result. Suppose a simplified accumulator circuit has a register (A), an input (x), and a control bit `add`. At each rising clock edge:

- if `add = 1`, the next state is (A+x);
- if `add = 0`, the next state remains (A).

Assume (A) initially contains 3.

| Before edge (A) | Input (x) | `add` | Candidate next state | After edge (A) |
|---:|---:|:---:|---:|---:|
| 3 | 4 | 1 | 7 | 7 |
| 7 | 9 | 0 | 7 | 7 |
| 7 | 2 | 1 | 9 | 9 |

Between edges, the combinational adder may produce candidate values, but the architectural state changes only at the capture event specified by the model. This separation permits a trace to treat each update as a discrete step despite continuous electrical activity underneath.

The clock is not the source of computation. Logic derives candidate outputs; storage retains selected values; the clock coordinates when retained state changes. Nor does a clock make all activity occur simultaneously. Different signals have finite delays, and correct synchronous design requires **setup time** and **hold time**: intervals for which an input must be stable before and after the capture edge.

> **Common misconception — “A faster clock always means a faster computer.”**  
> Clock frequency measures coordination cycles, not useful work. Performance depends on work completed per cycle, memory behaviour, instruction mix, parallel execution resources, software design, and many other constraints. Frequency is one factor, not a universal speed rating.
