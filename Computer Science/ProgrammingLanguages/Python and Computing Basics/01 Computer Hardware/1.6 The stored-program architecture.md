# 1.6 The stored-program architecture

Early automatic machines and specialised calculators could embody operations directly in wiring or mechanical arrangement. Reconfiguring such a machine could require physical alteration. A **stored-program computer** represents instructions in addressable memory, allowing the machine to load a different instruction sequence as data rather than being rewired for every task.

The classical explanatory model is the **von Neumann architecture**, named after John von Neumann and associated with a broader history of stored-program computing. Its central feature is that instructions and ordinary data occupy the same general memory and travel through a shared computational organisation. Real contemporary processors modify this simple model with caches, pipelines, separate instruction and data paths at some levels, multiple cores, speculative execution, and specialised accelerators. The model remains useful because it identifies the obligations common to executing stored instructions.

The principal components are:

- The **central processing unit** (**CPU**), which obtains and carries out instructions.
- **Main memory**, an addressable collection of storage locations holding instructions and data for active computation.
- **Input/output** (**I/O**) mechanisms, through which the machine exchanges information with devices and external systems.
- **Buses** or equivalent interconnections, which convey addresses, data, and control information among components.

The CPU is conventionally decomposed into a **control unit**, an **arithmetic logic unit** (**ALU**), and registers. The control unit coordinates instruction execution. The ALU performs arithmetic and Boolean operations. Registers retain immediately needed operands, addresses, instructions, and status. Modern CPUs contain many execution units and complex control structures, but these categories remain explanatory rather than claiming one literal box per label.

Main memory is **addressable**: each selectable location or small unit of storage has an **address**, a numeric identifier used to designate it. A memory read requests the pattern stored at an address. A memory write supplies an address and a pattern to retain there. Address and content must remain distinct. If location 100 contains the pattern 27, then 100 designates where; 27 is what is presently stored there.

A **bus** is a communication pathway carrying a related set of signals. In the simplified model, an address bus identifies a location, a data bus carries the pattern being transferred, and control lines identify operations such as read or write. Contemporary interconnects are more elaborate and may use packets, point-to-point links, queues, and protocols rather than one physically shared bundle. “Bus” in the introductory model names the communication function, not a promise about present-day wiring topology.

An **input device** supplies information to the computer: examples include keyboards, network interfaces, storage controllers, and sensors. An **output device** receives information: displays, network interfaces, and storage devices may serve this role. Many devices are bidirectional. I/O is not an afterthought: a computation that cannot receive a problem instance or expose a result has severely limited practical use.

### 1.6.1 A minimal machine state

To execute instructions, a simple CPU requires several named pieces of state:

- The **program counter** (**PC**) holds the address of the next instruction to fetch.
- The **instruction register** (**IR**) holds the instruction currently being decoded or executed.
- General-purpose registers hold operands and results.
- A **status register** may hold condition flags such as zero, negative, carry, or overflow.
- Memory holds the instruction sequence and larger working data.

An **instruction set architecture** (**ISA**) is the programmer-visible contract of a processor family: its instructions, registers, data types, addressing rules, and observable execution behaviour. The ISA is an abstraction. Different physical processors can implement the same ISA using different internal structures and still run the same machine-code programs.

> **Common misconception — “The CPU is the computer.”**  
> A CPU carries out instructions, but a usable computer also requires memory, interconnection, persistent storage, I/O devices, power, and software. Even the CPU label covers multiple cooperating control, execution, and storage structures.
