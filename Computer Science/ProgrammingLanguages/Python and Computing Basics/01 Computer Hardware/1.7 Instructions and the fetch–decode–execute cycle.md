# 1.7 Instructions and the fetch–decode–execute cycle

A **machine instruction** is a finite bit pattern that an ISA defines as an operation. An instruction normally identifies an **opcode**, meaning the operation to perform, and zero or more **operands**, meaning the values or locations involved. An operand may be encoded directly inside the instruction, held in a register, or stored in memory at a calculated address.

The **fetch–decode–execute cycle** is a conceptual account of instruction processing:

1. **Fetch:** use the program counter to obtain the next instruction from memory and place it in the instruction register.
2. **Advance:** update the program counter to the following sequential instruction, unless the architecture combines this step elsewhere.
3. **Decode:** interpret the instruction pattern according to the ISA, determining the operation and operands.
4. **Obtain operands:** read necessary registers or memory locations.
5. **Execute:** perform the arithmetic, logical, transfer, comparison, or control operation.
6. **Write back:** retain a result in a register or memory if the instruction requires it.
7. **Repeat:** fetch from the address now held by the program counter.

This is a semantic model, not a claim that every contemporary CPU performs one entire instruction before beginning the next. **Pipelining** overlaps stages of several instructions. **Out-of-order execution** permits some operations to proceed before earlier independent operations have completed. **Speculative execution** provisionally performs work before it is certain that the program will need the result. The processor must nevertheless preserve the architectural effects required by the ISA, except where the ISA explicitly leaves behaviour unspecified. The simple cycle explains the committed meaning; microarchitecture explains how a particular processor pursues it efficiently.

A **branch instruction** changes the program counter, either unconditionally or when a condition is satisfied. Without branches, the processor would move through memory in only one fixed sequence. Branches make selection and repetition possible. A loop is not a magical circular object: it is a sequence containing a branch that causes a previously addressed instruction to be fetched again while some continuation condition holds.

### Worked example 1.7 — A complete instruction trace

Consider a deliberately invented teaching ISA. It has four registers:

- `R0`, `R1`, and `R2` hold integers;
- `PC` holds the next instruction address.

Every instruction occupies one numbered memory location. The instruction meanings are:

| Instruction | Meaning |
|:---|:---|
| `LOAD R, a` | Copy the value from memory address `a` into register `R`. |
| `ADD D, A, B` | Add registers `A` and `B`; store the result in `D`. |
| `STORE R, a` | Copy register `R` into memory address `a`. |
| `HALT` | Stop instruction processing. |

Memory initially contains:

| Address | Content |
|---:|:---|
| 0 | `LOAD R0, 100` |
| 1 | `LOAD R1, 101` |
| 2 | `ADD R2, R0, R1` |
| 3 | `STORE R2, 102` |
| 4 | `HALT` |
| 100 | `7` |
| 101 | `5` |
| 102 | `0` |

The initial register state is `PC = 0`; the values in `R0`, `R1`, and `R2` are irrelevant until written.

**Cycle 1.** Fetch reads address 0 because `PC` contains 0. The instruction register receives `LOAD R0, 100`; `PC` advances to 1. Decode identifies a load from address 100 into `R0`. Operand retrieval reads 7 from address 100. Execution/write-back places 7 in `R0`.

**Cycle 2.** Fetch reads address 1. `PC` advances to 2. Decode identifies `LOAD R1, 101`. Memory address 101 supplies 5, which is written to `R1`.

**Cycle 3.** Fetch reads address 2. `PC` advances to 3. Decode identifies addition with source registers `R0` and `R1` and destination `R2`. Operand retrieval yields 7 and 5. The ALU computes 12, and write-back places 12 in `R2`.

**Cycle 4.** Fetch reads address 3. `PC` advances to 4. Decode identifies a store. The machine writes the pattern representing 12 from `R2` to memory address 102.

**Cycle 5.** Fetch reads address 4. Decode identifies `HALT`, and the machine stops. Memory address 102 now contains 12.

The complete architectural trace is:

| Completed instruction | `PC` | `R0` | `R1` | `R2` | Memory[102] |
|:---|---:|---:|---:|---:|---:|
| initial state | 0 | — | — | — | 0 |
| `LOAD R0, 100` | 1 | 7 | — | — | 0 |
| `LOAD R1, 101` | 2 | 7 | 5 | — | 0 |
| `ADD R2, R0, R1` | 3 | 7 | 5 | 12 | 0 |
| `STORE R2, 102` | 4 | 7 | 5 | 12 | 12 |
| `HALT` | 5 | 7 | 5 | 12 | 12 |

This example exposes the stored-program principle. Addresses 0–4 contain patterns interpreted as instructions; addresses 100–102 contain patterns interpreted as integer data. The memory hardware stores patterns in both cases. The current operation and ISA contract determine how a fetched pattern is interpreted.

It also exposes why a program consists of more than arithmetic. Only one instruction performs addition. The others move data, coordinate instruction order, and stop. Real programs spend substantial work arranging data and control around comparatively elementary operations.
