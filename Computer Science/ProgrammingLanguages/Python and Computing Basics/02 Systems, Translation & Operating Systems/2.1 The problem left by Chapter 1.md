# 2.1 The problem left by Chapter 1

Chapter 1 ended with a machine capable of fetching bit patterns from memory and interpreting them as instructions. That account explains how a stored-program processor can transform state, but it leaves two practical difficulties unresolved. First, people need a reliable means of expressing large instruction sequences without manually arranging every bit. Second, many programs need the same scarce processor, memory, storage, and devices without being permitted to corrupt one another. Programming languages address the first difficulty through layers of notation and translation. Operating systems address the second through controlled sharing, abstraction, and protection.

The two solutions are related. A language implementation is itself software executing under an operating system. An operating system is itself largely a collection of machine-code programs, built with languages and translation tools. Neither layer floats above the machine described in Chapter 1. Each makes the machine usable by establishing a more productive contract over lower-level behaviour.
