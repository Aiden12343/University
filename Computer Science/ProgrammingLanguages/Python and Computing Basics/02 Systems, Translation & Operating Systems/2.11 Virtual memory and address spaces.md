# 2.11 Virtual memory and address spaces

Programs issue memory accesses using **virtual addresses**. A process’s **virtual address space** is the set of virtual addresses and mappings visible to it. Hardware and the kernel cooperate to translate virtual addresses to physical memory locations or to detect that an access is invalid.

A fixed-size region used by this translation is commonly called a **page**. A **page table** records virtual-to-physical mappings and associated permissions such as readable, writable, executable, or accessible only in privileged mode. The processor’s **memory-management unit** (**MMU**) performs or assists translation. A **translation lookaside buffer** (**TLB**) caches recent address translations.

Virtual memory provides several distinct benefits:

1. Each process can receive a private, apparently contiguous address space despite fragmented physical placement.
2. Permissions can prevent writes to code, execution of ordinary data, or access to another process’s mappings.
3. Several processes can map the same physical read-only code or deliberately shared data.
4. Inactive pages can, under system policy, be moved between physical memory and persistent backing storage.
5. Files and devices can be mapped into an address space under controlled interfaces.

The term **virtual** does not mean imaginary. Virtual addresses are real operands in the architectural contract presented to a process; translation determines their current physical backing and permissions.

### Worked example 2.10 — Same virtual address, different physical data

Suppose Process A and Process B each read virtual address `0x1000`. A’s page table maps its virtual page to physical frame 42; B’s maps the same virtual number to physical frame 91. The source-level address number matches, but the protected process contexts produce different physical locations and potentially different values. If A writes to its mapping, B’s data is unaffected.

If both mappings deliberately point to frame 42 with shared writable permission, the processes can communicate through that memory but must now coordinate concurrent access. Protection and sharing are mapping policies; the address numeral alone determines neither.

An access to an unmapped page or a prohibited operation causes a hardware-detected fault transferred to the kernel. The kernel may establish a valid mapping—for example by loading a demanded page—or may terminate or signal the process. A **segmentation fault** is a common operating-system response to an invalid memory access in native code. The name does not imply that every system still uses historical segmentation as its principal memory model.

> **Common misconception — “Virtual memory is just using the disk as extra RAM.”**  
> Backing inactive pages with storage is one possible mechanism. The deeper abstraction is a protected, translated address space that separates process-visible addresses from physical placement and supports permissions and sharing.
