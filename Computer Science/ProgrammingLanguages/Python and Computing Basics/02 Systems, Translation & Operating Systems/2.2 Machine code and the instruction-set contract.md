# 2.2 Machine code and the instruction-set contract

**Machine code** is a sequence of instruction representations encoded for a particular instruction set architecture. The processor does not infer intent from those representations. It partitions instruction fields and applies the operation defined by the ISA.

Consider a fictional 16-bit instruction format:

| Bit positions | Field | Purpose |
|:---|:---|:---|
| 15–12 | opcode | selects one of sixteen operations |
| 11–8 | destination | selects one of sixteen registers |
| 7–4 | source A | selects one register |
| 3–0 | source B | selects one register |

The pattern `0010 0011 0001 0110` might mean `ADD R3, R1, R6` if opcode `0010` denotes addition. This meaning is not a property of the pattern in isolation. Under a different ISA, the same sixteen bits may denote another operation or no valid instruction at all.

An **instruction encoding** is the rule mapping instruction fields to bit patterns. A fixed-width encoding gives every instruction the same number of bits; a variable-width encoding allows different instructions to occupy different numbers. Fixed width can simplify locating and decoding instructions, while variable width can improve code density and provide a larger variety of operand forms. Neither policy is universally superior.

An **immediate operand** is a value encoded directly inside an instruction. A **register operand** names a processor register. A **memory operand** designates data in memory, usually through an **addressing mode**, a rule for calculating the effective address. A machine instruction’s limited bit width forces allocation choices: bits devoted to a larger immediate value or address cannot simultaneously identify more operations or registers.

### Worked example 2.1 — Decode an instruction field by field

Suppose the fictional ISA defines:

- opcode `0001`: copy one register to another;
- opcode `0010`: add two registers;
- opcode `0011`: subtract source B from source A;
- opcode `1111`: halt.

Decode `0011 0100 1001 0010`.

1. Bits 15–12 are `0011`, selecting subtraction.
2. Bits 11–8 are `0100`, selecting destination register 4.
3. Bits 7–4 are `1001`, selecting source register 9.
4. Bits 3–0 are `0010`, selecting source register 2.
5. The instruction is therefore `SUB R4, R9, R2`, with architectural effect (R4 \leftarrow R9-R2).

The arrow means “the destination becomes the value of the expression on the right”. It does not assert that subtraction is one physical event. A particular processor may realise the effect through several internal operations, provided its visible state satisfies the ISA contract.

Machine code is **architecture-specific**. A program compiled for one ISA does not ordinarily run as native instructions on another. An **emulator** is software that reproduces another machine’s specified behaviour, permitting foreign machine code to run at additional translation cost. **Binary translation** converts or dynamically maps instruction sequences from one ISA to another. These techniques reinforce rather than weaken the rule: an explicit mediator is required because the original bit patterns retain their original ISA meaning.

> **Common misconception — “Machine code is universal computer language.”**  
> Machine code is defined by an ISA. Different architectures assign different operations, registers, widths, and addressing rules to bit patterns. Universality belongs to general computation in principle, not to one portable machine-code vocabulary.
