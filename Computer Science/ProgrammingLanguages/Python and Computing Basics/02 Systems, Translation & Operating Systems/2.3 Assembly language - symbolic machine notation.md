# 2.3 Assembly language: symbolic machine notation

Writing machine code as binary or hexadecimal numerals is error-prone. A person must remember operation numbers, register fields, address values, and instruction layouts. **Assembly language** replaces many numeric fields with symbolic notation closely corresponding to an ISA. A short word such as `ADD` serves as a **mnemonic**, a memorable symbol for an opcode. Register names and **labels** replace numeric register encodings and instruction addresses.

An **assembler** translates assembly-language source into machine code. It performs mechanical work: parsing instruction syntax, mapping mnemonics to encodings, assigning addresses, resolving labels, and reporting violations of the assembly grammar or ISA constraints. Assembly language does not make the processor execute English words. The assembler emits the bit patterns the processor accepts.

### Worked example 2.2 — Labels remove hand-calculated branch addresses

Consider an assembly fragment for a teaching machine:

```text
        LOAD  R0, [count]
loop:   JZ    R0, done
        SUBI  R0, 1
        JMP   loop
done:   STORE R0, [result]
        HALT
count:  DATA  3
result: DATA  99
```

Square brackets are part of this fictional assembly syntax and mean “use the memory location named here”. `SUBI` subtracts an immediate value; `JZ` branches if a register contains zero; `JMP` branches unconditionally; `DATA` reserves a memory word containing an initial value.

The assembler’s first conceptual pass determines where each instruction or datum will reside and records label-to-address associations. Its second conceptual pass can replace `done`, `loop`, `count`, and `result` with their numeric encodings. Real assemblers may organise this work differently, but forward label references require the same information dependency: the address must be known before its final representation can be emitted or later repaired by a linker.

Tracing from `count = 3` gives:

| Arrival at `loop` | `R0` before `JZ` | Branch taken? | `R0` after `SUBI` |
|---:|---:|:---:|---:|
| 1 | 3 | no | 2 |
| 2 | 2 | no | 1 |
| 3 | 1 | no | 0 |
| 4 | 0 | yes | not executed |

The store writes zero to `result`. The loop terminates because each non-branching iteration reduces the non-negative value in `R0` by one. This is an informal **termination argument**: it identifies a bounded quantity that moves strictly towards a stopping condition.

Assembly exposes machine-level concerns that a higher-level language often abstracts: limited registers, explicit loads and stores, instruction addresses, calling conventions, and architecture-specific operations. It nevertheless remains a language with syntax, symbolic names, directives, and a translation phase. It is not identical to machine code.

> **Common misconception — “Assembly is machine code written with words.”**  
> Assembly is symbolic source translated into machine code. One source instruction often corresponds closely to one machine instruction, but directives, macros, pseudo-instructions, label resolution, and linker cooperation prevent a universal one-line-to-one-pattern rule.
