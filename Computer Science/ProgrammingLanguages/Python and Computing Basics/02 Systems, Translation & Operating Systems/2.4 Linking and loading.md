# 2.4 Linking and loading

Large programs are divided into separately translated units. One unit may call a function or access data defined in another before the final memory address of that definition is known. An **object file** is a compiler or assembler output containing machine code and data together with metadata needed for later combination. Here “object” is file-format terminology and is unrelated to the Python object model introduced in Chapter 5.

A **symbol** in this context is a named code or data entity recorded for translation and linking. A **relocation** identifies a location whose encoded address must be adjusted when final placement becomes known. A **linker** combines object files and libraries, resolves symbol references, applies relocations, and produces an executable file or another linked unit.

A **library** is a collection of reusable code or data exposed through an agreed interface. A **static library** contributes selected contents to a linked executable during the build. A **shared library** remains a separately managed binary that can be mapped and linked when a program is loaded or already running. Static and dynamic linking make different trade-offs in executable size, deployment, update coupling, startup work, and compatibility.

An **executable file** is a structured persistent representation containing code, data, metadata, entry information, and layout requirements recognised by the operating system’s program loader. It is not merely a raw stream of opcodes. The **loader** maps required regions into a new process, arranges runtime state, resolves or initiates shared-library linkage, and transfers control to an entry routine.

### Worked example 2.3 — Resolve one external call

Suppose `main.o` contains a call to symbol `sum_values` but does not define it. `arithmetic.o` defines `sum_values`. The call instruction reserves a field for a relative displacement and records a relocation saying, in effect, “replace this field with the distance from the instruction following this call to `sum_values`”.

If the linker places the next instruction at address 1,020 and `sum_values` at address 1,300, the required displacement is (1300-1020=280). The linker encodes 280 in the call field, subject to the ISA’s width and alignment rules. If no supplied object or library defines `sum_values`, the link fails. The source files may each have compiled successfully because syntax and local semantics were valid; the combined program is nevertheless incomplete.

This separates three failure stages:

| Stage | Example failure | What has been established already? |
|:---|:---|:---|
| Compilation/assembly | invalid syntax or impossible operand | source cannot yet produce valid object code |
| Linking | undefined external symbol | individual units translated, but their references cannot form a whole |
| Loading/runtime | missing shared library or invalid operation | a linked representation exists, but environment or execution prevents the requested run |
