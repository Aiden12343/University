# 2.6 Translation strategies: ahead-of-time compilation

A **compiler** is a program that translates a source representation into another representation while preserving specified meaning. In ordinary ahead-of-time use, source code is translated before the resulting program is run. The output may be native machine code, assembly, object code, bytecode for a virtual machine, or another programming language.

**Ahead-of-time compilation** (**AOT compilation**) performs substantial translation before execution. A typical pipeline contains:

1. **Lexical analysis:** characters are grouped into **tokens**, classified units such as identifiers, numerals, operators, and punctuation.
2. **Parsing:** tokens are checked against a grammar and organised into a structural representation, commonly an **abstract syntax tree** (**AST**).
3. **Semantic analysis:** the compiler checks rules not captured by surface grammar and resolves relationships such as declarations, scopes, or types where the language requires them.
4. **Intermediate representation:** source structures are lowered into one or more forms convenient for analysis and transformation.
5. **Optimisation:** meaning-preserving transformations seek properties such as reduced work, improved locality, or better machine utilisation.
6. **Code generation:** the compiler emits target instructions or another target representation.
7. **Assembly and linking:** when applicable, symbolic machine code becomes object code and separately translated units are combined.

An **optimisation** is a transformation intended to improve a chosen resource measure without changing the behaviour that the language requires the program to exhibit. This definition is stricter than “make it faster”. Removing a calculation is valid only if none of its required effects or failures are observable under the language rules. Optimisations operate inside the freedom left by the specification.

### Worked example 2.5 — A meaning-preserving simplification and its boundary

For pure integer arithmetic, the expression (x\times2+0) may appear replaceable by (x\times2). Removing addition by zero preserves the mathematical result. In a language with overloaded operations, however, `x + 0` might call user-defined behaviour with an observable effect or failure. A compiler may apply the simplification only when its analysis establishes conditions under which the language-visible behaviour remains equivalent.

The example establishes a general rule: an optimisation proof is relative to a semantic model. Algebra alone is insufficient when operations may allocate, raise exceptions, inspect state, or invoke user code.

AOT compilation can move analysis and optimisation cost out of repeated executions and can produce direct native code. It does not guarantee fast execution, complete error detection, or independence from runtime services. Some errors depend on input or environment and can occur only when the relevant path executes. Some language features require substantial runtime support even after native compilation.
