# 2.7 Interpretation and virtual machines

An **interpreter** is a program that carries out behaviour described by another program representation. It may read source structures directly, evaluate an AST, execute bytecode, or combine interpretation with compilation. Therefore “compiled” and “interpreted” are not mutually exclusive permanent properties of languages. They describe implementation strategies applied to representations.

A **virtual machine** in the language-runtime sense is an abstract execution machine implemented in software. It defines instructions, runtime state, and execution rules suited to a language implementation rather than to a physical processor. **Bytecode** is a compact instruction representation for such a machine. Despite its name, each bytecode instruction need not occupy exactly one byte.

Python provides an important example. The Python language is defined by its documented syntax and semantics. **CPython** is a particular implementation, written principally in C. CPython ordinarily compiles Python source into a code object containing bytecode and associated metadata, then evaluates that bytecode using its interpreter machinery. The physical processor executes the already compiled native instructions of CPython; those instructions implement the Python bytecode operations. Saying “Python is interpreted” omits this compilation stage and confuses a language with one implementation.

### Worked example 2.6 — Separate four programs and three representations

Suppose a file contains Python source `total = left + right` and runs under CPython.

1. The file’s characters are the source representation of the user’s program.
2. CPython’s compiler analyses that source and creates a code object containing Python bytecode and metadata.
3. CPython’s evaluation machinery reads the bytecode and performs the language-defined addition protocol.
4. CPython itself consists of native machine code currently executed by the physical CPU.
5. If `left` and `right` are user-defined objects, addition may call further Python code, producing new frames and further bytecode evaluation.

The word “program” may refer to the user’s Python program or to the CPython program implementing it. Precision requires naming which. Likewise, source, bytecode, and native machine code are distinct representations linked by explicit translation and execution relationships.

Interpretation can support interactive execution, portable intermediate representations, dynamic inspection, and adaptable runtime behaviour. Its costs may include dispatch work for each virtual instruction and less direct access to processor optimisation. These are tendencies, not laws. Sophisticated interpreters can outperform poor native code on a workload, and most performance depends on more than the presence of an interpreter loop.
