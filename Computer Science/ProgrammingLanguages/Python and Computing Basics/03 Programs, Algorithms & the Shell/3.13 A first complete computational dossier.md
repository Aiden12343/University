# 3.13 A first complete computational dossier

A **computational dossier** is the collection of claims and evidence required to defend a program rather than merely display it. For a small command-line program it contains:

1. the problem and admitted instances;
2. the specification, including invalid-input policy;
3. the data representations and their invariants;
4. the algorithm and termination argument;
5. the program representation and required implementation;
6. the invocation contract: command, arguments, CWD, and environment;
7. expected stdout, stderr, effects, and exit statuses;
8. independently derived expected results, called **test oracles**;
9. representative normal, boundary, and failure cases;
10. observations labelled by environment and version.

This dossier separates proof obligations. The specification judges intention. The invariant and termination argument judge the algorithm. Tests judge selected executions against oracles. A fresh-process run judges the durable source and invocation path. None substitutes for all the others.

### Worked example 3.12 — Dossier skeleton for maximum-of-input

Problem: read a non-empty file containing one signed decimal integer per line and print its maximum.

Specification choices that must be explicit:

- Is surrounding whitespace allowed?
- Are blank lines ignored or invalid?
- What text encoding is required?
- What happens for an empty file?
- Is there an integer-size limit?
- Must the program avoid retaining all values?
- What exact output format and newline are required?
- Which failures share an exit status?

Algorithm: parse one line at a time; initialise the retained maximum from the first admitted integer; compare each later integer and retain the larger. Invariant: after (k\geq1) admitted lines, retained `best` is the maximum of those (k) values. Termination: the file is finite and each iteration consumes one line. Space property: apart from input/output buffering, the algorithm retains constant-size summary state, though the integer representation may grow with input magnitude.

Oracles should not be copied from the program’s own calculation. For a small fixture, a human can order the values independently. For generated cases, a differently structured reference method may serve, but shared assumptions must be recognised. An oracle that repeats the same defect is not independent evidence.
