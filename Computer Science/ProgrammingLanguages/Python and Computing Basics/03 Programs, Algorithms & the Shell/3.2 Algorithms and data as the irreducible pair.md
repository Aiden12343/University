# 3.2 Algorithms and data as the irreducible pair

An execution transforms represented state. To determine the next state, a computational system needs both a rule and a current representation to which the rule applies. At the program level these roles appear as **algorithm** and **data**.

**Data** is represented information available to computation. It includes explicit input, retained variables, program configuration, file contents, network messages, and even the encoded program itself when one program processes another. An algorithm without data has nothing on which to operate. Data without an algorithm remains a representation without an active transformation rule.

This division is conceptual rather than a promise that two disjoint regions always exist. In a stored-program machine, instruction patterns are stored as data. An interpreter treats another program’s representation as its input data, then applies evaluation rules to it. A self-modifying program changes representations that later become its instructions. The roles remain distinct at a given explanatory moment: *which patterns are currently being treated as rules, and which as the state those rules transform?*

An algorithm normally consists of:

1. a set of admitted states or inputs;
2. elementary operations whose effects are defined;
3. a control rule selecting the next operation;
4. a stopping condition;
5. a result or externally visible effect.

The word **finite** in the definition of algorithm has two relevant senses. The method has a finite description, and for each admitted finite problem instance it must complete after a finite number of steps if total correctness is claimed. A finite description can generate an arbitrarily long computation because instructions may repeat.

### Worked example 3.2 — Euclid’s algorithm

The **greatest common divisor** of two non-negative integers, not both zero, is the greatest positive integer dividing both without remainder. Euclid’s algorithm repeatedly replaces the pair ((a,b)) with ((b,a\bmod b)) while (b\neq0). The symbol (mod) denotes the remainder after integer division.

For (a=1071), (b=462):

| Step | (a) | (b) | (a \bmod b) |
|---:|---:|---:|---:|
| 0 | 1071 | 462 | 147 |
| 1 | 462 | 147 | 21 |
| 2 | 147 | 21 | 0 |
| stop | 21 | 0 | — |

The result is 21. The central preserved property is

\[
\gcd(a,b)=\gcd(b,a\bmod b).
\]

This equality holds because any number dividing both (a) and (b) also divides (a-qb), including the remainder, and the converse follows by reconstructing (a=qb+r). The method terminates because when (b>0), the remainder satisfies (0\leq a\bmod b<b). The second component is a non-negative integer that strictly decreases until it reaches zero.

The example contains more than a recipe. It identifies a **loop invariant**, a property preserved across repetitions and useful at termination, and a **variant** or decreasing measure, a well-founded quantity demonstrating termination. Correctness requires both. An endlessly repeating procedure may preserve the right answer relation without ever producing the answer.
