# 3.3 Partial and total correctness

**Partial correctness** means: if the algorithm terminates on an admitted input, its result satisfies the specification. **Termination** means it does finish on every input under consideration. **Total correctness** combines partial correctness and termination.

These labels prevent a common logical error. Testing that several runs finished with correct answers provides observations about those runs; it does not prove termination for all admitted inputs. Conversely, showing that a loop counter reaches zero proves termination but not that the returned value is the required answer.

A **precondition** is a property required before an operation begins. A **postcondition** is a property required after successful completion. An invariant is required at designated intermediate points. Together they support local reasoning.

### Worked example 3.3 — Prove a maximum scan

Specification:

- Precondition: `values` is a finite non-empty sequence whose elements admit a consistent total ordering.
- Postcondition: return an element (m) from `values` such that every element (x) in `values` satisfies (x\leq m).
- Effect: do not modify `values`.

Algorithm in pseudocode:

```text
best := first element of values
for each remaining element item from left to right:
    if item is greater than best:
        best := item
return best
```

Invariant: immediately before each comparison, `best` is a maximum of the already processed prefix.

**Initialisation.** Before the first comparison, the processed prefix contains only the first element. `best` is that element, hence a maximum of the prefix.

**Maintenance.** Assume the invariant holds before processing `item`. If `item > best`, assigning `item` makes `best` at least as large as every old prefix member and equal to the new member. Otherwise the old `best` remains at least as large as `item` and every old member. In either case the invariant holds for the enlarged prefix.

**Termination.** The finite sequence has one fewer unprocessed element after every iteration. Eventually no elements remain.

**Postcondition.** At termination the processed prefix is the whole sequence. By the invariant, `best` is a maximum of the whole sequence. It was initialised or assigned only from input elements, so it is itself an input member. The algorithm satisfies the postcondition.

The non-empty precondition is necessary for this formulation because “first element” otherwise has no referent. One may design a different specification accepting empty input, but then its required result—sentinel, optional value, or explicit failure—must be stated rather than guessed.

> **Common misconception — “An invariant never changes.”**  
> The values mentioned by an invariant may change. The *property* remains true at the designated points. In the maximum scan, `best` can change while “best is a maximum of the processed prefix” remains true.
