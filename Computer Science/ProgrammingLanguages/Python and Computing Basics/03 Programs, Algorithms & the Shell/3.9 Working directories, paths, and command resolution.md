# 3.9 Working directories, paths, and command resolution

Every ordinary process has a **current working directory** (**CWD**), a directory used as the default base for resolving relative paths. An **absolute path** supplies an anchor independent of that ordinary base. A **relative path** requires a base before it designates a location.

If the CWD is `/home/learner/project`, the relative path `data/input.txt` resolves from that directory to `/home/learner/project/data/input.txt`. The directory containing the program’s source file need not equal the process CWD. Launching `/home/learner/project/app.py` while the shell is in `/home/learner` does not silently move the process into the source directory.

When a command name contains no explicit path, a shell ordinarily searches a configured sequence of directories. On many systems this sequence is exposed through an environment variable named `PATH`. An **environment variable** is a named string supplied as part of a process’s inherited environment. The precise command-resolution algorithm is shell- and platform-specific: aliases, functions, built-ins, executable extensions, hashing, and policy may participate. A rigorous diagnosis asks the shell which command it will invoke rather than guessing from a filename elsewhere.

### Worked example 3.8 — Same relative path, different target

Project tree:

```text
/study/project/
    app.py
    data/
        input.txt
```

From CWD `/study/project`, a request for `data/input.txt` designates the shown file. From CWD `/study`, the same relative text designates `/study/data/input.txt`, which may not exist. The string did not change; its implicit base did.

Relative paths are valuable because they preserve internal relationships when a project moves. Their correctness depends on a stated base. Absolute paths are explicit for one location but often non-portable. The choice is contractual, not stylistic.
