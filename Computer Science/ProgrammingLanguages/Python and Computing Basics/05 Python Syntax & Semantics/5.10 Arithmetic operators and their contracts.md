# 5.10 Arithmetic operators and their contracts

Python’s arithmetic operators include:

| Syntax | Conventional operation |
|:---:|:---|
| `a + b` | addition |
| `a - b` | subtraction |
| `a * b` | multiplication |
| `a / b` | true division |
| `a // b` | floor division |
| `a % b` | modulo/remainder paired with floor division |
| `a ** b` | exponentiation |
| `-a`, `+a` | unary negation and unary plus |

Operator syntax dispatches to type-defined protocols; the table gives conventional numeric meaning, not a universal restriction. Lists and strings define selected operators such as concatenation or repetition.

For compatible numeric values where the operation is defined, floor division and modulo satisfy:

\[
a = (a // b)\times b + (a \% b), \qquad b\neq0.
\]

Floor division rounds the quotient towards negative infinity, not towards zero.

```python
print(-7 // 3)
print(-7 % 3)
print((-7 // 3) * 3 + (-7 % 3))
```

Output:

```text
-3
2
-7
```

The quotient (-3) is the floor of approximately (-2.333). The remainder 2 reconstructs the dividend under the divisor-positive convention.

Division by numeric zero raises `ZeroDivisionError`. Floating-point infinity and NaN can arise through explicit construction or operations on existing special values, though ordinary division by zero still raises in Python. **NaN**, “not a number”, is unordered in a way that defeats reflexive equality:

```python
value = float("nan")
print(value == value)
print(value < 10)
print(value > 10)
```

All three ordinarily print `False`. Detect NaN with `math.isnan` under the relevant numeric contract, not with equality to another NaN.

### 5.10.1 Operators are protocol requests

The expression <code>a + b</code> does not universally mean numeric addition. It asks the operand types to implement the addition protocol. Built-in examples include:

~~~python
print(2 + 3)
print("py" + "thon")
print([1, 2] + [3])
~~~

The results are numeric sum, string concatenation, and new list concatenation. The shared punctuation signals a structural idea of addition while each type defines admitted operands, returned type, and cost.

For a binary operator, Python generally gives the left operand’s method an opportunity and can then try a reflected method on the right operand according to data-model precedence. A method returns <code>NotImplemented</code> to decline a pairing. If no applicable implementation succeeds, Python raises <code>TypeError</code>.

Operator overloading should preserve expectations relevant to the domain. Defining account addition to send a network request would be syntactically possible but semantically hostile: readers expect an expression-like operation with bounded and comprehensible effects.

### 5.10.2 True division and floor division

For integer operands, <code>/</code> produces a floating result:

~~~python
print(8 / 4)
print(type(8 / 4))
~~~

The value displays as <code>2.0</code> and has type <code>float</code>. Exact divisibility does not preserve integer type. Use <code>//</code> only when flooring is the intended mathematical operation, not merely to force an integer result.

With negative divisors, the reconstruction identity still governs signs:

~~~python
for dividend, divisor in [(-7, 3), (7, -3), (-7, -3)]:
    quotient, remainder = divmod(dividend, divisor)
    print(dividend, divisor, quotient, remainder)
    assert dividend == quotient * divisor + remainder
~~~

The remainder has the divisor’s sign or is zero under integer floor-division semantics. Languages that truncate towards zero produce different quotient/remainder pairs, so algorithms ported from them require review.

<code>divmod(a, b)</code> requests quotient and remainder together and returns a two-element tuple. A numeric type can implement this more coherently or efficiently than two unrelated calls.

### 5.10.3 Modulo is not a universal normalisation

For a positive modulus (m), <code>x % m</code> yields a representative in ([0,m)) for integers. This supports cyclic indices:

~~~python
next_index = (current_index + 1) % length
~~~

The precondition is <code>length &gt; 0</code>. Modulo by zero fails, and a negative modulus yields a different interval. Floating modulo inherits rounding complications. Security-sensitive modular arithmetic also requires algorithms resistant to timing leakage; ordinary <code>%</code> syntax makes no such promise.

The three-argument form <code>pow(base, exponent, modulus)</code> computes modular exponentiation without first constructing the potentially enormous full power:

~~~python
result = pow(7, 128, 13)
print(result)
~~~

For admitted integer arguments it is usually more efficient than <code>7 ** 128 % 13</code>. Current Python versions also define selected negative-exponent modular cases when an inverse exists. Consult the exact version contract rather than extrapolating.

### 5.10.4 Sequence repetition aliases elements

Multiplication on a sequence repeats references:

~~~python
rows = [[0] * 3] * 4
rows[0][0] = 9
print(rows)
~~~

All four outer positions refer to the same inner list, so every displayed row begins with 9. To construct independent rows:

~~~python
rows = [[0] * 3 for _ in range(4)]
~~~

The comprehension evaluates the inner list display once per iteration. The name <code>_</code> conventionally marks an unused loop value; it remains an ordinary name.

String and tuple repetition is safe from outer structural mutation because those outer objects are immutable, but a repeated tuple can still contain repeated references to mutable elements.

### 5.10.5 Bitwise operators

Integer bitwise operators treat integers according to an unbounded two’s-complement semantic model:

| Syntax | Operation |
|:---:|:---|
| <code>a &amp; b</code> | bitwise AND |
| <code>a &#124; b</code> | bitwise OR |
| <code>a ^ b</code> | bitwise exclusive OR |
| <code>~a</code> | bitwise complement |
| <code>a &lt;&lt; n</code> | left shift |
| <code>a &gt;&gt; n</code> | right shift |

For non-negative integers, shifting left by (n) positions multiplies by (2^n); shifting right performs floor division by (2^n):

~~~python
value = 13
print(value << 3)
print(value >> 2)
~~~

The outputs are 104 and 3. Negative shift counts raise <code>ValueError</code>. Python integer shifts do not silently discard high bits through fixed-width overflow; the integer expands subject to memory. When implementing a 32-bit protocol field, apply an explicit mask:

~~~python
MASK_32 = (1 << 32) - 1
wrapped = value & MASK_32
~~~

This represents reduction to the low 32 bits. Signed interpretation requires an additional rule.

### Worked example 5.7B — Pack and unpack flags

Assign bit meanings:

~~~python
READ = 1 << 0
WRITE = 1 << 1
EXECUTE = 1 << 2

permissions = READ | WRITE

print(bool(permissions & READ))
print(bool(permissions & EXECUTE))

permissions |= EXECUTE
permissions &= ~WRITE
print(permissions)
~~~

OR sets admitted bits, AND tests or retains bits, and complement constructs a mask that clears WRITE when combined with AND. The final integer is 5, whose low three bits are <code>101</code>.

Bit fields are compact protocol representations but less self-describing than sets of enumeration values. Document bit positions, admitted combinations, width, byte order, and unknown-bit policy.

### 5.10.6 Matrix multiplication syntax

The operator <code>@</code> requests matrix multiplication or another type-defined operation. Built-in numeric scalars do not define it:

~~~python
# 2 @ 3 raises TypeError.
~~~

Array libraries use it for linear algebra. The syntax belongs to Python’s operator grammar; mathematical meaning and dimensional constraints belong to the operand types. Chapter 16 develops array shapes and matrix products.

### 5.10.7 Arithmetic exceptions and partial effects

An arithmetic expression can fail through:

- incompatible operand types;
- division or modulo by zero;
- invalid domain conversion;
- memory exhaustion for enormous integers;
- user-defined operator code;
- floating exceptional values that propagate without raising.

The absence of an exception does not prove a finite or domain-valid result:

~~~python
value = float("inf") - float("inf")
print(value)
~~~

The result is NaN rather than an ordinary raised exception. Validate postconditions when infinities or NaNs are outside the admitted domain.

> **Common misconception — “Arithmetic operators have one meaning inherited from school mathematics.”**  
> Syntax dispatches type protocols under finite representations and evaluation order. Numeric laws apply only after establishing operand types, domains, rounding, and effects.
