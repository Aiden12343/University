# 5.13 `None` and absence

`None` is the sole instance of `NoneType`. It conventionally represents absence of a value, absence of a result, or a distinguished default under a particular interface. It is not zero, false, an empty string, or an undefined name.

Use identity comparison:

```python
if result is None:
    print("no result")
```

`None` is a **singleton**, meaning the language exposes one distinguished object for this role. Testing with `is` asks the exact required question. `== None` would permit an operand’s equality method to participate and obscures the singleton contract.

A function that reaches the end without an explicit `return` returns `None`. This does not mean the function did nothing; it may have performed effects. It means no other result object was specified.

### Worked example 5.9 — False value versus missing value

```python
def find_count(name: str) -> int | None:
    counts = {"open": 0, "closed": 4}
    return counts.get(name)


for key in ["open", "missing"]:
    result = find_count(key)
    if result is None:
        print(key, "has no record")
    else:
        print(key, "has count", result)
```

The count zero is a present value. A truth test such as `if not result` would collapse present zero and absent `None`, losing information. The interface uses a union of integer and `None`, so the branch tests precisely for `None`.

### 5.13.1 Absence has several models

An interface may represent absence through:

- <code>None</code>;
- an exception;
- a caller-supplied default;
- a unique sentinel object;
- an empty collection;
- an explicit result record with status and value fields.

These are not interchangeable. Dictionary subscription raises <code>KeyError</code> for an absent key; <code>mapping.get(key)</code> returns <code>None</code> by default. If <code>None</code> is a legitimate stored value, the default form collapses two states:

~~~python
mapping = {"present": None}
print(mapping.get("present"))
print(mapping.get("absent"))
~~~

Both observations display <code>None</code>. Use membership, exception handling, or a sentinel when distinction matters.

### 5.13.2 Unique sentinels

A **sentinel** is a distinguished value marking a boundary or special state. Construct a unique private sentinel:

~~~python
_MISSING = object()

value = mapping.get(key, _MISSING)
if value is _MISSING:
    handle_missing()
else:
    handle_present(value)
~~~

<code>object()</code> constructs an object whose identity is unique among live objects. No admitted user value can accidentally be identical to the private sentinel unless the application exposes it. Identity testing is appropriate because the sentinel contract is identity.

A plain object’s representation is not stable or descriptive. A public API may define a small sentinel class or enumeration member with a meaningful representation and serialisation policy. Sentinels ordinarily do not survive serialisation by identity unless the serialisation layer reconstructs the distinguished singleton deliberately.

### 5.13.3 Optional values and three-state logic

Suppose a configuration field admits:

- <code>None</code>: inherit the system policy;
- <code>False</code>: disable explicitly;
- <code>True</code>: enable explicitly.

This is a three-state domain. A truth test collapses inherit and disable:

~~~python
if setting:
    enable()
else:
    disable()
~~~

The correct dispatch is explicit:

~~~python
if setting is None:
    inherit()
elif setting:
    enable()
else:
    disable()
~~~

Static type notation <code>bool | None</code> documents the admitted runtime categories but does not document their meanings; prose and tests complete the contract.

### 5.13.4 Procedures conventionally return None

Mutation-oriented methods often return <code>None</code>:

~~~python
values = [3, 1, 2]
result = values.sort()

print(values)
print(result)
~~~

This design separates the updated receiver from a meaningful result. The common defect:

~~~python
values = values.sort()
~~~

rebinds <code>values</code> to <code>None</code> after sorting the original list, often losing the accessible reference to that list. Read method contracts rather than assume every transformation returns its receiver.

### 5.13.5 None is not a bottom value

There is no universal order making <code>None</code> less than every ordinary value:

~~~python
# None < 3 raises TypeError.
~~~

To sort optional values, define policy:

~~~python
values = [3, None, 1]
ordered = sorted(
    values,
    key=lambda value: (value is None, 0 if value is None else value),
)
print(ordered)
~~~

The key places present integers first and missing values last. The first tuple element is false for integers and true for <code>None</code>; only compatible numeric tie-breakers are then compared. An alternative policy could place missing values first or reject them.

> **Common misconception — “None is Python’s null pointer or an empty object.”**  
> It is a real singleton object used by conventions to represent absence. Its precise meaning comes from each interface, and its presence is distinct from an unbound name or missing mapping key.
