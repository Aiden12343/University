# 5.14 Truth values and Boolean contexts

A **Boolean context** is a language position that asks an object for truth, such as the condition of `if` or `while`, or operands of `not`, `and`, and `or`. Objects can define truth through `__bool__`; otherwise length through `__len__` may be used. Built-in zero numbers and empty collections are false; most other objects are true. This protocol is called **truth testing**.

```python
values = [0, 1, "", "0", [], [0], None]

for value in values:
    print(repr(value), bool(value))
```

The string `"0"` is non-empty and therefore true; it is not interpreted as numeric zero. `[0]` is a non-empty list and therefore true even though its element is false. Container truth usually answers whether the container is empty, not whether every element is true.

`not` returns a Boolean. `and` and `or` use short-circuit evaluation and return one of their operands:

```python
print("" or "fallback")
print("chosen" and 42)
```

`a or b` evaluates and returns `a` if `a` is true; otherwise it evaluates and returns `b`. `a and b` returns `a` if `a` is false; otherwise it evaluates and returns `b`. The second operand is not evaluated when the first decides the result.

### Worked example 5.10 — A valid default and an invalid collapse

```python
display_name = supplied_name or "Anonymous"
```

This is correct only if every false value, including the empty string, should select the default. If the contract distinguishes “explicitly supplied empty text” from “not supplied”, the expression collapses distinct states. Use a sentinel such as `None` and test identity instead.

Short-circuiting can guard an operation:

```python
if denominator != 0 and numerator / denominator > 2:
    print("ratio exceeds two")
```

When `denominator != 0` is false, division is not evaluated, so zero division is avoided. Reversing the operands would request division before the guard.

### 5.14.1 Truth protocol

For an object in a Boolean context, Python first seeks its truth method <code>__bool__</code>. If absent, it may use <code>__len__</code>, with zero meaning false and a positive length meaning true. If neither protocol is defined, instances are true by default.

User-defined truth methods can raise. Array libraries, for example, may reject the truth value of a multi-element array because “any element?” and “all elements?” are different questions. A Boolean context is therefore an operation request, not guaranteed coercion.

The constructor <code>bool(value)</code> applies the same truth-testing protocol and returns exactly <code>False</code> or <code>True</code>.

### 5.14.2 Short-circuit operators return operands

Derive <code>and</code>:

1. evaluate the left operand;
2. truth-test it;
3. if false, return that left object;
4. otherwise evaluate and return the right operand.

Derive <code>or</code>:

1. evaluate the left operand;
2. truth-test it;
3. if true, return that left object;
4. otherwise evaluate and return the right operand.

Therefore:

~~~python
empty: list[int] = []
fallback = [1, 2]

chosen = empty or fallback
print(chosen is fallback)
~~~

The operator does not convert the chosen list to <code>True</code>; it returns the list object. This enables defaults and guards while also propagating aliases.

### 5.14.3 Defaulting can collapse valid data

The pattern:

~~~python
limit = supplied_limit or 100
~~~

selects 100 when <code>supplied_limit</code> is 0, <code>0.0</code>, <code>False</code>, an empty value, or <code>None</code>. It is correct only if every false input means “use default”.

If only <code>None</code> means absent:

~~~python
limit = 100 if supplied_limit is None else supplied_limit
~~~

The conditional expression evaluates exactly one result branch after testing the condition. Zero is preserved.

### 5.14.4 Short-circuiting as a guard

This expression is safe only under a particular order:

~~~python
if index < len(items) and items[index] == target:
    ...
~~~

It still needs the lower-bound condition <code>index &gt;= -len(items)</code> if negative indices are admitted, or <code>0 &lt;= index</code> if they are not. A complete non-negative guard is:

~~~python
if 0 <= index < len(items) and items[index] == target:
    ...
~~~

The chained comparison checks both bounds and evaluates <code>index</code> once. Only if it succeeds does subscription occur.

Guards do not provide atomicity against concurrent mutation. Another thread or callback could change <code>items</code> between length check and subscription if the object is shared and operations release control. Concurrency requires a stronger synchronisation or snapshot contract in Chapter 14.

### 5.14.5 any and all

The functions <code>any</code> and <code>all</code> short-circuit over an iterable:

~~~python
values = [2, 4, 7, 8]

has_odd = any(value % 2 for value in values)
all_positive = all(value > 0 for value in values)
~~~

<code>any</code> returns true after the first true element and false if exhausted without one. <code>all</code> returns false after the first false element and true if exhausted without one.

The empty cases follow logic:

\[
\operatorname{any}(\varnothing)=\text{False},\qquad
\operatorname{all}(\varnothing)=\text{True}.
\]

The second result is **vacuous truth**: no element violates the predicate. If an application requires at least one element, test non-emptiness separately.

### 5.14.6 Boolean arithmetic versus predicates

A **predicate** is an operation intended to classify input with a truth-valued result. Give it a name exposing the proposition:

~~~python
def is_admitted(value: int) -> bool:
    return 0 <= value <= 100
~~~

Returning 0 or 1 would work in Boolean contexts but weakens the declared contract. Returning the original value from a predicate can create false results for admitted zero. Use explicit Boolean comparisons when the operation claims to answer a proposition.

### Worked example 5.10A — Preserve four input states

An optional text field can contain:

1. no submission, represented by <code>None</code>;
2. explicit empty text, <code>""</code>;
3. whitespace-only text;
4. non-empty text.

Classify without premature truth collapse:

~~~python
def classify_text(value: str | None) -> str:
    if value is None:
        return "absent"
    if value == "":
        return "empty"
    if value.isspace():
        return "whitespace"
    return "content"
~~~

The order matters. Calling <code>isspace</code> on <code>None</code> would fail, and <code>"".isspace()</code> is false because there are no whitespace code points. A single <code>if not value</code> would merge only the first two states and leave the third separate, which is neither a complete collapse nor the required classification.

> **Common misconception — “Truth testing discovers whether a value is valid.”**  
> Truth is a type protocol, usually encoding emptiness or zero. Domain validity can distinguish many true values and many false values and requires its own predicate.
