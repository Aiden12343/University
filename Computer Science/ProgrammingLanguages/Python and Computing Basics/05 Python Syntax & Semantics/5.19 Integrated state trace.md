# 5.19 Integrated state trace

Trace this program without running it:

```python
outer = [[1], [2]]
alias = outer
copy = outer.copy()

outer[0] += [3]
copy.append([4])
alias = [[9]]

print(outer)
print(copy)
print(alias)
print(outer is copy)
print(outer[0] is copy[0])
```

Construct the object graph.

1. Two inner lists (I_1=[1]) and (I_2=[2]) are created.
2. Outer list (O=[I_1,I_2]) is created; `outer` binds to (O).
3. `alias` binds to (O).
4. Shallow copy (C=[I_1,I_2]) is created; `copy` binds to (C).
5. `outer[0]` evaluates to (I_1). In-place list addition mutates (I_1) to `[1, 3]`; both outer containers still reference it.
6. A new inner list (I_3=[4]) is appended only to (C).
7. New inner list (I_4=[9]) and outer list (A=[I_4]) are created; `alias` is rebound from (O) to (A).

Output:

```text
[[1, 3], [2]]
[[1, 3], [2], [4]]
[[9]]
False
True
```

The trace uses every central distinction: object identity, name binding, aliasing, shallow copying, mutation, rebinding, equality-independent identity, and evaluation of a subscription target.

### 5.19.1 A notation for semantic traces

Use:

- (N:name\mapsto O_i) for a namespace binding;
- (O_i:T[v]) for an object of type (T) and abstract value or state (v);
- (O_i\rightarrow O_j) for a retained reference;
- (E_k) for an externally observable effect;
- (X_k) for a raised exception.

The notation distinguishes relationships without pretending to expose literal memory layout. For:

~~~python
source = [1, 2]
alias = source
copy = source.copy()
~~~

the graph is:

\[
N:\text{source}\mapsto O_1,\qquad
N:\text{alias}\mapsto O_1,\qquad
N:\text{copy}\mapsto O_2,
\]

where (O_1) and (O_2) are distinct lists but initially reference equal integer objects in equal order. The model can omit immutable-element identities when they are irrelevant, provided that omission is stated.

### 5.19.2 Full evaluation trace with partial failure

Consider:

~~~python
events: list[str] = []


def observe(label: str, value: object) -> object:
    events.append(label)
    return value


records = [[1], [2]]
alias = records
copy = records.copy()

try:
    alias[0] += observe("extend", [3])
    result = observe("left", 10) / observe("zero", 0)
except ZeroDivisionError:
    events.append("division failed")

print(records)
print(copy)
print(events)
~~~

Trace:

1. The empty list (E) is constructed and bound to <code>events</code>.
2. The function definition executes, creating a function object whose global name lookups can later find <code>events</code>.
3. Inner lists (I_1=[1]) and (I_2=[2]) are constructed.
4. Outer list (O=[I_1,I_2]) is constructed and bound to <code>records</code>.
5. <code>alias</code> is bound to (O).
6. Shallow copy (C=[I_1,I_2]) is constructed and bound to <code>copy</code>.
7. The augmented subscription target identifies (O) and index zero, obtaining (I_1).
8. <code>observe("extend", [3])</code> constructs a new list, appends <code>"extend"</code> to (E), and returns that list.
9. In-place list addition mutates (I_1) to [1,3]; storing it back in (O) preserves that reference.
10. The assignment to <code>result</code> begins by evaluating its right side.
11. The left call appends <code>"left"</code> and returns integer 10.
12. The right call appends <code>"zero"</code> and returns integer 0.
13. Division raises <code>ZeroDivisionError</code>. No new binding of <code>result</code> occurs.
14. The handler appends <code>"division failed"</code>.
15. Both (O) and (C) expose the mutation of shared (I_1).

Output:

~~~text
[[1, 3], [2]]
[[1, 3], [2]]
['extend', 'left', 'zero', 'division failed']
~~~

The exception prevents one target binding but reverses none of the earlier list mutations or event appends.

### 5.19.3 Text, bytes, and numeric boundary trace

Suppose input bytes are:

~~~python
payload = b"quantity=0007\n"
~~~

Process them under the contract “ASCII-compatible UTF-8 record, exact field name, decimal integer value, terminal newline required”:

~~~python
text = payload.decode("utf-8")

if not text.endswith("\n"):
    raise ValueError("record requires terminal newline")

line = text.removesuffix("\n")
name, separator, source_value = line.partition("=")

if separator == "" or name != "quantity":
    raise ValueError("invalid quantity record")

quantity = int(source_value, 10)

if not 0 <= quantity <= 1_000_000:
    raise ValueError("quantity outside admitted range")
~~~

Representation stages:

1. <code>payload</code> is thirteen byte values.
2. UTF-8 decoding yields thirteen code points because every byte is ASCII-range.
3. The terminal newline is validated and removed under an exact suffix rule.
4. Partitioning returns three strings while preserving whether a separator was found.
5. Field-name comparison tests exact code-point sequence.
6. Decimal parsing collapses the four-character representation <code>"0007"</code> to integer value 7.
7. Range validation establishes the domain invariant.

If original spelling matters for audit, retain <code>source_value</code>. The integer alone cannot reconstruct whether the input was <code>7</code>, <code>07</code>, or <code>0007</code>.

### 5.19.4 Equality, identity, and hashing trace

~~~python
first = (1, "A")
second = tuple([1, "A"])
mapping = {first: "stored"}

print(first == second)
print(first is second)
print(mapping[second])
~~~

The tuples compare equal element by element. Their identities may differ and must not be relied upon. Because equal hashable tuples have equal hashes, <code>second</code> selects the association inserted under <code>first</code>. The dictionary retains its original key object; lookup equivalence does not replace it.

The key’s transitive elements are immutable and hashable. Replacing the string with a list would make tuple hashing fail and prohibit dictionary-key use.

### 5.19.5 A semantic proof-obligation checklist

For every unfamiliar Python expression or statement, ask:

1. Which source grammar form is this?
2. Which subexpressions exist, and how are they grouped?
3. In what order are those subexpressions evaluated?
4. Which names are looked up, bound, rebound, or deleted?
5. Which runtime objects are produced?
6. Which identities are shared?
7. Which operations can mutate existing objects?
8. Which protocols perform dispatch?
9. Which implicit conversions occur?
10. Which exceptions or non-returning paths are possible?
11. Which effects can occur before failure?
12. Which statements commit target changes?
13. Which claims are language guarantees and which are implementation observations?
14. Which domain invariant is gained or lost?
15. What oracle would expose an incorrect but non-exceptional result?

This checklist is intentionally more demanding than mentally executing syntax. It converts program reading into an explicit semantics exercise.
