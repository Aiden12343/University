# 5.2 Expressions and statements

An **expression** is syntax that, when evaluated successfully, produces a value. A **statement** is a complete instruction in Python’s execution grammar. Some statements contain expressions; an expression can also appear as an expression statement.

Examples of expressions:

```python
42
left + right
convert(text)
record.name
items[index]
```

Examples of statements:

```python
answer = 42
return answer
import math
if answer > 0:
    print(answer)
```

Assignment is a statement, not an expression, under ordinary `=` syntax. It does not produce a value that can be nested arbitrarily. The assignment expression operator `:=`, introduced for selected expression contexts, is a different construct with additional restrictions and should be used only when binding during expression evaluation improves the control model.

Evaluation has an order defined by the language. Operands are not mathematical symbols whose values appear outside time; their evaluation may call functions, raise exceptions, mutate objects, or perform I/O. Parentheses determine grouping but do not by themselves reverse operand evaluation order.

### Worked example 5.1 — Trace an expression with effects

```python
def observe(label: str, value: int) -> int:
    print(label)
    return value


result = observe("left", 2) + observe("right", 3) * 4
print(result)
```

The output is:

```text
left
right
14
```

Trace:

1. The right side of assignment must be evaluated before `result` can be bound.
2. Python evaluates the left operand of `+`, calling `observe("left", 2)`. The call prints `left` and returns integer 2.
3. The right operand of `+` is the multiplication expression. Its left operand calls `observe("right", 3)`, prints `right`, and returns 3.
4. Multiplication produces 12.
5. Addition produces 14.
6. Assignment binds `result` to the resulting integer object.
7. The final call prints 14.

Precedence determines that multiplication is grouped inside addition. It does not mean multiplication’s source appears or executes before the left operand of the surrounding addition.

### 5.2.1 Expression categories

Useful expression categories include:

- **primary expressions**, such as attribute references, subscriptions, slicings, and calls;
- **literal displays**, which construct containers or textual and numeric values;
- **unary operations**, which have one explicit operand;
- **binary operations**, which have two explicit operands;
- **comparisons**, including membership and identity tests;
- **Boolean operations**, which short-circuit;
- **conditional expressions**, which select one of two result expressions;
- **lambda expressions**, which create anonymous function objects;
- **comprehensions and generator expressions**, which describe iterative construction.

The last two categories are derived in Chapters 8 and 6 respectively. Their presence here prevents a false simplification: an expression can create a function, iterate, mutate state through calls, or suspend computation. “Expression” means value-producing syntax, not “small calculation without effects”.

### 5.2.2 Simple and compound statements

A **simple statement** occupies one logical line as a grammar unit. Assignment, <code>return</code>, <code>raise</code>, <code>import</code>, <code>pass</code>, <code>break</code>, and <code>continue</code> are examples. Several simple statements can technically share one line separated by semicolons, but ordinary source places one per line because sequencing and revision are then explicit.

A **compound statement** contains one or more clauses controlling suites. Conditional, loop, function-definition, class-definition, exception-handling, and context-management statements are compound. The header and indentation establish control structure:

~~~python
if admitted:
    process()
else:
    reject()
~~~

The colon and nested suite are grammatical. The newlines and indentation communicate which call belongs to which alternative.

The statement <code>pass</code> performs no operation. It supplies a syntactically required suite while a design is incomplete or while emptiness is intentional:

~~~python
if condition_requiring_no_action:
    pass
else:
    perform_action()
~~~

An ellipsis literal, <code>...</code>, is an expression producing the singleton <code>Ellipsis</code>; it is sometimes used as a placeholder by convention but is not semantically identical to <code>pass</code>.

### 5.2.3 Assignment has a time order

For ordinary assignment, Python evaluates the right-hand expression before committing target assignments. In chained assignment:

~~~python
left = right = make_value()
~~~

<code>make_value()</code> is called once. Both names are then bound to the one resulting object. This does not construct two copies.

For multiple targets separated by commas:

~~~python
left, right = compute_left(), compute_right()
~~~

the right-side expressions are evaluated from left to right, the produced elements are organised for unpacking, and then targets receive them from left to right. Target assignment itself can execute user code for attributes or subscriptions, so partial target effects are possible if a later target assignment fails.

### Worked example 5.1B — Partial target assignment

~~~python
class RejectingRecord:
    def __setattr__(self, name: str, value: object) -> None:
        if name == "forbidden":
            raise ValueError("field rejected")
        object.__setattr__(self, name, value)


record = RejectingRecord()
ordinary = 0

ordinary, record.allowed, record.forbidden = 1, 2, 3
~~~

This example uses a class and a special method before Chapter 9; minimally, the method intercepts attribute assignment. All three right-side integers are obtained first. Then <code>ordinary</code> becomes 1 and <code>record.allowed</code> becomes 2. Assignment to <code>record.forbidden</code> raises. Python does not transactionally roll back the earlier target effects.

The lesson applies without custom classes: unpacking to several list positions or attributes can partially mutate state. If all-or-nothing update is required, validate and construct a complete new state before one controlled commit.

### 5.2.4 Assignment expressions

The operator <code>:=</code> evaluates an expression, binds its value to a name under assignment-expression scope rules, and also yields that value as the surrounding expression’s result. It exists to avoid repeating an effectful or costly expression when the obtained value participates in a condition:

~~~python
if (line := input_stream.readline()) != "":
    process(line)
~~~

The call occurs once. Its returned string is bound to <code>line</code>, then compared with the end-of-file marker. The required parentheses make the intended grouping visible in this context.

Do not use assignment expressions merely to compress successive statements:

~~~python
# Obscure:
print(total := width * height)

# Clear when the binding has independent meaning:
total = width * height
print(total)
~~~

The construct is valuable when binding and selection are one conceptual event, particularly in loops and comprehensions. Its grammar restricts targets and positions to prevent ambiguity; it is not ordinary assignment transplanted everywhere.

### 5.2.5 Evaluation order versus mathematical equivalence

In arithmetic over exact mathematical numbers, (a+b=b+a). Program expressions can contain effects or exceptional behaviour:

~~~python
left() + right()
right() + left()
~~~

Even if returned numeric values commute under addition, the programs can print in a different order, mutate shared state differently, or fail before calling the other operand. Algebraic rewrites are semantics-preserving only after establishing purity, totality over admitted inputs, and compatible numeric representation.

Floating-point arithmetic also invalidates some real-number identities because rounding occurs after operations. For example, association can fail:

~~~python
large = 1.0e16
print((large + -large) + 1.0)
print(large + (-large + 1.0))
~~~

The first commonly produces 1.0; the second commonly produces 0.0 because adding 1.0 to <code>-large</code> cannot retain the small increment at binary64 precision. Parentheses can therefore affect numeric value even without effects.

### 5.2.6 Expression statements discard ordinary results

An expression statement evaluates an expression and ordinarily discards its result. It remains meaningful when evaluation has an intended effect:

~~~python
log_event("started")
collection.append(item)
~~~

The returned objects, often <code>None</code>, are ignored. A bare literal in a script:

~~~python
42
~~~

computes an integer and discards it. A string literal as the first statement of a module, class, or function can be recognised as a **docstring**, a documentation convention with specified runtime exposure. Elsewhere, a bare string usually has no useful effect.

> **Common misconception — “Every line returns something.”**  
> Expressions produce values; statements govern execution; a function call may return a value; a source line is only physical layout. These classifications overlap in structured ways but are not synonyms.
