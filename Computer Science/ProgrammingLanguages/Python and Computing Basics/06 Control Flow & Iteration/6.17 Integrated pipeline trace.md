# 6.17 Integrated pipeline trace

```python
def admitted_integers(fields: list[str]):
    for position, field in enumerate(fields, start=1):
        stripped = field.strip()
        if not stripped:
            continue
        try:
            value = int(stripped)
        except ValueError as error:
            raise ValueError(f"field {position} is not an integer") from error
        if value >= 0:
            yield value


fields = [" 4 ", "", "-2", "7"]
values = admitted_integers(fields)
result = sum(value * value for value in values)
print(result)
```

Trace:

1. Calling `admitted_integers` creates a generator; its body has not run.
2. `sum` requests items from the generator expression.
3. The generator expression requests an item from `values`.
4. `enumerate` requests `" 4 "`; stripping produces `"4"`; conversion produces 4; the non-negative condition yields 4.
5. The generator expression squares 4 and supplies 16 to `sum`.
6. The empty field becomes `""`; `continue` skips conversion.
7. `"-2"` converts successfully but fails the non-negative filter, so nothing is yielded.
8. `"7"` yields 7; the outer expression supplies 49.
9. Exhaustion propagates normally through both iteration layers; `sum` produces 65.

If a field is `"x"`, `int` raises `ValueError`; the handler raises a contextual `ValueError`; neither generator completes normally; `sum` does not produce a result. Laziness moves parsing failure to consumption time.

### 6.17.1 Pipeline stages

The integrated example contains:

1. a finite reusable list source;
2. a generator function that enumerates, strips, filters, parses, validates, and yields;
3. a generator expression that squares;
4. a terminal consumer, <code>sum</code>;
5. contextual exception translation.

Control moves demand-first from the terminal consumer back through the layers. It is inaccurate to imagine the inner generator completing before the outer begins. For each admitted field, one value travels through the complete pipeline before the next source field is requested.

### 6.17.2 Pipeline invariant

After (k) source fields have been consumed successfully, define:

- (A_k) as the ordered sequence of non-empty, parseable, non-negative integers among those fields;
- (T_k) as the partial total maintained by <code>sum</code>.

Invariant:

\[
T_k = \sum_{x\in A_k} x^2.
\]

Empty fields and negative values extend the consumed prefix without changing (A_k) or (T_k). An admitted non-negative integer appends (x) and adds (x^2). Exhaustion makes the consumed prefix the whole finite input, yielding the postcondition.

A malformed field causes exceptional completion. The invariant still describes prefix state, but no ordinary result is returned. If <code>sum</code> has no external effect, that partial accumulator becomes inaccessible with its frame. If a downstream consumer writes after every value, prefix effects persist.

### 6.17.3 A staged all-or-nothing alternative

~~~python
def parse_all(fields: list[str]) -> list[int]:
    result = []

    for position, field in enumerate(fields, start=1):
        stripped = field.strip()
        if not stripped:
            continue

        try:
            value = int(stripped, 10)
        except ValueError as error:
            raise ValueError(
                f"field {position} is not an integer"
            ) from error

        if value >= 0:
            result.append(value)

    return result


values = parse_all(fields)
result = sum(value * value for value in values)
~~~

This materialises admitted integers. It requires (O(n)) references for (n) admitted values, but it establishes complete parsing before aggregation or later external effects. The lazy and eager versions compute the same ordinary result on finite valid input; their resource and failure-time contracts differ.

### 6.17.4 Generalised command pipeline

~~~python
from dataclasses import dataclass
from typing import Iterable, Iterator


@dataclass(frozen=True)
class ParsedInteger:
    line_number: int
    value: int


class InputRecordError(ValueError):
    def __init__(
        self,
        line_number: int,
        source: str,
    ) -> None:
        self.line_number = line_number
        self.source = source
        super().__init__(
            f"line {line_number}: invalid integer {source!r}"
        )


def parse_lines(
    lines: Iterable[str],
) -> Iterator[ParsedInteger]:
    for line_number, line in enumerate(lines, start=1):
        content = line.partition("#")[0].strip()
        if not content:
            continue

        try:
            value = int(content, 10)
        except ValueError as error:
            raise InputRecordError(
                line_number,
                content,
            ) from error

        yield ParsedInteger(line_number, value)
~~~

The annotation types are a flagged forward use developed in Chapter 12. The immutable record preserves provenance alongside value. Comment removal uses the first <code>#</code> anywhere, which is correct only for a grammar with no quoted strings or escaped comment marker. A stronger grammar needs a lexer.

### Worked example 6.11 — Bounded consumer with truthful completion

~~~python
def first_non_negative(
    records: Iterable[ParsedInteger],
) -> ParsedInteger | None:
    for record in records:
        if record.value >= 0:
            return record
    return None
~~~

This consumer can terminate after one admitted match even if the source is unbounded. Its result says nothing about malformed data later in the source because those records were never requested. The statement “input is valid” would therefore overclaim. The correct claim is “a non-negative parsed record was found before any requested prefix failure”.

### 6.17.5 Complete validation consumer

~~~python
def summarise(
    records: Iterable[ParsedInteger],
) -> tuple[int, int, int | None, int | None]:
    count = 0
    total = 0
    minimum = None
    maximum = None

    for record in records:
        value = record.value
        count += 1
        total += value

        if minimum is None or value < minimum:
            minimum = value
        if maximum is None or value > maximum:
            maximum = value

    return count, total, minimum, maximum
~~~

Invariant after each loop boundary:

- <code>count</code> equals records consumed;
- <code>total</code> equals their mathematical integer sum;
- if count is zero, minimum and maximum are <code>None</code>;
- otherwise minimum and maximum are the extrema of consumed values.

For a finite source, normal exhaustion yields a complete summary. For an unbounded source, the function need not return. For a failing source, it raises and exposes no returned partial tuple, though source effects already occurred.
