# 9.12 Special methods and operator protocols

Names beginning and ending with double underscores are commonly called **special methods** or **dunder methods**. Python syntax and built-ins consult these methods through type-defined protocol rules.

Examples:

| Syntax/operation | Principal protocol methods |
|:---|:---|
| `len(obj)` | `__len__` |
| `obj[key]` | `__getitem__` |
| `obj[key] = value` | `__setitem__` |
| `for x in obj` | `__iter__`, then iterator protocol; sequence fallback in selected cases |
| `x in obj` | `__contains__` or iteration fallback |
| `obj()` | `__call__` |
| `a + b` | `__add__`, reflected/cooperative routes |
| `with obj` | `__enter__`, `__exit__` |
| `repr(obj)` | `__repr__` |

Special-method lookup often occurs on the type, not through ordinary instance attribute lookup. Assigning `instance.__len__ = ...` does not ordinarily change `len(instance)`. This design supports interpreter optimisation and consistent protocol behaviour.

### Worked example 9.4 — A finite interval collection

```python
class ClosedInterval:
    def __init__(self, start: int, stop: int) -> None:
        if stop < start:
            raise ValueError("stop must not precede start")
        self.start = start
        self.stop = stop

    def __contains__(self, value: object) -> bool:
        if not isinstance(value, int):
            return False
        return self.start <= value <= self.stop

    def __len__(self) -> int:
        return self.stop - self.start + 1

    def __iter__(self):
        return iter(range(self.start, self.stop + 1))


interval = ClosedInterval(3, 5)
print(4 in interval)
print(len(interval))
print(list(interval))
```

Output:

```text
True
3
[3, 4, 5]
```

The class supports containment, sizing, and iteration as one coherent finite inclusive interval. `__len__` must return a non-negative integer within platform constraints. A mathematically enormous interval may exceed the representable `Py_ssize_t` range used by `len`, even though iteration could conceptually proceed; protocol limits are part of implementation-facing design.

Do not call dunder methods directly when a public operation exists. `len(obj)` expresses the protocol and allows Python to enforce its rules; `obj.__len__()` names one method implementation directly.

### 9.12.1 Special lookup commonly starts from the type

For implicit syntax, the interpreter often resolves a special method on <code>type(obj)</code>, bypassing an identically named entry placed only on the instance:

~~~python
class Sized:
    def __len__(self) -> int:
        return 3


item = Sized()
item.__len__ = lambda: 100

print(item.__len__())          # 100: ordinary attribute/call
print(len(item))               # 3: special lookup through type
~~~

This prevents metaclass/type operations from becoming confused by instance-level special attributes and enables optimized slots. To customize protocol behaviour per instance, the class-level special method can delegate to instance strategy state.

### 9.12.2 Truth testing uses __bool__ then __len__

<code>bool(obj)</code> and conditional contexts first seek <code>__bool__</code>. If absent, they may use <code>__len__</code>; zero is false and nonzero true. Otherwise ordinary objects are truthy.

~~~python
class QueueView:
    def __init__(self, items: list[object]) -> None:
        self._items = items

    def __len__(self) -> int:
        return len(self._items)
~~~

The view is false exactly when the referenced list is empty. <code>__bool__</code> must return an actual bool; <code>__len__</code> must return a non-negative integer fitting the length protocol. Negative length raises <code>ValueError</code> rather than meaning true or unknown.

Truth should be unsurprising. A database query object should not execute remote I/O merely because it appears in <code>if query</code>; use an explicit method such as <code>query.exists()</code>.

### 9.12.3 __len__ is cardinality under a finite sized protocol

Length should represent a non-negative count of elements under the object’s collection abstraction. A lazy/unbounded stream may have no meaningful length and should omit the protocol rather than guess or consume itself.

CPython’s <code>len</code> converts through an index-sized integer and raises <code>OverflowError</code> for lengths beyond <code>sys.maxsize</code>, even if a custom object mathematically represents more elements. An object may offer a separate arbitrary-precision cardinality property.

### 9.12.4 __length_hint__ is not a correctness value

Iterators can expose an estimated remaining length through <code>__length_hint__</code>, used by consumers for preallocation. The hint can be inaccurate and must never control result correctness.

~~~python
from operator import length_hint

iterator = iter(range(10))
print(length_hint(iterator))
next(iterator)
print(length_hint(iterator))
~~~

Consumers may ignore the hint. Producers should return a non-negative estimate and avoid expensive side effects.

### 9.12.5 __iter__ and __next__ divide iterable from iterator

An iterable’s <code>__iter__</code> returns an iterator. An iterator’s <code>__iter__</code> returns itself, and <code>__next__</code> returns the next item or raises <code>StopIteration</code> permanently after exhaustion under the ordinary protocol.

~~~python
class Countdown:
    def __init__(self, start: int) -> None:
        self._start = start

    def __iter__(self):
        current = self._start
        while current > 0:
            yield current
            current -= 1
~~~

Countdown is reusable because each <code>iter(countdown)</code> creates a new generator. Making the Countdown object itself hold <code>current</code> and return <code>self</code> would make it a one-shot iterator and cause simultaneous loops to share position.

### 9.12.6 __getitem__ can provide sequence iteration fallback

If no <code>__iter__</code> is available, selected iteration machinery can request integer items beginning at zero until <code>IndexError</code>:

~~~python
class Squares:
    def __getitem__(self, index: int) -> int:
        if index < 0 or index >= 5:
            raise IndexError(index)
        return index * index
~~~

This legacy sequence fallback requires <code>IndexError</code> for exhaustion; returning a sentinel loops forever. Modern classes should define <code>__iter__</code> when iteration semantics matter. A mapping with integer keys should not accidentally claim sequence iteration through <code>__getitem__</code>.

### 9.12.7 Subscription receives keys or slice objects

<code>obj[key]</code> calls the subscription protocol with the evaluated key. Slice syntax packages boundaries into a <code>slice</code> object:

~~~python
class TraceSelection:
    def __getitem__(self, key):
        print(repr(key))
        return None


trace = TraceSelection()
trace[3]
trace[1:10:2]
~~~

A sequence implementation should support negative-index and slice normalization under a documented policy, commonly using <code>slice.indices(length)</code>. A mapping can accept arbitrary hashable keys and need not treat slices specially.

### 9.12.8 Assignment and deletion protocols own invariant transitions

<code>obj[key] = value</code> and <code>del obj[key]</code> call <code>__setitem__</code> and <code>__delitem__</code>. A fixed-size vector might permit replacement but reject deletion/insertion. A validated mapping should normalize/check keys before commit.

Returning values from these methods is ignored by assignment syntax; convention uses <code>None</code>. Failure after partial mutation needs an exception-safety guarantee.

### 9.12.9 __contains__ can outperform iteration fallback

For <code>item in container</code>, Python uses <code>__contains__</code> when available, otherwise iteration, and in selected cases the sequence protocol. A graph reachability object might perform a hash lookup rather than linearly iterating nodes.

<code>__contains__</code> should answer membership under the collection’s equality domain and return truth-convertible output. It must not be confused with substring search, identity, or key versus value membership; the type defines the question.

### 9.12.10 __reversed__ can exploit representation

<code>reversed(obj)</code> can call <code>__reversed__</code>; otherwise it may use length plus integer indexing for suitable sequences. A linked or tree representation can supply efficient reverse traversal without supporting all indexing.

Returning a materialized reversed list changes memory/laziness compared with an iterator. State this in the protocol implementation and avoid mutating the source during traversal unless consistency is defined.

### 9.12.11 __call__ turns state into callable behaviour

~~~python
class Threshold:
    def __init__(self, minimum: float) -> None:
        self.minimum = minimum

    def __call__(self, value: float) -> bool:
        return value >= self.minimum
~~~

An instance can be supplied as a predicate while exposing configuration for inspection. <code>callable(instance)</code> becomes true because the type defines <code>__call__</code>. The same concurrency, mutation, and exception contracts as functions apply.

### 9.12.12 Numeric conversion protocols are explicit claims

<code>int(obj)</code>, <code>float(obj)</code>, <code>complex(obj)</code>, and <code>operator.index(obj)</code> consult conversion protocols such as <code>__int__</code>, <code>__float__</code>, <code>__complex__</code>, and <code>__index__</code> under their rules.

<code>__index__</code> claims exact integer semantics suitable for slicing, indexing, and integer byte conversion; <code>__int__</code> can be a lossy conversion such as truncation. A numeric type should not implement <code>__index__</code> if conversion can lose fractional information.

### 9.12.13 String/bytes conversion is not serialization

<code>bytes(obj)</code> can use <code>__bytes__</code>, but its result has no universal schema. Likewise <code>str</code>/<code>repr</code> are representations. A wire format needs version, byte order, length, validation, and compatibility rules. Implementing <code>__bytes__</code> can provide a convenient canonical byte representation only when its contract defines those dimensions.

### 9.12.14 Context manager methods encode cleanup decisions

<code>with manager as value</code> calls <code>__enter__</code>, executes the body, then calls <code>__exit__</code> if entry completed. <code>__exit__</code> receives exception type/value/traceback or three None values and returns truthy to suppress an exception.

~~~python
class Transaction:
    def __enter__(self):
        self.begin()
        return self

    def __exit__(self, exc_type, exc_value, traceback) -> bool:
        if exc_type is None:
            self.commit()
        else:
            self.rollback()
        return False
~~~

Returning false preserves the body exception. Commit/rollback can themselves fail and replace/contextualize it. Failed <code>__enter__</code> does not trigger this object’s <code>__exit__</code> automatically, so entry must clean partial acquisitions itself.

### 9.12.15 Async context and iteration use distinct protocols

<code>async with</code> uses <code>__aenter__</code>/<code>__aexit__</code>, which return awaitables. <code>async for</code> uses <code>__aiter__</code>/<code>__anext__</code> and <code>StopAsyncIteration</code>. A synchronous method returning a coroutine is not automatically a correct async protocol implementation unless the specific method contract calls for an awaitable.

Resource cancellation during asynchronous entry, body, or exit requires explicit handling. Chapter 14 develops these protocols.

### 9.12.16 Comparison methods define separate operations

Python exposes <code>__lt__</code>, <code>__le__</code>, <code>__eq__</code>, <code>__ne__</code>, <code>__gt__</code>, and <code>__ge__</code>. Defining <code>__lt__</code> and <code>__eq__</code> does not automatically synthesize every other ordering method unless a helper such as <code>functools.total_ordering</code> is used.

<code>total_ordering</code> generates missing comparisons from supplied ones, reducing code but adding call/stack complexity and relying on coherent laws. Direct implementation may be faster/clearer for core value types.

### 9.12.17 Hash protocol requires integer output

<code>__hash__</code> must return an integer. Python may truncate it to platform hash width. Returning a Boolean technically produces an integer subtype but yields terrible distribution; returning a string raises.

Setting <code>__hash__ = None</code> declares unhashability and makes <code>isinstance(obj, collections.abc.Hashable)</code> reflect it more accurately than defining a method that raises TypeError when called.

### 9.12.18 Copy protocols can customize graph reconstruction

The <code>copy</code> module can invoke <code>__copy__</code> and <code>__deepcopy__</code>. A deep-copy method receives a memo mapping that must be used to preserve sharing and terminate cycles.

A resource-owning object should often reject copying rather than duplicate a socket/lock/file ambiguously. Immutable values can return self for copy if identity sharing is compatible. Copy behavior is a public ownership contract.

### 9.12.19 Pickle reduction is executable reconstruction

Pickling can consult <code>__reduce__</code>, <code>__reduce_ex__</code>, <code>__getnewargs_ex__</code>, <code>__getstate__</code>, and <code>__setstate__</code>. These hooks define how objects are reconstructed and can bypass ordinary initialization. Loading untrusted pickle data can execute arbitrary code and must never be treated as safe parsing.

Versioned state migration and invariant validation are required even for trusted data. JSON or schema-based formats trade object fidelity for explicit data boundaries.

### 9.12.20 Attribute and item protocols should not recurse naively

Inside <code>__getattribute__</code>, using <code>self._data</code> restarts <code>__getattribute__</code>; inside <code>__setattr__</code>, assigning <code>self._data = value</code> restarts assignment. Delegate to <code>object.__getattribute__</code>/<code>object.__setattr__</code> or <code>super()</code> under the class protocol.

Similar recursion can arise when <code>__repr__</code> prints self, <code>__hash__</code> hashes a set containing self, or <code>__eq__</code> compares cyclic graphs. Special methods form a mutually interacting protocol system.

### 9.12.21 __missing__ belongs to dict subclasses

For a dict subclass, subscription can call <code>__missing__(self, key)</code> when a key is absent. Other operations such as <code>get</code> do not necessarily invoke it.

~~~python
class ZeroDict(dict[str, int]):
    def __missing__(self, key: str) -> int:
        return 0
~~~

This returns zero without inserting. A defaultdict instead calls a factory and inserts on missing subscription. Same surface result, different mutation.

### 9.12.22 Index coercion and slicing

Objects defining <code>__index__</code> can act as exact integer indices. Sequence implementers receiving a key may use <code>operator.index</code> rather than <code>int</code> so a float such as 1.2 is rejected rather than truncated.

For slices, <code>slice.indices(length)</code> normalizes None, negative boundaries, and step direction; step zero raises. Reusing this method prevents subtle divergence from built-in sequence rules.

### 9.12.23 __format__ and f-string dispatch

As §9.7 established, formatting is a separate protocol. Format specifications are strings supplied after the colon. A custom type should either document its mini-language or delegate compatible specifications to an underlying value. Silently accepting unknown specs makes errors difficult to detect.

### 9.12.24 Special-method law checklist

Before implementing a protocol, ask:

1. What abstract operation does syntax promise?
2. What result type and sentinel/exception signal are required?
3. What algebraic laws or temporal rules must hold?
4. Does lookup occur on the type or instance?
5. Which reflected/fallback methods can be tried?
6. Can methods invoke arbitrary user code or recurse?
7. What mutation/aliasing occurs?
8. What happens on partial failure?
9. What time/space bounds will callers infer?
10. Which implementation/version limits constrain values?

### Worked example 9.5E — A reusable arithmetic progression

~~~python
from operator import index


class Progression:
    def __init__(self, start: int, stop: int, step: int = 1) -> None:
        start = index(start)
        stop = index(stop)
        step = index(step)
        if step == 0:
            raise ValueError("step must not be zero")
        self._range = range(start, stop, step)

    def __len__(self) -> int:
        return len(self._range)

    def __iter__(self):
        return iter(self._range)

    def __reversed__(self):
        return reversed(self._range)

    def __contains__(self, value: object) -> bool:
        return value in self._range

    def __getitem__(self, key):
        selected = self._range[key]
        if isinstance(selected, range):
            return type(self)(selected.start, selected.stop, selected.step)
        return selected

    def __repr__(self) -> str:
        return (
            f"{type(self).__name__}("
            f"{self._range.start}, {self._range.stop}, {self._range.step})"
        )
~~~

The class delegates arithmetic and normalization to range. Integer indexing returns an int; slicing returns another Progression, preserving the abstraction. Membership inherits range’s arithmetic behavior. Exact index conversion rejects lossy floats. Its length remains limited by <code>len(range)</code> platform constraints even though range can represent enormous endpoints.

### Worked example 9.5F — A safe resource context state machine

~~~python
class Session:
    def __init__(self, opener) -> None:
        self._opener = opener
        self._resource = None

    def __enter__(self):
        if self._resource is not None:
            raise RuntimeError("session already entered")
        resource = self._opener()
        self._resource = resource
        return self

    def execute(self, command: str):
        if self._resource is None:
            raise RuntimeError("session is not active")
        return self._resource.execute(command)

    def __exit__(self, exc_type, exc_value, traceback) -> bool:
        resource = self._resource
        self._resource = None
        if resource is not None:
            resource.close()
        return False
~~~

The absent/active state is represented by <code>None</code>, assuming no valid resource equals that sentinel. Entry publishes the resource only after opener succeeds. Exit clears internal state before close, so re-entrant observation sees inactive and repeated exit does not close twice. If close raises, it can replace a body exception; a production design must decide chaining/reporting.

### Worked example 9.5G — Container protocol coherence

For a finite sequence-like object, test laws:

\[
len(x)=\#list(x),
\]

\[
x[i]=list(x)[i]\quad\text{for every valid }i,
\]

\[
(v\in x)=any(v==e\text{ for }e\text{ in }x),
\]

and

\[
list(reversed(x))=list(x)[::-1].
\]

These laws can be weakened when membership uses a different equivalence or traversal is live, but then the type must document why. Implementing methods independently without coherence creates a collection whose size, indexing, and iteration disagree.

> **Common misconception — “Defining a dunder method with the right name is enough.”**  
> Each special method participates in a lookup/fallback protocol and must satisfy result, error, algebraic, mutation, and resource laws. Name recognition is only the entry point.
