# 9.7 Representation methods

`__repr__` should return an unambiguous developer-facing string representation. `__str__` should return a user-oriented textual form when the type has one. If `__str__` is absent, `object` machinery can fall back to `__repr__`.

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"Point(x={self.x!r}, y={self.y!r})"

    def __str__(self) -> str:
        return f"({self.x}, {self.y})"
```

`!r` requests each component’s `repr`, preserving distinctions useful for diagnosis. A representation that resembles a constructor should only claim reconstructability when it truly provides it under a named environment.

Never place secrets indiscriminately in either representation. Objects appear in logs, tracebacks, notebooks, and debugging tools. Representation is an information-release boundary.

### 9.7.1 repr and str serve different audiences

The conventional goals are:

- <code>repr(obj)</code>: developer-oriented, unambiguous where practical, rich enough to identify type and relevant state;
- <code>str(obj)</code>: user-oriented textual form when the domain has one.

There is no requirement that either be unique, stable across versions, parseable, or safe for logs unless the type’s contract adds it. <code>object.__repr__</code> usually includes type and identity-like address information, which is diagnostic but nondeterministic.

### 9.7.2 Reconstructable representation is conditional

~~~python
class Point:
    def __repr__(self) -> str:
        return f"Point(x={self.x!r}, y={self.y!r})"
~~~

This resembles source construction only if Point is bound to the intended class, constructor semantics match fields, component representations are valid in the evaluation environment, and no hidden state exists. Using <code>eval(repr(obj))</code> is unsafe on untrusted text and brittle even for trusted objects. Representation is not serialization.

### 9.7.3 repr must return an actual string

If <code>__repr__</code> returns a non-string, Python raises <code>TypeError</code>. If it raises another exception, logging or diagnostics that attempted representation can fail and potentially mask the original problem.

~~~python
class Broken:
    def __repr__(self):
        return 42
~~~

Keep representations robust, bounded, and free of avoidable external dependencies. A database query inside <code>__repr__</code> can block a debugger or trigger recursion during error handling.

### 9.7.4 Recursive structures need cycle handling

Built-in containers detect direct/indirect recursive representation and display an ellipsis marker:

~~~python
values: list[object] = []
values.append(values)
print(repr(values))            # [[...]]
~~~

A custom <code>__repr__</code> traversing arbitrary child graphs can recurse forever. <code>reprlib.recursive_repr</code> helps guard recursive entry for a method:

~~~python
from reprlib import recursive_repr


class Node:
    def __init__(self) -> None:
        self.children: list["Node"] = []

    @recursive_repr(fillvalue="...")
    def __repr__(self) -> str:
        return f"Node(children={self.children!r})"
~~~

Cycle-safe output does not prove the graph is valid; it only makes diagnostic representation terminate under the decorator’s model.

### 9.7.5 Bound representation length

Representing a million-element collection can allocate a huge string and flood logs. <code>reprlib</code> can abbreviate nested structures for diagnostics. Custom objects can include counts and selected previews:

~~~python
def __repr__(self) -> str:
    preview = self._items[:3]
    return f"Dataset(count={len(self._items)}, preview={preview!r})"
~~~

The truncation policy must not imply the preview is complete. Representation work should usually be proportional to a bounded preview rather than entire retained data.

### 9.7.6 Secret-bearing fields need explicit redaction

~~~python
class Credentials:
    def __init__(self, username: str, token: str) -> None:
        self.username = username
        self._token = token

    def __repr__(self) -> str:
        return f"Credentials(username={self.username!r}, token=<redacted>)"
~~~

Dataclass-generated repr includes fields by default; mark sensitive fields <code>repr=False</code>. Redaction must cover nested objects, exceptions, request URLs, and alternative formatting paths. Hiding a token from repr does not secure its memory or prevent deliberate attribute access.

Avoid exposing secret length, prefix, or hash unless the threat model permits it. Stable opaque identifiers can correlate records without releasing credentials.

### 9.7.7 str fallback and user meaning

If a class defines <code>__repr__</code> but not <code>__str__</code>, ordinary <code>str(obj)</code> can fall back to the repr. Define <code>__str__</code> only if a natural human-facing representation exists.

For Money, user formatting depends on locale, currency metadata, and rounding. One context-free <code>__str__</code> may be inadequate; an explicit formatter accepting locale/policy can be better. Special methods have constrained signatures and cannot receive arbitrary application context conveniently.

### 9.7.8 __format__ owns format-specification behaviour

<code>format(obj, spec)</code> and f-string fields call <code>obj.__format__(spec)</code>. The default object implementation supports limited behavior and often delegates an empty specification to str.

~~~python
class Percentage:
    def __init__(self, ratio: float) -> None:
        self.ratio = ratio

    def __format__(self, specification: str) -> str:
        if specification == "compact":
            return f"{self.ratio:.0%}"
        if specification == "precise":
            return f"{self.ratio:.4%}"
        if specification:
            raise ValueError(f"unknown format specification: {specification!r}")
        return str(self)

    def __str__(self) -> str:
        return f"{self.ratio:%}"
~~~

A custom mini-language becomes public API and requires documentation, validation, and compatibility. Delegating standard numeric specs to an underlying value can reduce novelty.

### 9.7.9 Representations can invoke representations recursively

Using <code>{self.field!r}</code> invokes the field’s repr, which can execute arbitrary user code, be expensive, expose secrets, or raise. A container’s repr similarly represents its elements. Diagnostic formatting is a callback graph, not a guaranteed pure primitive.

Error handlers should guard against secondary representation failure when handling untrusted plugin objects. A safe fallback can include type and identity without calling custom repr, though even type metadata should be bounded.

### 9.7.10 Equality and representation have different contracts

Two equal values can have different representations, especially when original spelling or metadata is preserved:

~~~python
from decimal import Decimal

print(Decimal("1.0") == Decimal("1.00"))
print(repr(Decimal("1.0")), repr(Decimal("1.00")))
~~~

Representation can reveal non-equality-relevant state. Conversely, two unequal objects can share an abbreviated representation. Never use repr as a general equality key or database identity.

### 9.7.11 repr is not a stable wire or cache key

Library upgrades can alter repr punctuation, field order, qualified names, address formatting, or truncation. Cache keys and serialized protocols need explicit structured canonical encodings. Tests that assert complete repr strings are appropriate when repr is the feature under test; otherwise they can create brittle coupling.

### Worked example 9.3E — A bounded graph representation

~~~python
class Graph:
    def __init__(self, adjacency: dict[str, set[str]]) -> None:
        self._adjacency = {
            node: frozenset(neighbours)
            for node, neighbours in adjacency.items()
        }

    def __repr__(self) -> str:
        node_count = len(self._adjacency)
        edge_count = sum(len(neighbours) for neighbours in self._adjacency.values())
        sample = sorted(self._adjacency)[:3]
        return (
            f"Graph(nodes={node_count}, directed_edges={edge_count}, "
            f"sample_nodes={sample!r})"
        )
~~~

Representation is bounded to three sorted node identifiers plus scalar counts; it does not traverse every neighbor in output. Computing edge count still traverses all adjacency sets, so repr is \(O(V+E)\) even though output is bounded. If this is too expensive, maintain a validated edge count or omit it; maintaining a cache adds an invariant.

### Worked example 9.3F — Dataclass secret redaction

~~~python
from dataclasses import dataclass, field


@dataclass(frozen=True)
class ApiSession:
    account_id: str
    token: str = field(repr=False)


session = ApiSession("acct-7", "highly-secret")
print(repr(session))           # ApiSession(account_id='acct-7')
~~~

The generated repr omits token. Equality and hashing rules can still include the field unless configured differently, and <code>session.token</code> remains accessible. Redaction addresses accidental representation disclosure only.

> **Common misconception — “repr is a serialization format that eval can safely reverse.”**  
> Reconstructability is optional and context-dependent; evaluating untrusted representations is code execution. Use an explicit versioned serialization protocol.
