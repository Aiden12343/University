# 11.15 `pathlib`

`pathlib` separates path value construction from filesystem effects.

```python
from pathlib import Path

root = Path.cwd()
source_paths = sorted(root.glob("src/**/*.py"))
for source_path in source_paths:
    print(source_path.relative_to(root))
```

Sorting supplies stable display absent from directory traversal contracts. `relative_to` is lexical/path-structural under its mode and raises when the path is not under the supplied base; it is not by itself a security-grade containment proof across symbolic links.

Use `PurePath`, `PurePosixPath`, or `PureWindowsPath` when manipulating path syntax without filesystem access, especially when reasoning about a foreign platform’s path grammar. Use `Path` for concrete current-platform operations.

### 11.15.1 Path objects and temporary directories

`tempfile` creates temporary files and directories under platform-appropriate mechanisms.

```python
from pathlib import Path
from tempfile import TemporaryDirectory


with TemporaryDirectory() as directory:
    root = Path(directory)
    sample = root / "sample.txt"
    sample.write_text("controlled\n", encoding="utf-8")
    assert sample.read_text(encoding="utf-8") == "controlled\n"
```

Temporary resources improve test isolation but are not automatically secret, durable, or immune to local adversaries. Use the secure creation APIs rather than inventing names from timestamps or predictable random values. A context exit attempts cleanup; tests should still account for platform-specific open-handle behaviour and cleanup failure.

### 11.15.2 Conversion between path protocols and strings

Objects implementing <code>os.PathLike</code> can be passed to many filesystem APIs. <code>os.fspath</code> obtains their underlying string or bytes representation:

~~~python
import os
from pathlib import Path


path = Path("data/report.csv")
assert os.fspath(path) == "data/report.csv"
~~~

Convert to <code>str</code> only when an external API requires text. Retaining a <code>Path</code> preserves path-specific operations and prevents accidental use of generic string methods as though path grammar were ordinary text.

Path equality and hashing are lexical under the path flavour's case rules; they do not resolve filesystem identity:

~~~python
left = Path("data/../data/report.csv")
right = Path("data/report.csv")
~~~

Their relationship must not be inferred as a universal same-file result without resolution and a concrete filesystem observation.

### 11.15.3 Convenience methods materialise

<code>read_text</code>, <code>read_bytes</code>, <code>write_text</code>, and <code>write_bytes</code> combine acquisition, transfer, and closure:

~~~python
configuration = Path("config.json").read_text(encoding="utf-8")
~~~

They are excellent when whole content is known to be small and all-at-once semantics simplify code. They materialise the complete value. They also offer less control over staged replacement, incremental limits, and intermediate flushing than an explicit <code>open</code> block.

<code>write_text</code> uses write/truncate semantics. It does not automatically write atomically. A name such as “write” should never be read as “transactionally replace”.

### 11.15.4 Selection and traversal APIs

Choose traversal by the shape needed:

| Operation | Result shape | Principal caution |
|---|---|---|
| <code>iterdir</code> | direct child paths | arbitrary filesystem order and mid-iteration change |
| <code>glob</code> | paths matching a relative pattern | pattern/version/platform semantics |
| <code>rglob</code> | recursive matches | cycles, links, depth, errors, and unbounded results |
| <code>walk</code> in Python 3.12+ | directory, child-directory names, filenames | mutation and link policy; unavailable on older runtimes |

Patterns are not shell expansion and not regular expressions. Hidden-name and recursive-link behaviour has evolved across Python versions; consult the documentation for the supported range.

If deterministic processing matters, sort using a stated key. If freshness matters, remember that sorting materialises and delays action while the directory can keep changing.

### 11.15.5 Relationship methods are lexical unless documented otherwise

<code>relative_to(base)</code> constructs a path relative to <code>base</code> when the path is structurally beneath it under the selected mode. <code>is_relative_to</code> reports that lexical relationship. Neither follows links:

~~~python
candidate = Path("/srv/public/images/logo.png")
base = Path("/srv/public")

assert candidate.is_relative_to(base)
assert candidate.relative_to(base) == Path("images/logo.png")
~~~

These methods are valuable for display, manifests, and already-trusted canonical paths. They are not security checks on unresolved attacker-controlled paths.

### 11.15.6 Metadata-preserving copying is a policy

<code>pathlib</code> concentrates path operations, while <code>shutil</code> provides higher-level copying and tree operations. “Copy a file” leaves choices about:

- contents only or metadata too;
- symbolic link itself or its target;
- overwriting existing destinations;
- sparse regions and extended attributes;
- permissions and owner;
- partial destination after failure;
- verification and durable commit.

<code>shutil.copyfile</code>, <code>copy</code>, and <code>copy2</code> make different metadata promises and remain platform-limited. None is a cross-filesystem transaction. Choose the narrowest operation whose documented behaviour matches the requirement and stage when partial destinations are unacceptable.
