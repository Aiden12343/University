# 11.17 Integrated serialisation pipeline

Requirement: read CSV measurements, validate them, compute per-sensor summaries, and emit strict JSON.

Architecture:

1. filesystem adapter opens UTF-8 CSV with controlled newline handling;
2. `csv.DictReader` frames records;
3. domain parser converts and validates sensor ID, timestamp, and finite numeric value;
4. aggregator updates typed state under invariants;
5. serialiser converts domain records to JSON-supported primitives under a versioned schema;
6. JSON encoder rejects non-finite numbers and emits stable key order for reproducible fixtures;
7. output replacement uses a temporary sibling and explicit replacement policy;
8. context managers release every acquired resource.

The JSON object should include a schema version rather than assume the consumer knows which fields exist:

```json
{
  "schema_version": 1,
  "sensors": [
    {
      "id": "north",
      "count": 3,
      "minimum": 18.5,
      "maximum": 21.0
    }
  ]
}
```

Stable textual order helps review and tests but is not the semantic identity of a JSON object. Consumers validate schema and types independently. A future incompatible schema receives a new version and migration policy.

### 11.17.1 Refine the requirements before implementing

The earlier sketch used floating JSON numbers for minima and maxima. That was sufficient to show document shape, but it left precision and units implicit. We now revise the model explicitly rather than silently changing it.

The complete pipeline accepts a CSV document with this schema:

~~~text
sensor_id,observed_at,value_milliunits
north,2026-09-06T12:00:00+00:00,18500
north,2026-09-06T12:01:00+00:00,21000
~~~

Its contract is:

1. input bytes are strict UTF-8 without a required BOM;
2. CSV uses the exact <code>MeasurementDialect</code> and exact header order;
3. a sensor ID contains 1–64 ASCII letters, digits, full stops, underscores, or hyphens;
4. each timestamp includes a UTC offset and is normalised to UTC;
5. values are integer milliunits in the inclusive range \(-10^{12}\) through \(10^{12}\);
6. at most 1,000,000 records and 100,000 distinct sensor IDs are accepted;
7. output schema version 2 stores count, minimum, maximum, and sum as JSON integers, preserving exact integer arithmetic;
8. sensor records are sorted by sensor ID for reproducible output;
9. no destination replacement occurs unless input parsing, validation, aggregation, and complete output staging all succeed;
10. optional durability requests are reported only under supported local-platform assumptions.

The decision to store <code>sum_milliunits</code> and <code>count</code>, rather than a rounded average, preserves enough information for consumers to choose their own rounding. The unit in each member name prevents a bare integer from being misread as base units.

### 11.17.2 Domain and diagnostic types

~~~python
from dataclasses import dataclass
from datetime import datetime
from pathlib import Path


@dataclass(frozen=True, slots=True)
class Measurement:
    sensor_id: str
    observed_at: datetime
    value_milliunits: int


@dataclass
class Summary:
    count: int = 0
    sum_milliunits: int = 0
    minimum_milliunits: int | None = None
    maximum_milliunits: int | None = None

    def add(self, value: int) -> None:
        self.count += 1
        self.sum_milliunits += value
        if self.minimum_milliunits is None or value < self.minimum_milliunits:
            self.minimum_milliunits = value
        if self.maximum_milliunits is None or value > self.maximum_milliunits:
            self.maximum_milliunits = value
~~~

After every <code>add</code>, the invariant is:

\[
\texttt{count} > 0,\quad
\texttt{minimum} \leq v_i \leq \texttt{maximum},\quad
\texttt{sum} = \sum_{i=1}^{\texttt{count}} v_i.
\]

Python integers expand as needed, so the sum does not overflow at a fixed machine width. Resource consumption still grows with digit count, but the record/value limits bound it for this application.

Diagnostics carry structured location:

~~~python
class ImportFailure(ValueError):
    def __init__(
        self,
        path: Path,
        message: str,
        *,
        record_number: int | None = None,
        physical_line: int | None = None,
        field: str | None = None,
    ) -> None:
        self.path = path
        self.record_number = record_number
        self.physical_line = physical_line
        self.field = field
        self.detail = message

        parts = [str(path)]
        if record_number is not None:
            parts.append(f"record {record_number}")
        if physical_line is not None:
            parts.append(f"physical line {physical_line}")
        if field is not None:
            parts.append(f"field {field!r}")
        super().__init__(": ".join(parts) + f": {message}")
~~~

Programmatic callers can inspect attributes rather than parse the message.

### 11.17.3 Lexical validators

~~~python
import re
from datetime import timezone


SENSOR_ID = re.compile(r"[A-Za-z0-9._-]{1,64}\Z")
MIN_VALUE = -(10**12)
MAX_VALUE = 10**12


def parse_sensor_id(raw: str) -> str:
    if SENSOR_ID.fullmatch(raw) is None:
        raise ValueError(
            "expected 1..64 ASCII letters, digits, '.', '_', or '-'"
        )
    return raw


def parse_timestamp(raw: str) -> datetime:
    try:
        value = datetime.fromisoformat(raw)
    except ValueError as error:
        raise ValueError("invalid date-time syntax") from error
    if value.tzinfo is None or value.utcoffset() is None:
        raise ValueError("UTC offset is required")
    return value.astimezone(timezone.utc)


def parse_milliunits(raw: str) -> int:
    if not raw:
        raise ValueError("value is empty")
    try:
        value = int(raw, 10)
    except ValueError as error:
        raise ValueError("value is not a base-10 integer") from error
    if not MIN_VALUE <= value <= MAX_VALUE:
        raise ValueError(
            f"value lies outside {MIN_VALUE}..{MAX_VALUE}"
        )
    return value
~~~

<code>int</code> accepts surrounding whitespace and signs. If the lexical schema intends the stricter grammar <code>-?(0|[1-9][0-9]*)</code>, validate with a full match before conversion. The present contract should say whether <code>+1</code>, <code>01</code>, and spaces are accepted. For exact interchange, a regular-expression check is appropriate:

~~~python
INTEGER_TEXT = re.compile(r"-?(?:0|[1-9][0-9]*)\Z")


def parse_strict_milliunits(raw: str) -> int:
    if INTEGER_TEXT.fullmatch(raw) is None:
        raise ValueError("expected canonical base-10 integer syntax")
    value = int(raw)
    if not MIN_VALUE <= value <= MAX_VALUE:
        raise ValueError("value is outside the permitted range")
    return value
~~~

The pipeline will use this stricter form, making output/import reproducible and rejecting ambiguous producer variations.

### 11.17.4 CSV adapter

~~~python
import csv
from collections.abc import Iterator


HEADER = ["sensor_id", "observed_at", "value_milliunits"]
MAX_RECORDS = 1_000_000


def iter_measurements(path: Path) -> Iterator[Measurement]:
    try:
        stream = path.open(
            "r",
            encoding="utf-8",
            errors="strict",
            newline="",
        )
    except OSError as error:
        raise RuntimeError(f"cannot open measurement input {path}") from error

    with stream:
        reader = csv.reader(stream, dialect=MeasurementDialect)
        try:
            received_header = next(reader)
        except StopIteration as error:
            raise ImportFailure(path, "CSV document is empty") from error
        except csv.Error as error:
            raise ImportFailure(
                path,
                "malformed CSV header",
                physical_line=reader.line_num,
            ) from error

        if received_header != HEADER:
            raise ImportFailure(
                path,
                f"expected header {HEADER!r}; received {received_header!r}",
                physical_line=reader.line_num,
            )

        for record_index in range(1, MAX_RECORDS + 2):
            try:
                row = next(reader)
            except StopIteration:
                return
            except csv.Error as error:
                raise ImportFailure(
                    path,
                    "malformed CSV record",
                    record_number=record_index,
                    physical_line=reader.line_num,
                ) from error

            if record_index > MAX_RECORDS:
                raise ImportFailure(
                    path,
                    f"record count exceeds {MAX_RECORDS}",
                    record_number=record_index,
                    physical_line=reader.line_num,
                )
            if len(row) != 3:
                raise ImportFailure(
                    path,
                    f"expected 3 fields; received {len(row)}",
                    record_number=record_index,
                    physical_line=reader.line_num,
                )

            parsers = (
                ("sensor_id", parse_sensor_id),
                ("observed_at", parse_timestamp),
                ("value_milliunits", parse_strict_milliunits),
            )
            values: list[object] = []
            for raw, (field_name, parser) in zip(
                row,
                parsers,
                strict=True,
            ):
                try:
                    values.append(parser(raw))
                except ValueError as error:
                    raise ImportFailure(
                        path,
                        str(error),
                        record_number=record_index,
                        physical_line=reader.line_num,
                        field=field_name,
                    ) from error

            sensor_id, observed_at, value_milliunits = values
            assert isinstance(sensor_id, str)
            assert isinstance(observed_at, datetime)
            assert type(value_milliunits) is int
            yield Measurement(
                sensor_id,
                observed_at,
                value_milliunits,
            )
~~~

The assertions tell a static checker and future maintainer what follows from the parser table; they are internal consistency checks, not external validation. A more sophisticated design can use separately typed local assignments to avoid the heterogeneous <code>list[object]</code>.

Record index counts data records starting at one, whereas the header occupies physical line one and quoted values can span more lines. Both coordinates are included where available.

### 11.17.5 Aggregation with cardinality limits

~~~python
MAX_SENSORS = 100_000


def aggregate(
    measurements: Iterator[Measurement],
) -> dict[str, Summary]:
    summaries: dict[str, Summary] = {}
    for measurement in measurements:
        summary = summaries.get(measurement.sensor_id)
        if summary is None:
            if len(summaries) >= MAX_SENSORS:
                raise ValueError(
                    f"distinct sensor count exceeds {MAX_SENSORS}"
                )
            summary = Summary()
            summaries[measurement.sensor_id] = summary
        summary.add(measurement.value_milliunits)
    return summaries
~~~

The aggregate stores one Summary per distinct sensor and therefore has \(O(k)\) additional space for \(k\) sensors, bounded by <code>MAX_SENSORS</code>. It performs expected \(O(n)\) dictionary work for \(n\) records under ordinary hashing assumptions. Chapter 13 will analyse adversarial and worst-case hash-table behaviour.

The function ignores timestamps after validation. If the report requires first/last observation, duplicate-timestamp policy, chronological input, or interval completeness, those fields must enter the invariant. Parsing a field and then not using it may still be required to reject malformed records, but unused schema elements deserve review.

### 11.17.6 JSON document construction

~~~python
def summary_document(
    summaries: dict[str, Summary],
) -> dict[str, object]:
    sensors: list[dict[str, object]] = []
    for sensor_id in sorted(summaries):
        summary = summaries[sensor_id]
        if (
            summary.count <= 0
            or summary.minimum_milliunits is None
            or summary.maximum_milliunits is None
        ):
            raise AssertionError("aggregate invariant is broken")
        sensors.append(
            {
                "id": sensor_id,
                "count": summary.count,
                "sum_milliunits": summary.sum_milliunits,
                "minimum_milliunits": summary.minimum_milliunits,
                "maximum_milliunits": summary.maximum_milliunits,
            }
        )

    return {
        "schema_version": 2,
        "unit": "milliunit",
        "sensors": sensors,
    }
~~~

Sorting by Python string code-point order defines reproducibility. It is not locale collation. Because sensor IDs are restricted to a small ASCII alphabet, the order is simple and cross-system.

Empty input produces an empty sensor array rather than an error. That is a deliberate semantic decision: the file had a valid header and zero observations. A completely empty file was rejected earlier because it has no schema declaration.

### 11.17.7 Staged output

~~~python
import json
import os
from tempfile import NamedTemporaryFile


def replace_json(
    destination: Path,
    document: dict[str, object],
    *,
    durable: bool = False,
) -> None:
    parent = destination.parent.resolve(strict=True)
    temporary_name: str | None = None

    try:
        with NamedTemporaryFile(
            mode="w",
            encoding="utf-8",
            errors="strict",
            newline="\n",
            dir=parent,
            prefix=f".{destination.name}.",
            suffix=".tmp",
            delete=False,
        ) as stream:
            temporary_name = stream.name
            json.dump(
                document,
                stream,
                ensure_ascii=False,
                allow_nan=False,
                sort_keys=True,
                indent=2,
            )
            stream.write("\n")
            stream.flush()
            if durable:
                os.fsync(stream.fileno())

        os.replace(temporary_name, destination)
        temporary_name = None
        if durable:
            synchronise_directory(parent)
    finally:
        if temporary_name is not None:
            Path(temporary_name).unlink(missing_ok=True)
~~~

Failure before <code>os.replace</code> leaves the prior destination unchanged under the assumed local-filesystem namespace model and attempts to remove the temporary. Failure in directory synchronisation occurs after replacement and therefore has the indeterminate durability status discussed in §11.6.8; a production API should return or raise a specialised status rather than a generic failure suggesting no effect.

The code does not preserve prior destination permissions or ownership. A freshly created temporary has the temporary API's permissions, which become the destination's after replacement. The output contract must decide whether that is desirable.

### 11.17.8 Orchestration

~~~python
def build_measurement_report(
    source: Path,
    destination: Path,
    *,
    durable: bool = False,
) -> None:
    measurements = iter_measurements(source)
    summaries = aggregate(measurements)
    document = summary_document(summaries)
    replace_json(destination, document, durable=durable)
~~~

The orchestration's phase order is significant:

~~~mermaid
flowchart TD
    A["Open and decode CSV"] --> B["Parse and validate records"]
    B --> C["Aggregate bounded state"]
    C --> D["Construct JSON values"]
    D --> E["Stage encoded output"]
    E --> F["Replace destination"]
~~~

No output resource is acquired until complete input validation and aggregation finish. This avoids leaving a temporary for invalid input and ensures the previous destination remains during import. It also means the aggregate must fit memory; an external store would be needed beyond the sensor cardinality bound.

If source and destination are the same pathname, input is closed by exhaustion before replacement, but allowing that surprising use can complicate diagnostics and recovery. A public interface may reject it using a best-effort same-file check while still documenting races.

### 11.17.9 Command-line boundary

The shell-facing adapter turns arguments and exceptions into exit status and separated output:

~~~python
import argparse
import sys


def main(arguments: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("source", type=Path)
    parser.add_argument("destination", type=Path)
    parser.add_argument(
        "--durable",
        action="store_true",
        help="request supported file and directory synchronisation",
    )
    options = parser.parse_args(arguments)

    try:
        build_measurement_report(
            options.source,
            options.destination,
            durable=options.durable,
        )
    except (ImportFailure, RuntimeError, OSError, ValueError) as error:
        print(f"error: {error}", file=sys.stderr)
        return 2
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
~~~

The broad tuple is acceptable at the outer process boundary only because every listed failure maps to a failed command and preserved diagnostic. A mature application distinguishes invalid input, unavailable input, output failure, and durability ambiguity with separate exit codes or structured events.

<code>argparse</code> itself handles usage errors and exits by default. Passing an explicit argument list makes <code>main</code> testable without mutating <code>sys.argv</code>.

### 11.17.10 Test matrix

Unit tests should cover:

| Layer | Representative cases |
|---|---|
| bytes/text | valid UTF-8, invalid sequence, BOM policy, mixed newlines |
| CSV grammar | quoted delimiter, embedded line ending, escaped quote, malformed quote |
| header | exact, missing, duplicate, reordered, extra |
| sensor ID | boundary lengths, invalid punctuation, non-ASCII lookalikes |
| timestamp | UTC, non-zero offset, naive, invalid date, daylight transition representation |
| integer | zero, signs under chosen grammar, leading zero, bounds, one beyond each bound, huge digits |
| resources | record limit, field limit, distinct-sensor limit |
| aggregate | singleton, negatives, repeated sensor, exact sum/min/max |
| JSON | version, integer types, sorted sensors, empty dataset, final newline |
| failure atomicity | invalid last record, encoder fault, full temporary storage, replace failure |
| durability | sync call order under a fake; supported-platform integration tests |
| ownership | streams closed, abandoned generator, temporary removed before commit |

Fault tests should inject behaviour at interfaces rather than rely solely on filling a real disk. Integration tests on representative filesystems remain necessary because a fake cannot establish external atomicity or durability.

### 11.17.11 Evidence and residual claims

The implementation can establish:

- exact parsing and domain rules under tested Python versions;
- bounded record and key counts;
- no intentional pickle use;
- deterministic JSON representation for the allowed value domain;
- staged one-name replacement under the selected operating-system interface;
- cleanup attempts through lexical context managers.

It cannot establish from Python source alone:

- atomic rename behaviour on every mount;
- persistence through all power-loss scenarios;
- absence of concurrent writers;
- confidentiality of temporary or output data;
- correctness of clocks embedded by producers;
- authenticity or authority of the input;
- uninterrupted cleanup after process termination;
- mathematical suitability of the milliunit measurements for a scientific analysis.

A reference implementation is rigorous when these limits are stated, not when they are hidden behind the word “safe”.
