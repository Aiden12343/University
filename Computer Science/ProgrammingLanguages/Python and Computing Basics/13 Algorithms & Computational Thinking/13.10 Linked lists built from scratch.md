# 13.10 Linked lists built from scratch

A **linked list** stores each element in a node containing a value and a reference to another node. It avoids a contiguous reference array but introduces per-node allocation and pointer traversal.

```python
from dataclasses import dataclass
from typing import Generic, Iterator, TypeVar

T = TypeVar("T")


@dataclass(slots=True)
class Node(Generic[T]):
    value: T
    next: "Node[T] | None" = None


class SinglyLinkedList(Generic[T]):
    def __init__(self) -> None:
        self._head: Node[T] | None = None
        self._tail: Node[T] | None = None
        self._length = 0

    def append(self, value: T) -> None:
        node = Node(value)
        if self._tail is None:
            self._head = node
        else:
            self._tail.next = node
        self._tail = node
        self._length += 1

    def prepend(self, value: T) -> None:
        node = Node(value, self._head)
        self._head = node
        if self._tail is None:
            self._tail = node
        self._length += 1

    def __len__(self) -> int:
        return self._length

    def __iter__(self) -> Iterator[T]:
        current = self._head
        while current is not None:
            yield current.value
            current = current.next
```

Invariants:

- length zero iff head and tail are both `None`;
- non-empty tail’s `next` is `None`;
- following `next` from head visits exactly `_length` nodes and ends at tail;
- no cycle exists.

Prepend and append are (O(1)) with retained tail. Index lookup is (O(n)) because nodes must be followed. Removing after a known node is (O(1)), but finding that node may be (O(n)). Compared with CPython list, linked nodes have poor spatial locality and substantial object overhead. The structure is not automatically more efficient because insertion notation looks direct.

### Cycle detection

Floyd’s tortoise-and-hare algorithm advances one reference by one edge and another by two. If a finite linked structure has a cycle reachable from head, they eventually meet; if the fast pointer reaches `None`, no cycle exists.

```python
def has_cycle(head: Node[object] | None) -> bool:
    slow = head
    fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next if slow is not None else None
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```

Time is (O(n)); additional space is (O(1)). Identity comparison is required because the question is whether pointers reach the same node, not whether node values compare equal.

### 13.10.1 Abstract data type and representation

An **abstract data type** (**ADT**) specifies values and operations independently of a concrete storage arrangement. A sequence ADT might promise length, iteration, insertion, and deletion. A dynamic array and linked list are representations that realise some version of that interface with different costs.

The abstraction boundary matters because “linked list” is often used for both an interface and a node representation. A caller should not receive internal node references unless those references are deliberately part of the API. Exposing them permits external rewiring that can invalidate length, tail, and acyclicity.

The teaching class above owns its nodes but not the values referenced from them. Appending a mutable object stores a reference; later mutation through another alias is visible during iteration. This follows Python’s reference semantics and is not specific to linked lists.

Memory differs from the sketch of boxes and arrows. Each Python node is an object with runtime metadata and two references; allocation may scatter nodes. A CPython list stores references in a contiguous internal array, enabling compact iteration and efficient indexed access. The linked list saves suffix shifts for an insertion after a known node but often costs more memory per element and more cache misses.

> **Common misconception 13.41 — “A linked list is an abstract sequence, while a list is a physical array.”**  
> Both names can be used ambiguously. Separate the ADT contract from the representation that implements it before comparing costs.

### 13.10.2 Complete singly linked operations

Removing the first equal value illustrates predecessor tracking and boundary repair:

~~~python
from dataclasses import dataclass
from typing import Generic, Iterator, TypeVar

T = TypeVar("T")


@dataclass(slots=True)
class Link(Generic[T]):
    value: T
    next: "Link[T] | None" = None


class LinkedSequence(Generic[T]):
    def __init__(self) -> None:
        self._head: Link[T] | None = None
        self._tail: Link[T] | None = None
        self._length = 0

    def append(self, value: T) -> None:
        node = Link(value)
        if self._tail is None:
            self._head = node
        else:
            self._tail.next = node
        self._tail = node
        self._length += 1

    def remove_first(self, value: T) -> None:
        previous: Link[T] | None = None
        current = self._head

        while current is not None and current.value != value:
            previous = current
            current = current.next

        if current is None:
            raise ValueError("value is absent")

        if previous is None:
            self._head = current.next
        else:
            previous.next = current.next

        if current is self._tail:
            self._tail = previous

        self._length -= 1
        current.next = None

    def __iter__(self) -> Iterator[T]:
        current = self._head
        while current is not None:
            yield current.value
            current = current.next

    def assert_invariants(self) -> None:
        count = 0
        current = self._head
        final: Link[T] | None = None
        seen: set[int] = set()

        while current is not None:
            identity = id(current)
            if identity in seen:
                raise AssertionError("cycle in linked sequence")
            seen.add(identity)
            count += 1
            final = current
            current = current.next

        assert count == self._length
        assert final is self._tail
        assert (self._length == 0) == (self._head is None)
        assert (self._length == 0) == (self._tail is None)
        assert self._tail is None or self._tail.next is None
~~~

During the search loop, <code>previous</code> is either absent when <code>current</code> is the head or points to the unique node whose <code>next</code> is <code>current</code>. The two rewiring branches remove the matched node from the reachable chain. If the removed node was the tail, the predecessor becomes the new tail; removing the sole node makes both head and tail absent.

Setting <code>current.next = None</code> is not needed for CPython reference counting to collect an otherwise unreachable acyclic node, but it makes detachment explicit if an internal node reference is observed during debugging. The value object remains alive if other references exist.

The invariant checker deliberately costs \(O(n)\) and uses \(O(n)\) extra space to detect cycles. Such checks are useful in tests and debug builds; invoking them after every constant-time operation changes the observed operation cost to \(O(n)\).

> **Common misconception 13.42 — “Deletion from a linked list is \(O(1)\).”**  
> Rewiring after a known predecessor is constant-time. Locating a value or predecessor from the head is \(O(n)\), and the public operation’s bound must include that search.

### 13.10.3 Doubly and circularly linked structures

A **doubly linked list** stores both next and previous references. Given a node, it can remove that node in \(O(1)\) without searching for its predecessor. This adds storage and doubles the relationships that must remain consistent:

\[
x.next=y\quad\Longleftrightarrow\quad y.previous=x
\]

for adjacent nodes. Head has no predecessor and tail has no successor under a non-circular representation.

A **circular linked list** connects the tail back to the head. It can represent round-robin scheduling without a distinguished terminal <code>None</code>. Its traversal needs another stopping rule—return to the start or count exactly the stored length. Ordinary “continue until <code>None</code>” traversal does not terminate.

A circular doubly linked list often uses a permanent **sentinel node** whose next and previous links point to itself when empty. Insertion then rewires the same four references at every position and avoids separate empty/head/tail cases. The sentinel does not represent a user value; it simplifies the representation invariant.

These representations are valuable inside deques, least-recently-used policies, intrusive operating-system lists, and allocators. They do not make random position lookup efficient; locating the \(i\)-th node still follows links.

> **Common misconception 13.43 — “Adding backward links makes a linked list support \(O(1)\) indexing.”**  
> It permits traversal from either end and constant-time removal of a known node. Reaching an arbitrary rank still costs \(O(\min(i,n-i))\).

### 13.10.4 Mutation during traversal

An iterator holds traversal state. Mutation can invalidate its assumptions:

~~~python
def remove_after(
    predecessor: Link[T],
) -> T:
    victim = predecessor.next
    if victim is None:
        raise IndexError("no node follows predecessor")
    predecessor.next = victim.next
    victim.next = None
    return victim.value
~~~

If a generator has already yielded <code>predecessor.value</code> and retained <code>predecessor.next</code> only after resumption, removal timing changes which node it visits. A robust container chooses and documents a policy:

- prohibit structural mutation and detect it with a modification counter;
- define iterator behaviour for selected mutations;
- iterate a snapshot at \(O(n)\) extra storage;
- expose lower-level cursor operations that coordinate mutation.

Python lists permit mutation during iteration but results follow index mechanics and are frequently surprising. Dictionaries and sets detect certain size changes and raise. These are container-specific contracts, not a universal Python rule.

Aliasing internal nodes creates a second issue: a node removed from one list could be inserted into another while still carrying a successor link. An **intrusive list**, where linkage lives inside the user object, must define single-list ownership or support multiple independent link fields.

### 13.10.5 Floyd’s meeting and cycle-entry arguments

Suppose a reachable chain has a non-cyclic prefix of length \(\mu\) followed by a cycle of length \(\lambda\). Once the slow pointer enters the cycle, the fast pointer is also in the cycle. Relative to the slow pointer, the fast pointer gains one edge per iteration. Modulo \(\lambda\), repeated addition of one visits every residue, so within at most \(\lambda\) further iterations their positions coincide.

After a meeting, the cycle entry can be found without knowing \(\lambda\): place one pointer at the head, leave one at the meeting, and advance both one edge at a time. They meet at the entry.

~~~python
def cycle_entry(
    head: Link[object] | None,
) -> Link[object] | None:
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        assert slow is not None
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            break
    else:
        return None

    seeker = head
    while seeker is not slow:
        assert seeker is not None
        assert slow is not None
        seeker = seeker.next
        slow = slow.next
    return seeker
~~~

For the arithmetic, if the first meeting occurs after \(t\) slow steps, then the fast pointer has taken \(2t\) steps and their difference \(t\) is a multiple of \(\lambda\). Since \(t=\mu+r\), where \(r\) is the meeting position measured from cycle entry, \(\mu+r\equiv0\pmod\lambda\). Advancing the meeting pointer by \(\mu\) edges therefore reaches the entry modulo the cycle exactly when the head pointer reaches it.

The algorithm detects cycles in a functional graph where each node has at most one successor. General directed-graph cycle detection requires other methods because a single fast path need not explore every branch.

> **Common misconception 13.44 — “The tortoise-and-hare method detects cycles in any graph.”**  
> Its constant-space proof uses a single-successor chain. General graphs require traversal state, ordering structure, or specialised algorithms.
