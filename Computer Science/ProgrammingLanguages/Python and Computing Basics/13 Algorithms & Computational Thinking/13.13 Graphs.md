# 13.13 Graphs

A **graph** (G=(V,E)) consists of vertices (V) and edges (E) connecting them. A graph is **directed** when an edge has orientation and **undirected** when connection is symmetric. Edges may carry weights or labels.

Representations:

- **adjacency list:** map each vertex to its neighbours; space (O(V+E)), suitable for sparse graphs;
- **adjacency matrix:** (V\times V) table; space (O(V^2)), constant-time edge lookup under array model;
- **edge list:** collection of edges; simple for algorithms that scan all edges.

### Breadth-first search

Breadth-first search (**BFS**) explores an unweighted graph in non-decreasing distance from a start vertex using a queue.

```python
from collections import deque
from collections.abc import Hashable, Mapping, Iterable
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def bfs_distances(
    graph: Mapping[V, Iterable[V]],
    start: V,
) -> dict[V, int]:
    distances = {start: 0}
    queue = deque([start])

    while queue:
        vertex = queue.popleft()
        for neighbour in graph.get(vertex, ()):
            if neighbour not in distances:
                distances[neighbour] = distances[vertex] + 1
                queue.append(neighbour)

    return distances
```

Invariant: every discovered vertex has its shortest unweighted distance recorded; the queue contains discovered but not fully explored vertices in non-decreasing distance. A neighbour is marked discovered before enqueueing, preventing repeated insertion through multiple incoming edges.

With adjacency lists and expected constant hash operations, time is (O(V+E)) over the reachable subgraph and space is (O(V)).

### Depth-first search

Depth-first search (**DFS**) explores a path as far as possible before backtracking, using recursion or an explicit stack. It supports reachability, components, cycle analysis, topological ordering, and structural traversals. A visited set distinguishes new vertices from repeated graph references; trees do not require it when acyclicity and unique parenthood are guaranteed.

```python
def dfs(graph: dict[str, list[str]], start: str) -> list[str]:
    order: list[str] = []
    visited: set[str] = set()
    stack = [start]

    while stack:
        vertex = stack.pop()
        if vertex in visited:
            continue
        visited.add(vertex)
        order.append(vertex)
        stack.extend(reversed(graph.get(vertex, [])))

    return order
```

Reversing neighbours makes the first listed neighbour emerge first from the LIFO stack. Traversal order is representation policy and should not be mistaken for graph semantics.

### 13.13.1 Graph vocabulary and modelling choices

A graph is **simple** when it has no self-loops or parallel edges under the relevant directedness. A **self-loop** connects a vertex to itself. **Parallel edges** are distinct edges with the same endpoints. A **multigraph** permits parallel edges. These distinctions affect representation: a neighbour set collapses parallel edges, while an edge list or neighbour list with edge records preserves them.

For a directed edge \(u\to v\), \(u\) is a predecessor of \(v\) and \(v\) a successor of \(u\). **Out-degree** counts edges leaving a vertex; **in-degree** counts those entering. In an undirected graph, degree counts incident edge ends, with a self-loop conventionally contributing two.

A **walk** is a sequence of incident vertices and edges permitting repetition. A **trail** repeats no edge; a **path** ordinarily repeats no vertex. Some texts use “path” more loosely, so formal work should state the convention. A **cycle** is a closed path of positive length, with details for loops and two-edge multigraph cycles depending on the graph model.

Connectivity also depends on direction:

- an undirected graph is connected when every pair has a path;
- directed vertices are **strongly connected** when each reaches the other;
- a directed graph is **weakly connected** when replacing directed edges with undirected ones makes it connected.

A graph model must decide whether an endpoint absent from the adjacency mapping nonetheless exists as a vertex. In the earlier functions, a referenced neighbour is discovered even if it has no own mapping entry because <code>graph.get(neighbour, ())</code> treats its outgoing list as empty. Isolated vertices cannot be inferred unless explicitly represented.

> **Common misconception 13.54 — “A graph is just a dictionary of lists.”**  
> A dictionary of lists is one representation. It also embeds policies about missing vertices, duplicates, order, direction, labels, and mutation that the mathematical graph alone does not decide.

### 13.13.2 Representation costs

Let \(V=\lvert\mathcal V\rvert\) and \(E=\lvert\mathcal E\rvert\). For an undirected adjacency list, each ordinary edge is usually stored twice, once at each endpoint; this remains \(\Theta(V+E)\) storage. A directed edge is normally stored once in an outgoing list, though algorithms needing predecessors may maintain a reverse graph as well.

| Operation | Adjacency list | Adjacency set | Adjacency matrix | Edge list |
|---|---:|---:|---:|---:|
| enumerate neighbours of \(u\) | \(\Theta(deg(u))\) | \(\Theta(deg(u))\) expected iteration | \(\Theta(V)\) | \(\Theta(E)\) |
| test edge \(u,v\) | \(O(deg(u))\) | expected \(O(1)\) | \(O(1)\) | \(O(E)\) |
| enumerate all edges | \(\Theta(V+E)\) | \(\Theta(V+E)\) | \(\Theta(V^2)\) | \(\Theta(E)\) |
| storage | \(\Theta(V+E)\) | \(\Theta(V+E)\), larger constants | \(\Theta(V^2)\) | \(\Theta(V+E)\) if vertices retained separately |

These bounds assume constant-time vertex indexing or expected dictionary operations. A matrix needs a mapping from arbitrary vertex labels to row numbers. A bit-packed matrix uses far less space than a Python list of Boolean objects and can process many adjacency bits in machine-word operations; representation constants can change the practical density threshold.

A graph is **sparse** when \(E\) is closer to \(V\) than to \(V^2\), and **dense** when it contains a substantial fraction of possible edges. The terms are contextual rather than exact thresholds.

Immutable adjacency tuples can prevent accidental graph mutation during traversal. Mutable neighbour lists permit updates but can invalidate iterators or proofs. For an undirected graph, adding one logical edge must update both endpoint collections atomically from the model’s perspective.

> **Common misconception 13.55 — “Adjacency matrices are always wasteful.”**  
> They are asymptotically large for sparse graphs but provide constant-time edge tests, compact bit representations, predictable locality, and useful algebraic operations for dense graphs.

### 13.13.3 BFS as a shortest-path proof

For an unweighted graph, path length is edge count. BFS discovers the start at distance zero, then vertices at distance one, then distance two, and so on. The queue invariant can be sharpened:

1. discovered vertices have correct shortest distances;
2. queue distances are non-decreasing;
3. at most two consecutive distance levels occur in the queue;
4. every undiscovered neighbour of a dequeued vertex is discovered at one greater distance.

Why is a newly assigned distance shortest? Suppose BFS dequeues \(u\) at distance \(d\) and first discovers \(v\) through edge \(u\to v\), assigning \(d+1\). This gives a path of length \(d+1\). If a shorter path to \(v\) existed, its predecessor would have distance at most \(d-1\) and would have been processed earlier, causing \(v\) to be discovered already—a contradiction.

Retaining one predecessor reconstructs a shortest path:

~~~python
from collections import deque
from collections.abc import Hashable, Iterable, Mapping
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def bfs_path(
    graph: Mapping[V, Iterable[V]],
    start: V,
    goal: V,
) -> list[V] | None:
    parent: dict[V, V | None] = {start: None}
    pending = deque([start])

    while pending:
        vertex = pending.popleft()
        if vertex == goal:
            path: list[V] = []
            current: V | None = goal
            while current is not None:
                path.append(current)
                current = parent[current]
            path.reverse()
            return path

        for neighbour in graph.get(vertex, ()):
            if neighbour not in parent:
                parent[neighbour] = vertex
                pending.append(neighbour)

    return None
~~~

Marking discovery when enqueued is essential to the simple bound. Marking only when dequeued can enqueue the same vertex through many incoming edges, consuming additional time and space. The parent map simultaneously represents visited status and the shortest-path tree.

If several shortest paths exist, adjacency iteration order determines which parent is first. Deterministic output requires deterministic neighbour order. It does not change path length correctness.

Multi-source BFS initialises the queue with several distinct sources, all at distance zero. It computes distance to the nearest source in one traversal. This is preferable to running independent BFS from every source when only nearest-source distances are required.

> **Common misconception 13.56 — “BFS finds the shortest path in every graph.”**  
> It minimises edge count, equivalently total weight only when all relevant edges have the same non-negative weight. General weighted paths require an algorithm matched to weight structure.

### 13.13.4 DFS states and edge classification

Recursive DFS conceptually colours vertices:

- white: undiscovered;
- grey: discovered, with its recursive exploration unfinished;
- black: finished.

In a directed graph, an edge to a grey vertex is a **back edge** and witnesses a directed cycle. An edge to a black vertex may be a forward or cross edge depending on discovery ancestry. For an undirected graph, the edge back to the immediate parent is not by itself a cycle, but another visited neighbour can be.

An explicit stack must preserve enter/exit events if finish times matter:

~~~python
from collections.abc import Hashable, Iterator, Mapping, Sequence
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def dfs_events(
    graph: Mapping[V, Sequence[V]],
    start: V,
) -> Iterator[tuple[str, V]]:
    visited: set[V] = {start}
    stack: list[tuple[V, int]] = [(start, 0)]
    yield "enter", start

    while stack:
        vertex, next_index = stack[-1]
        neighbours = graph.get(vertex, ())

        if next_index == len(neighbours):
            stack.pop()
            yield "exit", vertex
            continue

        neighbour = neighbours[next_index]
        stack[-1] = (vertex, next_index + 1)
        if neighbour not in visited:
            visited.add(neighbour)
            stack.append((neighbour, 0))
            yield "enter", neighbour
~~~

A simpler stack that pushes all neighbours reproduces reachability but not necessarily recursive DFS finish structure. Algorithm names do not guarantee all downstream properties; the implementation must maintain the state the proof requires.

DFS over every undiscovered vertex creates a **depth-first forest**. In an undirected graph, each tree corresponds to a connected component. In a directed graph, forest roots and order depend on traversal sequence and do not alone identify strongly connected components.

> **Common misconception 13.57 — “Any stack-based reachability traversal has all DFS properties.”**  
> Reachability order may be sufficient for one task, while finish times, ancestor relations, and edge classification require a faithful depth-first activation structure.

### 13.13.5 Bipartite graphs and components

An undirected graph is **bipartite** if its vertices can be divided into two sets so every edge crosses between them. Equivalently, it has no odd-length cycle. BFS or DFS can assign alternating colours:

~~~python
from collections import deque
from collections.abc import Hashable, Iterable, Mapping
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def bipartition(
    graph: Mapping[V, Iterable[V]],
) -> dict[V, int] | None:
    colour: dict[V, int] = {}

    vertices = set(graph)
    for neighbours in graph.values():
        vertices.update(neighbours)

    for start in vertices:
        if start in colour:
            continue
        colour[start] = 0
        pending = deque([start])

        while pending:
            vertex = pending.popleft()
            for neighbour in graph.get(vertex, ()):
                if neighbour not in colour:
                    colour[neighbour] = 1 - colour[vertex]
                    pending.append(neighbour)
                elif colour[neighbour] == colour[vertex]:
                    return None

    return colour
~~~

If adjacent vertices receive the same colour, the two BFS-tree paths from their component root, together with the conflicting edge, contain an odd cycle. Conversely, alternating colours around any cycle return consistently only when the cycle length is even. Processing every component is necessary; starting from one vertex proves nothing about disconnected components.

### 13.13.6 Strongly connected components

A **strongly connected component** (**SCC**) is a maximal set of directed vertices each reachable from every other. Contracting each SCC to one **component vertex** produces the **condensation graph**, which is always a DAG: a cycle among distinct components would make their union strongly connected.

Kosaraju–Sharir’s algorithm performs:

1. DFS to compute vertices in decreasing finish-time order;
2. traversal of the transpose graph, in that order, collecting components.

It uses \(O(V+E)\) time and storage with adjacency lists. Tarjan’s algorithm finds SCCs in one DFS by maintaining discovery indices, low-link values, and a stack of active vertices.

~~~python
from collections.abc import Hashable, Iterable, Mapping
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def strongly_connected_components(
    graph: Mapping[V, Iterable[V]],
) -> list[list[V]]:
    index = 0
    indices: dict[V, int] = {}
    low: dict[V, int] = {}
    active: list[V] = []
    on_stack: set[V] = set()
    components: list[list[V]] = []

    vertices = set(graph)
    for neighbours in graph.values():
        vertices.update(neighbours)

    def visit(vertex: V) -> None:
        nonlocal index
        indices[vertex] = index
        low[vertex] = index
        index += 1
        active.append(vertex)
        on_stack.add(vertex)

        for neighbour in graph.get(vertex, ()):
            if neighbour not in indices:
                visit(neighbour)
                low[vertex] = min(low[vertex], low[neighbour])
            elif neighbour in on_stack:
                low[vertex] = min(low[vertex], indices[neighbour])

        if low[vertex] == indices[vertex]:
            component: list[V] = []
            while True:
                member = active.pop()
                on_stack.remove(member)
                component.append(member)
                if member == vertex:
                    break
            components.append(component)

    for vertex in vertices:
        if vertex not in indices:
            visit(vertex)

    return components
~~~

Here <code>indices[v]</code> records discovery order. <code>low[v]</code> is the smallest active discovery index reachable from \(v\) through zero or more DFS-tree edges followed by at most one edge to an active vertex, under the algorithm’s invariant. When <code>low[v] == indices[v]</code>, \(v\) is the root of an SCC occupying a suffix of the active stack.

The membership test against <code>on_stack</code> is crucial. An edge to an already completed component must not lower the current low-link value. Recursive depth can reach \(V\); a production implementation facing deep adversarial graphs may require an explicit-stack translation.

> **Common misconception 13.58 — “Mutual reachability can be found by treating a directed graph as undirected.”**  
> That finds weak components. Strong components require reachability in both directed senses and can differ radically.
