# 13.14 Topological ordering

A **directed acyclic graph** (**DAG**) has directed edges and no directed cycle. A **topological order** lists vertices so every edge (u\to v) places (u) before (v). It models prerequisites.

Kahn’s algorithm maintains each vertex’s incoming-edge count. Initially enqueue all zero-indegree vertices; repeatedly remove one, append it to the order, decrement outgoing neighbours, and enqueue newly zero-indegree vertices. If fewer than (|V|) vertices are produced, a cycle prevents a valid order.

Multiple topological orders can exist. Deterministic output requires a tie-breaking policy, such as a priority queue over labels. The algorithm’s correctness follows because only vertices with no remaining unmet predecessor are selected; cycle detection follows because every vertex in a remaining directed cycle retains at least one incoming edge from the cycle.

### 13.14.1 Kahn’s algorithm implemented

~~~python
import heapq
from collections.abc import Hashable, Iterable, Mapping
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def topological_order(
    graph: Mapping[V, Iterable[V]],
) -> list[V]:
    copied = {
        vertex: list(neighbours)
        for vertex, neighbours in graph.items()
    }
    vertices = set(copied)
    for neighbours in copied.values():
        vertices.update(neighbours)
    adjacency = {
        vertex: copied.get(vertex, [])
        for vertex in vertices
    }
    indegree: dict[V, int] = {vertex: 0 for vertex in adjacency}

    for neighbours in adjacency.values():
        for neighbour in neighbours:
            indegree[neighbour] += 1

    ready = [vertex for vertex, degree in indegree.items() if degree == 0]
    heapq.heapify(ready)
    order: list[V] = []

    while ready:
        vertex = heapq.heappop(ready)
        order.append(vertex)
        for neighbour in adjacency[vertex]:
            indegree[neighbour] -= 1
            if indegree[neighbour] == 0:
                heapq.heappush(ready, neighbour)

    if len(order) != len(indegree):
        raise ValueError("directed cycle prevents topological order")
    return order
~~~

The heap provides smallest-label tie-breaking and therefore requires mutually orderable vertex labels. A deque instead gives \(O(V+E)\) expected time under hashing but makes ties depend on construction and neighbour order. With a heap the bound is \(O((V+E)\log V)\) in a coarse account, or \(O(E+V\log V+E\log V)\) when heap events are separated; since each vertex is pushed once, a tighter form is \(O(E+V\log V)\) after adjacency construction.

The central invariant is that <code>indegree[v]</code> equals the number of incoming edges to \(v\) whose sources have not yet been emitted. A zero value therefore means all prerequisites represented in the graph have been emitted. Every edge is processed once.

Mutating a dictionary while iterating its dynamic view would raise, so the implementation’s adjacency-normalisation phase uses two stages. A reusable equivalent is:

~~~python
def normalise_adjacency(
    graph: Mapping[V, Iterable[V]],
) -> dict[V, list[V]]:
    copied = {
        vertex: list(neighbours)
        for vertex, neighbours in graph.items()
    }
    vertices = set(copied)
    for neighbours in copied.values():
        vertices.update(neighbours)
    return {
        vertex: copied.get(vertex, [])
        for vertex in vertices
    }
~~~

The copied neighbour lists also stabilise traversal against later mutation through ordinary source-list aliases during this call; they do not protect against concurrent mutation of the vertex objects themselves. This distinction is why representation discipline accompanies the graph proof.

### 13.14.2 DFS ordering and cycle witnesses

In a DAG, reverse DFS finish order is topological: for every edge \(u\to v\), either DFS explores \(v\) from \(u\) and finishes \(v\) first, or \(v\) was already finished; a grey \(v\) would witness a cycle.

A useful cycle error reports a witness rather than merely a Boolean. Maintain active-stack positions; an edge to a grey vertex closes the suffix from that vertex to the current one.

Python’s <code>graphlib.TopologicalSorter</code> supports topological scheduling in the standard library. Its input mapping is expressed as node to predecessors, not node to successors, and its staged API allows concurrently executing currently ready nodes before calling <code>done</code>. Read the representation contract rather than assuming the adjacency direction used by another algorithm.

> **Common misconception 13.59 — “A topological order exists for every directed graph if ties are chosen carefully.”**  
> A directed cycle imposes contradictory precedence. Tie-breaking selects among valid orders of a DAG; it cannot repair cyclic prerequisites.
