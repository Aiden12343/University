# 13.15 Weighted shortest paths and Dijkstra’s boundary

In a weighted graph, path length is the sum of edge weights. Dijkstra’s algorithm uses a priority queue to repeatedly settle the currently smallest tentative distance. It is correct when edge weights are non-negative.

The non-negative condition is essential. Once vertex (u) is selected as smallest, no route through a more distant unsettled vertex can return via a negative edge and improve (u). Negative edges invalidate this argument.

```python
import heapq
from collections.abc import Mapping, Iterable


def dijkstra(
    graph: Mapping[str, Iterable[tuple[str, float]]],
    start: str,
) -> dict[str, float]:
    distances = {start: 0.0}
    pending = [(0.0, start)]

    while pending:
        distance, vertex = heapq.heappop(pending)
        if distance != distances.get(vertex):
            continue

        for neighbour, weight in graph.get(vertex, ()):
            if weight < 0:
                raise ValueError("Dijkstra requires non-negative weights")
            candidate = distance + weight
            if candidate < distances.get(neighbour, float("inf")):
                distances[neighbour] = candidate
                heapq.heappush(pending, (candidate, neighbour))

    return distances
```

The heap can contain stale entries because Python’s `heapq` has no simple decrease-key operation. The equality check discards an entry whose distance no longer matches the best mapping. Complexity with adjacency lists and a binary heap is commonly (O((V+E)\log V)), often simplified to (O(E\log V)) for connected graphs with (E\geq V-1), under constant-time weight operations.

### 13.15.1 The shortest-path family

A shortest-path problem is not one algorithm:

| Weight/domain condition | Appropriate core method | Typical adjacency-list bound |
|---|---|---:|
| all edges equal | BFS | \(O(V+E)\) |
| weights are 0 or 1 | deque-based 0–1 BFS | \(O(V+E)\) |
| DAG, arbitrary real weights without problematic arithmetic | topological relaxation | \(O(V+E)\) |
| non-negative weights | Dijkstra with binary heap | \(O((V+E)\log V)\) |
| negative edges, no reachable negative cycle for finite answer | Bellman–Ford | \(O(VE)\) |
| all-pairs, dense/moderate graph | Floyd–Warshall | \(\Theta(V^3)\) |
| goal-directed non-negative search with admissible heuristic | A* | instance/heuristic dependent |

An edge **relaxation** tests whether a path to \(v\) through \(u\) improves the current upper bound:

\[
dist[v]\leftarrow
\min(dist[v],\,dist[u]+w(u,v)).
\]

If it improves, record \(u\) as predecessor when paths must be reconstructed. “Relax” means make the constraint less restrictive by lowering an upper estimate; it does not mean pause execution.

The output may ask for one source to every reachable vertex, one source–target path, all pairs, only a distance, or an actual path. Storing predecessors costs \(O(V)\). Enumerating all equally shortest paths can require exponentially large output, even when computing one distance is polynomial.

Weights also need algebraic assumptions. Floating-point addition is not exact or associative, NaN invalidates comparisons, and enormous positive or negative values may require domain policy. Dijkstra’s abstract proof assumes an ordered additive weight structure, not merely objects accepted by <code>+</code>.

> **Common misconception 13.60 — “Shortest path means run Dijkstra.”**  
> Weight restrictions and requested output select the method. BFS is simpler and asymptotically better for equal weights; negative edges require another proof.

### 13.15.2 Dijkstra’s settled-set proof

Let \(S\) contain settled vertices. The invariant is:

1. for every \(u\in S\), \(dist[u]\) equals the true shortest distance \(\delta(start,u)\);
2. for every discovered unsettled \(v\), \(dist[v]\) is the length of a concrete path whose internal vertices are settled;
3. the priority queue contains candidates sufficient to expose the smallest current unsettled distance.

Initially, the start has distance zero and no settled vertices make the invariant vacuous. Suppose \(u\) is the unsettled vertex of minimum tentative distance. If a shorter path to \(u\) existed, take the first vertex \(y\) on that path outside \(S\), with predecessor \(x\in S\). Relaxation from \(x\) established

\[
dist[y]\le\delta(start,x)+w(x,y)=\delta(start,y).
\]

Because tentative distances are lengths of actual paths, \(dist[y]\ge\delta(start,y)\), hence equality. Non-negative remaining edges make \(\delta(start,y)\le\delta(start,u)\), so \(y\)’s tentative distance is no greater than the alleged shorter distance to \(u\), contradicting selection of \(u\) unless \(u\) is already optimal. Thus settling preserves the invariant.

The proof reveals the boundary. With a negative later edge, the first unsettled point on an allegedly shorter path need not have distance no greater than the destination. A settled value can be improved later.

One small counterexample has edges \(s\to a\) of weight 2, \(s\to b\) of weight 5, and \(b\to a\) of weight \(-4\). Dijkstra settles \(a\) at 2 before \(b\), but the path \(s,b,a\) has length 1. Some implementations that permit reopening vertices can still obtain an answer on some negative-edge graphs, but the Dijkstra proof and standard bound no longer apply.

A robust implementation can return parents:

~~~python
import heapq
import itertools
from collections.abc import Hashable, Iterable, Mapping
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def dijkstra_paths(
    graph: Mapping[V, Iterable[tuple[V, float]]],
    start: V,
) -> tuple[dict[V, float], dict[V, V | None]]:
    distance: dict[V, float] = {start: 0.0}
    parent: dict[V, V | None] = {start: None}
    sequence = itertools.count()
    pending: list[tuple[float, int, V]] = [
        (0.0, next(sequence), start)
    ]

    while pending:
        current_distance, _, vertex = heapq.heappop(pending)
        if current_distance != distance.get(vertex):
            continue

        for neighbour, weight in graph.get(vertex, ()):
            if weight < 0:
                raise ValueError("negative edge weight")
            candidate = current_distance + weight
            if candidate < distance.get(neighbour, float("inf")):
                distance[neighbour] = candidate
                parent[neighbour] = vertex
                heapq.heappush(
                    pending,
                    (candidate, next(sequence), neighbour),
                )

    return distance, parent
~~~

The sequence field prevents comparison of vertex labels when distances tie. The stale-entry check uses exact equality with a value previously stored from the same calculation; this is different from using equality as a general tolerance test. Applications with NaN or custom numeric values must strengthen validation.

> **Common misconception 13.61 — “A single negative edge is harmless if it is not chosen early.”**  
> Correctness is a universal guarantee. A negative edge can create a later improvement to a settled vertex, destroying the argument on which Dijkstra rests.

### 13.15.3 Bellman–Ford and negative cycles

Bellman–Ford repeatedly relaxes every edge. After \(i\) full passes, every shortest path using at most \(i\) edges has been accounted for. A simple shortest path in a graph of \(V\) vertices uses at most \(V-1\) edges; otherwise it repeats a vertex and contains a cycle.

~~~python
from collections.abc import Hashable, Iterable
from typing import TypeVar

V = TypeVar("V", bound=Hashable)


def bellman_ford(
    vertices: Iterable[V],
    edges: Iterable[tuple[V, V, float]],
    start: V,
) -> dict[V, float]:
    vertex_list = list(vertices)
    edge_list = list(edges)
    distance = {vertex: float("inf") for vertex in vertex_list}
    distance[start] = 0.0

    for _ in range(max(0, len(vertex_list) - 1)):
        changed = False
        for source, target, weight in edge_list:
            candidate = distance[source] + weight
            if candidate < distance[target]:
                distance[target] = candidate
                changed = True
        if not changed:
            break

    for source, target, weight in edge_list:
        if distance[source] + weight < distance[target]:
            raise ValueError("reachable negative-weight cycle")

    return distance
~~~

The final pass detects a reachable negative cycle: another improvement after \(V-1\) passes implies a beneficial repeated cycle. When such a cycle can reach the queried destination, no finite shortest path exists because traversing the cycle repeatedly reduces path length without bound.

The code assumes every edge endpoint appears in <code>vertices</code>; that is a precondition. It also allows the expression infinity plus a finite weight, which remains infinity for ordinary floats. A custom numeric domain might require explicitly skipping unreachable sources.

### 13.15.4 DAG paths, all pairs, and A*

In a DAG, process vertices in topological order and relax outgoing edges once. All predecessors of a vertex have already been processed, so its distance is final even if edges are negative. Cycles—not negativity alone—are what force repeated relaxation.

Floyd–Warshall defines \(D^{(k)}[i,j]\) as the shortest \(i\)-to-\(j\) path whose internal vertices come from the first \(k\) vertices. The recurrence is

\[
D^{(k)}[i,j]
=
\min\left(
D^{(k-1)}[i,j],
D^{(k-1)}[i,k]+D^{(k-1)}[k,j]
\right).
\]

An in-place matrix implementation uses three nested loops with the intermediate vertex outermost, yielding \(\Theta(V^3)\) time and \(\Theta(V^2)\) storage. Reordering those loops without re-proving the invariant can invalidate the dynamic program.

A* orders the frontier by

\[
f(v)=g(v)+h(v),
\]

where \(g\) is known path cost and \(h\) estimates remaining cost. An **admissible heuristic** never overestimates true remaining cost; a **consistent heuristic** also satisfies a triangle-like condition \(h(u)\le w(u,v)+h(v)\). Under appropriate conditions, A* returns an optimal path and can explore much less than Dijkstra. A zero heuristic reduces it to Dijkstra. Worst-case exploration can still be large; heuristic quality and state representation dominate.

> **Common misconception 13.62 — “A* is always faster than Dijkstra and Bellman–Ford is always safer.”**  
> A* gains only from a valid informative heuristic and may incur overhead. Bellman–Ford handles negative edges at higher cost but still must report reachable negative cycles rather than a finite answer.
