# 13.17 Greedy algorithms

A **greedy algorithm** makes a locally optimal choice and does not reconsider it. Greedy choice is correct only when a proof connects local choice to a global optimum.

Interval scheduling: choose the maximum number of mutually non-overlapping intervals. Sorting by earliest finish time and repeatedly choosing the next interval starting after the last finish is optimal.

Exchange argument: take any optimal schedule. Its first interval cannot finish earlier than the greedy first choice. Replace the optimal first interval with the greedy choice; no later selected interval becomes invalid because the replacement finishes no later. Repeating the exchange transforms an optimum into the greedy schedule without reducing count.

Choosing earliest start or shortest interval lacks this exchange property and admits counterexamples. Greedy algorithms are not defined by appearing sensible; they are defined by a choice rule supported by a structural proof.

### 13.17.1 Greedy-choice and optimal-substructure properties

A greedy proof usually separates two claims:

1. **greedy-choice property:** some optimal solution begins with, or can be transformed to include, the locally chosen item;
2. **optimal substructure:** after fixing that choice, the remainder of an optimal solution is optimal for the residual problem.

An **exchange argument** takes an arbitrary optimum and replaces one of its choices with the greedy choice without worsening the objective. A **stays-ahead argument** shows that after every prefix of choices, the greedy partial solution is at least as favourable by a relevant measure. A **cut property** proves that a locally light edge is safe for a partition of a graph. These are proof patterns, not magic phrases; the transformation and preserved feasibility must be shown.

Interval scheduling illustrates the complete contract. Intervals are half-open \([start,finish)\), so one may begin exactly when another finishes:

~~~python
from dataclasses import dataclass
from typing import TypeVar

T = TypeVar("T")


@dataclass(frozen=True)
class Interval:
    start: int
    finish: int
    label: str


def maximum_compatible(
    intervals: list[Interval],
) -> list[Interval]:
    if any(item.finish < item.start for item in intervals):
        raise ValueError("finish precedes start")

    ordered = sorted(
        intervals,
        key=lambda item: (item.finish, item.start, item.label),
    )
    chosen: list[Interval] = []
    last_finish: int | None = None

    for item in ordered:
        if last_finish is None or item.start >= last_finish:
            chosen.append(item)
            last_finish = item.finish

    return chosen
~~~

Sorting costs \(O(n\log n)\); the selection scan is \(O(n)\). If input is already sorted by finish time under the same tie policy, the scan alone is linear. The objective is maximum count, not maximum occupied time or total value. Weighted interval scheduling has a different recurrence and generally requires dynamic programming.

The exchange proof does not depend on label tie-breaking. Labels make output deterministic among equal finish/start values. Determinism is an engineering property layered over optimal cardinality.

> **Common misconception 13.67 — “Once a greedy rule works on many examples, induction proves it.”**  
> Induction can propagate a valid safe-choice lemma, but it cannot supply that lemma. A counterexample may show the first local choice excludes every optimum.

### 13.17.2 Fractional and indivisible choices

In **fractional knapsack**, each item has value \(v_i\), weight \(w_i>0\), and may be divided. Sorting by density \(v_i/w_i\) and taking the greatest densities first is optimal: if a solution contains lower-density mass while omitting available higher-density mass, exchanging equal weight increases value.

In **0/1 knapsack**, each item is indivisible. The same rule fails. With capacity 50 and items \((value,weight)=(60,10),(100,20),(120,30)\), density-greedy takes the first two for value 160; the latter two fit exactly and yield 220. Divisibility supplied the exchange operation. Removing it changes the problem’s structure.

This contrast is central to algorithm design: a proof attaches not merely to an objective but to the feasible-set structure. Rules valid for continuous allocation, matroids, or interval systems need not survive additional constraints.

### 13.17.3 Huffman coding

Given symbols with positive frequencies, a **prefix code** assigns bit strings so no codeword is a prefix of another. Such a code is represented by a binary tree whose leaves are symbols; a symbol’s depth is its code length. Huffman’s algorithm repeatedly combines the two least frequent current trees.

~~~python
import heapq
import itertools
from dataclasses import dataclass


@dataclass(frozen=True)
class HuffmanNode:
    symbol: str | None
    frequency: int
    left: "HuffmanNode | None" = None
    right: "HuffmanNode | None" = None


def huffman_tree(
    frequencies: dict[str, int],
) -> HuffmanNode:
    if not frequencies:
        raise ValueError("at least one symbol is required")
    if any(value <= 0 for value in frequencies.values()):
        raise ValueError("frequencies must be positive")

    sequence = itertools.count()
    pending = [
        (
            frequency,
            next(sequence),
            HuffmanNode(symbol, frequency),
        )
        for symbol, frequency in frequencies.items()
    ]
    heapq.heapify(pending)

    while len(pending) > 1:
        left_frequency, _, left = heapq.heappop(pending)
        right_frequency, _, right = heapq.heappop(pending)
        combined_frequency = left_frequency + right_frequency
        combined = HuffmanNode(
            None,
            combined_frequency,
            left,
            right,
        )
        heapq.heappush(
            pending,
            (combined_frequency, next(sequence), combined),
        )

    return pending[0][2]
~~~

The sibling lemma establishes that two least frequent symbols can be deepest sibling leaves in some optimal tree. Contracting them into a pseudo-symbol reduces the problem; induction then proves repeated greedy combination optimal for expected code length. The algorithm takes \(O(k\log k)\) time for \(k\) symbols with a binary heap.

An actual file format must serialise the tree or a canonical codebook, define the single-symbol case, pack bits, store lengths, detect corrupt streams, and account for header overhead. The greedy tree theorem is only one layer of a compressor.

### 13.17.4 Minimum spanning trees

For a connected undirected weighted graph, a **spanning tree** connects every vertex without cycles. A **minimum spanning tree** (**MST**) minimises total edge weight. It is not a shortest-path tree: minimising sum over chosen infrastructure edges differs from minimising distance from one source.

For a partition of vertices into a set \(S\) and its complement, an edge crossing the partition crosses a **cut**. The cut property states that a minimum-weight crossing edge is safe for some MST, with tie qualifications. If an MST lacks chosen light edge \(e\), adding \(e\) creates a cycle containing another cut-crossing edge \(f\). Replacing \(f\) by \(e\) preserves a spanning tree and does not increase total weight.

**Kruskal’s algorithm** sorts edges by non-decreasing weight and adds an edge exactly when it joins two currently separate components. A **disjoint-set union** (**DSU**, or union–find) structure maintains those components.

~~~python
from dataclasses import dataclass
from typing import Generic, TypeVar

T = TypeVar("T")


class DisjointSet(Generic[T]):
    def __init__(self, values: list[T]) -> None:
        self._parent = {value: value for value in values}
        self._size = {value: 1 for value in values}

    def find(self, value: T) -> T:
        parent = self._parent[value]
        if parent != value:
            self._parent[value] = self.find(parent)
        return self._parent[value]

    def union(self, left: T, right: T) -> bool:
        left_root = self.find(left)
        right_root = self.find(right)
        if left_root == right_root:
            return False

        if self._size[left_root] < self._size[right_root]:
            left_root, right_root = right_root, left_root
        self._parent[right_root] = left_root
        self._size[left_root] += self._size[right_root]
        return True


@dataclass(frozen=True)
class Edge(Generic[T]):
    weight: float
    left: T
    right: T


def kruskal(
    vertices: list[T],
    edges: list[Edge[T]],
) -> list[Edge[T]]:
    components = DisjointSet(vertices)
    chosen: list[Edge[T]] = []

    for edge in sorted(edges, key=lambda item: item.weight):
        if components.union(edge.left, edge.right):
            chosen.append(edge)
            if len(chosen) == len(vertices) - 1:
                break

    if vertices and len(chosen) != len(vertices) - 1:
        raise ValueError("graph is disconnected")
    return chosen
~~~

**Path compression** in <code>find</code> points visited nodes nearer the root. **Union by size** attaches the smaller tree below the larger. Together, a sequence of \(m\) operations over \(n\) items takes \(O(m\alpha(n))\), where \(\alpha\) is the inverse Ackermann function, which grows extraordinarily slowly. This is an amortised result, not a claim that the structure is literally constant-time.

Edge sorting dominates Kruskal at \(O(E\log E)\), commonly written \(O(E\log V)\) for a simple connected graph because \(E\le V^2\) and \(E\ge V-1\). If the graph is disconnected, the same process yields a minimum spanning forest unless the contract, as above, rejects it.

Prim’s algorithm grows one tree by repeatedly taking a cheapest edge crossing from reached to unreached vertices. With adjacency lists and a binary heap its common bound is \(O(E\log V)\). Kruskal and Prim rely on the same family of safe-edge properties but maintain different partial solutions.

> **Common misconception 13.68 — “A minimum spanning tree gives shortest routes from its root.”**  
> It minimises total tree edge weight. Individual source-to-vertex paths may be longer than those in a shortest-path tree.
