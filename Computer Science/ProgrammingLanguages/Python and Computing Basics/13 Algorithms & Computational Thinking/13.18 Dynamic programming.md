# 13.18 Dynamic programming

**Dynamic programming** solves overlapping subproblems under optimal-substructure or compositional recurrence, retaining results to avoid recomputation. A design requires:

1. state meaning;
2. recurrence connecting states;
3. base cases;
4. evaluation order ensuring dependencies are available;
5. final-state selection;
6. optional reconstruction information;
7. complexity in number of states and transitions.

### Worked example 13.2 — Minimum coins

Given positive coin denominations and a non-negative target, find the minimum number of coins whose values sum to target, with unlimited reuse.

State (dp[a]): minimum coins needed to form amount (a), or infinity if impossible.

Base: (dp[0]=0).

Recurrence:

\[
dp[a]=1+\min_{c\in coins,\ c\leq a} dp[a-c].
\]

```python
def minimum_coins(coins: list[int], target: int) -> int | None:
    if target < 0 or any(coin <= 0 for coin in coins):
        raise ValueError("target must be non-negative and coins positive")

    unreachable = target + 1
    dp = [0] + [unreachable] * target

    for amount in range(1, target + 1):
        for coin in coins:
            if coin <= amount:
                dp[amount] = min(dp[amount], 1 + dp[amount - coin])

    return None if dp[target] == unreachable else dp[target]
```

The sentinel `target + 1` is safely greater than any possible solution because using a coin of value at least 1 cannot require more than target coins. Time is (O(target\times |coins|)); space is (O(target)). This is pseudo-polynomial: target’s numeric value can be exponential in its bit-length representation.

A greedy largest-coin-first rule works for some denomination systems but fails generally; coins `[1, 3, 4]`, target 6 yields greedy `4+1+1` (three) while optimum is `3+3` (two).

### 13.18.1 Subproblem graphs and evaluation orders

A dynamic program can be understood as evaluating a directed acyclic dependency graph:

- each state is a vertex;
- an edge points from a state to a dependency;
- base states have no unresolved dependencies;
- memoisation discovers the reachable graph on demand;
- tabulation chooses a topological evaluation order in advance.

**Memoisation** caches results of a top-down recursive specification. **Tabulation** fills a table bottom-up. They may compute different state sets and expose different operational limits even when implementing the same recurrence.

~~~python
from functools import cache


@cache
def fibonacci_memoised(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative")
    if n < 2:
        return n
    return fibonacci_memoised(n - 1) + fibonacci_memoised(n - 2)


def fibonacci_tabulated(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative")
    previous = 0
    current = 1
    for _ in range(n):
        previous, current = current, previous + current
    return previous
~~~

Both compute \(\Theta(n)\) states rather than the exponential repeated-call tree of naive recursion. The memoised version retains \(\Theta(n)\) cached integers and can reach Python’s recursion limit. The tabulated version retains two evolving integers, though their bit lengths grow with \(n\); calling its memory \(O(1)\) is valid only in a unit-cost word abstraction that ignores arbitrary-precision integer size.

The cache is attached to the function and persists across calls until cleared or discarded. Its retained memory and interaction with tests are part of the implementation. Memoisation keys require hashable arguments and assume a result depends only on those arguments and relevant immutable context.

> **Common misconception 13.69 — “Memoisation always turns recursion into an efficient algorithm.”**  
> It removes repeated evaluation only when many calls share states. The number of distinct states, transition cost, cache memory, recursion depth, and key correctness still require analysis.

### 13.18.2 Longest common subsequence

A **subsequence** is obtained by deleting zero or more elements without changing the order of those retained; it need not be contiguous. For sequences \(A\) and \(B\), define

\[
L[i,j]
=
\text{length of a longest common subsequence of }A[:i]\text{ and }B[:j].
\]

Base states \(L[0,j]=L[i,0]=0\). For \(i,j>0\):

\[
L[i,j]=
\begin{cases}
L[i-1,j-1]+1,
& A[i-1]=B[j-1],\\
\max(L[i-1,j],L[i,j-1]),
& \text{otherwise}.
\end{cases}
\]

~~~python
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def longest_common_subsequence(
    left: Sequence[T],
    right: Sequence[T],
) -> list[T]:
    rows = len(left) + 1
    columns = len(right) + 1
    length = [
        [0] * columns
        for _ in range(rows)
    ]

    for i in range(1, rows):
        for j in range(1, columns):
            if left[i - 1] == right[j - 1]:
                length[i][j] = length[i - 1][j - 1] + 1
            else:
                length[i][j] = max(
                    length[i - 1][j],
                    length[i][j - 1],
                )

    result: list[T] = []
    i = len(left)
    j = len(right)
    while i > 0 and j > 0:
        if left[i - 1] == right[j - 1]:
            result.append(left[i - 1])
            i -= 1
            j -= 1
        elif length[i - 1][j] >= length[i][j - 1]:
            i -= 1
        else:
            j -= 1

    result.reverse()
    return result
~~~

For lengths \(n\) and \(m\), table construction takes \(\Theta(nm)\) equality/constant table operations and \(\Theta(nm)\) integer-reference storage. Reconstruction takes \(O(n+m)\). Ties can yield several valid longest subsequences; choosing upward on equality creates one deterministic policy.

The length alone can be computed with \(O(\min(n,m))\) table space because a row depends only on the previous row and current partial row. That optimisation discards information needed by the straightforward reconstruction. Hirschberg’s divide-and-conquer method reconstructs an LCS in linear auxiliary space at the cost of a subtler argument.

The recurrence requires proof. If final elements are equal, there exists an optimum using that shared element under the standard argument. If unequal, an LCS omits at least one of them, so the optimum belongs to one of the two smaller prefix pairs. The table is not an arbitrary two-dimensional loop; its axes and branches encode this exhaustive decomposition.

### 13.18.3 Edit distance

The Levenshtein **edit distance** between two sequences is the minimum number of single-element insertions, deletions, and substitutions needed to transform one into the other, each assigned unit cost here.

Let \(D[i,j]\) be the distance from the first \(i\) source elements to the first \(j\) target elements. Base cases are \(D[i,0]=i\) deletions and \(D[0,j]=j\) insertions. The recurrence is

\[
D[i,j]
=
\min
\begin{cases}
D[i-1,j]+1 & \text{delete},\\
D[i,j-1]+1 & \text{insert},\\
D[i-1,j-1]+[A[i-1]\ne B[j-1]] & \text{match/substitute}.
\end{cases}
\]

Each final edit type is exhaustive, and removing it leaves the corresponding prefix subproblem. Weighted or restricted edit operations change the recurrence. Transposition, affine gap costs, Unicode normalisation, and domain-specific tokenisation are not incidental details; they define different distance measures.

~~~python
def edit_distance(source: str, target: str) -> int:
    previous = list(range(len(target) + 1))

    for source_index, source_character in enumerate(source, start=1):
        current = [source_index]
        for target_index, target_character in enumerate(
            target,
            start=1,
        ):
            deletion = previous[target_index] + 1
            insertion = current[target_index - 1] + 1
            substitution = (
                previous[target_index - 1]
                + (source_character != target_character)
            )
            current.append(min(deletion, insertion, substitution))
        previous = current

    return previous[-1]
~~~

The Boolean inequality converts to integer 0 or 1. Time is \(\Theta(nm)\), and row compression uses \(\Theta(m)\) storage. Swapping arguments so the shorter string becomes the table width reduces auxiliary space to \(O(\min(n,m))\) without changing symmetric unit-cost distance.

> **Common misconception 13.70 — “Dynamic programming is a table-filling technique.”**  
> The table is a representation. The essential work is defining a complete, non-circular state recurrence and a valid dependency order; some dynamic programs use dictionaries, DAG nodes, bitsets, or only a few rolling states.

### 13.18.4 Zero–one knapsack and reconstruction

For items \((w_i,v_i)\), capacity \(C\), and indivisible one-use choices, define

\[
K[i,c]
=
\text{maximum value attainable using the first }i
\text{ items within capacity }c.
\]

If \(w_i>c\), item \(i\) cannot be selected. Otherwise:

\[
K[i,c]
=
\max\left(
K[i-1,c],
v_i+K[i-1,c-w_i]
\right).
\]

The first branch excludes the item; the second includes it and therefore moves to the previous item row, enforcing use at most once.

One-dimensional tabulation must iterate capacities downward:

~~~python
def knapsack_value(
    items: list[tuple[int, int]],
    capacity: int,
) -> int:
    if capacity < 0:
        raise ValueError("capacity must be non-negative")
    if any(weight <= 0 for weight, _ in items):
        raise ValueError("weights must be positive")

    best = [0] * (capacity + 1)
    for weight, value in items:
        for current in range(capacity, weight - 1, -1):
            best[current] = max(
                best[current],
                value + best[current - weight],
            )
    return best[capacity]
~~~

Descending order ensures <code>best[current - weight]</code> still belongs to the previous conceptual item row. Ascending order would allow the current item’s newly updated state to be reused, silently changing the problem to unbounded knapsack.

The cost is \(O(nC)\) time and \(O(C)\) storage. This is pseudo-polynomial in numeric capacity. Recovering chosen items requires a decision table, persistent parent information, recomputation, or a more elaborate compressed representation. Optimising value and producing a witness are related but distinct outputs.

### 13.18.5 Backtracking, pruning, and branch-and-bound

**Backtracking** explores a decision tree incrementally, abandoning a partial candidate as soon as it cannot lead to a feasible solution. It is systematic search rather than dynamic programming: different paths may reach states treated as distinct unless memoisation merges them.

The \(n\)-queens problem asks for \(n\) queens on an \(n\times n\) chessboard with no shared row, column, or diagonal. Placing one queen per row removes row conflicts; sets retain occupied columns and diagonals:

~~~python
def n_queens(n: int) -> list[tuple[int, ...]]:
    if n < 0:
        raise ValueError("n must be non-negative")

    solutions: list[tuple[int, ...]] = []
    columns: set[int] = set()
    descending: set[int] = set()
    ascending: set[int] = set()
    placement: list[int] = []

    def search(row: int) -> None:
        if row == n:
            solutions.append(tuple(placement))
            return

        for column in range(n):
            down_key = row - column
            up_key = row + column
            if (
                column in columns
                or down_key in descending
                or up_key in ascending
            ):
                continue

            columns.add(column)
            descending.add(down_key)
            ascending.add(up_key)
            placement.append(column)
            search(row + 1)
            placement.pop()
            ascending.remove(up_key)
            descending.remove(down_key)
            columns.remove(column)

    search(0)
    return solutions
~~~

The mutable sets and placement list represent the choices on exactly the current recursion path. Every addition before recursion is reversed after it, restoring the loop invariant for the next branch. If recursion could raise unexpectedly and the caller intended recovery, <code>try/finally</code> or immutable state would be needed to guarantee restoration.

Worst-case search remains exponential or factorial depending on the bound. Pruning improves explored instances but does not by itself establish a polynomial worst case.

**Branch-and-bound** addresses optimisation by computing a bound on the best objective any completion of a partial candidate could achieve. A branch can be discarded when that optimistic bound cannot beat the incumbent solution. Correctness requires the bound truly be optimistic in the appropriate direction. A merely plausible estimate can prune the optimum.

Memoisation and backtracking can combine when a compact state fully determines future possibilities. If path history affects admissible continuations, caching only an incomplete state produces wrong answers.

> **Common misconception 13.71 — “Pruning changes an exponential algorithm into a polynomial one.”**  
> It can transform practical behaviour on structured instances while leaving worst-case growth exponential. A stronger complexity claim needs a bound over all admitted inputs.
