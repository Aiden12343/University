# 13.2 Asymptotic notation

Let (f(n)) represent resource use and (g(n)) a comparison growth function.

(f(n)\in O(g(n))) means there exist positive constants (c) and (n_0) such that

\[
0\leq f(n)\leq c\,g(n) \quad\text{for all } n\geq n_0.
\]

Big-O gives an asymptotic upper bound. It does not necessarily give a tight bound. (3n+7\in O(n)), but it is also in (O(n^2)); the linear bound conveys more information.

(f(n)\in \Omega(g(n))) supplies an asymptotic lower bound. (f(n)\in \Theta(g(n))) means both upper and lower bounds hold, giving a tight growth class.

Constants and lower-order terms disappear because for sufficiently large (n), growth dominates them under the definition. They remain important in actual performance. An (O(n)) algorithm with an enormous constant can lose to an (O(n\log n)) algorithm across every practical input.

### Worked example 13.1 — Derive a linear bound

```python
def contains(values: list[int], target: int) -> bool:
    for value in values:
        if value == target:
            return True
    return False
```

For (n) elements:

- best case: first element matches, one comparison, (Theta(1));
- worst case: target absent or final, (n) comparisons, (Theta(n));
- average case requires a probability distribution over target location and absence; without one, “average (O(n))” is underspecified.

Additional space is (Theta(1)) under a model where loop references and counters have bounded size relative to (n). Input storage is not counted as additional space because the function receives it.

### 13.2.1 The notation denotes sets of functions

The expression \(O(g)\) denotes a set of functions, not a running time and not a value produced by a program. More precisely,

\[
O(g)=
\left\{
f\;\middle|\;
\exists c>0,\ \exists n_0,\ \forall n\ge n_0:
0\le f(n)\le c\,g(n)
\right\},
\]

where \(f\) and \(g\) are eventually non-negative. It is therefore formally preferable to write \(f\in O(g)\), although the widespread equality-like notation \(f=O(g)\) is conventionally understood as set membership. The corresponding lower and tight-bound sets are

\[
\Omega(g)=
\left\{
f\;\middle|\;
\exists c>0,\ \exists n_0,\ \forall n\ge n_0:
0\le c\,g(n)\le f(n)
\right\}
\]

and

\[
\Theta(g)=O(g)\cap\Omega(g).
\]

The constants may differ between the upper- and lower-bound proofs. Nothing in the definitions requires equality of operation counts, nor does membership describe what happens below \(n_0\).

Consider \(f(n)=6n^2+4n+9\). For every \(n\ge1\),

\[
6n^2+4n+9
\le 6n^2+4n^2+9n^2
=19n^2.
\]

Taking \(c=19\) and \(n_0=1\) proves \(f\in O(n^2)\). Also \(f(n)\ge6n^2\), so \(f\in\Omega(n^2)\). Consequently \(f\in\Theta(n^2)\). These witnesses are not uniquely or optimally chosen; their purpose is to satisfy the quantifiers.

The quantifier order matters. The statement chooses fixed \(c\) and \(n_0\) that work for every sufficiently large \(n\). Permitting a different \(c\) for each \(n\) would make the definition nearly vacuous: one could hide arbitrary growth in a changing “constant”.

> **Common misconception 13.6 — “The constants in Big-O may depend on the input.”**  
> They may depend on the algorithm, cost model, and fixed parameters excluded from \(n\), but once chosen they must work for all \(n\ge n_0\). A quantity that varies with \(n\) is not a constant with respect to \(n\).

### 13.2.2 Upper bounds are directional claims

If \(f\in\Theta(n)\), then \(f\in O(n^2)\), \(f\in O(n^3)\), and \(f\in O(2^n)\). All are true upper bounds; only the first is tight among these choices. Big-O alone does not mean “grows exactly like”. Conversely, \(f\in\Omega(1)\) says only that it is eventually bounded below by a positive constant multiple of 1. It does not say that \(f\) is constant.

A useful reporting convention is:

- use \(\Theta\) when a matching bound has been established;
- use \(O\) when only an upper guarantee is intended or known;
- use \(\Omega\) for an unavoidable lower cost;
- state worst, average, expected, or amortised case separately.

The phrase “binary search is \(O(\log n)\)” commonly abbreviates “the worst-case number of comparisons made by this implementation on a sorted random-access sequence of length \(n\) is in \(O(\log n)\)”. The abbreviation is convenient only after the omitted qualifications are shared.

> **Common misconception 13.7 — “\(O(n^2)\) means the algorithm takes at least quadratic time.”**  
> Big-O is an upper bound. A lower claim uses \(\Omega\); an exact asymptotic growth class uses \(\Theta\).

### 13.2.3 Strict asymptotic separation

Two further notations express bounds that are not tight even up to a constant. We say

\[
f\in o(g)
\quad\Longleftrightarrow\quad
\forall c>0,\ \exists n_0,\ \forall n\ge n_0:
0\le f(n)<c\,g(n).
\]

Equivalently, when the quotient is defined and non-negative eventually,

\[
\lim_{n\to\infty}\frac{f(n)}{g(n)}=0.
\]

Thus \(n\in o(n\log n)\) and \(n\log n\in o(n^2)\). The notation \(\omega(g)\) is the strict lower counterpart: \(f\in\omega(g)\) when \(f/g\) grows without bound. Lower-case \(o\) must not be used merely as typographic variation of upper-case \(O\).

These relations let an analysis distinguish “no faster asymptotically” from “strictly slower asymptotically”. They are particularly useful in limit arguments and lower-bound theory, though most implementation discussions can be expressed with \(O\), \(\Omega\), and \(\Theta\).

> **Common misconception 13.8 — “Little-o and Big-O are interchangeable.”**  
> \(f\in o(g)\) excludes a matching constant-order term; \(f\in O(g)\) permits one. For example, \(3n\in O(n)\) but \(3n\notin o(n)\).

### 13.2.4 Algebra of asymptotic bounds

For eventually non-negative functions, several rules support compositional analysis:

\[
O(f)+O(g)=O(f+g)=O(\max(f,g)),
\]

\[
O(f)\cdot O(g)=O(fg),
\]

and, for a positive constant \(a\),

\[
O(a f)=O(f).
\]

These are set-level abbreviations. Operationally, sequential phases add costs, while nested independent repetitions often multiply them.

Suppose a program first scans \(n\) records in \(O(n)\), then sorts them in \(O(n\log n)\), then performs 30 constant-time summary operations. Its total upper bound is

\[
O(n)+O(n\log n)+O(30)=O(n\log n).
\]

This simplification does not license deleting terms involving independent variables. If a graph operation costs \(O(V+E)\), neither \(V\) nor \(E\) can generally be dropped: a graph may contain many isolated vertices, or a dense graph may have \(E=\Theta(V^2)\). Only a proved relationship among variables permits substitution.

Products also require attention to dependent loop bounds. The following function does not perform \(n^2\) increments:

~~~python
def advance_two_frontiers(left: list[int], right: list[int]) -> int:
    i = 0
    j = 0
    steps = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            i += 1
        else:
            j += 1
        steps += 1

    return steps
~~~

Each iteration increases exactly one of \(i\) and \(j\). The variant

\[
(\lvert left\rvert-i)+(\lvert right\rvert-j)
\]

decreases by one, so the loop performs at most \(\lvert left\rvert+\lvert right\rvert-1\) iterations. One loop containing two indices is linear in their combined extent. Syntactic loop count is not a proof of a complexity class.

> **Common misconception 13.9 — “Nested loops multiply and consecutive loops add, without exception.”**  
> That heuristic works only when iteration domains have the assumed independence. Derive how many times the body executes; shared monotone progress, early exit, and triangular ranges alter the sum.

### Worked example 13.2A — Translate loops into sums

~~~python
def triangular_work(n: int) -> int:
    operations = 0
    for outer in range(n):
        for inner in range(outer):
            operations += 1
    return operations
~~~

For outer values \(0,1,\ldots,n-1\), the inner body runs \(0,1,\ldots,n-1\) times. Hence

\[
T(n)=\sum_{i=0}^{n-1}i=\frac{n(n-1)}2\in\Theta(n^2).
\]

Replacing the inner range with <code>range(0, n, outer + 1)</code> would produce a different sum:

\[
\sum_{i=1}^{n}\left\lceil \frac{n}{i}\right\rceil
\in\Theta(n\log n).
\]

The harmonic term appears because \(n/i\) iterations occur for each step width \(i\). Surface resemblance between two nested-loop fragments does not determine their cost.

### 13.2.5 Logarithms and exponentials

For bases \(a,b>1\),

\[
\log_a n=\frac{\log_b n}{\log_b a}.
\]

The denominator is constant with respect to \(n\); therefore all fixed bases greater than one define the same \(\Theta(\log n)\) class. Bases retain explanatory value. Repeated halving suggests \(\log_2 n\); traversing a balanced \(b\)-ary tree suggests \(\log_b n\).

The ceiling of a logarithm frequently counts discrete levels. If an interval of length \(n\) is halved until its length is at most 1, the number of halvings is \(\lceil\log_2 n\rceil\) for \(n>0\). If a binary tree has levels numbered from zero and is complete through height \(h\), it contains

\[
1+2+\cdots+2^h=2^{h+1}-1
\]

nodes. Solving for height gives \(h=\Theta(\log n)\).

Repeated multiplication and repeated division are inverse descriptions. A capacity that doubles \(k\) times reaches \(2^k\); reaching capacity \(n\) requires \(k=\lceil\log_2 n\rceil\) doublings. An algorithm whose branching creates two recursive calls at each of \(n\) independent choices can create \(2^n\) leaves. Confusing these two patterns reverses the role of the exponent.

> **Common misconception 13.10 — “A loop with multiplication is exponential.”**  
> A loop variable multiplied by two reaches \(n\) after logarithmically many iterations. Exponential work arises when the amount of work itself multiplies across depth, as in an unpruned binary recursion tree of depth \(n\).

### 13.2.6 Several input parameters

When a cost depends on more than one dimension, preserve that dependence:

~~~python
def shared_values(left: list[int], right: list[int]) -> list[int]:
    result: list[int] = []
    for a in left:
        for b in right:
            if a == b:
                result.append(a)
                break
    return result
~~~

If \(n=\lvert left\rvert\) and \(m=\lvert right\rvert\), the worst-case number of equality tests is \(nm\), so the comparison cost is \(\Theta(nm)\). Calling it \(\Theta(n^2)\) silently assumes \(m=\Theta(n)\). That assumption may be justified for a square matrix but is false for arbitrary inputs.

For an \(r\times c\) matrix stored densely, visiting every cell is \(\Theta(rc)\). Relative to total cell count \(N=rc\), the same traversal is \(\Theta(N)\). Both descriptions are correct; the former exposes shape and the latter uses encoded collection size.

With fixed parameters, state what is held fixed. A regular expression engine may be linear in text length for a compiled fixed pattern yet exponential when both pattern and text are variable under a backtracking implementation. A database query may be logarithmic in row count given a maintained index but linear in query-result size \(z\); reporting \(O(\log n+z)\) preserves the unavoidable output term.

> **Common misconception 13.11 — “Every size variable can be renamed \(n\).”**  
> Renaming is harmless only when it does not erase independent dimensions. \(O(V+E)\), \(O(rc)\), and \(O(nm)\) communicate structural facts that a single \(n\) can conceal.

### 13.2.7 Recurrences describe recursive cost

A **recurrence relation** defines a quantity using values on smaller inputs. Recursive algorithms naturally induce recurrences, but the recurrence must account for the actual subproblem sizes and non-recursive work.

Binary search gives

\[
T(n)=T(\lfloor n/2\rfloor)+\Theta(1),
\quad T(0)=\Theta(1),
\]

whose solution is \(\Theta(\log n)\). Merge sort gives

\[
T(n)=2T(n/2)+\Theta(n)
\]

for powers of two: two half-size sorts and linear merging. Its solution is \(\Theta(n\log n)\).

Naive recursive Fibonacci gives

\[
T(n)=T(n-1)+T(n-2)+\Theta(1),
\]

which is exponential, whereas the numeric Fibonacci sequence obeys the same additive shape without the extra recursive recomputation interpretation. A recurrence is a mathematical definition; its meaning comes from what \(T\) measures.

#### Substitution

The **substitution method** proposes a bound and proves it by induction. For merge sort, suppose \(T(n)\le cn\log_2 n+dn\) for smaller powers of two. Then

\[
\begin{aligned}
T(n)
&\le 2\left(c\frac n2\log_2\frac n2+d\frac n2\right)+an\\
&=cn(\log_2 n-1)+dn+an\\
&=cn\log_2 n+dn+(a-c)n.
\end{aligned}
\]

Choosing \(c\ge a\), together with a suitable base-case constant, closes the upper-bound induction. A matching lower argument establishes \(\Theta(n\log n)\).

#### Recursion trees

A **recursion tree** arranges subcalls by depth and sums non-recursive work at each level. For merge sort, level \(j\) has \(2^j\) problems of size \(n/2^j\). Linear work per problem makes total level work

\[
2^j\Theta(n/2^j)=\Theta(n).
\]

There are \(\log_2 n+1\) levels, yielding \(\Theta(n\log n)\). This is a derivation device, not the runtime call stack itself.

#### The Master theorem

For recurrences of the form

\[
T(n)=aT(n/b)+f(n),
\quad a\ge1,\ b>1,
\]

compare \(f(n)\) with \(n^{\log_b a}\), the work represented by the leaves:

1. if \(f(n)=O(n^{\log_b a-\varepsilon})\) for some \(\varepsilon>0\), then \(T(n)=\Theta(n^{\log_b a})\);
2. if \(f(n)=\Theta(n^{\log_b a}\log^k n)\) for fixed \(k\ge0\), then \(T(n)=\Theta(n^{\log_b a}\log^{k+1}n)\);
3. if \(f(n)=\Omega(n^{\log_b a+\varepsilon})\) and an appropriate regularity condition holds, then \(T(n)=\Theta(f(n))\).

The theorem is a pattern theorem, not a universal recursion solver. It does not directly apply to unequal partitions such as \(T(n)=T(n/3)+T(2n/3)+n\), decrementing recurrences such as \(T(n)=T(n-1)+n\), or history-dependent subproblem sizes. Those require substitution, summation, Akra–Bazzi-type results, or another justified method.

> **Common misconception 13.12 — “Every recursive function can be analysed by the Master theorem.”**  
> The theorem applies to a restricted recurrence form and stated side conditions. First derive the recurrence; then select a method that actually covers it.
