# 13.3 Common growth classes

| Class | Characteristic example |
|:---:|:---|
| (Theta(1)) | list index under dynamic-array model |
| (Theta(\log n)) | binary search comparisons |
| (Theta(n)) | full sequence scan |
| (Theta(n\log n)) | efficient comparison sorting |
| (Theta(n^2)) | all unordered pairs or nested full scans |
| (Theta(2^n)) | enumerate every subset |
| (Theta(n!)) | enumerate every permutation |

Logarithm base differs only by a constant factor for asymptotic classification. Binary search naturally uses base two because each comparison halves the remaining interval.

Polynomial growth can still be impractical; exponential algorithms can be appropriate for small fixed (n), pruned search, or unavoidable exact problems. Complexity informs design but does not decide requirements.

### 13.3.1 A hierarchy, not a stopwatch

For sufficiently large \(n\), the familiar hierarchy is

\[
1
\prec \log n
\prec n^\alpha
\prec n
\prec n\log n
\prec n^2
\prec n^3
\prec c^n
\prec n!
\prec n^n,
\]

where \(0<\alpha<1\), \(c>1\), and \(f\prec g\) here means \(f\in o(g)\). The ordering is asymptotic. It makes no assertion about the crossing point: a cubic algorithm with small constants may outperform a linear one with costly remote I/O for all deployed sizes.

A thought experiment nevertheless reveals scale. If an abstract machine performs \(10^8\) charged operations per second, an \(n^2\) procedure at \(n=10^6\) requires \(10^{12}\) operations, or approximately \(10^4\) seconds under the deliberately unrealistic assumption of uniform operations. A \(2^n\) procedure crosses \(10^{12}\) operations near \(n=40\). The arithmetic is not a benchmark; it exposes why growth rate constrains feasible input size.

The most relevant size is the largest admitted by the service contract, not the size used in a demonstration. If a batch currently contains 200 items but an unbounded API accepts 200,000, a quadratic duplicate check carries operational risk even if today’s timing appears negligible.

> **Common misconception 13.13 — “A better asymptotic class is always faster.”**  
> Growth classes compare eventual scaling under a model. Constants, locality, vectorised native work, allocation, input distribution, and maximum deployed size decide measured performance within the relevant range.

### 13.3.2 Output-sensitive and parameterised bounds

An **output-sensitive algorithm** expresses its cost partly in terms of output size. Reporting every match between two collections may inherently require \(\Omega(z)\) time merely to emit \(z\) matches. A bound such as \(O((n+m)\log n+z)\) distinguishes search overhead from production of results.

A **parameterised analysis** isolates a structural parameter \(k\) in addition to total input size \(n\). A procedure with cost

\[
O(2^k n^3)
\]

is exponential in \(k\) but polynomial in \(n\). It may be practical when \(k\) is guaranteed small. A problem is **fixed-parameter tractable** with respect to \(k\) if it admits a bound \(f(k)n^{O(1)}\) for some computable function \(f\). This vocabulary will be used only as a classification in this chapter; parameterised-complexity theory is substantially deeper.

Input-sensitive bounds can also use disorder measures. Insertion sort takes \(\Theta(n+I)\) movements and comparisons under suitable counting, where \(I\) is the number of **inversions**—pairs out of desired order. This explains its adaptiveness more precisely than giving only quadratic worst-case cost.

> **Common misconception 13.14 — “Exponential dependence makes an algorithm categorically useless.”**  
> Dependence on a small parameter, aggressive pruning, approximation, or tiny bounded instances can make exponential worst-case methods appropriate. The bound must identify which quantity is in the exponent.

### 13.3.3 Polynomial does not mean practical

An algorithm is commonly called **polynomial-time** when its worst-case cost is bounded by \(O(n^k)\) for some fixed \(k\), under a conventional machine and encoded input length. This boundary is theoretically significant because polynomial algorithms compose and are comparatively robust under reasonable machine simulations. It is not a synonym for feasible.

\(n^{100}\) is polynomial and almost never usable for non-trivial \(n\). An \(O(n^3)\) dense matrix algorithm may be entirely appropriate for \(n=200\) and prohibitive for \(n=10^6\). A pseudo-polynomial \(O(nT)\) dynamic program may be excellent when numeric target \(T\) is below ten thousand despite not being polynomial in \(\log T\).

Likewise, worst-case exponential algorithms can solve large structured instances while failing on much smaller adversarial ones. **Combinatorial explosion** refers to a search space whose number of candidates grows exponentially or faster; it identifies a scaling mechanism, not an observed duration.

> **Common misconception 13.15 — “Polynomial-time means efficient in practice.”**  
> Polynomial-time is a coarse theoretical tractability category. Exponent, constants, representation, memory traffic, input structure, and operational limits remain decisive.
