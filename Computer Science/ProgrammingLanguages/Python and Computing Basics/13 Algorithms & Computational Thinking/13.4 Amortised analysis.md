# 13.4 Amortised analysis

Amortised analysis bounds the total cost across a sequence without assuming random inputs. A dynamic array append may cost 1 when capacity remains and proportional to current length when resizing. If capacity grows geometrically, each existing reference participates in only a bounded number of copies relative to later appends.

For capacities 1, 2, 4, 8, ..., reaching (n) elements copies fewer than

\[
1+2+4+\cdots+\frac{n}{2}<n
\]

existing elements across resizes, plus (n) ordinary writes. Total work is (O(n)), so average charge across (n) appends is amortised (O(1)).

Amortised is not probabilistic and does not promise each operation is cheap. Real-time systems may reject an occasional (O(n)) pause even when throughput is excellent.

### 13.4.1 Aggregate analysis

The **aggregate method** bounds the total cost \(T(n)\) of a sequence of \(n\) operations and divides by \(n\). Consider a stack supporting <code>push</code>, <code>pop</code>, and <code>clear</code>, where <code>clear</code> pops every current item:

~~~python
class ClearingStack:
    def __init__(self) -> None:
        self._items: list[int] = []

    def push(self, item: int) -> None:
        self._items.append(item)

    def pop(self) -> int:
        return self._items.pop()

    def clear(self) -> None:
        while self._items:
            self._items.pop()
~~~

One <code>clear</code> may cost \(\Theta(n)\), but across any sequence beginning empty, an item can be popped only after it was pushed and at most once before being pushed again. There are at most \(n\) pushes and at most \(n\) removals among \(n\) public operations. Ignoring dynamic-array resizing already analysed separately, total abstract stack work is \(O(n)\), hence \(O(1)\) amortised per operation.

This conclusion applies to the entire operation set and the stated initial condition. Starting with \(m\) pre-existing elements gives \(O(n+m)\) total removal work. Amortised claims must identify the sequences over which cost is spread.

### 13.4.2 The accounting method

The **accounting method** assigns an artificial **amortised charge** to each operation. Cheap operations may be overcharged; the surplus is stored as conceptual credit that pays for later expensive operations. Credits must never become negative if the proof is to establish an upper bound.

For the clearing stack, charge 2 units to <code>push</code>: one pays for insertion and one is stored on the pushed item. Charge 0 or 1 to removal depending on the primitive convention; the stored credit pays for the item’s eventual pop. Because every removable item carries its credit, a mass clear is prepaid.

For a table that doubles when full, a constant charge on each insertion can pay for its own write and reserve credits for future reference copies. Exact credit placement depends on the growth rule. The accounting currency is not real time or memory; it is a proof device whose total dominates actual charged work.

> **Common misconception 13.16 — “Amortised cost is average cost over random inputs.”**  
> Amortised analysis places a deterministic bound on every admitted operation sequence as a whole. It requires no probability distribution.

### 13.4.3 The potential method

The **potential method** summarises stored credit with a non-negative function \(\Phi(D)\) of data-structure state \(D\). If operation \(i\) changes state \(D_{i-1}\) to \(D_i\) with actual cost \(c_i\), define amortised cost

\[
\widehat c_i
=c_i+\Phi(D_i)-\Phi(D_{i-1}).
\]

Summing telescopes:

\[
\sum_{i=1}^n\widehat c_i
=
\sum_{i=1}^n c_i+\Phi(D_n)-\Phi(D_0).
\]

If \(\Phi(D_0)=0\) and \(\Phi(D_n)\ge0\), then total actual cost does not exceed total amortised cost.

For a binary counter, represent a non-negative integer as bits. Increment flips trailing ones to zero and the following zero to one. Let actual cost be the number of flipped bits and potential be the number of one bits. If an increment encounters \(t\) trailing ones, actual cost is \(t+1\); potential changes by \(1-t\). Therefore

\[
\widehat c=(t+1)+(1-t)=2.
\]

Every increment has amortised cost at most 2 although incrementing \(0111\ldots1\) flips many bits.

~~~python
def increment_little_endian(bits: list[int]) -> None:
    index = 0
    while index < len(bits) and bits[index] == 1:
        bits[index] = 0
        index += 1
    if index == len(bits):
        bits.append(1)
    else:
        bits[index] = 1
~~~

The list stores the least significant bit first. Its representation invariant requires every entry to be 0 or 1 and, if canonical representation is required, the final bit of a non-empty list to be 1. The amortised proof concerns bit flips; list resizing contributes its own amortised cost.

> **Common misconception 13.17 — “An amortised \(O(1)\) operation never pauses for linear work.”**  
> Individual operations may remain expensive. Amortised bounds control total cost across a sequence, not per-operation latency.

### 13.4.4 Resizing in both directions

A dynamic table that grows at load 1 and shrinks immediately whenever one element is removed can **thrash**: alternating insert and delete around the boundary repeatedly copies the table. A design uses hysteresis—different thresholds for growth and shrinkage. For example, double when full but halve only when occupancy falls below one quarter. The unused interval absorbs oscillation.

A suitable potential rises as the table approaches either resize threshold and falls when a resize restores slack. This establishes constant amortised update cost while keeping capacity within a constant factor of logical size. It also illustrates a general principle: an amortised guarantee depends on policy, not merely on the data structure’s name.

CPython’s list growth and shrinkage policies are implementation details rather than Python language guarantees. Their exact constants can change across releases. The portable semantic fact is that a list is a mutable sequence; complexity statements about its current implementation should be labelled and verified against the relevant implementation.

> **Common misconception 13.18 — “Amortised analysis hides an assumption about favourable input order.”**  
> A valid amortised proof covers every sequence satisfying its preconditions. A policy vulnerable to an adversarial oscillation has not earned the claimed bound.
