# 15.14 Weak references

A **weak reference** designates an object without keeping it alive. It permits caches, registries, and observer structures that should not own object lifetime.

```python
import weakref


class Record:
    pass


record = Record()
reference = weakref.ref(record)
print(reference() is record)

del record
print(reference())
```

In ordinary CPython execution, the final result becomes `None` after the object is collected. The timing is implementation-sensitive; the interface requires callers to handle the object disappearing between operations.

Not every type supports weak references. Slotted classes require a weak-reference slot. Weak mappings use identity/lifetime-aware weak references and have concurrency/liveness subtleties.

### 15.14.1 Dereference and test must be one operation

Calling a weak reference returns the referent if it is still alive or <code>None</code> after death. The race-safe idiom obtains one strong local result and tests it:

~~~python
from weakref import ReferenceType


def use_if_alive(reference: ReferenceType[object]) -> str | None:
    value = reference()
    if value is None:
        return None
    return type(value).__name__
~~~

Do not first call <code>reference()</code> to test and call it again to use. The last external strong reference can disappear between the two calls—through another thread in a free-threaded build, a callback, or other permitted execution. Assigning the result to <code>value</code> creates a strong local reference for the rest of the function’s use interval.

The referent itself can legitimately be <code>None</code> only if the weak-referenceable type permits an object identical to <code>None</code>; the built-in singleton is not weak-referenceable, so <code>None</code> serves unambiguously as a dead-result sentinel for <code>weakref.ref</code>.

A weak-reference callback is invoked when the referent is about to be finalised under applicable implementation rules. The callback receives the weak-reference object, not a live strong reference to the dying referent. Capturing the referent strongly in the callback would prevent the callback condition from arising:

~~~python
import gc
import weakref


events: list[str] = []


class Document:
    pass


document = Document()
reference = weakref.ref(
    document,
    lambda ref: events.append("document released"),
)

del document
gc.collect()

assert reference() is None
assert events == ["document released"]
~~~

The variable <code>reference</code> keeps the weak-reference object alive so its callback remains registered. Exceptions raised by weak callbacks are treated as unraisable and reported similarly to finaliser exceptions. Callback order among several weak references is implementation/documentation-sensitive and should not coordinate correctness.

> **Common misconception 15.56 — “Checking weak() is not None and then calling weak() again safely retrieves the same object.”**  
> The referent can die between calls. Call once, bind the result strongly, test that local, and use it only while the local remains in scope.

### 15.14.2 Weak containers encode non-ownership policies

<code>WeakValueDictionary</code> holds values weakly and removes entries when those values die. <code>WeakKeyDictionary</code> holds keys weakly and removes entries when keys die. <code>WeakSet</code> holds its members weakly. These structures are appropriate only when some independent owner controls lifetime.

### Worked example 15.19 — An interning cache that does not own results

~~~python
import gc
import weakref


class Symbol:
    def __init__(self, spelling: str) -> None:
        self.spelling = spelling


symbols: weakref.WeakValueDictionary[str, Symbol] = (
    weakref.WeakValueDictionary()
)


def symbol(spelling: str) -> Symbol:
    existing = symbols.get(spelling)
    if existing is not None:
        return existing
    created = Symbol(spelling)
    symbols[spelling] = created
    return created


first = symbol("alpha")
second = symbol("alpha")
assert first is second

del first, second
gc.collect()
assert "alpha" not in symbols
~~~

In concurrent use the get/create/store sequence requires a lock if identity uniqueness is an invariant. The container’s own memory integrity does not make the compound interning operation atomic.

Weak-key mappings have an equality/identity subtlety. Inserting a distinct but equal key can update the value associated with the original stored weak key; when that original object dies, the entry can disappear even if the equal object remains. Identity-keyed semantics should use an explicit identity wrapper or a registry designed and tested for that requirement.

Classes using <code>__slots__</code> do not automatically support weak references. Include <code>__weakref__</code> unless a base class already supplies support:

~~~python
import weakref


class SlottedRecord:
    __slots__ = ("name", "__weakref__")

    def __init__(self, name: str) -> None:
        self.name = name


record = SlottedRecord("entry")
assert weakref.ref(record)() is record
~~~

<code>weakref.finalize</code> registers a callback to run at most once when an object dies, or optionally at interpreter exit. It keeps itself alive, but its callback arguments must not own the monitored object, directly or through a bound method:

### Worked example 15.20 — A finaliser whose callback does not capture its owner

~~~python
import gc
import weakref


released: list[int] = []


class NativeHandle:
    def __init__(self, identifier: int) -> None:
        self.identifier = identifier
        self._finalizer = weakref.finalize(
            self,
            released.append,
            identifier,
        )

    def close(self) -> None:
        self._finalizer()


handle = NativeHandle(17)
handle.close()
assert released == [17]

del handle
gc.collect()
assert released == [17]
~~~

Explicit <code>close</code> gives deterministic cleanup and invoking the finaliser makes it inactive, so later collection does not duplicate the release. For a real handle, the callback must be idempotent or guarded and must tolerate shutdown conditions. A context manager should expose the primary ownership protocol; finalisation is a fallback.

> **Common misconception 15.57 — “weakref.finalize guarantees prompt and unconditional external-resource cleanup.”**  
> Process termination, retained referents, shutdown ordering, and callback failure can prevent or delay it. Use explicit close/context management for correctness and finalization only as a fallback.

Weak references help diagnose reachability without adding ownership. They do not explain why deallocated objects may leave process memory high; that question belongs to allocator layers and operating-system accounting.
