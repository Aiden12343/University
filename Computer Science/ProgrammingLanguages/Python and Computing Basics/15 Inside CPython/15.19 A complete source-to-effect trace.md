# 15.19 A complete source-to-effect trace

Source:

```python
def increment(mapping: dict[str, int], key: str) -> int:
    mapping[key] = mapping.get(key, 0) + 1
    return mapping[key]


counts: dict[str, int] = {}
print(increment(counts, "accepted"))
```

Trace across levels:

1. **Source decoding:** bytes become Unicode source under encoding rules.
2. **Tokenisation/parsing:** tokens form module, function definition, annotations, calls, subscriptions, and assignment nodes.
3. **Symbol analysis:** `mapping` and `key` are parameters; name uses are classified; module `counts` is global to the module code.
4. **Compilation:** module and function code objects are created; constants and names enter compiler-selected metadata; bytecode and exception/position tables are emitted.
5. **Module evaluation:** annotation and function-definition machinery creates a function object and binds `increment`; a dictionary is created and bound to `counts`.
6. **Call evaluation:** `print` and `increment` are resolved; argument expressions obtain the dictionary and string; a frame is created for `increment`.
7. **Method lookup:** `mapping.get` resolves dictionary method behaviour; bound call returns default integer 0 because key is absent.
8. **Addition:** integer protocol produces integer 1; implementation can use specialised paths while preserving semantics.
9. **Dictionary assignment:** string hash selects a table path; absence is established; an entry retains references to key and value; dictionary mutates without identity change.
10. **Return subscription:** lookup finds the entry and returns integer 1 from the function frame.
11. **Frame completion:** local strong references are released under CPython ownership; shared dictionary remains reachable from module name `counts`.
12. **Output call:** `print` converts result to text, writes through a text stream and lower I/O layers.

The expression is not atomic as an application transaction. Two threads can interleave lookup and assignment. A custom mapping can execute arbitrary Python code in `.get`, subscription, and assignment. The trace’s fast built-in path is conditioned on actual type.

### 15.19.1 The trace is a branching causal graph, not a linear translation

The twelve-stage outline above selects the successful exact-dictionary/integer path. A faithful account must expose branch points. <code>mapping.get</code> may invoke a descriptor; hashing <code>key</code> can execute user code; equality can mutate the mapping; allocation can fail; addition can return <code>NotImplemented</code>; assignment can call an arbitrary mapping protocol; <code>print</code> can fail during conversion or writing. Compiler output does not determine which of these branches occurs until runtime types and state are known.

At each boundary, distinguish four propositions:

| Label | Example proposition |
|:---|:---|
| L: language | argument expressions are evaluated before the call |
| P: documented CPython/Python interface | <code>dis.get_instructions</code> exposes instruction records for this build |
| I: private CPython implementation | a guarded exact-dict path consults a particular internal table routine |
| E: experiment | after the recorded warm-up, this site displayed a named specialised opcode |

An implementation claim should identify source revision and guards. An experiment should record inputs and tool perturbation. A language claim should not be justified only by one disassembly. This labelling prevents a mechanism observed on the fast path from being mistaken for behaviour guaranteed for subclasses and proxies.

### Worked example 15.30 — Trace closure state, protocol dispatch, mutation, and failure

Consider a callable object produced by a closure:

~~~python
from collections.abc import Callable, MutableMapping


class AuditMap(dict[str, int]):
    def __setitem__(self, key: str, value: int) -> None:
        if value < 0:
            raise ValueError("negative totals are forbidden")
        super().__setitem__(key, value)


def make_adjuster(
    scale: int,
) -> Callable[[MutableMapping[str, int], str, int], int]:
    calls = 0

    def adjust(
        records: MutableMapping[str, int],
        key: str,
        amount: int,
    ) -> int:
        nonlocal calls
        calls += 1
        previous = records.get(key, 0)
        updated = previous + amount * scale
        records[key] = updated
        return updated

    return adjust


adjust = make_adjuster(2)
ledger = AuditMap()
assert adjust(ledger, "credit", 5) == 10

try:
    adjust(ledger, "credit", -10)
except ValueError as error:
    assert str(error) == "negative totals are forbidden"

assert ledger == {"credit": 10}
~~~

#### Phase A: source, grammar, and symbols

The source bytes decode, tokenise, and parse into a module containing an import, class definition, function definition, assignments, assertion, <code>try</code>, handler, and final assertion (L). The class method’s zero-argument <code>super()</code> causes compiler support for a <code>__class__</code> cell (I, observable through P). The outer function binds <code>scale</code> and <code>calls</code>; the inner function reads both and assigns <code>calls</code> under <code>nonlocal</code> (L). Symbol analysis therefore makes them cells in the outer code and free variables in the inner code (I/P).

The annotation <code>Callable[[MutableMapping[str, int], str, int], int]</code> has annotation semantics determined by the version and active future statements (L). It does not make the runtime arguments conform, insert a type check, or select specialised bytecode. Static analysers use it under their own rules.

#### Phase B: compilation and definition execution

Compilation constructs code objects for the module, class body, methods, outer function, and inner function (I). The nested code objects appear among constants of enclosing code objects under compiler-selected layout (P/I). Names, locals, cells, positions, flags, and exception regions are encoded. No <code>AuditMap</code> instance or closure cell value yet exists.

Module evaluation resolves the import, executes the class body in its prepared namespace, constructs <code>AuditMap</code>, and binds it (L/P). It creates <code>make_adjuster</code> with the module globals. Calling <code>make_adjuster(2)</code> creates a frame, binds <code>scale</code>, binds <code>calls</code> to integer 0 in a cell, constructs <code>adjust</code> with the two required cells, returns it, and releases other frame state subject to retained objects (I). The closure cells—not the full outer frame—remain reachable through <code>adjust</code>.

#### Phase C: successful call and frame setup

The first assertion resolves <code>adjust</code> and <code>ledger</code>, evaluates literal arguments, and calls the function (L). Vectorcall can transmit arguments without a tuple/dict pair (I), but signature binding still associates <code>records</code>, <code>key</code>, and <code>amount</code> with the supplied objects (L/I). A new frame or internal activation is initialised with its code, globals, built-ins, locals-plus entries, closure cells, stack position, and exception state (I).

<code>calls += 1</code> loads the cell’s integer, performs addition, and stores the new integer into the same cell (L). Integers are immutable: the old 0 is not modified. Reference ownership of the cell’s old referent is released; the cached/immortal status of small integers is an implementation detail.

The call <code>records.get(key, 0)</code> evaluates the primary and arguments in order (L). Because <code>AuditMap</code> inherits the built-in method without overriding <code>get</code>, descriptor lookup produces a callable behaviour bound to <code>records</code>. The implementation can use a method/vectorcall fast path, but subclass and mutation guards determine eligibility (I). No entry exists, so the integer default is returned under mapping semantics.

Multiplication computes <code>amount * scale</code>, then addition computes <code>previous + result</code> (L). With exact small integers, specialised paths may perform checked native arithmetic and construct/reuse a Python integer result (I/E); overflow of a fixed native intermediate must fall back to arbitrary-precision arithmetic rather than wrap (L/I).

#### Phase D: overridden assignment and re-entrant call

The subscription assignment is not permitted to bypass <code>AuditMap.__setitem__</code> merely because the base is a dictionary (L). The protocol invokes the override. A new method frame binds <code>self</code>, <code>key</code>, and <code>value</code>. It compares <code>value < 0</code>. The false branch evaluates zero-argument <code>super()</code> using the compiler-provided <code>__class__</code> cell and current receiver, resolves the base implementation, and inserts the entry (L/I).

The dictionary obtains or reuses a hash for the string, probes its compact table, retains strong references to key and value, updates used/capacity metadata, and preserves insertion order (some L, some I). Allocation/resizing can occur and fail before mutation commits. The method returns <code>None</code>; the inner function returns <code>updated</code>; frames release local ownership; and the assertion compares the returned integer to 10.

#### Phase E: exceptional call and partial state

The second call first increments <code>calls</code> from one to two. It computes <code>previous=10</code> and <code>updated=-10</code>. These effects occur before subscription assignment. The overridden setter sees a negative value and raises <code>ValueError</code>. The language does not roll back the closure increment or local calculations. No base dictionary insertion occurs because the override raises first, so <code>ledger["credit"]</code> remains 10.

At the C/evaluator boundary, the raise establishes exception state and returns through error paths. The setter frame finds no local handler, contributes traceback state, and unwinds. The adjuster frame likewise unwinds. The module frame’s exception table identifies the <code>except ValueError as error</code> handler. Matching binds the exception temporarily; the message assertion succeeds; suite completion clears the handler target (L/I).

Reference decrements during unwinding release local operands and frames unless tracebacks or tooling retain them. The closure cell for <code>calls</code> remains reachable through <code>adjust</code> with value 2. The exception’s usual handler target has been cleared, so its traceback graph can be reclaimed once other temporaries vanish; immediate timing is a CPython mechanism rather than a language promise.

#### Phase F: mutation, atomicity, and external observations

The final mapping equality confirms that the successful entry remains and the failed update did not reach the base setter. It says nothing about <code>calls</code>, which records attempts rather than commits. If the intended invariant were “count successful adjustments”, the increment must move after assignment or be protected by a wider transaction with rollback.

Two threads calling the closure can race over both <code>calls += 1</code> and mapping read-modify-write. The conventional GIL does not promise compound atomicity; a custom method executes Python and free-threaded builds allow parallel interpreter execution. A lock around the whole semantic transaction is required if shared use is part of the contract.

This one example crosses parsing, scope cells, nested code, function construction, call transport, frames, specialised arithmetic, descriptors, inheritance, dictionary storage, reference ownership, and exception tables. There is no honest one-arrow translation from a source line to a processor instruction. Each abstraction selects a boundary and hides a graph of guarded operations.

> **Common misconception 15.71 — “A complete internal trace assigns exactly one opcode and one C function to each source expression.”**  
> Compilation can fold, split, merge, or add operations; runtime dispatch branches by type and cache state; one opcode can invoke nested Python and many native functions. A faithful trace is a versioned branching graph.
