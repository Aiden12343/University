# 16.10 Vectorisation and native kernels

**Vectorisation** is the expression of bulk operations over arrays so that regular iteration can occur inside optimised compiled code or specialised hardware rather than through one Python interpreter cycle per element. It does not mean that every operation uses a CPU vector instruction, nor that asymptotic complexity changes. Adding \(n\) elements remains \(\Theta(n)\); the constant factors and memory-access behaviour change.

Compare:

~~~python
import numpy as np


def python_squares(values: list[float]) -> list[float]:
    return [value * value for value in values]


def array_squares(values: np.ndarray) -> np.ndarray:
    return values * values
~~~

The list comprehension performs iteration and arithmetic through Python objects. The array expression requests elementwise multiplication from NumPy. A native loop can read compact values, multiply them, and write compact results. The operation still allocates an output unless an explicit safe in-place operation or output buffer is used.

Vectorisation can be misapplied. A sequence of array expressions may allocate several full-sized temporaries:

~~~python
import numpy as np

x = np.array([0.0, 3.0, 6.0])
y = np.array([0.0, 4.0, 8.0])
centre_x = 1.0
centre_y = 2.0
distance = np.sqrt((x - centre_x) ** 2 + (y - centre_y) ** 2)
~~~

The implementation may create arrays for differences, squares, sum, and root result. Whether an optimiser fuses operations depends on the library and execution system; ordinary NumPy syntax does not promise fusion. For data larger than memory, chunking, an expression engine, or a different array system may be necessary.

### Worked example 16.9 — Measured comparison with a correctness oracle

~~~python
from timeit import timeit

import numpy as np


def python_squares(values: list[float]) -> list[float]:
    return [value * value for value in values]


def array_squares(values: np.ndarray) -> np.ndarray:
    return values * values


python_values = [float(i) for i in range(100_000)]
array_values = np.asarray(python_values)

expected = python_squares(python_values)
actual = array_squares(array_values)
assert np.allclose(actual, expected)

python_time = timeit(
    lambda: python_squares(python_values),
    number=20,
)
array_time = timeit(
    lambda: array_squares(array_values),
    number=20,
)

print(python_time, array_time)
~~~

<code>np.allclose</code> implements a tolerance-based comparison appropriate to many, but not all, floating calculations. A tolerance is a domain decision: defaults are not proof of scientific adequacy. Timing follows correctness and uses repeated measurements. The observed ratio applies to the versions, machine, sizes, dtype, and operation tested.

### 16.10.1 Universal functions separate loop selection from iteration

A NumPy **universal function**, abbreviated **ufunc**, implements an elementwise operation with broadcasting, dtype resolution, casting rules and one or more compiled inner loops. A ufunc reports its number of inputs and outputs and the registered dtype signatures exposed by the build.

~~~python
import numpy as np


operation = np.add
assert isinstance(operation, np.ufunc)
assert operation.nin == 2
assert operation.nout == 1
print(operation.types[:10])
~~~

A signature such as two float64 inputs producing float64 identifies a loop family, not a guarantee of one hardware SIMD instruction. NumPy can select CPU-dispatched kernels according to architecture/build and can use scalar cleanup loops for tails or alignment. Object signatures invoke Python operations.

Ufuncs provide methods beyond ordinary calls: <code>reduce</code>, <code>accumulate</code>, <code>reduceat</code>, <code>outer</code> and <code>at</code> where supported. Their semantics differ:

~~~python
import numpy as np


values = np.array([1, 2, 3, 4])
assert np.add.reduce(values) == 10
assert np.array_equal(np.add.accumulate(values), [1, 3, 6, 10])
assert np.array_equal(np.multiply.outer([1, 2], [3, 4]), [[3, 4], [6, 8]])
~~~

Reduction requires an associative-like interpretation for intuitive regrouping, yet floating addition is only approximately associative. <code>maximum</code> with NaNs differs from <code>fmax</code>; choosing a ufunc includes its exceptional-value contract.

> **Common misconception 16.28 — “A ufunc is simply a Python loop hidden behind shorter syntax.”**  
> It is a dispatch and iteration abstraction selecting dtype-specific inner loops, broadcasting and casting. Some loops are native numeric kernels; object loops can still invoke Python per element.

### 16.10.2 out and where control storage and selection

Many ufuncs accept <code>out</code>, allowing a caller-provided array to receive results, and <code>where</code>, selecting positions at which the operation writes. The output must satisfy shape, dtype, casting and writeability constraints.

~~~python
import numpy as np


numerator = np.array([10.0, 20.0, 30.0])
denominator = np.array([2.0, 0.0, 5.0])
result = np.full(3, np.nan)

np.divide(
    numerator,
    denominator,
    out=result,
    where=denominator != 0,
)

assert np.allclose(result[[0, 2]], [5.0, 6.0])
assert np.isnan(result[1])
~~~

Positions where <code>where</code> is false retain the prior contents of <code>out</code>. If no initialised output is supplied, false positions in a newly allocated output can remain uninitialised under ufunc documentation; code must initialise when those values can be observed.

An output can alias an input where the operation supports safe overlap handling. NumPy detects and buffers many ordinary overlaps, but exact performance and semantics of pathological partially overlapping views require care. Avoid obscure aliasing in public APIs.

~~~python
import numpy as np


values = np.array([1.0, 2.0, 3.0])
np.multiply(values, 2.0, out=values)
assert np.array_equal(values, [2.0, 4.0, 6.0])
~~~

In-place computation reduces an output allocation but changes caller-visible state and can use the input dtype. Multiplying an integer array by a non-integral float in place can fail its casting rule rather than silently convert the array to float.

> **Common misconception 16.29 — “Using out always makes an expression faster and memory-free.”**  
> It reuses one destination buffer; broadcasting checks, temporary overlap buffers, dtype conversion and other intermediate expressions can remain. Mutation and casting also change the contract.

### 16.10.3 np.vectorize provides convenience, not compiled speed

<code>np.vectorize</code> adapts a Python scalar callable to array-like broadcasting and output assembly. Its implementation is essentially a convenience loop and ordinarily does not compile the callable into a native numeric kernel.

~~~python
import numpy as np


def classify(value: int) -> str:
    return "negative" if value < 0 else "non-negative"


classify_many = np.vectorize(classify, otypes=[str])
labels = classify_many(np.array([-2, 0, 3]))
assert labels.tolist() == ["negative", "non-negative", "non-negative"]
~~~

The explicit <code>otypes</code> avoids an initial probe call used to infer output type, which could duplicate side effects. The operation still enters Python for elements. For performance, first seek a native ufunc/composition, boolean indexing, a compiled extension/Numba/Cython kernel, or an algorithm reducing work. For clarity on modest data, a list comprehension can be preferable.

<code>frompyfunc</code> creates a ufunc-like object from a Python callable, but its outputs have object dtype and execution remains Python-level. Generalized ufuncs extend signatures with named core dimensions, allowing operations such as matrix multiplication across broadcast batch axes; they are a powerful protocol, not automatic compilation of arbitrary Python.

> **Common misconception 16.30 — “Calling np.vectorize converts Python code into machine-vector instructions.”**  
> It mainly supplies broadcasting and result assembly around repeated Python calls. Its name describes interface shape, not optimisation.

### 16.10.4 Expression boundaries often materialise temporaries

Ordinary eager NumPy evaluates subexpressions and produces arrays unless an operation can safely write in place or the implementation has a narrow optimisation. The expression

\[
y=\sqrt{(x-a)^2+(z-b)^2}
\]

can allocate difference, square, sum and result buffers. Python syntax does not request kernel fusion. Tools such as <code>numexpr</code>, JIT compilers, GPU array systems or compiler frameworks can fuse under their own semantics, but transfer and compilation costs enter the model.

Algebraic rewrites can reduce temporaries:

~~~python
import numpy as np


def distances_in_place(
    x: np.ndarray,
    z: np.ndarray,
    centre_x: float,
    centre_z: float,
) -> np.ndarray:
    if x.shape != z.shape:
        raise ValueError("coordinate shapes must match")
    result = np.subtract(x, centre_x, dtype=np.float64)
    np.square(result, out=result)
    temporary = np.subtract(z, centre_z, dtype=np.float64)
    np.square(temporary, out=temporary)
    np.add(result, temporary, out=result)
    np.sqrt(result, out=result)
    return result


assert np.allclose(
    distances_in_place(np.array([3.0]), np.array([4.0]), 0.0, 0.0),
    [5.0],
)
~~~

This version still allocates two full buffers but controls peak count and leaves inputs unchanged. A block loop may reduce peak memory further. More compact code is not necessarily more memory-efficient; profile allocation and correctness.

Reductions replace an axis with a summary and expose the numerical consequences of operation order.
