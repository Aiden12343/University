# 16.12 Randomness, generators, and reproducibility

A **pseudorandom number generator** is a deterministic state machine that produces a sequence designed to satisfy selected statistical properties. Given identical algorithm, initial state, and call sequence, it repeats. A **seed** initialises or helps initialise the state. Seeding supports reproducibility; it does not make simulated observations genuinely independent, unbiased, secure, or representative.

Modern NumPy code creates an explicit generator:

~~~python
import numpy as np

rng = np.random.default_rng(20260904)
sample = rng.normal(loc=0.0, scale=1.0, size=1_000)

print(sample.mean())
print(sample.std(ddof=1))
~~~

The result is a simulated sample from the generator’s implementation of a normal distribution with requested parameters. The empirical mean will usually be near, not equal to, zero. <code>ddof=1</code> selects a divisor adjusted by one for the sample standard deviation calculation.

A literal seed in a published example makes the example repeatable. A real experiment should record generator family and library version because streams can differ across algorithms or compatibility promises. Security tokens require the <code>secrets</code> module or an approved cryptographic generator, not a scientific simulation generator.

### 16.12.1 The generator separates state from distribution

NumPy’s random architecture distinguishes a **BitGenerator** from a **Generator**. A BitGenerator owns and advances a finite internal state, producing unsigned integer bit patterns. A Generator transforms those bits into samples from distributions and supplies operations such as permutation and sampling without replacement. This separation matters because two experiments can request the same normal distribution while using different underlying bit generators, and because stream compatibility belongs to the bit-generating algorithm rather than to the abstract probability distribution.

<code>default_rng</code> is a convenience constructor. Code that merely requires a sound contemporary default should use it and should not presume that the default algorithm is an eternal file format. Code whose audit contract requires a named algorithm can construct it explicitly:

~~~python
import numpy as np

bit_generator = np.random.PCG64(20260904)
rng = np.random.Generator(bit_generator)

uniforms = rng.random(4)
integers = rng.integers(0, 10, size=4)
print(uniforms)
print(integers)
~~~

The first call advances the state before the second call. Interchanging the calls changes both results even though the initial seed remains fixed. Reproducibility therefore requires the ordered sequence of random requests, including their shapes and distribution parameters. A seed alone is not a complete record of the realised stream.

A generator should ordinarily be passed into a stochastic function instead of being recreated inside it. Dependency injection makes the state transition visible and permits the caller to control replication:

~~~python
from collections.abc import Sequence

import numpy as np
from numpy.typing import NDArray


def bootstrap_mean(
    values: Sequence[float],
    repetitions: int,
    rng: np.random.Generator,
) -> NDArray[np.float64]:
    data = np.asarray(values, dtype=np.float64)
    if data.ndim != 1 or data.size == 0:
        raise ValueError("values must be a non-empty one-dimensional sequence")
    draws = rng.choice(data, size=(repetitions, data.size), replace=True)
    return draws.mean(axis=1)


first = bootstrap_mean([3.0, 5.0, 8.0], 5, np.random.default_rng(17))
second = bootstrap_mean([3.0, 5.0, 8.0], 5, np.random.default_rng(17))
assert np.array_equal(first, second)
~~~

The annotations describe the interface but do not prove statistical correctness. The caller can now reproduce the five replicates; it can also create one continuing generator and make successive calls when distinct portions of one stream are required.

> **Common misconception 16.34 — “A pseudorandom seed is a magic label for one random sample.”**  
> A seed initialises generator state. The realised values also depend on the bit-generator algorithm, software implementation, distribution method, call order, requested shapes, and every preceding state transition.

### 16.12.2 Seed sequences and parallel streams

Parallel simulation creates a stream-allocation problem. Giving every worker the same seed duplicates work. Giving workers consecutive small integer seeds is not the principled definition of independent streams; it asks the seeding mechanism and generator to turn related inputs into acceptably separated states, while making experiment composition fragile. NumPy’s <code>SeedSequence</code> mixes input entropy into appropriately sized initial states and can **spawn** child seed sequences with recorded positions in a tree.

~~~python
import numpy as np

root = np.random.SeedSequence(0x5EED_2026)
children = root.spawn(4)
generators = [np.random.default_rng(child) for child in children]

worker_means = [generator.standard_normal(100_000).mean()
                for generator in generators]
print(worker_means)
print([child.spawn_key for child in children])
~~~

The four child streams are deterministically reproducible from the root entropy and spawn structure, yet they do not begin with identical states. The spawn keys document the children’s positions. A real multiprocessing program can send one child sequence to each worker. It should base assignment on stable task identities where scheduling order may change, and record the mapping from task to child.

Stream allocation must match the semantic unit of repeatability. Suppose an experiment simulates 100 scenarios on four workers. If each worker owns a long stream, moving from four to five workers changes which random numbers reach each scenario. If each scenario owns a spawned stream, its result can remain stable as worker count changes. The latter costs additional state management but makes the computation invariant to scheduling. Reproducibility is an architectural property, not a final call to <code>seed</code>.

Several methods consume state in different ways:

- <code>permutation(x)</code> returns a permuted copy or permuted indices, whereas <code>shuffle(x)</code> changes an array in place;
- <code>choice</code> samples from a finite collection, and its probability vector must be non-negative and sum to one within numerical tolerance;
- sampling without replacement imposes a population-size constraint and dependence between selected items;
- distribution parameters define different conventions across libraries, so one must confirm whether a parameter is a variance, standard deviation, rate, scale, probability, or count.

The mathematical model should be stated before its API spelling. A call can be executable while parameterising the wrong distribution.

> **Common misconception 16.35 — “Different seeds prove that parallel simulation streams are independent.”**  
> Statistical independence is a property of an ideal probabilistic model; deterministic generator streams can only be designed and tested to avoid known harmful overlap and correlation. Use a documented stream-splitting or spawning method, record the allocation, and test the whole simulation.

### 16.12.3 Monte Carlo estimates and simulation error

A **Monte Carlo method** estimates a quantity by computation on pseudorandom draws. If (X_1,\ldots,X_n) are independent draws with finite variance and the target is \(\mu=\operatorname{E}[X]\), the sample mean

\[
\hat{\mu}_n=\frac{1}{n}\sum_{i=1}^{n}X_i
\]

has standard error \(\sigma/\sqrt{n}\), where \(\sigma\) is the standard deviation of (X). Consequently, reducing Monte Carlo standard error by a factor of ten ordinarily requires roughly one hundred times as many independent draws. This square-root law distinguishes genuine precision from the visual smoothness of a large output table.

### Worked example 16.10 — Estimate an integral and its Monte Carlo error

For (U\) uniformly distributed on ([0,1]),

\[
\operatorname{E}[4/(1+U^2)]
=\int_0^1 \frac{4}{1+x^2}\,dx
=\pi.
\]

This identity turns estimation of an integral into estimation of a mean.

~~~python
from math import sqrt

import numpy as np

rng = np.random.default_rng(8_081)
n = 500_000
u = rng.random(n)
terms = 4.0 / (1.0 + u * u)

estimate = terms.mean()
monte_carlo_se = terms.std(ddof=1) / sqrt(n)
print(f"estimate={estimate:.6f}")
print(f"estimated Monte Carlo SE={monte_carlo_se:.6f}")
~~~

The estimated standard error quantifies variation from the finite random computation under the assumed independent-draw design. It does not include floating-point error, implementation defects, or error in the identity used to represent the target. Nor does agreement with the known value in one seeded run validate an arbitrary simulation.

For correlated Markov-chain samples, quasi-random sequences, importance sampling, antithetic variables, or stratified designs, the independent sample-mean formula may be wrong or wasteful. **Variance reduction** changes the estimator to obtain more information from a computational budget without changing the target. It must preserve unbiasedness or quantify any introduced bias. Diagnostics should examine convergence as computation grows, stability across independent streams, impossible states, conserved quantities, and comparison with analytically soluble special cases.

A simulation has at least three separable validity layers:

1. **model validity** asks whether the stochastic model represents the phenomenon relevant to the question;
2. **algorithmic validity** asks whether the simulation algorithm samples the declared model or an adequately characterised approximation;
3. **implementation validity** asks whether the program correctly implements the algorithm.

More samples address Monte Carlo variation only. They cannot correct a poor model, discretisation bias, an off-by-one transition, or a misinterpreted unit.

Scientific pseudorandomness is also distinct from unpredictability against an adversary. The <code>secrets</code> module obtains randomness suitable for tokens from the operating system:

~~~python
import secrets

reset_token = secrets.token_urlsafe(32)
assert len(reset_token) >= 32
~~~

No reproducible literal seed should be introduced for a password reset token. Conversely, using an opaque operating-system seed for every scientific run can make debugging and replication needlessly difficult. The purposes conflict and require different interfaces.

> **Common misconception 16.36 — “A very large simulation is automatically accurate.”**  
> Increasing the number of draws can reduce one component of sampling error. It does not remove model misspecification, biased estimators, dependence, poor stream allocation, discretisation error, numerical instability, or programming defects.
