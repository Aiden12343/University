# 16.13 Linear algebra as array structure

**Linear algebra** studies vectors, matrices, linear transformations, and related structures. A **vector** is, at this level, an ordered finite collection of numbers interpreted as one mathematical object. A **matrix** is a rectangular arrangement of numbers. Although one-dimensional and two-dimensional arrays can represent vectors and matrices, an array acquires mathematical meaning only through the surrounding contract.

For vectors \(x=(x_1,\ldots,x_n)\) and \(y=(y_1,\ldots,y_n)\), the **dot product** is

\[
x\mathbin{\cdot}y=\sum_{i=1}^{n}x_i y_i.
\]

For a matrix \(A\) with \(m\) rows and \(n\) columns and a vector \(x\) of length \(n\), the matrix-vector product produces length \(m\):

\[
(Ax)_i=\sum_{j=1}^{n}A_{ij}x_j.
\]

The inner dimensions must agree because each output combines corresponding entries of one row and the vector.

### Worked example 16.11 — Scores as a matrix-vector product

~~~python
import numpy as np

features = np.array(
    [
        [2.0, 5.0, 1.0],
        [4.0, 1.0, 3.0],
    ]
)
weights = np.array([0.5, -1.0, 2.0])

scores = features @ weights
print(scores)  # [-2.0, 7.0]
~~~

The infix operator <code>@</code> requests matrix multiplication. The first score is

\[
2(0.5)+5(-1)+1(2)=-2.
\]

The second is

\[
4(0.5)+1(-1)+3(2)=7.
\]

Elementwise multiplication would instead yield a two-by-three array. The distinction between elementwise and algebraic multiplication is semantic, not cosmetic.

A **linear transformation** preserves vector addition and scalar multiplication. Matrix multiplication composes such transformations. Numerical linear algebra must additionally consider conditioning and rounding. An **ill-conditioned** problem is one in which small input perturbations can cause large output changes. A stable implementation cannot recover information that the problem formulation makes inherently sensitive.

### 16.13.1 Arrays, vectors, matrices, and batches

Shape is syntactic metadata; mathematical role is semantic. A NumPy array with shape <code>(3,)</code> has one axis and is neither a row matrix of shape <code>(1, 3)</code> nor a column matrix of shape <code>(3, 1)</code>. Transposing a one-dimensional array therefore leaves its shape unchanged. Adding an axis makes the distinction explicit:

~~~python
import numpy as np

x = np.array([2.0, 3.0, 5.0])
row = x[np.newaxis, :]       # shape (1, 3)
column = x[:, np.newaxis]    # shape (3, 1)

assert x.T.shape == (3,)
assert row.T.shape == (3, 1)
outer = column @ row
assert outer.shape == (3, 3)
~~~

The operation <code>column @ row</code> has matching inner dimensions of one and produces an outer product. This illustrates a broader point: a line that executes is not thereby semantically justified. Shape assertions should state the intended contract directly.

A rank-three array may represent a batch of matrices, a colour image, a spatiotemporal field, or something else. NumPy’s <code>matmul</code> treats the last two axes as matrix axes and broadcasts preceding axes as batch axes. Elementwise functions treat every axis positionally. Names such as “tensor” do not settle which transformation is valid.

~~~python
import numpy as np

matrices = np.array(
    [
        [[1.0, 0.0], [0.0, 1.0]],
        [[2.0, 1.0], [1.0, 2.0]],
    ]
)
vectors = np.array([[3.0, 4.0], [5.0, 6.0]])

products = matrices @ vectors[..., np.newaxis]
assert products.shape == (2, 2, 1)
print(products[..., 0])
~~~

The first axis identifies two paired cases. Inserting the final axis represents each vector as a two-by-one matrix, avoiding reliance on special one-dimensional <code>matmul</code> rules. Domain-facing code benefits when axis meanings are documented next to shape requirements.

> **Common misconception 16.37 — “An array’s number of dimensions determines its mathematical meaning.”**  
> Dimensionality and shape constrain possible operations, but do not identify observations, features, coordinates, matrix rows, colour channels, or batch axes. Those meanings belong to the data contract.

### 16.13.2 Linear systems: solve, do not invert

A square linear system asks for (x) satisfying

\[
Ax=b.
\]

Writing (x=A^{-1}b) is mathematically legitimate when (A) is invertible, but explicitly computing an inverse is usually the wrong numerical algorithm. <code>numpy.linalg.solve</code> factors (A) and solves for (x) without materialising every entry of (A^{-1}). This generally requires less work, less storage, and a more favourable error path.

~~~python
import numpy as np

A = np.array([[3.0, 1.0], [1.0, 2.0]])
b = np.array([9.0, 8.0])

x = np.linalg.solve(A, b)
residual = b - A @ x

print(x)                         # [2. 3.]
print(np.linalg.norm(residual))  # close to zero
~~~

The **residual** (r=b-A\hat{x}) measures how nearly the computed (hat{x}) satisfies the supplied equations. A small residual is necessary but not always sufficient for a small **forward error** (|x-\hat{x}|). If (A) is ill-conditioned, widely separated solutions can produce similar right-hand sides. A residual should be scaled relative to magnitudes, for example through a normwise **backward error**:

\[
\eta =
\frac{\|b-A\hat{x}\|}
     {\|A\|\,\|\hat{x}\|+\|b\|}.
\]

A small backward error says that (hat{x}) exactly solves a nearby problem. Whether that suffices depends on the problem’s sensitivity.

For a nonsingular matrix and a compatible norm, the **condition number** is

\[
\kappa(A)=\|A\|\,\|A^{-1}\|.
\]

Roughly, it bounds how relative perturbations may be amplified. Condition numbers near one are favourable for this measure; very large values warn that input uncertainty or rounding may dominate meaningful digits. The condition number describes the problem, while **numerical stability** describes the algorithm. A stable algorithm applied to an ill-conditioned problem can return the best answer the data permit without returning many accurate digits.

~~~python
import numpy as np

well = np.array([[2.0, 0.0], [0.0, 3.0]])
nearly_singular = np.array([[1.0, 1.0], [1.0, 1.0 + 1e-12]])

print(np.linalg.cond(well))
print(np.linalg.cond(nearly_singular))
~~~

The second matrix has rows that are almost linearly dependent. Reporting a long decimal solution without its condition and input precision would imply information that the system may not contain.

> **Common misconception 16.38 — “Matrix inversion is the normal way to solve a linear system.”**  
> The inverse is a mathematical representation, not ordinarily the preferred computational method. Use a solver or factorisation matched to the matrix structure, then assess residual, conditioning, and input uncertainty.

### 16.13.3 Rank, least squares, singular values, and eigensystems

The **rank** of a matrix is the number of linearly independent directions represented by its rows or columns. If an (m\times n) design matrix has dependent columns, different coefficient vectors can encode the same fitted values. In floating-point computation, “dependent” requires a tolerance because tiny singular values may reflect either meaningful weak information or numerical noise.

When (Ax=b) has more equations than unknowns and no exact solution, **least squares** selects a coefficient vector minimising the squared residual norm:

\[
\hat{x}=\arg\min_x \|Ax-b\|_2^2.
\]

~~~python
import numpy as np

t = np.array([0.0, 1.0, 2.0, 3.0])
observed = np.array([1.1, 2.9, 5.2, 6.8])
design = np.column_stack([np.ones(t.size), t])

coefficients, residual_sums, rank, singular_values = np.linalg.lstsq(
    design,
    observed,
    rcond=None,
)
fitted = design @ coefficients

print(coefficients)      # intercept, slope
print(rank)
print(singular_values)
print(observed - fitted)
~~~

The two columns represent an intercept and a linear trend. <code>lstsq</code> also exposes estimated rank and singular values, making structural diagnosis possible. Forming the normal equations (A^TAx=A^Tb) by hand squares the condition number and is often less stable than the factorisations used by a numerical library.

The **singular value decomposition** factors an (m\times n) matrix as

\[
A=U\Sigma V^{T},
\]

where (U) and (V) have orthonormal columns under the appropriate form, and (Sigma) contains non-negative singular values. It reveals rank, dominant directions, and conditioning; it also underlies pseudoinverses, low-rank approximation, and principal-component methods. A small singular value denotes a direction in which the mapping strongly contracts information.

An **eigenvector** (v\neq0) of a square matrix (A) satisfies (Av=\lambda v), where (lambda) is its eigenvalue. Eigenvectors are not the same objects as singular vectors. General matrices can have complex eigenvalues, repeated or defective eigenspaces, and numerically delicate decompositions. Symmetric real matrices admit real eigenvalues and orthogonal eigenvectors, so algorithms such as <code>numpy.linalg.eigh</code> exploit that structure and should be preferred over a general eigensolver when its preconditions hold.

Norm choice also matters. For a vector (x),

\[
\|x\|_1=\sum_i |x_i|,
\qquad
\|x\|_2=\sqrt{\sum_i x_i^2},
\qquad
\|x\|_\infty=\max_i |x_i|.
\]

These summarise different geometries. The Frobenius norm of a matrix treats all entries as one vector; the matrix two-norm measures maximum amplification under the vector two-norm. An unqualified phrase such as “the matrix norm” is incomplete.

Linear algebra routines may call optimised BLAS or LAPACK libraries whose thread counts and floating reduction order differ between machines. Results should agree within an error contract, not necessarily bit for bit. Inputs must also be finite when the routine assumes finite values. Checking shapes, dtypes, finiteness, symmetry, definiteness, and rank expectations before fitting is part of scientific programming.

> **Common misconception 16.39 — “A tiny residual proves that the recovered parameters are accurate and meaningful.”**  
> A small residual measures agreement with the supplied equations. Ill-conditioning, non-identifiability, measurement error, model misspecification, and unit scaling can leave parameters unstable or substantively meaningless.
