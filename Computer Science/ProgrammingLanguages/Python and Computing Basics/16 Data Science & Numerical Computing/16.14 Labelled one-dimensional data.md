# 16.14 Labelled one-dimensional data

NumPy axes are primarily positional. Real tables often need labels, heterogeneous columns, missing-value conventions, and relational operations. pandas supplies these abstractions. A pandas **Series** is a one-dimensional labelled array-like object. It has values and an **index**, an ordered collection of labels used for selection and alignment.

~~~python
import pandas as pd

population = pd.Series(
    [67.6, 83.2, 59.6],
    index=["France", "Germany", "Italy"],
    name="population_millions",
)

print(population.loc["Germany"])
print(population.iloc[1])
~~~

<code>loc</code> performs label-oriented selection. <code>iloc</code> performs integer-position-oriented selection. The values happen to agree for the given index, but the questions differ. A Series with integer labels makes the distinction indispensable: label 1 need not be position 1.

Series arithmetic ordinarily aligns labels:

~~~python
import pandas as pd

left = pd.Series({"a": 10, "b": 20})
right = pd.Series({"b": 3, "c": 4})
print(left + right)
~~~

The operation matches <code>b</code> with <code>b</code>. Labels present on only one side have no counterpart and normally produce missing results. Positional NumPy addition of two length-two arrays would instead pair first with first and second with second. Alignment prevents some silent mistakes while creating another responsibility: indices must represent the intended keys and be checked for duplicates.

> **Common misconception 16.40 — “pandas arithmetic is ordinary list arithmetic with labels displayed beside it.”**  
> Labels participate in computation. Alignment can reorder, introduce missing values, or multiply rows when keys are duplicated. Inspect the index as data, not decoration.

### 16.14.1 The index is an alignment contract

An Index is an immutable sequence in the sense that its individual labels cannot be assigned in place. Immutability permits sharing and protects internal indexing structures, but it does not guarantee that labels are unique, sorted, meaningful, or permanent. Assigning an entirely new Index to an object remains possible. A <code>RangeIndex</code> compactly represents a regular integer range and is a suitable default only when rows have no domain identifier requiring explicit representation.

Index design should answer three questions:

1. Does each label identify exactly one observational unit?
2. Is label order meaningful, merely presentational, or arbitrary?
3. Should labels participate in arithmetic alignment, joins, and assignment?

If an external identifier is mutable, reused, or non-unique, making it the sole index can conceal those facts. Retaining it as an ordinary column and using a simple row index is often clearer. Conversely, a stable, verified identifier can make accidental positional combination harder.

~~~python
import pandas as pd

temperature = pd.Series(
    [18.2, 21.5, 16.9],
    index=pd.Index(["station-c", "station-a", "station-b"], name="station_id"),
    name="temperature_c",
    dtype="float64",
)

canonical = temperature.reindex(["station-a", "station-b", "station-c", "station-d"])
assert canonical.index.name == "station_id"
assert pd.isna(canonical.loc["station-d"])
~~~

<code>reindex</code> conforms an object to a requested label set and order. It is not the same as sorting: it may introduce missing rows or discard labels absent from the target. Filling introduced gaps with a constant or propagation method is a substantive transformation and must not be hidden inside routine alignment.

Duplicate labels change selection cardinality. With a unique index, selecting one label normally yields one scalar or row-like object. With duplicates, the same expression can yield multiple results; operations may form many-to-many alignments.

~~~python
import pandas as pd

measurements = pd.Series(
    [4.1, 4.4, 5.0],
    index=["A", "A", "B"],
    name="voltage",
)

selected = measurements.loc["A"]
assert isinstance(selected, pd.Series)
assert selected.size == 2
assert not measurements.index.is_unique
~~~

Duplicates are not intrinsically invalid: repeated observations of one entity are normal in longitudinal data. The error is failing to include the occasion identifier when uniqueness is required. A **MultiIndex** represents labels at multiple levels, such as <code>(device_id, observed_at)</code>. It enables hierarchical slicing and reshaping, but also increases the number of implicit alignment rules a reader must track. Ordinary columns plus an explicit composite-key validation are sometimes easier to audit.

> **Common misconception 16.41 — “A pandas index is automatically a primary key.”**  
> An Index may contain duplicates and missing-like labels, and its meaning is not inferred. A primary-key claim requires explicit uniqueness, nullability, stability, and domain validation.

### 16.14.2 Alignment is a labelled outer operation by default

Binary Series arithmetic generally forms the union of labels and aligns matching occurrences. This resembles an outer join followed by an operation. To request another missing-data rule, use an explicit method:

~~~python
import pandas as pd

planned = pd.Series({"north": 10, "south": 12}, dtype="int64")
observed = pd.Series({"south": 9, "west": 7}, dtype="int64")

ordinary = planned - observed
missing_as_zero = planned.subtract(observed, fill_value=0)

assert pd.isna(ordinary.loc["north"])
assert missing_as_zero.loc["north"] == 10
assert missing_as_zero.loc["west"] == -7
~~~

The second result says that absence on one side means a numerical zero. That may be correct for additive counts after proving complete category enumeration; it may be false for unreported measurements. <code>fill_value</code> is therefore a modelling decision expressed through an arithmetic method.

Alignment also governs assignment from a Series. Values are matched by index rather than consumed solely in visible order:

~~~python
import pandas as pd

frame = pd.DataFrame({"site": ["north", "south"]}, index=["A", "B"])
scores = pd.Series({"B": 0.8, "A": 0.3})
frame["score"] = scores

assert frame.loc["A", "score"] == 0.3
assert frame.loc["B", "score"] == 0.8
~~~

When position is genuinely intended, convert only at a deliberate boundary and assert length, for example by assigning <code>scores.to_numpy()</code>. Removing labels discards safeguards as well as overhead. A robust program should make that loss visible.

Series also has a dtype and an optional name. Its Index has its own dtype and name. These metadata can survive aggregation, concatenation, and serialisation differently. Tests should therefore verify not only displayed values but also labels, order, dtype, name, and missingness where downstream semantics depend on them.

> **Common misconception 16.42 — “If two Series have the same length, arithmetic pairs their elements by position.”**  
> pandas ordinarily pairs by labels. Equal lengths neither ensure equal label sets nor prevent duplicate-driven expansion. Assert the intended alignment or convert explicitly at a checked positional boundary.
