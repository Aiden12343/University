# 16.15 DataFrames, columns, rows, and schemas

A pandas **DataFrame** is a two-dimensional labelled table whose columns may have different dtypes. Its row index labels observations; its column index labels variables. Internally, representation details vary by version and dtype, so user code should depend on documented operations rather than a supposed “list of rows” implementation.

~~~python
from io import StringIO

import pandas as pd

csv_text = """device_id,site,latency_ms,ok
A17,north,83,true
A18,south,107,false
A19,north,91,true
"""

devices = pd.read_csv(
    StringIO(csv_text),
    dtype={
        "device_id": "string",
        "site": "string",
        "latency_ms": "int64",
        "ok": "boolean",
    },
)

print(devices.dtypes)
~~~

The explicit dtype mapping is a partial **schema**: a declaration of field names, representations, constraints, and meanings. Dtypes alone are insufficient. A complete schema can specify nullability, units, allowed categories, uniqueness, ranges, and cross-field rules. Reading text without a schema asks inference heuristics to guess from observed tokens. A later file containing an empty field, an unusual identifier, or a value outside the initial range can change the inferred dtype or fail.

The constructor does not establish that device identifiers are unique or latency values non-negative. Validation must encode those invariants:

~~~python
import pandas as pd

devices = pd.DataFrame(
    {
        "device_id": pd.Series(["A17", "A18", "A19"], dtype="string"),
        "latency_ms": pd.Series([83, 107, 91], dtype="int64"),
        "ok": pd.Series([True, False, True], dtype="boolean"),
    }
)

assert devices["device_id"].notna().all()
assert devices["device_id"].is_unique
assert devices["latency_ms"].ge(0).all()
assert devices["ok"].notna().all()
~~~

Assertions are suitable for an analysis whose failure should stop execution, but library boundaries may need explicit exception types and messages. Validation is executable specification, not clerical tidying.

### 16.15.1 Columnar representation and logical dtypes

A DataFrame presents a rectangular interface, but its columns are separate labelled arrays and need not share one physical representation. Numeric columns may use NumPy dtypes; nullable integers, strings, categoricals, time zones, and third-party arrays may use pandas **extension dtypes**. Consequently, selecting the heterogeneous table as one NumPy array can require a common dtype—often <code>object</code>—and can discard logical metadata.

~~~python
import pandas as pd

catalogue = pd.DataFrame(
    {
        "part_id": pd.Series(["P01", "P02"], dtype="string"),
        "quantity": pd.Series([4, pd.NA], dtype="Int64"),
        "active": pd.Series([True, False], dtype="boolean"),
    }
)

array = catalogue.to_numpy()
print(array.dtype)       # commonly object for this heterogeneous table
print(catalogue.dtypes)  # preserves one logical dtype per column
~~~

The capitalised nullable dtype <code>Int64</code> is not the same spelling as NumPy’s fixed-width <code>int64</code>. It represents integers together with missingness. Likewise, the pandas string dtype is not equivalent to an arbitrary Python-object column containing some strings. Library versions have changed string inference and storage defaults; code intended to span pandas 2.2 and 3.x should request required dtypes explicitly, test its supported versions, and avoid depending on the exact <code>repr</code> of dtype objects.

Categorical dtype stores values relative to a declared category set and can record whether categories are ordered. It can reduce memory for repeated labels and, more importantly, express a finite domain. It does not mean that the observed category codes are quantitative:

~~~python
import pandas as pd

priority_type = pd.CategoricalDtype(
    categories=["low", "medium", "high"],
    ordered=True,
)
priority = pd.Series(["high", "low", "medium"], dtype=priority_type)

assert priority.min() == "low"
assert list(priority.cat.categories) == ["low", "medium", "high"]
~~~

Changing category order changes comparisons and summaries. Unrecognised input may become missing when coerced to an existing categorical domain, so validation should detect it before or during conversion.

> **Common misconception 16.43 — “A DataFrame is internally a matrix, so every column shares one dtype.”**  
> The two-dimensional interface is heterogeneous and column-oriented. Conversion to one NumPy array may coerce values, allocate storage, and lose extension metadata; select homogeneous columns and state the boundary explicitly.

### 16.15.2 Parsing is a fallible transformation

A text file contains characters, not intrinsically typed integers, dates, Boolean values, or nulls. A parser applies lexical rules, locale assumptions, missing-token conventions, quoting rules, encodings, and conversion policy. The same token <code>01/02/03</code> admits multiple dates; <code>1,234</code> can denote a thousands-grouped number or a decimal under different conventions; an empty string may mean absent, deliberately blank, or malformed.

Production ingestion should therefore separate at least four layers:

- **transport validation**: the file exists, is complete, has the expected encoding and checksum, and belongs to the expected delivery;
- **syntactic parsing**: records and fields satisfy a declared serialization grammar;
- **representation validation**: tokens can be converted into required dtypes without silent loss;
- **semantic validation**: keys, units, ranges, dependencies, and population rules hold.

~~~python
from io import StringIO

import pandas as pd

source = StringIO(
    "device_id,observed_at,latency_ms,status\n"
    "A17,2026-09-01T10:30:00Z,83,ok\n"
    "A18,2026-09-01T10:31:00Z,NA,offline\n"
)

frame = pd.read_csv(
    source,
    usecols=["device_id", "observed_at", "latency_ms", "status"],
    dtype={"device_id": "string", "status": "string"},
    na_values={"latency_ms": ["NA"]},
    keep_default_na=False,
)
frame["observed_at"] = pd.to_datetime(
    frame["observed_at"],
    utc=True,
    errors="raise",
)
frame["latency_ms"] = pd.to_numeric(
    frame["latency_ms"],
    errors="raise",
).astype("Int64")
~~~

<code>keep_default_na=False</code> prevents pandas’ broad default token set from silently treating strings such as particular abbreviations as missing; the application supplies a column-specific rule instead. This is not universally preferable—rather, it demonstrates that null recognition is part of the schema. <code>errors="raise"</code> stops at invalid syntax instead of converting it to missing and erasing the distinction between “not observed” and “could not parse”. For very large inputs, chunking controls memory but adds a global-invariant problem: uniqueness and cross-row validation must span chunks, not restart for each one.

Schema validation should produce informative failures rather than a cascade of bare assertions. A small boundary function can concentrate rules:

~~~python
import pandas as pd


def validate_device_frame(frame: pd.DataFrame) -> None:
    required = {"device_id", "observed_at", "latency_ms", "status"}
    missing_columns = required.difference(frame.columns)
    if missing_columns:
        raise ValueError(f"missing columns: {sorted(missing_columns)}")
    if frame["device_id"].isna().any():
        raise ValueError("device_id must not be missing")
    if frame.duplicated(["device_id", "observed_at"]).any():
        raise ValueError("(device_id, observed_at) must be unique")
    if frame["latency_ms"].dropna().lt(0).any():
        raise ValueError("latency_ms must be non-negative")
    allowed = {"ok", "offline", "degraded"}
    unexpected = set(frame["status"].dropna()).difference(allowed)
    if unexpected:
        raise ValueError(f"unexpected statuses: {sorted(unexpected)}")
~~~

This function still lacks unit verification, time bounds, dtype checks, and the rule connecting offline status to missing latency. A mature data contract reports several failures with row provenance rather than forcing one repair-and-rerun cycle per field.

> **Common misconception 16.44 — “Once a CSV loads without an exception, it has become valid data.”**  
> Successful parsing proves only that some parser interpretation succeeded. It does not establish identifier integrity, units, permissible values, population membership, temporal consistency, or fitness for an estimand.

### 16.15.3 Copy-on-write and interoperability boundaries

pandas has moved to a **copy-on-write** model, enabled by default in pandas 3.0, in which objects derived from another behave as logical copies and physical data may remain shared until a mutation requires separation. The design removes many user-visible ambiguities of view-versus-copy mutation, but it does not make memory irrelevant. A selection can share storage transiently; mutation can then allocate unexpectedly. Programs supporting older versions must account for their documented behaviour or pin a minimum version.

Methods such as <code>copy(deep=True)</code> copy pandas-managed data buffers but do not recursively clone arbitrary Python objects stored inside object-dtype cells. Likewise, <code>to_numpy(copy=False)</code> is a request to avoid an unnecessary copy, not a promise that none will occur. Heterogeneous dtype coercion, extension arrays, memory layout, and safety rules can force allocation.

At a library boundary, write down what survives:

| Property | DataFrame | Typical NumPy conversion |
|---|---|---|
| row labels | retained | discarded unless exported separately |
| column labels | retained | discarded unless exported separately |
| heterogeneous dtypes | retained by column | coerced to a common representation |
| nullable extension semantics | retained | may become object, sentinel, or mask |
| time-zone dtype | retained | may require conversion or object values |
| physical-copy guarantee | operation-dependent | operation- and dtype-dependent |

When a numerical routine expects a dense, finite matrix, make the conversion an audited operation:

~~~python
import numpy as np
import pandas as pd

features = pd.DataFrame(
    {"temperature_c": [18.5, 20.1], "pressure_kpa": [101.2, 100.9]},
    index=["case-a", "case-b"],
)

matrix = features.to_numpy(dtype=np.float64, copy=True)
if not np.isfinite(matrix).all():
    raise ValueError("numerical features must be finite")
assert matrix.shape == (2, 2)
~~~

The explicit copy gives the numerical component independent writable storage; labels are deliberately left behind after their order and shape have been checked. The caller should retain a mapping from output rows to case identifiers.

> **Common misconception 16.45 — “Calling copy, selecting columns, or converting to NumPy has one timeless memory behaviour.”**  
> Copying and sharing depend on pandas version, dtype, operation, and requested guarantees. Program against documented semantics, isolate interoperability boundaries, and measure memory when it is operationally material.
