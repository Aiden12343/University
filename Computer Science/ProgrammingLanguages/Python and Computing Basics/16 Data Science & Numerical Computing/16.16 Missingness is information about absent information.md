# 16.16 Missingness is information about absent information

A **missing value** records that a field lacks an ordinary observed value under a convention. Missingness has several causes:

- the value exists but was not measured;
- the value is inapplicable;
- collection failed;
- a respondent declined;
- a join found no matching record;
- a parser could not interpret a token;
- a privacy rule suppressed the value.

Collapsing these causes into one marker can destroy information. A schema may need a value column plus a reason column.

pandas supports several missing sentinels depending on dtype, including <code>NaN</code>, <code>NaT</code>, <code>None</code>, and <code>pd.NA</code>. Their equality, truth testing, and propagation rules differ. Use documented predicates such as <code>isna</code>, not equality with a sentinel.

~~~python
import pandas as pd

records = pd.DataFrame(
    {
        "reading": pd.Series([12.5, pd.NA, 9.0], dtype="Float64"),
        "missing_reason": pd.Series(
            [pd.NA, "sensor_offline", pd.NA],
            dtype="string",
        ),
    }
)

print(records["reading"].isna())
print(records["reading"].mean(skipna=True))
~~~

The mean excludes the missing record because <code>skipna=True</code>. That is a calculation rule, not a justification. If sensors fail more often under extreme conditions, observed readings are systematically selected and the mean of available values can be biased.

Statistical literature distinguishes:

- **missing completely at random**: missingness is independent of observed and unobserved relevant values under the model;
- **missing at random**: after conditioning on observed variables, missingness does not depend on the missing value;
- **missing not at random**: dependence remains on unobserved value or unmodelled causes.

These are assumptions about a data-generating process, not labels a library can infer from a null marker. Deleting rows, filling with a mean, forward-filling, or modelling missingness changes the estimand and uncertainty. Each requires a domain and statistical argument.

### 16.16.1 Sentinels, masks, and three-valued logic

IEEE floating-point <code>NaN</code> was designed to represent undefined or unavailable numerical results within a floating format. Python’s <code>None</code> is a general singleton. <code>NaT</code> serves date-time-like missingness. <code>pd.NA</code> is a scalar intended to support missingness across nullable extension dtypes. They can all appear “missing” to <code>pandas.isna</code>, yet their propagation, equality, hashing, truth conversion, and coercion are not interchangeable.

Nullable Boolean operations use a form of **Kleene three-valued logic**. Besides true and false, a proposition may be unknown. Some results can nevertheless be determined: false AND unknown is false, while true AND unknown remains unknown; true OR unknown is true, while false OR unknown remains unknown.

~~~python
import pandas as pd

unknown = pd.Series([pd.NA], dtype="boolean")
assert (False & unknown).iloc[0] == False
assert pd.isna((True & unknown).iloc[0])
assert (True | unknown).iloc[0] == True
assert pd.isna((False | unknown).iloc[0])
~~~

An unknown value has no single Boolean truth, so <code>bool(pd.NA)</code> raises rather than choosing a branch. Comparisons commonly propagate unknown:

~~~python
import pandas as pd

value = pd.NA
assert pd.isna(value == 7)
assert pd.isna(value == pd.NA)
assert pd.isna(value)
~~~

The last predicate is the proper missingness test. The second comparison does not mean “both are the same missing sentinel”; it asks whether two unknown substantive values are equal, which is unknown. In contrast, IEEE NaN is unequal to itself under ordinary equality. Code that mixes these conventions and then calls <code>bool</code> can fail or silently select rows differently after dtype conversion.

Reductions require an explicit policy. With <code>skipna=True</code>, a sum or mean ignores missing entries. For sum-like operations, an all-missing group may otherwise resemble a structural zero unless <code>min_count</code> is used:

~~~python
import pandas as pd

values = pd.Series([pd.NA, pd.NA], dtype="Float64")

default_sum = values.sum()
guarded_sum = values.sum(min_count=1)
assert default_sum == 0.0
assert pd.isna(guarded_sum)
~~~

Zero observed total and no observed values answer different questions. Similar distinctions arise between an empty group, an all-missing group, and a group whose observed values sum to zero.

> **Common misconception 16.46 — “All missing-value markers behave like one universal null.”**  
> NaN, NaT, None, and pd.NA inhabit different type systems and propagation rules. Use dtype-aware operations and <code>isna</code>; test equality, Boolean filtering, reductions, grouping, and serialisation at boundaries.

### 16.16.2 Mechanisms, selection, and identifiability

Let (Y) be a variable that may be missing and (R) an indicator equal to one when (Y) is observed. “Missing completely at random” is approximately a statement that (R) is independent of both observed and missing relevant data. “Missing at random” permits observation probability to depend on recorded variables (X), but not additionally on unobserved (Y) after conditioning on (X). “Missing not at random” permits residual dependence on the unobserved value or an omitted cause.

These definitions are model-relative. Adding an explanatory variable can make a missing-at-random assumption more plausible, but no pattern of null markers alone establishes the mechanism. Moreover, a mechanism may differ by field and subpopulation: an automated sensor outage, an optional survey question, and administrative censoring need separate models.

**Complete-case analysis** discards any unit missing a required value. It changes both sample size and population composition. Under strong conditions it can estimate some associations without bias, but it is not a neutral cleanup operation. **Available-case analysis** lets each calculation use its own observed subset, which can produce a covariance matrix whose entries refer to different populations and which need not have valid matrix properties.

**Single imputation** fills one value per gap. Mean imputation preserves neither distributional spread nor relationships and treats estimates as observations, generally understating uncertainty. Forward fill asserts that the previous observed state remains applicable; interpolation asserts a trajectory between observations; filling zero asserts a real zero. Each is a model.

**Multiple imputation** creates several completed datasets by drawing plausible values under an imputation model, performs the analysis on each, and combines within- and between-imputation uncertainty. It is not merely repeating mean fill with several seeds. The imputation model should include variables and structures needed by the analysis, and its assumptions remain contestable.

A **missingness indicator** records whether a value was absent. It can preserve predictive information, but in a causal or policy analysis it can also encode site practices, access barriers, or future information. Whether an indicator is available at prediction time must be checked. Inapplicable values deserve a structural representation separate from unknown values; for example, pregnancy count may be inapplicable rather than unrecorded for part of a population.

> **Common misconception 16.47 — “Dropping missing rows is conservative because it invents no values.”**  
> Deletion selects a different realised sample and can alter the estimand. It may introduce more bias than a justified model, while still understating uncertainty through reduced and non-representative data.

### 16.16.3 Diagnose and report missingness before treating it

A missing-data report should count absence by variable, unit, time, source, and relevant groups; inspect co-occurrence patterns; distinguish reasons; and compare observed characteristics of units with and without a field. Such comparisons cannot reveal unobserved values, but they can refute simplistic assumptions and expose pipeline defects.

~~~python
import pandas as pd

observations = pd.DataFrame(
    {
        "site": ["north", "north", "south", "south"],
        "reading": pd.Series([3.2, pd.NA, pd.NA, 8.1], dtype="Float64"),
        "quality": pd.Series(["good", "offline", "offline", "good"], dtype="string"),
    }
)

report = (
    observations.assign(reading_missing=observations["reading"].isna())
    .groupby("site", dropna=False, observed=False)
    .agg(
        rows=("site", "size"),
        missing_readings=("reading_missing", "sum"),
    )
)
report["missing_fraction"] = report["missing_readings"] / report["rows"]
print(report)
~~~

The table describes observed missingness, not its causal mechanism. Counts should accompany fractions: one missing value out of two and five hundred out of one thousand have the same fraction but different information. A sudden time-localised increase may identify an ingestion failure; a stable group disparity may identify access or collection differences.

Treatment should be evaluated by **sensitivity analysis**: repeat the substantive analysis under plausible alternative assumptions and determine which conclusions depend on unverifiable choices. For example, bounds can assign missing outcomes to best- and worst-case categories; a pattern-mixture model can shift imputed values; an attrition-weighted analysis can vary observation probabilities. A conclusion robust across a credible range is stronger than one resting on a single automatic fill.

Never overwrite raw fields with imputed values without provenance. Preserve at least the original column, an observation/imputation indicator, method and model version, and—where multiple imputation is used—the imputation identity. Rounded presentation should not obscure that downstream variance must include imputation uncertainty.

> **Common misconception 16.48 — “A sophisticated imputation algorithm recovers the values that were really missing.”**  
> Imputation generates analytically useful plausible values under assumptions; it does not observe the counterfactual records. Uncertainty and sensitivity to those assumptions remain part of the result.
