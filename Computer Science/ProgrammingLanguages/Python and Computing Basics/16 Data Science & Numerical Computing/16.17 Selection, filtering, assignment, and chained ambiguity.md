# 16.17 Selection, filtering, assignment, and chained ambiguity

A Boolean Series can select rows:

~~~python
import pandas as pd

devices = pd.DataFrame(
    {
        "device_id": ["A17", "A18", "A19"],
        "site": ["north", "south", "north"],
        "latency_ms": [83, 107, 91],
    }
)

slow_north = devices.loc[
    (devices["site"] == "north") & (devices["latency_ms"] >= 90),
    ["device_id", "latency_ms"],
]
~~~

Parentheses are required because comparison and bitwise operator precedence do not express the intended grouping without them. The operators <code>&</code>, <code>|</code>, and <code>~</code> perform elementwise Boolean combination. Python’s scalar <code>and</code>, <code>or</code>, and <code>not</code> ask for one truth value and are inappropriate for a many-element mask.

Assignment should make selection and target explicit:

~~~python
import pandas as pd

devices = pd.DataFrame(
    {
        "device_id": ["A17", "A18", "A19"],
        "site": ["north", "south", "north"],
        "latency_ms": [83, 107, 91],
    }
)

devices.loc[devices["latency_ms"] >= 100, "latency_band"] = "high"
devices.loc[devices["latency_ms"] < 100, "latency_band"] = "ordinary"
~~~

Historically, chained expressions such as <code>frame[mask]["column"] = value</code> have been unreliable because an intermediate object may be a view-like or copied object. pandas’ copy-on-write evolution changes details, but the sound principle remains: use one documented indexing operation to identify the rows and column being assigned, and test under the supported pandas version.

### 16.17.1 Selection has an indexer, an axis, and a result shape

The bracket operator is overloaded: <code>frame["column"]</code> selects a column, a list selects multiple columns, and a Boolean object can filter rows. Explicit <code>loc</code> and <code>iloc</code> make two-axis intent clearer. Label slices through <code>loc</code> ordinarily include both endpoints when present, unlike half-open Python positional slices. Integer labels make this contrast especially dangerous.

~~~python
import pandas as pd

frame = pd.DataFrame(
    {"value": [10, 20, 30, 40]},
    index=pd.Index([2, 4, 6, 8], name="record_id"),
)

by_label = frame.loc[2:6, "value"]
by_position = frame.iloc[0:2, 0]

assert by_label.tolist() == [10, 20, 30]
assert by_position.tolist() == [10, 20]
~~~

A scalar selector can reduce dimensionality: one row and one column can return a scalar, one column can return a Series, and a list of one column returns a DataFrame. Downstream code should request and assert the required dimensionality rather than infer it from sample output. <code>at</code> and <code>iat</code> are scalar-oriented accessors; they do not change the distinction between labels and positions.

Boolean Series filtering aligns by label. This is protective when the mask was derived from the same frame, but a stale or independently reordered mask can raise or answer another question. A NumPy Boolean array instead acts positionally.

~~~python
import pandas as pd

frame = pd.DataFrame({"value": [5, 7, 9]}, index=["a", "b", "c"])
mask = pd.Series([True, False, True], index=["c", "b", "a"])

selected = frame.loc[mask]
assert selected.index.tolist() == ["a", "c"]
~~~

The visible Boolean order was <code>c, b, a</code>, but selection retained frame order after matching labels. Before accepting an external mask, assert that its index is unique and equal to the target index, or reindex it under an explicit missing-label policy.

<code>query</code> provides an expression language convenient for readable filters, while callable indexers can defer a selection until a method chain reaches the relevant object. Both are tools, not different semantics. External values interpolated into a query should use the documented variable mechanism and must not be confused with safe SQL parameterisation or arbitrary Python evaluation.

> **Common misconception 16.49 — “loc and iloc differ only in spelling.”**  
> <code>loc</code> interprets labels and aligns Boolean Series; <code>iloc</code> interprets integer positions. Their slice endpoints and accepted selectors differ. Integer-labelled indices make accidental substitution particularly deceptive.

### 16.17.2 Assignment, ownership, and atomic intent

An assignment has a target set, a source, an alignment rule, a dtype consequence, and an ownership consequence. Expressing the target in one indexing operation makes these reviewable:

~~~python
import pandas as pd

frame = pd.DataFrame(
    {"status": ["new", "new", "new"], "score": [0.2, 0.8, 0.6]},
    index=["x", "y", "z"],
)

target = frame["score"].ge(0.6)
frame.loc[target, "status"] = "review"

assert frame.loc["x", "status"] == "new"
assert frame.loc[["y", "z"], "status"].eq("review").all()
~~~

In pandas 3.0’s default copy-on-write semantics, chained assignment cannot update the original object through a temporary selection and is treated as invalid usage. This gives a firmer model than historical heuristics, but the single-operation form remains the portable and auditable expression. A method returning a new frame must be assigned or chained; assuming that it mutates its receiver loses changes.

Assigning a Series aligns its index. Assigning an array-like generally follows position. Scalar assignment broadcasts. These are distinct contracts:

~~~python
import pandas as pd

frame = pd.DataFrame(index=["a", "b", "c"])
frame["aligned"] = pd.Series({"c": 30, "a": 10, "b": 20})
frame["positional"] = [30, 10, 20]
frame["constant"] = 1

assert frame.loc["a"].to_dict() == {
    "aligned": 10,
    "positional": 30,
    "constant": 1,
}
~~~

An incompatible value can cause dtype promotion, raise, or—under evolving library rules—emit a warning before future rejection. Do not rely on silently placing text into a numeric column. Create or cast the destination to its intended dtype, then validate. Assignment involving duplicate labels deserves special testing because one-to-many alignment can occur.

Many apparent mutation problems are better expressed functionally: use <code>assign</code>, <code>where</code>, <code>mask</code>, or a method chain to construct a result, then bind that result to a new name. Functional style does not eliminate memory sharing, but it makes dataflow clearer. In performance-critical work, profile before replacing clarity with fragile in-place operations.

> **Common misconception 16.50 — “If an assignment emits no warning, it must have changed the intended DataFrame.”**  
> Warnings are version-dependent diagnostics, not a proof system. Use a single explicit target operation, retain the returned object where required, and test values, dtypes, labels, and untouched rows.
