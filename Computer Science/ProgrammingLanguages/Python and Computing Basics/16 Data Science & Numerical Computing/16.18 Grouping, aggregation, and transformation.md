# 16.18 Grouping, aggregation, and transformation

The **split–apply–combine** pattern partitions observations into groups, applies a function within each group, and combines group results. In pandas, <code>groupby</code> constructs a grouped operation object; an aggregation then reduces each group.

~~~python
import pandas as pd

devices = pd.DataFrame(
    {
        "device_id": ["A17", "A18", "A19"],
        "site": ["north", "south", "north"],
        "latency_ms": [83, 107, 91],
        "ok": [True, False, True],
    }
)

summary = (
    devices.groupby("site", as_index=False)
    .agg(
        observations=("device_id", "size"),
        mean_latency_ms=("latency_ms", "mean"),
        successful=("ok", "sum"),
    )
    .sort_values("mean_latency_ms", ascending=False)
)

print(summary)
~~~

The named aggregations state input column and operation. <code>size</code> counts rows, including rows whose other fields are missing. <code>count</code> ordinarily counts non-missing values in the selected column. <code>sum</code> over Boolean values counts true values under their numeric interpretation, provided missingness and dtype rules match the contract.

An **aggregation** returns fewer rows per group, commonly one. A **transformation** returns a result aligned to each original row:

~~~python
import pandas as pd

devices = pd.DataFrame(
    {
        "site": ["north", "south", "north"],
        "latency_ms": [83, 107, 91],
    }
)

devices["site_mean_latency"] = (
    devices.groupby("site")["latency_ms"].transform("mean")
)
devices["latency_above_site_mean"] = (
    devices["latency_ms"] - devices["site_mean_latency"]
)
~~~

The group mean repeats for every member so subtraction aligns by row index. This is useful but can leak information in machine-learning validation if group statistics are computed before separating training and evaluation data. Branch B formalises that failure.

Group operations have semantic edge cases: whether missing keys form a group, whether categorical combinations absent from the data appear, whether group order is sorted, and how empty groups behave. Reproducible work sets relevant options and tests boundary cases.

### 16.18.1 Specify the partition before the calculation

A grouping key induces an equivalence relation: rows belong to the same group when their key tuples compare as the grouping rules require. Multiple keys define intersections, not separate summaries. Before calling <code>groupby</code>, state whether missing keys are excluded, whether categorical levels absent from the observations should appear, and whether output order carries meaning.

~~~python
import pandas as pd

events = pd.DataFrame(
    {
        "region": pd.Categorical(
            ["north", "north", "south", None],
            categories=["north", "south", "west"],
        ),
        "status": ["ok", "failed", "ok", "ok"],
        "latency_ms": [80.0, 120.0, 95.0, 88.0],
    }
)

summary = (
    events.groupby(
        "region",
        dropna=False,
        observed=False,
        sort=True,
    )
    .agg(rows=("status", "size"), mean_latency=("latency_ms", "mean"))
)
print(summary)
~~~

<code>dropna=False</code> requests a group for a missing key. <code>observed=False</code> permits the unobserved categorical level <code>west</code> to appear. These options have had changing defaults or deprecation paths across pandas releases; production code should state behaviour it relies upon and test against supported versions. Empty categorical groups can produce identities or missing values depending on the reduction, so zero rows must not be confused with zero events of a measured kind.

Counting operations answer different questions:

- <code>size</code> counts rows in the group;
- <code>count</code> counts non-missing values for each selected column;
- <code>nunique(dropna=...)</code> counts distinct values under a missingness policy;
- summing a Boolean predicate counts true results only if missing Boolean values are treated deliberately.

Named aggregation supplies stable output names and makes heterogeneous rules inspectable. A custom callable receives a Series and must declare what it does with empty input, missing values, dtype, and ordering. If units differ between columns, a compact aggregation dictionary can disguise invalid combinations.

> **Common misconception 16.51 — “groupby simply splits visible rows by equal text.”**  
> Group formation depends on key dtype, missing-key policy, categorical levels, multiple-key tuples, ordering options, and sometimes time-bin rules. The partition is part of the estimand and must be specified.

### 16.18.2 Aggregation, transformation, filtering, and general application

Grouped operations have contracts distinguished by result cardinality:

- **aggregation** maps each group to one or a fixed small number of summary values;
- **transformation** returns a value aligned to every original row;
- **filtering** retains or removes whole groups according to a group-level predicate;
- general **application** permits arbitrary results but gives pandas less structural information and often entails more overhead.

Choose the narrowest contract that expresses the operation. Built-in vectorised aggregations usually communicate intent and outperform a Python function invoked once per group.

~~~python
import pandas as pd

sales = pd.DataFrame(
    {
        "store": ["A", "A", "B", "B", "B"],
        "amount": [10.0, 14.0, 5.0, 8.0, 11.0],
    }
)

grouped = sales.groupby("store")["amount"]
sales["store_mean"] = grouped.transform("mean")
sales["centred"] = sales["amount"] - sales["store_mean"]
large_stores = sales.groupby("store").filter(lambda group: len(group) >= 3)

assert sales.groupby("store")["centred"].sum().abs().lt(1e-12).all()
assert large_stores["store"].unique().tolist() == ["B"]
~~~

The near-zero assertion tolerates floating representation. The filtering lambda sees an entire DataFrame group and returns one Boolean. It does not filter individual rows by amount. A group-wise Python <code>apply</code> can emulate many operations, but output-index rules, inclusion of grouping columns, and performance have evolved; use it only when aggregation, transformation, or vectorised methods cannot state the calculation.

Group order is not a substitute for time order. Operations such as <code>shift</code>, <code>diff</code>, and cumulative sums use row order within each group. Sort by the declared sequence key and verify uniqueness before applying them:

~~~python
import pandas as pd

readings = pd.DataFrame(
    {
        "device": ["A", "B", "A", "B"],
        "time": pd.to_datetime(
            ["2026-01-02", "2026-01-01", "2026-01-01", "2026-01-02"],
            utc=True,
        ),
        "value": [12.0, 20.0, 10.0, 25.0],
    }
).sort_values(["device", "time"])

readings["change"] = readings.groupby("device")["value"].diff()
~~~

The first row in each device has no predecessor and therefore a missing change. Filling it with zero would assert “no change”, not “change unavailable”.

### 16.18.3 Windows are groups with ordered, overlapping membership

A **rolling window** computes over a moving set of neighbouring observations. A count window such as <code>rolling(3)</code> includes three rows under the specified alignment. A time-offset window such as <code>rolling("3h")</code> includes observations whose timestamps fall inside an interval. These are equivalent only for perfectly regular sampling at a matching frequency.

An **expanding window** begins at an origin and grows through the ordered data. An **exponentially weighted** calculation discounts older values according to a parameterisation such as span, centre of mass, half-life, or smoothing factor. These parameterisations relate mathematically but should not be mixed casually.

~~~python
import pandas as pd

series = pd.Series(
    [2.0, 4.0, 8.0, 16.0],
    index=pd.to_datetime(
        ["2026-01-01 00:00", "2026-01-01 01:00",
         "2026-01-01 04:00", "2026-01-01 05:00"],
        utc=True,
    ),
)

by_rows = series.rolling(window=2, min_periods=1).mean()
by_time = series.rolling(window="2h", min_periods=1, closed="both").mean()

print(pd.DataFrame({"two_rows": by_rows, "two_hours": by_time}))
~~~

At 04:00, the previous row occurred three hours earlier. The row-count window includes it; the two-hour time window does not. Parameters such as <code>closed</code>, <code>center</code>, and <code>min_periods</code> alter boundary inclusion, labelling, and missing output. In predictive work, a centred window or backward fill can use future observations and cause temporal leakage.

> **Common misconception 16.52 — “A rolling mean is defined once its window size is given.”**  
> One must also specify row-count versus duration membership, ordering, endpoint closure, label alignment, minimum observations, grouping boundaries, missingness, and whether future values are permitted.
