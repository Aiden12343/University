# 16.26 The end-to-end analytical contract

A defensible analysis is a pipeline of contracts:

1. **Question:** state population, estimand, decision, and relevant time.
2. **Provenance:** identify sources, collection procedures, licences, and revisions.
3. **Ingestion:** preserve raw input immutably and record a checksum.
4. **Schema validation:** verify fields, types, units, keys, ranges, and missingness.
5. **Transformation:** make each derivation deterministic, named, and tested.
6. **Exploration:** distinguish hypothesis generation from confirmation.
7. **Modelling:** state assumptions, fit procedure, and uncertainty method.
8. **Verification:** test code, reconcile counts, inspect residuals or failure slices, and reproduce from a clean environment.
9. **Communication:** report magnitude, uncertainty, exclusions, and limitations.
10. **Archival:** retain code, metadata, environment lock, and exact input version as permitted.

### Worked example 16.16 — A small validated analysis module

~~~python
from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path

import pandas as pd


@dataclass(frozen=True)
class LatencySummary:
    observations: int
    mean_ms: float
    median_ms: float


def load_latencies(path: Path) -> pd.DataFrame:
    frame = pd.read_csv(
        path,
        dtype={
            "request_id": "string",
            "latency_ms": "Float64",
        },
    )
    required = {"request_id", "latency_ms"}
    missing_columns = required.difference(frame.columns)
    if missing_columns:
        raise ValueError(
            f"missing required columns: {sorted(missing_columns)}"
        )
    if frame["request_id"].isna().any():
        raise ValueError("request_id contains missing values")
    if not frame["request_id"].is_unique:
        raise ValueError("request_id must be unique")
    if frame["latency_ms"].isna().any():
        raise ValueError("latency_ms contains missing values")
    if frame["latency_ms"].lt(0).any():
        raise ValueError("latency_ms must be non-negative")
    return frame


def summarise_latencies(frame: pd.DataFrame) -> LatencySummary:
    values = frame["latency_ms"]
    return LatencySummary(
        observations=len(values),
        mean_ms=float(values.mean()),
        median_ms=float(values.median()),
    )
~~~

The loader is not merely a call to <code>read_csv</code>. It establishes a boundary at which malformed input becomes an explicit exception. The immutable dataclass names the summary fields. The conversion to Python <code>float</code> chooses an outward scalar representation. Tests must cover absent columns, duplicate identifiers, missing and negative latencies, empty input, malformed text, and valid input. The specification must decide whether empty input is invalid; the code as written permits it until summary calculations produce missing results, so an empty-frame check is an identified requirement rather than a hidden accident.

### 16.26.1 Contracts between analytical stages

Each pipeline stage should have explicit preconditions, postconditions, and provenance. A **precondition** is an obligation the caller must satisfy; a **postcondition** is an obligation the stage guarantees if its preconditions hold. A **data contract** combines structural rules with semantic definitions, ownership, allowed evolution, and response to violation.

For example, an ingestion stage may accept UTF-8 CSV conforming to a versioned external schema and guarantee a canonical table with UTC timestamps, unique composite keys, SI units, nullable extension dtypes, and a rejection report. A modelling stage should consume only that canonical contract, not rediscover parser assumptions.

Silent coercion weakens a boundary. If malformed numerical tokens become nulls, a later missing-value policy cannot distinguish collection absence from parse failure. If unknown categorical values become “other”, a vocabulary break may pass unnoticed. Quarantine invalid records with reason codes and source locations when operations permit recovery; otherwise fail the batch atomically.

Contracts evolve. Adding an optional column can be backward-compatible; renaming a field, changing units, redefining a status, or relaxing uniqueness can break consumers even if a parser still runs. Semantic versioning of data schemas is useful only when compatibility meanings are documented and tested against real consumers.

### 16.26.2 Reconciliation and analytical invariants

An **invariant** is a property intended to remain true across a transformation. Counts, totals, key sets, units, and temporal bounds often provide inexpensive high-value checks. The appropriate invariant depends on the operation:

| Transformation | Candidate checks |
|---|---|
| filter | output keys are a subset; exclusions have reason counts; output rows plus rejected rows reconcile to input |
| unit conversion | keys and missingness unchanged; inverse conversion agrees within tolerance; dimensional units change as declared |
| many-to-one enrichment | left row count and key multiplicity preserved; unmatched count reported |
| deduplication | removed rows grouped by duplicate rule; chosen survivor deterministic; measure changes reconciled |
| aggregation | group totals reconcile with overall total under identical missing policy |
| reshape | key/value pairs preserved when invertibility is claimed |
| sampling | frame, inclusion probabilities, seed strategy, and realised sample identifiers retained |

Assertions about total rows alone are insufficient. A transformation can drop one row and duplicate another. Compare key multisets or keyed hashes where identity matters. Aggregate reconciliation must avoid cancelling positive and negative errors; compare group-level differences as well as grand totals.

~~~python
import pandas as pd


def enrich_orders(
    orders: pd.DataFrame,
    customers: pd.DataFrame,
) -> pd.DataFrame:
    required_orders = {"order_id", "customer_id", "amount"}
    required_customers = {"customer_id", "segment"}
    if not required_orders.issubset(orders.columns):
        raise ValueError("orders schema is incomplete")
    if not required_customers.issubset(customers.columns):
        raise ValueError("customers schema is incomplete")
    if not orders["order_id"].is_unique:
        raise ValueError("order_id must be unique")
    if customers["customer_id"].isna().any():
        raise ValueError("customer key must not be missing")

    result = orders.merge(
        customers[["customer_id", "segment"]],
        on="customer_id",
        how="left",
        validate="many_to_one",
        indicator=True,
    )
    if len(result) != len(orders):
        raise AssertionError("enrichment changed order cardinality")
    if not result["_merge"].eq("both").all():
        missing = result.loc[result["_merge"].ne("both"), "customer_id"]
        raise ValueError(f"unmatched customer keys: {missing.unique().tolist()}")
    return result.drop(columns="_merge")
~~~

The function makes failures local to the join. In a production interface, input frames might be copied or treated as read-only by convention, and exact dtype/unit contracts would be checked. Tests should include empty-but-valid tables, missing columns, null keys, duplicate right keys, unmatched keys, zero and negative amounts according to domain, and preserved row order only if order is promised.

### 16.26.3 Separate computation from publication

An analysis benefits from three output layers:

1. **machine-readable results** retain full numerical precision, keys, units, and schema;
2. **diagnostic artefacts** retain exclusions, residuals, validation summaries, warnings, and intermediate checks;
3. **publication artefacts** apply rounding, labels, ordering, captions, and visual design for readers.

Rounding should occur only in the publication layer. If a displayed percentage is 100%, the machine output may reveal 99.6%; if rounded categories are reused for calculation, errors accumulate. A table should state denominators and missingness rather than forcing readers to infer them from percentages.

A **manifest** records an execution: analysis identifier, code revision, input identifiers and cryptographic hashes, schema versions, parameters, environment identity, start/end times, random-stream strategy, and output hashes. A cryptographic hash identifies bytes with extremely high collision resistance; it does not establish that the bytes are correct, ethical, or legally usable. Remote data referenced by a mutable URL require an archived version or provider snapshot identifier where permitted.

Review should be possible without rerunning everything. Store validation summaries and small canonical test fixtures. For regulated, safety-critical, or high-impact work, independent code review, analysis reproduction, access controls, and sign-off records may be required. Privacy constrains what can be archived: reproducibility does not authorise copying personal or licensed data. Synthetic fixtures and controlled access can preserve verification while respecting governance.

### 16.26.4 Test the analytical claim, not only helper functions

Unit tests can verify parsers and transformations; integration tests exercise connected stages; regression tests detect unintended output changes; property-based tests generate many inputs satisfying or violating invariants; metamorphic tests check relations when an exact answer is unavailable. Examples include:

- permuting rows should not change an order-insensitive aggregate;
- converting metres to centimetres should multiply finite values by 100 while preserving missingness and keys;
- duplicating every observation should preserve an unweighted mean but double a count;
- splitting a dataset into chunks and combining sufficient statistics should reproduce the full-pass result within an error budget;
- serialising and reading a canonical table should preserve its declared schema and values.

Tests must include adversarial and degenerate cases: zero rows, one row, all missing, all equal, extreme magnitudes, duplicate keys, invalid Unicode, boundary timestamps, DST transitions, unknown categories, infinities, and values just inside and outside permitted ranges. A golden output copied from the same buggy implementation merely freezes the bug; derive expectations analytically or through an independent method where possible.

> **Common misconception 16.71 — “A reproducible notebook with passing unit tests makes an analysis correct.”**  
> Reproducibility and software tests expose and constrain implementation. They do not establish measurement validity, representativeness, causal identification, model adequacy, ethical legitimacy, or whether the declared estimand answers the decision.
