# 16.8 Views, copies, and aliasing

A **view** is an array object whose logical elements refer to storage also reachable through another array. A **copy** owns or refers to independently duplicated element storage. This distinction is Chapter 5’s aliasing model applied to array buffers rather than ordinary container references.

Basic slicing ordinarily produces views where possible. Advanced indexing—such as selecting with an integer array or Boolean mask—ordinarily produces copies. The precise categories are part of NumPy’s documented indexing model and must be learned because accidental sharing corrupts state while accidental copying wastes time and memory.

### Worked example 16.7 — Mutation through a view

~~~python
import numpy as np

source = np.array([10, 20, 30, 40, 50])
window = source[1:4]       # basic slice: ordinarily a view
window[0] = 999

selected = source[[1, 3]]  # advanced integer indexing: a copy
selected[0] = -1

print(source)
print(window)
print(selected)
~~~

The assignment through <code>window</code> changes storage shared with <code>source</code>, so <code>source[1]</code> becomes 999. The later assignment changes the independent <code>selected</code> buffer and does not restore or replace <code>source[1]</code>. The two indexing expressions look similar but establish different ownership graphs.

When independence is part of a function contract, make it explicit:

~~~python
import numpy as np


def centred_copy(values: np.ndarray) -> np.ndarray:
    result = values.astype(np.float64, copy=True)
    result -= result.mean()
    return result
~~~

The type hint says only that an array enters and leaves. The docstring and tests should state dtype, shape preservation, missing-value policy, mutation policy, and behaviour for empty input. An annotation cannot express the whole numerical contract.

> **Common misconception 16.22 — “Assigning an array copies its data.”**  
> <code>b = a</code> binds another name to the same array object. A slice may create a different array object that shares a buffer. Only an operation documented to copy establishes independent element storage.

### 16.8.1 Basic and advanced indices can appear in one expression

Basic indexing consists of integers, slices, ellipsis, <code>None</code>/<code>newaxis</code> and tuples composed of them. It ordinarily selects through strides and returns a view for array-valued results. Advanced indexing uses integer or Boolean arrays/lists and returns a copy. When basic and advanced components are mixed, advanced index arrays broadcast together and their placement influences output-axis order.

~~~python
import numpy as np


cube = np.arange(3 * 4 * 5).reshape(3, 4, 5)

basic = cube[:, 1:3, :]
advanced = cube[:, [1, 3], :]
mask = cube[:, :, 0] % 2 == 0
selected_first_values = cube[:, :, 0][mask]

assert np.shares_memory(cube, basic)
assert not np.shares_memory(cube, advanced)
assert selected_first_values.ndim == 1
~~~

A Boolean mask consumes the axes it addresses and returns selected elements in documented traversal order, commonly a one-dimensional result for a full-shape mask. Assignment through advanced indexing is special: the selection used to determine targets can be temporary, yet the assignment writes to the original array. Repeated target indices do not imply repeated accumulation.

~~~python
import numpy as np


values = np.zeros(3, dtype=np.int64)
indices = np.array([0, 0, 1])
values[indices] += 1

# The duplicate index is generally updated once through buffered assignment.
assert values.tolist() == [1, 1, 0]

accumulated = np.zeros(3, dtype=np.int64)
np.add.at(accumulated, indices, 1)
assert accumulated.tolist() == [2, 1, 0]
~~~

<code>ufunc.at</code> performs unbuffered indexed application for repeated targets. It is slower than ordinary vectorised operations in many cases and is not a concurrency primitive; it exists because indexed accumulation has semantics distinct from buffered fancy assignment.

> **Common misconception 16.23 — “If an advanced index contains the same position twice, augmented assignment updates it twice.”**  
> Advanced assignment can buffer selected values and write a target once. Use a documented accumulation operation such as <code>add.at</code> or grouped reduction when repeats matter.

### 16.8.2 Memory sharing is not captured by one immediate base pointer

The <code>.base</code> attribute names an object through which a view’s memory is exposed, but chains and intermediary arrays make identity tests unreliable as a general overlap detector. <code>np.shares_memory</code> determines whether overlap is certain, potentially doing expensive exact analysis for unusual striding. <code>np.may_share_memory</code> performs a conservative bounds test that can report possible sharing when none exists.

~~~python
import numpy as np


base = np.arange(20)
evens = base[::2]
odds = base[1::2]

assert np.may_share_memory(evens, odds)
assert not np.shares_memory(evens, odds)
~~~

Their byte-span bounds overlap, but individual addressed elements do not. For routine slicing, exact checks are manageable; adversarial stride constructions can make exact overlap analysis combinatorially expensive, so the API exposes a work bound.

Setting <code>array.flags.writeable = False</code> prevents writes through that array object under supported operations. It does not make a shared buffer globally immutable if another writable alias exists:

~~~python
import numpy as np


owner = np.arange(4)
readonly = owner.view()
readonly.flags.writeable = False

owner[0] = 99
assert readonly[0] == 99
~~~

The flag protects an access path, not the storage from all owners. Passing a view into untrusted extension code also requires that the extension honour buffer flags and bounds.

> **Common misconception 16.24 — “A read-only view makes its underlying data immutable.”**  
> It forbids writes through that view. A writable alias, owning array, memory map or native pointer may still change the shared bytes.

Array ownership is already non-local. Broadcasting adds virtual repetition through shape/stride logic and therefore requires explicit output-size reasoning.
