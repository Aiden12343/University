# 16.9 Broadcasting as shape algebra

**Broadcasting** is NumPy’s rule for applying elementwise operations to arrays with compatible but unequal shapes without conceptually spelling out repeated copies. Shapes are compared from their trailing axes. Two dimensions are compatible when they are equal or one of them is 1. Missing leading dimensions are treated as 1 for compatibility.

For shapes <code>(2, 3)</code> and <code>(3,)</code>, trailing dimensions 3 and 3 match; the second operand is treated as applicable to each of the two rows. For <code>(4, 1, 3)</code> and <code>(2, 3)</code>, compare from the right: 3 matches 3, 1 is compatible with 2, and the missing leading dimension is compatible with 4. The result shape is <code>(4, 2, 3)</code>.

### Worked example 16.8 — Centre each sensor column

~~~python
import numpy as np

readings = np.array(
    [
        [10.0, 100.0, 1.0],
        [12.0, 110.0, 5.0],
        [14.0, 120.0, 9.0],
    ]
)

column_means = readings.mean(axis=0)
centred = readings - column_means

print(column_means.shape)  # (3,)
print(centred)
~~~

<code>readings</code> has shape <code>(3, 3)</code> and <code>column_means</code> shape <code>(3,)</code>. Broadcasting aligns the three means with the three columns for every row. The subtraction returns a new array. It does not mutate <code>readings</code>.

Broadcasting can also create an enormous logical result. Combining shape <code>(1_000_000, 1)</code> with <code>(1, 1_000_000)</code> defines a trillion-element result. The inputs occupy modest memory; materialising the output does not. Shape analysis must precede execution.

### 16.9.1 Align shapes from the trailing edge

Given operand shapes, pad the shorter shape on the left with conceptual ones, then compare dimensions from right to left. For each position, all non-one dimensions must agree; the result uses that agreed size, or one if every dimension is one. A zero-length dimension is compatible with another zero or one but not an unrelated positive size.

For ((8,1,6,1)) and ((7,1,5)), left-padding gives ((8,1,6,1)) and ((1,7,1,5)). Comparisons are (1) with (5), (6) with (1), (1) with (7), and (8) with (1); the result is ((8,7,6,5)).

Use the library to verify a reasoning result without allocating data:

~~~python
import numpy as np


shape = np.broadcast_shapes((8, 1, 6, 1), (7, 1, 5))
assert shape == (8, 7, 6, 5)

try:
    np.broadcast_shapes((3, 4), (2, 4))
except ValueError:
    incompatible = True
else:
    incompatible = False

assert incompatible
~~~

Broadcasting compatibility is syntactic shape algebra, not proof of semantic alignment. A vector of three sensor offsets can broadcast across the last axis of a matrix even when that last axis actually denotes time. Named axes or explicit wrapper types can prevent such coincidental compatibility.

> **Common misconception 16.25 — “If two arrays broadcast, they represent compatible quantities.”**  
> Broadcasting checks axis lengths from the right. It cannot know axis names, units, coordinate order or whether the intended relationship is pairwise, outer or aligned by labels.

### 16.9.2 Singleton axes express intended repetition

<code>np.newaxis</code> (the value <code>None</code>) inserts a length-one axis. <code>expand_dims</code> does the same through an explicit axis parameter. These operations ordinarily create views and make orientation visible.

~~~python
import numpy as np


points = np.array([1.0, 4.0, 9.0])
column = points[:, np.newaxis]   # shape (3, 1)
row = points[np.newaxis, :]      # shape (1, 3)
pairwise_differences = column - row

assert pairwise_differences.shape == (3, 3)
assert pairwise_differences[1, 2] == -5.0
~~~

Subtracting two shape-((3,)) vectors is elementwise and returns three values. Reorienting one as a column and one as a row constructs an **outer** difference matrix with every pair. This is a semantic choice, not merely repair for an error message.

Reductions with <code>keepdims=True</code> retain reduced axes as singleton dimensions, facilitating later broadcasting:

~~~python
import numpy as np


values = np.arange(12, dtype=np.float64).reshape(3, 4)
row_means = values.mean(axis=1, keepdims=True)
centred = values - row_means

assert row_means.shape == (3, 1)
assert centred.shape == values.shape
assert np.allclose(centred.mean(axis=1), 0.0)
~~~

Without <code>keepdims</code>, row means have shape ((3,)), which does not align with the four-column trailing axis. Adding a new axis later works, but retaining it documents which dimension was reduced.

> **Common misconception 16.26 — “Adding newaxis only changes display formatting.”**  
> It changes dimensional structure and therefore indexing and broadcasting. A row and a column vector with equal values can produce radically different result shapes.

### 16.9.3 Broadcast inputs can be virtual while outputs are material

Broadcasting can expose a view whose stride is zero along repeated dimensions, avoiding physical repetition of the input. An elementwise output generally requires storage for every result unless an output buffer or lazy/fused system changes the operation.

Before executing, calculate:

\[
\text{output bytes}=\left(\prod_k d_k\right)\times\text{itemsize}.
\]

For a pairwise distance matrix among one million points, (10^{12}) float64 entries require eight trillion raw bytes—approximately 8 TB decimal or 7.28 TiB binary—before temporaries. Compact inputs do not make the Cartesian output compact.

A block algorithm can keep peak memory bounded:

~~~python
from collections.abc import Iterator
import numpy as np


def squared_distance_blocks(
    left: np.ndarray,
    right: np.ndarray,
    block_rows: int,
) -> Iterator[tuple[slice, np.ndarray]]:
    if left.ndim != 2 or right.ndim != 2:
        raise ValueError("inputs must be two-dimensional")
    if left.shape[1] != right.shape[1]:
        raise ValueError("feature dimensions must match")
    if block_rows <= 0:
        raise ValueError("block_rows must be positive")

    for start in range(0, left.shape[0], block_rows):
        stop = min(start + block_rows, left.shape[0])
        difference = left[start:stop, None, :] - right[None, :, :]
        yield slice(start, stop), np.sum(difference * difference, axis=2)


left = np.array([[0.0, 0.0], [1.0, 0.0]])
right = np.array([[0.0, 1.0], [2.0, 0.0]])
blocks = list(squared_distance_blocks(left, right, block_rows=1))
assert np.array_equal(blocks[0][1], [[1.0, 4.0]])
~~~

Each yielded result still has <code>block_rows × len(right)</code> entries, and the three-dimensional difference temporary can dominate. The algebraic identity ‖(x-y)‖² = ‖(x)‖² + ‖(y)‖² − 2(x\cdot y) can reduce temporary dimensionality but may suffer cancellation for nearby large vectors. Performance and numerical error must be evaluated together.

> **Common misconception 16.27 — “Broadcasting is free because it does not copy repeated inputs.”**  
> Input repetition can be virtual, but result allocation, computation and temporaries scale with the broadcast result. Inspect shape and peak memory before execution.

Broadcasting supplies the iteration geometry. Universal functions supply dtype-resolved native loops over that geometry.
