# 17.12 Classification, scores, and decisions

**Classification** predicts membership among discrete target categories. A binary classifier may produce:

- a class label;
- a continuous score ranking cases;
- an estimated probability, if calibrated and interpreted accordingly.

A **decision threshold** turns a score or probability into an action. Changing the threshold changes false-positive and false-negative rates without refitting the underlying score model.

For a positive class:

- **true positive**: predicted positive and actually positive;
- **false positive**: predicted positive and actually negative;
- **true negative**: predicted negative and actually negative;
- **false negative**: predicted negative and actually positive.

The resulting **confusion matrix** supports:

\[
\text{precision}=\frac{TP}{TP+FP},
\qquad
\text{recall}=\frac{TP}{TP+FN},
\]

\[
\text{specificity}=\frac{TN}{TN+FP}.
\]

Precision depends on prevalence in the evaluated population. Recall is also called sensitivity. Accuracy can be high for a rare class when a model always predicts the majority class.

### Worked example 17.6 — Thresholds encode costs

~~~python
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix
from sklearn.model_selection import train_test_split

X, y = make_classification(
    n_samples=600,
    n_features=12,
    weights=[0.8, 0.2],
    random_state=7,
)
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    stratify=y,
    random_state=42,
)
model = LogisticRegression(max_iter=2_000).fit(X_train, y_train)

probabilities = model.predict_proba(X_test)[:, 1]

for threshold in (0.2, 0.5, 0.8):
    decisions = probabilities >= threshold
    matrix = confusion_matrix(y_test, decisions)
    print(threshold, matrix)
~~~

Lowering the threshold ordinarily marks more cases positive, often increasing recall and false positives. The correct threshold cannot be chosen from an abstract preference for 0.5. It depends on capacity, consequences, prevalence, calibration, and stakeholder constraints. If the same test data select the threshold and report its performance, evaluation is contaminated.

The **receiver operating characteristic curve**, or ROC curve, plots true-positive rate against false-positive rate over thresholds. Its area, ROC AUC, estimates a ranking probability under assumptions. The precision–recall curve can be more informative about positive predictions under severe class imbalance. Neither supplies calibration or a deployment decision by itself.

### 17.12.1 Confusion metrics have denominators and operating conditions

Sensitivity divides true positives by actual positives; specificity divides true negatives by actual negatives; precision divides true positives by predicted positives. A metric is undefined when its denominator is zero, and software may warn, return zero, or use a configured convention.

Prevalence affects precision even if sensitivity and specificity remain fixed. With sensitivity \(s\), false-positive rate \(f\), and prevalence \(\pi\),

\[
P(Y=1\mid \widehat Y=1)
=\frac{s\pi}{s\pi+f(1-\pi)}.
\]

Deployment prevalence must therefore accompany a positive predictive value. Case-control samples constructed with artificial class ratios cannot directly estimate operational precision without reweighting or modelling.

Balanced accuracy averages sensitivity across classes under its definition. F-scores combine precision and recall through a harmonic mean but omit true negatives and encode an implicit trade-off through \(\beta\). Matthews correlation and chance-corrected measures capture other aspects. No metric becomes universal by using more entries of the confusion matrix.

> **Common misconception 17.29 — “Precision and recall are properties of a classifier.”**  
> They are properties of a classifier, threshold, labelled population, prevalence, and evaluation procedure. They change when any of these changes.

### 17.12.2 Ranking, probability, and decisions are distinct

ROC AUC estimates the probability that a randomly selected positive receives a higher score than a randomly selected negative, with tie conventions. It is threshold-independent only in the sense of integrating across thresholds; it weights operating regions that may never be used. It can remain high while probability calibration is poor.

Precision–recall curves expose positive-prediction quality across recall levels and depend on prevalence. Average precision summarises a particular interpolation/ranking convention; it is not simply area under any plotted polygon. Compare implementations and baselines.

Decision-curve or expected-utility analysis evaluates thresholds against consequences. Capacity constraints may require selecting the top \(k\) cases rather than a fixed probability threshold. If scores tie at the boundary, the tie rule must be specified.

~~~python
import numpy as np
from sklearn.metrics import (
    average_precision_score,
    brier_score_loss,
    roc_auc_score,
)

y_true = np.array([0, 0, 1, 1, 1, 0])
scores = np.array([0.05, 0.40, 0.35, 0.80, 0.75, 0.10])

print("ROC AUC", roc_auc_score(y_true, scores))
print("average precision", average_precision_score(y_true, scores))
print("Brier loss", brier_score_loss(y_true, scores))
~~~

The three numbers evaluate ranking or probability quality differently. None determines the action threshold.

> **Common misconception 17.30 — “ROC AUC tells us how accurate the predicted probabilities are.”**  
> AUC evaluates pairwise ranking. Any monotone transformation preserves ranking while changing probability values and calibration.

### 17.12.3 Multiclass, multilabel, and abstaining systems

In multiclass classification, classes are mutually exclusive under the target definition. Per-class metrics can be **macro-averaged** equally across classes, **weighted** by support, or **micro-averaged** over pooled decisions. Macro averaging gives rare classes equal class-level influence; micro averaging emphasises frequent case decisions. State the aggregation.

Multilabel classification permits several positive labels per case. Exact-match accuracy is stringent; per-label and per-instance metrics answer different questions. Hierarchical taxonomies may count near-misses differently from unrelated classes.

An **abstaining** classifier can defer uncertain cases. Coverage—the fraction receiving automatic decisions—and selective risk must be reported together. If difficult cases are sent to humans, human performance, workload, delay, and correlated errors become part of the system. Rejecting cases is not cost-free.

> **Common misconception 17.31 — “Multiclass accuracy summarises performance equally across classes.”**  
> It weights cases equally, so frequent classes dominate. Per-class errors, aggregation convention, ordinal severity, and abstention require explicit treatment.
