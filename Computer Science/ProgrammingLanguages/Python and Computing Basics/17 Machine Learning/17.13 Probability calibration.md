# 17.13 Probability calibration

A classifier is **calibrated** when, among cases assigned probability near \(p\), approximately proportion \(p\) experience the event under the evaluated conditions. Discrimination and calibration differ. A model can rank cases well but assign probabilities that are systematically too high.

Calibration must be evaluated on data not used to fit the calibration mapping. Reliability diagrams group predictions and compare average predicted probability with empirical frequency; binning introduces sampling variability and resolution choices. Proper scoring rules such as log loss and Brier score evaluate probabilistic predictions, but a single score still hides local failures.

Distribution shift can invalidate calibration. A model calibrated where prevalence is 10% may not remain calibrated where prevalence is 2%, even if some conditional relationships persist.

### 17.13.1 Calibration is conditional on a forecasting population

Perfect calibration means \(P(Y=1\mid \hat p=p)=p\) in an ideal formulation. It does not imply useful discrimination: a constant forecast equal to prevalence can be calibrated while ranking nobody. Nor does good discrimination imply calibration.

Empirical reliability diagrams bin forecasts, then plot event frequency against mean forecast within each bin. Equal-width and equal-frequency bins reveal different details. Sparse bins have high uncertainty; adaptive bin choice can tell a preferred story. Report counts and uncertainty, and supplement plots with proper scores.

The Brier score decomposes under conventions into reliability (calibration), resolution (variation of outcome rates across forecast groups), and uncertainty (base-rate variation). A lower total can result from better calibration or discrimination-like resolution. Calibration error summaries based on bins are estimator-dependent and can reward coarse forecasts.

> **Common misconception 17.32 — “A reliability curve on the diagonal proves individual probabilities are correct.”**  
> Calibration is a group-frequency property under a population and binning estimate. It does not verify any one case’s counterfactual probability.

### 17.13.2 Calibrating a model is another fitted procedure

Platt-style sigmoid calibration fits a logistic mapping from scores to probabilities. Isotonic regression fits a monotone stepwise mapping and is more flexible but can overfit small calibration sets. Temperature scaling adjusts logits by a learned scalar and is common in neural classification. Each assumes the score–outcome relation is stable into deployment.

Calibration must use data not used to fit the base model’s parameters. Cross-fitted calibration obtains predictions from models that did not train on each calibration case. A final calibrated model may then comprise several fitted components or refit according to a documented procedure.

Threshold selection should follow calibration if the threshold assumes probability semantics. Recalibration can change decisions even when ranking is identical. After prevalence shift, intercept or prior correction may help under restrictive conditional-stability assumptions; arbitrary concept drift requires new evidence.

~~~python
from sklearn.calibration import CalibratedClassifierCV
from sklearn.datasets import make_classification
from sklearn.linear_model import SGDClassifier
from sklearn.model_selection import train_test_split

X, y = make_classification(
    n_samples=600,
    n_features=12,
    weights=[0.75, 0.25],
    random_state=21,
)
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.3,
    stratify=y,
    random_state=21,
)

base = SGDClassifier(loss="hinge", random_state=21)
calibrated = CalibratedClassifierCV(base, method="sigmoid", cv=5)
calibrated.fit(X_train, y_train)
probabilities = calibrated.predict_proba(X_test)[:, 1]
assert ((0.0 <= probabilities) & (probabilities <= 1.0)).all()
~~~

The inner folds protect calibration cases from their corresponding base fits. The held-out test data remain untouched until evaluation.

> **Common misconception 17.33 — “Calibration is a cosmetic post-processing step.”**  
> It is a learned model with data requirements, variance, assumptions, and shift sensitivity. It must be included in validation and versioning.
