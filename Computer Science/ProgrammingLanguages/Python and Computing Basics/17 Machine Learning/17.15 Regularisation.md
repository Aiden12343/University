# 17.15 Regularisation

**Regularisation** modifies fitting to discourage selected forms of complexity. Ridge regression adds a squared coefficient penalty:

\[
\sum_{i=1}^{n}(\hat{y}_i-y_i)^2
+\lambda\sum_{j=1}^{p}\beta_j^2.
\]

The non-negative hyperparameter \(\lambda\) controls the trade-off. Larger values pull coefficients towards zero. Lasso uses an absolute-value penalty \(\lambda\sum_j|\beta_j|\) and can produce exact zero coefficients under many conditions.

Regularisation depends on scale: a one-unit coefficient for metres is not comparable to a one-unit coefficient for millimetres. Standardisation inside the validation pipeline is therefore often essential. Penalising or not penalising the intercept is an implementation choice that affects results.

Regularisation introduces bias deliberately to reduce variance or improve other properties. It is not evidence that coefficients selected as nonzero are scientifically true. Hyperparameters chosen after extensive search must be evaluated as part of the selection procedure.

### 17.15.1 Ridge, lasso, and elastic net alter the objective

Ridge uses the squared \(L_2\) norm, lasso the \(L_1\) norm, and elastic net combines them:

\[
\min_\beta
\frac{1}{n}\|X\beta-y\|_2^2
+\lambda\left(
\alpha\|\beta\|_1
+\frac{1-\alpha}{2}\|\beta\|_2^2
\right).
\]

Symbols and normalising constants vary by library. In scikit-learn’s logistic regression, <code>C</code> is conventionally inverse regularisation strength rather than \(\lambda\). Reusing a numeric hyperparameter across estimators without checking definitions is invalid.

Ridge shrinks correlated coefficients towards a distributed solution and makes a singular least-squares problem uniquely solvable under ordinary penalisation. Lasso’s corners can set coefficients exactly to zero, but with highly correlated features it may select one unstable representative. Elastic net combines grouping and sparsity tendencies.

~~~python
import numpy as np
from sklearn.linear_model import ElasticNet, Lasso, Ridge
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(4)
X = rng.normal(size=(200, 6))
X[:, 5] = X[:, 0] + 0.02 * rng.normal(size=200)
y = 3.0 * X[:, 0] - 1.5 * X[:, 2] + rng.normal(scale=0.5, size=200)

models = {
    "ridge": Ridge(alpha=1.0),
    "lasso": Lasso(alpha=0.05, max_iter=20_000),
    "elastic": ElasticNet(alpha=0.05, l1_ratio=0.5, max_iter=20_000),
}

for name, estimator in models.items():
    pipeline = make_pipeline(StandardScaler(), estimator)
    pipeline.fit(X, y)
    print(name, pipeline[-1].coef_)
~~~

The coefficients are expressed on standardised features inside the final estimator. Correlation between columns 0 and 5 permits several predictive allocations.

> **Common misconception 17.36 — “Lasso identifies the true important variables.”**  
> It selects a sparse predictive solution relative to scale, penalty, correlations, sample, and model. Zero or non-zero status is not causal or scientific truth.

### 17.15.2 Hyperparameter selection, intercepts, and regularisation paths

Regularisation strength must be selected inside validation. Scaling, imputation, and feature generation are refitted for every fold. Searching a penalty after viewing test performance leaks the test set.

The intercept is often excluded from penalty because it represents a baseline rather than sensitivity, but behaviour depends on solver and representation. Centring data can separate intercept from slopes; sparse matrices complicate centring. One-hot encodings with all levels plus an intercept are linearly dependent, yet regularised solvers can still select a convention. Dropping a level changes coefficient reference, not predictive information under ordinary full-rank coding.

A **regularisation path** follows coefficients as penalty strength changes. It can reveal instability and correlated substitutions. Selecting the visually pleasing sparsity from the full data and then quoting ordinary validation as if fixed is another adaptive choice.

Regularisation does not always reduce computational cost. Sparse coefficients can accelerate compatible prediction paths, but lasso optimisation can be slower than ridge; dense libraries may still multiply all columns; feature-selection overhead and schema maintenance remain.

> **Common misconception 17.37 — “Regularisation prevents overfitting.”**  
> It restricts or biases one aspect of the fitted solution and often improves generalisation. Its strength can itself overfit validation data, and it cannot repair leakage, shift, label defects, or an unsuitable representation.
