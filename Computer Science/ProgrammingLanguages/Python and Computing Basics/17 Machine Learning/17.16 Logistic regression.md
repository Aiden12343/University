# 17.16 Logistic regression

For binary targets, logistic regression models a linear function of features as the **log-odds** of the positive class. If \(p=P(Y=1\mid x)\), the odds are \(p/(1-p)\), and the log-odds are

\[
\log\left(\frac{p}{1-p}\right)
=\beta_0+\beta^\mathsf{T}x.
\]

Solving for \(p\) applies the logistic function:

\[
p=\frac{1}{1+\exp(-z)},
\qquad
z=\beta_0+\beta^\mathsf{T}x.
\]

The logistic function maps every real score to a number between 0 and 1. Parameters are fitted by maximising likelihood or equivalently minimising log loss under the Bernoulli model, usually with regularisation in practical software.

A coefficient \(\beta_j\) adds \(\beta_j\) to log-odds for a one-unit feature increase holding represented other features fixed; exponentiating gives an odds multiplier. Odds are not probabilities, and “holding fixed” need not describe a feasible intervention.

### 17.16.1 Likelihood and stable computation

For independent Bernoulli targets \(y_i\), the conditional likelihood is

\[
\prod_i p_i^{y_i}(1-p_i)^{1-y_i}.
\]

Taking negative logarithms gives binary log loss. Logarithms turn products into sums and improve computation, while stable implementations avoid explicitly evaluating \(\exp(z)\) where it would overflow. The identity

\[
\log(1+\exp z)
\]

is computed through a stable **softplus** formulation.

~~~python
import numpy as np


def stable_sigmoid(scores: np.ndarray) -> np.ndarray:
    z = np.asarray(scores, dtype=np.float64)
    result = np.empty_like(z)
    positive = z >= 0
    result[positive] = 1.0 / (1.0 + np.exp(-z[positive]))
    exponential = np.exp(z[~positive])
    result[~positive] = exponential / (1.0 + exponential)
    return result


probabilities = stable_sigmoid(np.array([-1_000.0, 0.0, 1_000.0]))
assert probabilities[0] == 0.0
assert probabilities[1] == 0.5
assert probabilities[2] == 1.0
~~~

The exact endpoint rounding at extreme finite scores is a floating representation result, not a claim of metaphysical certainty. A production system may clip probabilities for downstream log loss or decision contracts.

> **Common misconception 17.38 — “Logistic regression fits class labels by least squares.”**  
> Standard logistic fitting optimises Bernoulli likelihood or log loss, usually with regularisation. The logistic link connects a linear score to conditional probability.

### 17.16.2 Separation, class weights, and multiclass formulations

If a hyperplane perfectly separates training classes, unregularised maximum-likelihood coefficients can diverge in magnitude: increasing them drives likelihood towards its supremum without a finite optimum. Regularisation yields a finite solution but coefficient magnitude then depends strongly on penalty.

Class weighting changes the empirical objective. It does not synthesize new minority information or guarantee calibrated probabilities for deployment prevalence. Oversampling can have similar loss effects for some solvers while changing stochastic optimisation, regularisation normalisation, and duplicated dependence.

For more than two classes, **multinomial logistic regression** models a vector of scores followed by softmax:

\[
P(Y=k\mid x)=\frac{\exp(z_k)}
{\sum_j\exp(z_j)}.
\]

Subtracting the maximum score before exponentiation gives the same probabilities and reduces overflow. Adding one constant to every class score also leaves softmax unchanged, so parameterisation needs an identifiability convention or regularisation.

One-versus-rest fits one binary problem per class, and its outputs need not form a coherent multinomial probability distribution without normalisation/calibration. The chosen formulation affects training cost, probability semantics, and class interactions.

> **Common misconception 17.39 — “Balancing class weights corrects class imbalance.”**  
> It changes optimisation priorities. Evaluation prevalence, probability calibration, threshold costs, rare-subgroup coverage, and label quality remain separate problems.

### 17.16.3 Discriminative, generative, and margin-based alternatives

Logistic regression is **discriminative**: it models \(P(Y\mid X)\) directly through a decision score. A **generative classifier** instead models \(P(X\mid Y)\) and \(P(Y)\), then applies Bayes’ rule:

\[
P(Y=k\mid X=x)
=
\frac{p(x\mid Y=k)P(Y=k)}
{\sum_j p(x\mid Y=j)P(Y=j)}.
\]

Gaussian naive Bayes assumes features are conditionally independent given the class and models each continuous feature with a class-specific Gaussian distribution. “Naive” names the strong factorisation

\[
p(x\mid Y=k)=\prod_j p(x_j\mid Y=k).
\]

The assumption is usually false literally, yet the resulting decision rule can work when estimation simplicity outweighs dependence misspecification. Correlated repeated measurements can cause extreme overconfidence because redundant evidence is multiplied.

Linear discriminant analysis models class-conditional multivariate Gaussians sharing one covariance matrix; its log posterior odds are linear in \(x\). Quadratic discriminant analysis permits separate covariance matrices and produces quadratic boundaries. Covariance estimation becomes unstable when features are numerous relative to cases, requiring regularisation.

~~~python
from sklearn.datasets import make_classification
from sklearn.metrics import log_loss, roc_auc_score
from sklearn.model_selection import train_test_split
from sklearn.naive_bayes import GaussianNB
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = make_classification(
    n_samples=1_000,
    n_features=20,
    n_informative=6,
    n_redundant=8,
    random_state=15,
)
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    stratify=y,
    random_state=15,
)
models = {
    "logistic": make_pipeline(
        StandardScaler(),
        LogisticRegression(max_iter=2_000),
    ),
    "naive_bayes": GaussianNB(),
}

for name, candidate in models.items():
    candidate.fit(X_train, y_train)
    probability = candidate.predict_proba(X_test)[:, 1]
    print(
        name,
        {
            "auc": roc_auc_score(y_test, probability),
            "log_loss": log_loss(y_test, probability),
        },
    )
~~~

The redundant features deliberately strain conditional independence. Ranking and log loss can respond differently because the latter strongly penalises overconfident probability errors. This is one dataset, not a universal ranking of algorithms.

Generative models can simulate inputs under their assumptions and can exploit structure when labelled data are scarce, but a good density model is not necessary for a good decision boundary. Discriminative models can devote capacity to the boundary while providing no coherent model of \(X\). The choice follows task, sample size, missing-data mechanism, probability needs, and assumption fit.
