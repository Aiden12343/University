# 17.24 Computation graphs and the chain rule

A **computation graph** represents an expression as nodes connected by value dependencies. Consider

\[
u=wx,\qquad
v=u+b,\qquad
\hat{y}=v,\qquad
L=(\hat{y}-y)^2.
\]

To determine how \(w\) affects \(L\), multiply local derivatives along the path. This is the **chain rule**:

\[
\frac{dL}{dw}
=
\frac{dL}{d\hat{y}}
\frac{d\hat{y}}{dv}
\frac{dv}{du}
\frac{du}{dw}.
\]

Here,

\[
\frac{dL}{d\hat{y}}=2(\hat{y}-y),
\qquad
\frac{du}{dw}=x,
\]

and the two identity steps contribute 1, so

\[
\frac{dL}{dw}=2(\hat{y}-y)x.
\]

**Automatic differentiation** records or transforms primitive operations and systematically applies derivative rules. It is not numerical guessing of derivatives and not symbolic algebra in the usual sense. **Reverse-mode automatic differentiation** efficiently computes gradients of one scalar loss with respect to many parameters by propagating sensitivities backwards through the graph. **Backpropagation** is this reverse accumulation applied to layered neural computations.

### 17.24.1 Forward mode, reverse mode, and vector products

A computation graph is a directed acyclic graph for an ordinary finite expression: edges carry values from prerequisite operations to consumers. A forward evaluation computes nodes in topological order. Differentiation associates each primitive with a rule for propagating local sensitivities.

**Forward-mode automatic differentiation** propagates a tangent \(\dot{x}\) alongside each primal value \(x\). Given \(y=f(x)\), it computes the Jacobian--vector product \(J_f(x)\dot{x}\). One forward sweep efficiently answers how all outputs change along one chosen input direction.

**Reverse mode** first computes primal values, then propagates adjoints from outputs backwards. Given an output cotangent \(\bar y\), it computes the vector--Jacobian product \(\bar y^\mathsf{T}J_f(x)\). One reverse sweep is efficient when a scalar loss has many input parameters, which is the dominant training case. It needs primal intermediates or a way to recompute them, creating a memory--computation trade-off known as **checkpointing**.

For a scalar loss \(L\), each node accumulates contributions from every downstream path. If \(u\) feeds two operations, its adjoint is the sum of both path contributions. Backpropagation is not merely multiplying derivatives along one chain; it is reverse dynamic programming over a graph with accumulation at branches.

> **Common misconception 17.54 — “Backpropagation is the optimiser.”**  
> Backpropagation computes derivatives. An optimiser such as SGD or Adam uses those derivatives to propose parameter updates; the two mechanisms have separate state and failure modes.

### 17.24.2 A manual reverse pass and gradient check

For

\[
L(w,b)=(wx+b-y)^2,
\]

a forward pass stores \(u=wx\), \(\hat y=u+b\), and \(r=\hat y-y\). Reverse accumulation begins with \(\bar L=1\):

\[
\bar r=2r,\qquad
\bar{\hat y}=\bar r,\qquad
\bar b=\bar{\hat y},\qquad
\bar u=\bar{\hat y},\qquad
\bar w=\bar u x.
\]

The bars denote sensitivities of the final loss with respect to intermediates. A value used by several downstream operations receives the sum of their contributions.

~~~python
from collections.abc import Callable
import numpy as np


def loss_and_gradient(
    parameters: np.ndarray,
    *,
    x: float,
    y: float,
) -> tuple[float, np.ndarray]:
    weight, bias = parameters
    residual = weight * x + bias - y
    loss = residual * residual
    gradient = np.array(
        [2.0 * residual * x, 2.0 * residual],
        dtype=np.float64,
    )
    return float(loss), gradient


def numerical_gradient(
    function: Callable[[np.ndarray], float],
    point: np.ndarray,
    *,
    step: float = 1e-6,
) -> np.ndarray:
    result = np.empty_like(point, dtype=np.float64)
    for index in range(point.size):
        offset = np.zeros_like(point, dtype=np.float64)
        offset[index] = step
        result[index] = (
            function(point + offset) - function(point - offset)
        ) / (2.0 * step)
    return result


theta = np.array([0.7, -0.2])
loss, analytic = loss_and_gradient(theta, x=1.5, y=2.0)
numeric = numerical_gradient(
    lambda value: loss_and_gradient(value, x=1.5, y=2.0)[0],
    theta,
)
assert loss >= 0.0
assert np.allclose(analytic, numeric, rtol=1e-6, atol=1e-8)
~~~

Finite-difference checking costs at least one or two forward evaluations per checked coordinate; reverse mode obtains all scalar-loss parameter gradients in a small multiple of forward cost. Checks are consequently sampled for large systems.

### 17.24.3 Graph lifetime, mutation, and non-differentiable boundaries

Operator-overloading frameworks construct a dynamic graph as operations run; source-transformation and compilation systems can stage a graph before execution. Control flow may therefore be recorded, traced, specialised, or compiled under different contracts. Code with data-dependent Python side effects can behave differently under tracing.

A **stop-gradient** or detach operation treats a value as constant for differentiation while ordinarily retaining its numerical value. This is useful for targets, alternating procedures, and estimators with deliberately blocked paths, but an accidental detach silently removes learning signals. In-place mutation can overwrite a primal value required by the reverse rule. Framework version counters and errors catch some cases; aliasing through views makes the underlying storage relation important.

Not every program is differentiable: indexing decisions, comparisons, sampling of discrete values, external I/O, and arbitrary Python operations can break a gradient path. Surrogate gradients, continuous relaxations, score-function estimators, or reformulated objectives address particular cases, each with assumptions and variance. Automatic differentiation computes the derivative of the implemented differentiable program; it does not guarantee that this derivative answers the intended scientific question.

> **Common misconception 17.55 — “If automatic differentiation returns a gradient, the model and implementation are correct.”**  
> It differentiates the executed operations under library conventions. Wrong targets, broadcasting, leakage, detached paths, unstable arithmetic, or an unsuitable objective can all yield valid derivatives of the wrong computation.
