# 17.3 Instances, design matrices, and target vectors

An **instance** is one modelled case. In common tabular supervised learning, \(n\) instances with \(p\) numerical features form a **design matrix** \(X\) of shape \(n\times p\). Row \(i\) represents instance \(i\); column \(j\) represents feature \(j\). Targets form a vector \(y\) of length \(n\), or a matrix for multiple outputs.

\[
X =
\begin{bmatrix}
x_{11} & \cdots & x_{1p}\\
\vdots & \ddots & \vdots\\
x_{n1} & \cdots & x_{np}
\end{bmatrix},
\qquad
y =
\begin{bmatrix}
y_1\\
\vdots\\
y_n
\end{bmatrix}.
\]

The notation does not guarantee that rows are independent or that columns are meaningful numbers. One person can contribute several rows. A postcode encoded as 17 is not seventeen units of anything. Representation design precedes matrix arithmetic.

A **model** is a parameterised or otherwise selected mapping from inputs to outputs. Write \(f_\theta(x)\), where \(\theta\) denotes model parameters. **Parameters** are values learned during fitting. **Hyperparameters** configure the model class or learning process and are chosen outside an individual fit, commonly through validation. The boundary can depend on formulation; the key question is whether the value is estimated by the stated fitting objective.

### 17.3.1 Shape is an interface; features are claims

For ordinary single-output regression, scikit-learn commonly expects \(X\) with shape <code>(n_samples, n_features)</code> and \(y\) with shape <code>(n_samples,)</code>. A single case must usually remain two-dimensional at prediction time:

~~~python
import numpy as np

training_features = np.array(
    [
        [18.0, 3.0],
        [24.0, 7.0],
        [31.0, 4.0],
    ],
    dtype=np.float64,
)
targets = np.array([0, 1, 1], dtype=np.int64)
one_case = np.array([[27.0, 5.0]], dtype=np.float64)

assert training_features.shape == (3, 2)
assert targets.shape == (3,)
assert one_case.shape == (1, 2)
~~~

The outer pair of brackets on <code>one_case</code> is not decoration. It preserves the sample axis, allowing the same interface to represent one or many cases. A one-dimensional array of length two is ambiguous between two one-feature cases and one two-feature case; robust APIs reject or explicitly reshape it.

Every column embodies a representation decision. A timestamp might become hour-of-day, time-since-event, cyclical sine/cosine coordinates, or an ordered raw count. A word might become a token identity, count, subword sequence, or learned vector. These encodings make different relationships easy or difficult for the model class. A linear model cannot express a periodic boundary between hour 23 and hour 0 from an untransformed integer without engineered terms, whereas a tree treats numerical order differently from a one-hot encoding.

A **feature map** \(\phi\) transforms a raw case \(r\) into a represented vector \(x=\phi(r)\). If \(\phi\) learns vocabulary, means, categories, principal components, or target statistics, it is itself a fitted estimator and belongs inside the training boundary. Calling it “preprocessing” does not make it informationally neutral.

> **Common misconception 17.6 — “Once data are numerical, they are valid model features.”**  
> Numerical storage does not establish scale, order, unit, availability, reliability, or permissible use. Encoding is a model of what distinctions and relationships should matter.

### 17.3.2 Dense, sparse, structured, and sequence representations

A **dense matrix** allocates a value for every sample–feature coordinate. A **sparse matrix** stores principally non-zero values and their coordinates or compressed index structure. Text count vectors can have millions of possible tokens but only hundreds present in one document, making sparse storage essential. Converting such a matrix to dense form can exhaust memory before fitting begins.

Sparse representation does not mean computational cost depends only on sample count. Algorithms vary in sparse support, may densify intermediate state, and can have cost proportional to non-zero entries, features, or model parameters. Centring a sparse matrix by subtracting feature means ordinarily makes absent zeros non-zero and destroys sparsity; scaling without centring may be required.

Structured inputs need not be forced into one flat dense matrix. Images use height, width, and channel axes; sequences add position and possibly batch axes; graphs contain nodes, edges, attributes, and adjacency structure; sets lack meaningful order. A model architecture introduces inductive assumptions appropriate to these symmetries. Flattening an image preserves every pixel value but discards explicit neighbourhood structure from the interface.

Feature names and ordering form a schema. A production model fitted on <code>[age, usage]</code> will accept an equally shaped <code>[usage, age]</code> array and calculate nonsense without a structural exception. Preserve names until a validated conversion boundary, record category vocabularies, and reject missing, extra, reordered, or incompatible fields.

~~~python
from dataclasses import dataclass

import numpy as np
from numpy.typing import NDArray


@dataclass(frozen=True)
class FeatureBatch:
    values: NDArray[np.float64]
    names: tuple[str, ...]

    def __post_init__(self) -> None:
        if self.values.ndim != 2:
            raise ValueError("values must have sample and feature axes")
        if self.values.shape[1] != len(self.names):
            raise ValueError("feature count does not match names")
        if len(set(self.names)) != len(self.names):
            raise ValueError("feature names must be unique")
        if not np.isfinite(self.values).all():
            raise ValueError("features must be finite")


batch = FeatureBatch(
    values=np.array([[18.0, 3.0], [24.0, 7.0]]),
    names=("age_years", "monthly_usage_hours"),
)
~~~

The dataclass does not prove that age was measured accurately or usage was available at prediction time. It enforces a narrow computational contract and keeps feature identity adjacent to storage.

> **Common misconception 17.7 — “The design matrix is the dataset.”**  
> It is one model-facing representation. Identifiers, provenance, labels, units, time availability, grouping, and governance metadata must survive elsewhere so results can be interpreted and audited.
