# 17.8 Transformers, pipelines, and column-wise preprocessing

A scikit-learn **transformer** commonly implements <code>fit</code> to learn transformation state and <code>transform</code> to apply it. A **pipeline** orders transformers followed by a final estimator and treats them as one estimator for fitting, prediction, and hyperparameter selection.

Tabular data often mix numeric and categorical variables. A **one-hot encoding** represents a category using indicator columns. If categories are red, green, and blue, one-hot encoding can create three binary features. The integers 0, 1, and 2 would instead imply an order and distance that nominal categories do not possess.

~~~python
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

numeric_features = ["age", "monthly_usage"]
categorical_features = ["plan"]

numeric_pipeline = make_pipeline(
    SimpleImputer(strategy="median"),
    StandardScaler(),
)
categorical_pipeline = make_pipeline(
    SimpleImputer(strategy="most_frequent"),
    OneHotEncoder(handle_unknown="ignore"),
)

preprocessor = ColumnTransformer(
    [
        ("numeric", numeric_pipeline, numeric_features),
        ("categorical", categorical_pipeline, categorical_features),
    ]
)

model = make_pipeline(
    preprocessor,
    LogisticRegression(max_iter=1_000),
)
~~~

The code declares separate transformations by column role. Median and most-frequent imputation are fitted from training data because they reside inside the pipeline. <code>handle_unknown="ignore"</code> defines behaviour for a category unseen during fitting: its one-hot indicators are zero. This prevents an exception but does not prove the model behaves sensibly on a novel population.

Imputation is modelling. Filling a missing age with the median asserts a computational value and can obscure missingness mechanisms. Adding missing indicators or using a model designed for missing values may be appropriate, but each choice requires validation.

### 17.8.1 Fit-dependent transformations are estimators

A transformer that learns means, variances, category vocabularies, quantiles, selected columns, imputation values, or projection directions is an estimator. Its <code>fit</code> consumes training information; its <code>transform</code> applies the learned mapping. The distinction permits the same validation machinery to clone and refit every stage.

<code>fit_transform</code> is not universally equivalent to <code>fit(X).transform(X)</code>. Some algorithms use training-specific shortcuts or leave-one-out/cross-fitted representations to avoid self-influence. A custom transformer must document the relation and preserve sample order.

Column selection is part of the contract. Selecting by dtype can change when an upstream parser infers a different dtype; selecting by name fails visibly when a schema changes. Production systems commonly prefer an explicit versioned list with checks for missing and unexpected fields.

~~~python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

frame = pd.DataFrame(
    {
        "age": [24.0, 31.0, np.nan, 46.0],
        "usage": [3.0, 8.0, 5.0, 2.0],
        "plan": ["basic", "plus", "basic", "premium"],
    }
)

preprocessor = ColumnTransformer(
    [
        (
            "numeric",
            make_pipeline(
                SimpleImputer(strategy="median", add_indicator=True),
                StandardScaler(),
            ),
            ["age", "usage"],
        ),
        (
            "categorical",
            OneHotEncoder(handle_unknown="ignore"),
            ["plan"],
        ),
    ],
    remainder="drop",
    verbose_feature_names_out=True,
)

encoded = preprocessor.fit_transform(frame)
assert encoded.shape[0] == len(frame)
print(preprocessor.get_feature_names_out())
~~~

The fitted feature names are the output schema. <code>handle_unknown="ignore"</code> maps an unseen category to all-zero indicators for that field; it does not mean the category is semantically equivalent to an absent category. An explicit infrequent/unknown policy may be more appropriate.

> **Common misconception 17.19 — “Preprocessing is a deterministic formatting step outside the model.”**  
> Any transformation that learns from data is fitted state and part of the selected predictor. It must be trained, versioned, tested, and evaluated within the same boundary.

### 17.8.2 Sparse outputs, feature names, and memory

One-hot encoding can produce a sparse matrix. A <code>ColumnTransformer</code> combines sparse and dense branches according to a density threshold, so adding one dense branch can change the final representation and memory. Downstream estimators differ in sparse support. Inspect output type and calculate worst-case dimensions before fitting.

High-cardinality categories create many columns and rare levels. Alternatives include hashing, learned embeddings, regularised target encodings, hierarchical grouping, and models with native categorical handling. Each introduces collisions, leakage risks, ordering assumptions, or library-specific semantics. Arbitrarily mapping categories to consecutive integers is valid only for algorithms that treat those integers as category codes rather than distances.

Feature lineage should map each model input back to raw source and transformation. Coefficients over standardised or one-hot columns cannot be interpreted without scale, reference category, and dropped/pooled levels. A pipeline can expose names while still losing higher-level semantic provenance unless the application stores it.

### 17.8.3 Composition, metadata, and custom transformers

Composite estimators may need information beyond \(X\) and \(y\): sample weights, groups, validation sets, or feature names. **Metadata routing** is the mechanism by which supported scikit-learn objects declare and forward such auxiliary arguments. A weight supplied to the final estimator but omitted from the scorer makes fitting and evaluation refer to different populations. Version-specific configuration must be tested because routing interfaces evolve.

A custom transformer should obey estimator conventions: constructor parameters are stored unchanged; <code>fit</code> returns <code>self</code>; learned attributes have trailing underscores; validation rejects incompatible shapes; transformation is deterministic unless randomness is declared; and cloning works. Prefer stateless <code>FunctionTransformer</code> only when the function truly needs no learned state and its schema behaviour is documented.

Pipeline caching can avoid refitting expensive transformers during search. Cache identity must include code and parameter state; cached fitted objects should be treated as derived artefacts, not edited manually. Caching changes performance, not the information boundary.

> **Common misconception 17.20 — “If a component accepts sample weights, the whole pipeline uses them.”**  
> Every transformer, estimator, scorer, splitter, and search layer has its own metadata contract. Unrouted weights or groups can silently change the target population or break independence.

> **Common misconception 17.21 — “One-hot encoding is lossless because every category gets a column.”**  
> Unknown handling, pooled infrequent levels, dropped reference columns, missing categories, sparse conversion, and schema drift can alter information. The representation is lossless only relative to a precisely fixed vocabulary and mapping.

### 17.8.3 Text, hashing, missingness, and stable schemas

Text requires a fitted representation before a conventional tabular estimator can consume it. A **vocabulary** maps selected tokens or character sequences to columns. Learning that vocabulary on all data leaks evaluation-distribution information even when targets are absent. Rare-term pruning, document-frequency thresholds, token normalisation, stop-word policy, and \(n\)-gram range all alter the hypothesis class.

A term-frequency–inverse-document-frequency representation reduces the influence of terms common across documents. Under one convention,

\[
\operatorname{tfidf}(t,d)
=
\operatorname{tf}(t,d)
\log\frac{1+n}{1+\operatorname{df}(t)}.
\]

Libraries vary in smoothing, normalisation, sublinear term frequency, and added constants. The formula and fitted document frequencies belong to the model artifact.

Feature hashing maps tokens into a fixed number of columns without storing a vocabulary. It supports streaming and avoids unknown-token columns, but collisions combine unrelated features and inverse interpretation is unavailable. The hashing function, seed or signed-hash convention, dimensionality, and tokenisation must remain stable.

~~~python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

documents = [
    "battery lasts all day",
    "excellent battery and screen",
    "screen failed after a week",
    "battery failed immediately",
    "reliable and bright display",
    "unreliable device returned",
]
targets = [1, 1, 0, 0, 1, 0]

text_model = make_pipeline(
    TfidfVectorizer(
        ngram_range=(1, 2),
        min_df=1,
    ),
    LogisticRegression(max_iter=2_000),
)
text_model.fit(documents, targets)
probability = text_model.predict_proba(
    ["bright screen and reliable battery"]
)[0, 1]
assert 0.0 <= probability <= 1.0
~~~

The six documents are pedagogical rather than adequate training data. The pipeline ensures that a validation routine would refit token vocabulary and inverse-document frequencies within each training fold.

Missingness can be represented by imputed values plus indicators. An indicator permits the model to associate absence with outcomes, which is useful if the mechanism remains stable and dangerous when collection policy changes. A distinct “missing” category for a nominal field does not mean missingness is semantically an ordinary category. Tree algorithms with native missing-value routing learn a direction from training data; their behaviour for changed missingness still requires validation.

A stable production schema must define output column order after every encoder. Training may observe categories \(A,B,C\), while a later batch contains \(A,D\); silently fitting a new encoder can retain the same array width while changing column meaning. Persist the fitted mapping, reject incompatible schema versions, and test known, unknown, rare, and missing categories.

Sparse transformations should remain sparse through composition. Centring a sparse matrix generally makes every implicit zero non-zero, causing memory explosion. Some estimator–dtype combinations densify internally. A pipeline capacity test should use realistic row count, vocabulary, category cardinality, and worst-case batch rather than a small sample alone.

### 17.8.4 Feature selection is fitting

Filter methods rank features using individual association with the target; wrapper methods evaluate subsets through model performance; embedded methods select during fitting through penalties or tree structure. Every target-dependent method is part of the estimator and must run inside each training fold.

Univariate selection can miss jointly useful features whose individual associations vanish, and it can select redundant correlates. Recursive feature elimination repeatedly fits a model and is computationally expensive. Lasso coefficients provide selection only relative to scale, penalty, and correlation. Stability selection repeats subsampling and selection to quantify frequency under a specified perturbation; frequency is not a causal probability.

Selection can reduce cost, improve conditioning, and support measurement policy, but predictive performance alone may not justify removing a feature required to audit harm or retaining one unavailable in production. The selected schema, selection scores, and rejected-feature reasons should be versioned.
