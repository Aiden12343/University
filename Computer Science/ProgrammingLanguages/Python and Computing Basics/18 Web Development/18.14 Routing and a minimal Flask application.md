# 18.14 Routing and a minimal Flask application

**Routing** maps a request’s method and target pattern to application behaviour. Flask is a deliberately small WSGI-oriented framework that supplies routing, request/response objects, templating integration, configuration, and extension points while leaving many architectural choices to the application.

~~~python
from __future__ import annotations

from flask import Flask, jsonify, request

app = Flask(__name__)

devices: dict[str, dict[str, str]] = {
    "A17": {"device_id": "A17", "status": "ok"},
}


@app.get("/devices/<device_id>")
def get_device(device_id: str):
    device = devices.get(device_id)
    if device is None:
        return jsonify(
            {
                "error": {
                    "code": "device_not_found",
                    "message": "No device has that identifier.",
                }
            }
        ), 404
    return jsonify(device)


@app.post("/devices")
def create_device():
    document = request.get_json(silent=False)
    if not isinstance(document, dict):
        return jsonify(
            {"error": {"code": "object_required"}}
        ), 400

    device_id = document.get("device_id")
    if not isinstance(device_id, str) or not device_id:
        return jsonify(
            {"error": {"code": "invalid_device_id"}}
        ), 422
    if device_id in devices:
        return jsonify(
            {"error": {"code": "device_exists"}}
        ), 409

    device = {"device_id": device_id, "status": "new"}
    devices[device_id] = device
    return jsonify(device), 201, {
        "Location": f"/devices/{device_id}"
    }
~~~

The decorator associates method and path pattern with each function. The path component is decoded and passed as <code>device_id</code>. The GET handler distinguishes absence from an empty value. The POST handler separates malformed/non-object content, a semantically invalid identifier, and a state conflict. A created response identifies its new resource.

The module-level dictionary is not a database. Multiple worker processes hold separate copies; restart erases it; threads can race; and unbounded input consumes memory. It is pedagogical state used to expose HTTP semantics.

Flask’s development server is for development. A production WSGI server controls workers, sockets, limits, timeouts, and graceful shutdown. Import strings and application factories help separate application construction from process launch:

~~~python
from flask import Flask


def create_app(config: dict[str, object] | None = None) -> Flask:
    app = Flask(__name__)
    if config is not None:
        app.config.from_mapping(config)

    from .devices import blueprint

    app.register_blueprint(blueprint)
    return app
~~~

An **application factory** constructs an application under explicit configuration. It supports isolated tests and multiple instances. Importing the blueprint inside the factory can avoid a cyclic import, but module organisation should make dependencies clear rather than rely on arbitrary import timing.

### 18.14.1 Request and application contexts

Flask exposes objects such as <code>request</code>, <code>session</code>, and <code>g</code> through context-local proxies. They resolve to state for the active request or application context; they are not ordinary global singleton request objects. Access outside the appropriate context raises an error rather than identifying an arbitrary request.

The request lifecycle includes URL matching, before-request hooks, view execution, error handling, response processing, session saving, and teardown. Teardown functions run for cleanup even after exceptions but should not conceal the original error. Hook ordering across application and blueprints is part of behaviour and deserves tests.

A **blueprint** records routes, handlers, templates, and static resources for registration on an application. It supports modular composition but is not an isolated process or security boundary. Dependencies should be injected through application extensions or explicit domain services rather than imported mutable globals.

Configuration can arrive from environment-specific objects or mappings. Secrets must not use committed default values. Fail startup if required keys, database URLs, trusted proxy settings, or cryptographic secrets are missing or malformed.

> **Common misconception 18.32 — “Flask’s <code>request</code> object is a process global and therefore unsafe.”**  
> It is a context-local proxy resolved for the active request. Mutable module globals remain shared and unsafe for request-specific state.

### 18.14.2 Separate transport, domain, and persistence

A route should translate protocol input into a domain command, invoke a service, and translate its result into an HTTP response. Embedding all validation, SQL, authorisation, email, and JSON construction in the view makes transaction and test boundaries invisible.

~~~python
from dataclasses import dataclass


@dataclass(frozen=True)
class RegisterDevice:
    device_id: str
    site_id: int


def parse_register_device(document: object) -> RegisterDevice:
    if not isinstance(document, dict):
        raise ValueError("an object is required")
    expected = {"device_id", "site_id"}
    if set(document) != expected:
        raise ValueError("fields do not match schema")

    device_id = document["device_id"]
    site_id = document["site_id"]
    if not isinstance(device_id, str) or not device_id.strip():
        raise ValueError("device_id must be non-empty text")
    if type(site_id) is not int or site_id <= 0:
        raise ValueError("site_id must be a positive integer")
    return RegisterDevice(device_id.strip(), site_id)


command = parse_register_device(
    {"device_id": "A17", "site_id": 3}
)
assert command.site_id == 3
~~~

Using <code>type(site_id) is int</code> deliberately rejects booleans, which are subclasses of <code>int</code> in Python but not valid identifiers here. A schema library can express the same boundary more systematically; the domain still decides the rule.

Exceptions crossing the route boundary should map through explicit handlers. A domain “device already exists” result can become 409; a database outage becomes a logged 503 or 500 under policy; an unexpected programming error remains unexpected and must not be mislabeled as bad input.

Template rendering uses automatic escaping appropriate to HTML text and ordinary attributes, but developers must avoid unsafe contexts and deliberate <code>Markup</code>/<code>safe</code> overrides. Static asset URLs, session configuration, maximum request size, and proxy trust are application-wide concerns, not decorations added after routes work.

> **Common misconception 18.33 — “A microframework produces microservices.”**  
> “Micro” describes the framework’s core and extension philosophy. Deployment boundaries, domain coupling, data ownership, and operational independence determine service architecture.
