# 18.2 Networks and layered agreements

A **computer network** is a collection of communicating systems joined by channels over which represented information is transferred. A **protocol** is a set of rules governing message structure, meaning, order, and participant behaviour. Participants need not share an implementation; they need compatible protocol behaviour.

Communication is organised in layers because no single component should need to solve electrical signalling, local delivery, internetwork routing, reliable byte transport, encryption, and application meaning simultaneously. A simplified web path contains:

1. a physical and link layer moves frames over a local medium;
2. the Internet Protocol routes packets between network addresses;
3. a transport protocol supplies application-to-application communication;
4. Transport Layer Security can authenticate a peer and protect content;
5. HTTP defines request and response semantics;
6. the application interprets resources and domain operations.

A **packet** is a bounded unit of represented network data. A **header** carries control metadata; a **payload** carries the data supplied by a higher layer. Each layer can wrap higher-layer data with its own header, a process called **encapsulation**. A receiving stack reverses the interpretation.

Layering is not perfect isolation. Packet loss affects transport latency; transport behaviour affects HTTP; TLS certificate errors affect application reachability. The model supplies disciplined questions: at which contract did observed behaviour first diverge?

### 18.2.1 Encapsulation, forwarding, and maximum transmission units

At each layer, a sender prepends or otherwise associates control information. An HTTP message becomes TLS records; those records are carried by transport segments or QUIC packets; network packets are placed in link-layer frames. The receiver validates and removes each layer’s representation before delivering its payload upward.

Routers ordinarily forward IP packets based on destination prefixes. They do not understand the application’s database transaction. Switches ordinarily forward link-layer frames within a local network. Firewalls and middleboxes may inspect more layers, translate addresses, terminate connections, or reject traffic. The neat layer model is therefore a reasoning aid, not a claim that every device is pure.

A link has a **maximum transmission unit** (MTU), the largest network-layer packet it can carry without fragmentation or another adaptation. Sending application data larger than an MTU is ordinary: transport and network mechanisms segment it. Problems arise when path MTU discovery fails, fragmentation is blocked inconsistently, or an application falsely assumes one write corresponds to one packet.

Checksums and message authentication protect different properties. A transport checksum detects accidental corruption under its design; a TLS authentication tag protects record integrity against attackers holding no valid key. Neither validates that the application’s content is semantically correct.

> **Common misconception 18.3 — “One application send produces one packet and one receive.”**  
> Layers segment, combine, retransmit, buffer, and frame data independently. Application protocols must define their own message boundaries and tolerate arbitrary transport chunking.

### 18.2.2 Latency, bandwidth, throughput, and capacity

**Latency** is elapsed time for an operation or transfer milestone. **Round-trip time** (RTT) is time for a signal to travel to a peer and a corresponding response to return. **Bandwidth** is a channel’s theoretical or configured transfer capacity; **throughput** is the achieved useful transfer rate. High bandwidth does not imply low latency.

For a request requiring sequential DNS, connection, TLS, and application round trips, latency contains both propagation and processing:

\[
T_{\text{request}}
\approx
T_{\text{DNS}}
+T_{\text{connect}}
+T_{\text{TLS}}
+T_{\text{server}}
+T_{\text{transfer}}.
\]

Connections, DNS answers, and TLS sessions can be reused, so this is not a universal fixed sum. HTTP/2 and HTTP/3 multiplex exchanges to reduce some connection costs, while congestion, loss, server queues, and head-of-line effects remain.

**Capacity** is the sustained workload a system can handle while meeting stated objectives. Little’s Law relates long-run average concurrency \(L\), arrival rate \(\lambda\), and time in system \(W\):

\[
L=\lambda W
\]

under stable conditions. At 200 requests per second and 0.25 seconds mean response time, approximately 50 requests are in the system on average. Tail latency and burstiness require additional headroom; an average is not a queue bound.

A **failure domain** is a set of components likely to fail together. Two application instances on one host do not protect against host failure. Two zones using one regional database do not protect against database-region failure. Redundancy claims must name the independent domain.

> **Common misconception 18.4 — “A fast network is one with a high advertised bandwidth.”**  
> Interactive performance depends on latency, loss, congestion, protocol round trips, server queues, and achieved throughput. Bandwidth is only one constraint.
