# 19.10 Path traversal

**Path traversal** occurs when untrusted path material escapes an intended root, commonly through parent segments, absolute paths, links, or platform-specific syntax. Prefix string tests are unreliable: <code>/safe-backup</code> begins with <code>/safe</code> as text but is not inside that directory.

~~~python
from pathlib import Path


def confined_path(root: Path, user_name: str) -> Path:
    if not user_name or "\x00" in user_name:
        raise ValueError("invalid name")

    root_resolved = root.resolve(strict=True)
    candidate = (root_resolved / user_name).resolve(strict=False)

    if not candidate.is_relative_to(root_resolved):
        raise ValueError("path escapes configured root")
    return candidate
~~~

The function resolves path components and compares path ancestry. It still has a time-of-check/time-of-use race if links or directories can change between validation and opening. Higher-assurance code uses directory-relative file-descriptor operations and flags that reject links where the operating system supports them, places storage under permissions attackers cannot mutate, or avoids client-selected filesystem names entirely.

Archive extraction requires validating every member path, link, device entry, size, count, and expansion total. A library convenience extraction call is not automatically a confinement policy.

### 19.10.1 Names, links, and races

An attacker can supply `..`, an absolute path, an alternate separator, a drive or device name, a trailing dot or space significant on one platform, a symbolic link, a hard link, or an archive member whose parent becomes a link during extraction. Even a generated leaf name is unsafe if an attacker can replace a parent directory. Windows reparse points and Unix symbolic links express related but non-identical behaviours; portable policy needs platform-specific enforcement.

A prefix comparison on text fails at component boundaries and under case or normalisation rules. `Path.resolve()` improves ordinary application validation but resolves through a mutable namespace. Between resolution and opening, another actor able to modify a directory can exchange a component. This is the classic race discussed in Section 19.24.

The strongest ordinary pattern is to open a trusted root directory, retain its descriptor, and resolve descendants relative to it using operating-system features that reject links and constrain traversal. Linux `openat2` can apply kernel resolution rules; traditional `openat`-style calls require careful component-by-component handling. Python exposes a portable subset through `dir_fd` and `follow_symlinks`, with feature availability reported in `os.supports_dir_fd` and related sets.

### Worked example 19.4 — Create a leaf beneath an opened directory

~~~python
from __future__ import annotations

import os
import re


LEAF_NAME = re.compile(r"[A-Za-z0-9][A-Za-z0-9._-]{0,63}\Z", re.ASCII)


def create_leaf(directory_fd: int, name: str, data: bytes) -> None:
    if not LEAF_NAME.fullmatch(name) or name in {".", ".."}:
        raise ValueError("invalid leaf name")

    flags = os.O_WRONLY | os.O_CREAT | os.O_EXCL
    if hasattr(os, "O_NOFOLLOW"):
        flags |= os.O_NOFOLLOW

    descriptor = os.open(name, flags, 0o600, dir_fd=directory_fd)
    try:
        with os.fdopen(descriptor, "wb") as stream:
            descriptor = -1
            stream.write(data)
            stream.flush()
            os.fsync(stream.fileno())
    finally:
        if descriptor != -1:
            os.close(descriptor)
~~~

The caller must obtain `directory_fd` from a trusted directory opened without attacker-controlled traversal and keep that directory protected. The single validated leaf grammar excludes separators. Exclusive creation prevents replacement of an existing name, and `O_NOFOLLOW` rejects a final symbolic link where supported. This example does not recurse into subdirectories, guarantee durability of the directory entry, or supply identical guarantees on every platform.

### 19.10.2 Archive extraction as a transaction

Treat extraction as a staged transaction. First inspect metadata and reject unsupported entry types, duplicate or colliding names, absolute paths, parent traversal, links, devices, excessive counts, and declared sizes. Then extract under a fresh restricted directory while counting actual output, enforcing a deadline, and rejecting any filesystem object inconsistent with policy. Finally validate the produced tree and atomically publish it to the application namespace. On failure, discard the staging directory without exposing partial content.

Python’s `tarfile` extraction filters reduce common hazards, and contemporary Python versions default to the `data` filter. The filter is a baseline, not a complete application policy: denial of service, duplicate names, nested content, platform collisions, parser vulnerabilities, and application-specific active formats remain. State the filter explicitly when supported so security does not depend on an interpreter-version default.

Storage services often avoid traversal by generating opaque object keys and retaining the user’s filename only as validated display metadata. Download responses then encode that metadata for the HTTP header context. Moving a string away from the filesystem does not make it universally safe; it changes the consumer grammar.

> **Common misconception 19.25 — “Removing `..` prevents path traversal.”**  
> Absolute paths, links, separators, devices, encodings, case rules, mutable parents, and platform-specific namespaces can escape without that exact substring.

> **Common misconception 19.26 — “`Path.resolve()` closes every traversal vulnerability.”**  
> It resolves one moment in a mutable namespace. If an attacker can change components before use, the checked path and opened object can differ.

> **Common misconception 19.27 — “A safe archive member path makes extraction safe.”**  
> Entry types, links, collisions, expansion, count, permissions, parser defects, partial publication, and active content also require policy.
