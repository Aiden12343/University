# 19.11 Command injection and subprocess boundaries

A shell parses metacharacters, substitutions, quoting, redirections, and pipelines. Combining untrusted text into a shell command lets it become grammar.

Unsafe:

~~~python
os.system(f"convert {source_name} {destination_name}")
~~~

Safer separation:

~~~python
from pathlib import Path
import subprocess


def convert_image(source: Path, destination: Path) -> None:
    subprocess.run(
        [
            "/usr/bin/convert",
            "--",
            str(source),
            str(destination),
        ],
        check=True,
        timeout=30,
        stdin=subprocess.DEVNULL,
        capture_output=True,
    )
~~~

An argument sequence bypasses shell grammar. An absolute executable path reduces path-search substitution. <code>--</code> asks compatible programs to stop interpreting later arguments as options. A timeout and captured output bound some behaviours, but output capture itself needs a size policy for hostile tools or files.

No-shell execution does not make arbitrary arguments safe. The invoked program has its own option and filename grammar; some tools interpret filenames, URLs, delegates, configuration, or file content with powerful effects. Run high-risk converters under restricted identity, filesystem, network, resource, and process controls.

### 19.11.1 Executable identity, environment, and option injection

Executable lookup is a security decision. A relative program name can resolve through a manipulated search path or current directory. Scripts can select an interpreter through their first line or file association. On Windows, batch files can involve shell parsing even when a caller did not explicitly request a shell. Prefer an absolute, deployed executable whose provenance is managed, and understand platform-specific launch semantics.

The environment influences dynamic libraries, Python imports, locale, configuration directories, proxies, certificate stores, and child tools. A restricted child should receive a minimal explicit environment and controlled working directory. Locale affects decoding and sometimes parsing; set encodings deliberately. Standard input should be closed or supplied from a bounded source so the child cannot wait indefinitely for an inherited terminal.

**Option injection** occurs when a data argument beginning with `-` is interpreted as an option. An argument list preserves argument boundaries but not the child program’s grammar. Use an option terminator where the program defines one, place fixed options before data, validate domain arguments, and prefer APIs that distinguish operands from options. Some utilities process configuration, delegates, embedded scripts, or URLs from input content, so a syntactically ordinary filename can still trigger powerful behaviour.

### 19.11.2 Resource-bounded child execution

`subprocess.run(..., timeout=...)` bounds how long the parent waits, but cleanup semantics need attention: descendant processes may survive, captured output can fill memory before timeout, and partial output may already have been written. Higher-assurance designs launch a process group or operating-system job, stream output through explicit byte limits, apply CPU/memory/file/process limits externally, and terminate the whole group on deadline.

~~~python
from __future__ import annotations

import subprocess


def identify_file(path: str, *, maximum_output: int = 4096) -> str:
    completed = subprocess.run(
        ["/usr/bin/file", "--brief", "--", path],
        stdin=subprocess.DEVNULL,
        stdout=subprocess.PIPE,
        stderr=subprocess.PIPE,
        timeout=5,
        check=False,
    )
    if len(completed.stdout) > maximum_output or len(completed.stderr) > maximum_output:
        raise ValueError("child output limit exceeded")
    if completed.returncode != 0:
        raise RuntimeError("file identification failed")
    return completed.stdout.decode("utf-8", errors="strict").rstrip("\n")
~~~

This illustrative wrapper prevents shell interpretation, fixes executable identity, terminates option parsing, closes input, sets a timeout, checks status, and rejects excessive captured output after completion. Because `subprocess.run` buffers output, it is not suitable when the child may emit arbitrarily large data; use incremental reads plus an external supervisor for hostile inputs.

Never incorporate raw child error output into an HTTP response or trusted log message. It may contain attacker-controlled filenames, control characters, environment details, or secrets. Map internal failure to a stable application error and retain redacted diagnostic evidence under access control.

> **Common misconception 19.28 — “`shell=False` prevents command injection completely.”**  
> It removes one shell grammar. Executable lookup, option parsing, environment, configuration, input formats, and child-program features remain attack surfaces.

> **Common misconception 19.29 — “A timeout stops the work safely.”**  
> Descendants, partial side effects, buffered output, external operations, and cleanup may outlive the parent’s wait. Cancellation semantics must be designed.

> **Common misconception 19.30 — “Escaping produces a universally safe command string.”**  
> Escaping is specific to one shell, platform, quoting context, and expansion phase. Structured argument APIs avoid constructing that grammar in the first place.
