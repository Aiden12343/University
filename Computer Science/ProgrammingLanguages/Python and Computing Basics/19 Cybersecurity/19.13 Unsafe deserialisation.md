# 19.13 Unsafe deserialisation

**Deserialisation** reconstructs values or objects from bytes or text. Some formats encode only inert data; others encode instructions for importing and invoking code. Python pickle is designed to reconstruct rich Python object graphs and can execute attacker-controlled operations while loading. It must never load untrusted data.

Unsafe boundary:

~~~python
import pickle

value = pickle.loads(untrusted_bytes)
~~~

Signing a pickle can establish that it came from a holder of a key, but does not make compromised producers, leaked keys, old vulnerable artifacts, or confused environments safe. Prefer a data-only format plus explicit schema validation.

~~~python
import json
from dataclasses import dataclass


@dataclass(frozen=True)
class DeviceRecord:
    device_id: str
    status: str


def decode_device(payload: bytes) -> DeviceRecord:
    document = json.loads(payload.decode("utf-8"))
    if not isinstance(document, dict):
        raise ValueError("object required")
    if set(document) != {"device_id", "status"}:
        raise ValueError("unexpected fields")

    device_id = document["device_id"]
    status = document["status"]
    if not isinstance(device_id, str) or not device_id:
        raise ValueError("invalid device_id")
    if status not in {"new", "ok", "offline"}:
        raise ValueError("invalid status")
    return DeviceRecord(device_id, status)
~~~

JSON avoids arbitrary Python reconstruction but remains untrusted structured input. Explicit validation defines the permitted domain.

### 19.13.1 Object reconstruction is execution authority

Pickle records instructions sufficient to reconstruct Python object graphs. Reconstruction can import globals and invoke reduction callables; therefore the security boundary is equivalent to executing code selected by the producer. An allowlist unpickler reduces reachable globals but is difficult to prove complete because allowed types can contain surprising construction behaviour and future versions can add paths. The safe default is that untrusted or cross-authority data never enters pickle, `shelve`, or APIs built upon it.

Authenticating a serialized object answers “was this byte string produced by a holder of the key and left unchanged?” It does not answer whether that producer was compromised, whether the object was intended for this service and operation, whether an old valid object is being replayed, or whether the receiving software still regards its instructions as safe. Signatures and MACs need domain separation, audience, version, purpose, freshness, and producer governance.

YAML implementations vary: some support only scalars, sequences, and mappings under a safe loader; others reconstruct language objects. XML libraries vary in entity, DTD, network, and expansion support. A format name alone does not establish a security profile. Record exact loader configuration and limit behaviour as part of the protocol.

### 19.13.2 Data contracts and evolution

A data-only envelope should carry a format version and a narrowly validated payload. Reject unknown fields when they could activate unintended behaviour; preserve or ignore them only under an explicit forward-compatibility rule. Distinguish missing from null, booleans from integers where the language does, and numbers from textual identifiers. Apply maximum depth, length, count, and numeric range before constructing expensive domain objects.

~~~python
from __future__ import annotations

import json
from dataclasses import dataclass


@dataclass(frozen=True)
class ImportEnvelope:
    version: int
    records: tuple[DeviceRecord, ...]


def decode_import(payload: bytes, *, maximum_records: int = 1000) -> ImportEnvelope:
    if len(payload) > 1_000_000:
        raise ValueError("import exceeds byte limit")
    document = json.loads(payload.decode("utf-8", errors="strict"))
    if not isinstance(document, dict) or set(document) != {"version", "records"}:
        raise ValueError("invalid envelope")
    if document["version"] != 1 or not isinstance(document["records"], list):
        raise ValueError("unsupported import version")
    if len(document["records"]) > maximum_records:
        raise ValueError("too many records")

    records = tuple(
        decode_device(json.dumps(item, separators=(",", ":")).encode("utf-8"))
        for item in document["records"]
    )
    return ImportEnvelope(version=1, records=records)
~~~

The example reuses the earlier record validator for clarity. A production implementation would validate parsed values directly rather than serialise each item again, and would impose nesting and number limits during parsing. The important separation is from external data, through a versioned schema, to immutable domain values—never directly to arbitrary application objects.

Migration is a security-sensitive interpreter. Old schema versions can bypass controls added later, and downgrade paths can resurrect deprecated semantics. Test every supported version against current invariants, authenticate its provenance where required, and delete unsupported artifacts under a retention policy.

> **Common misconception 19.33 — “Signing a pickle makes it safe.”**  
> It authenticates bytes under a key. A legitimate but compromised producer, replayed artifact, over-broad key, or unsafe allowed object can still execute harmful behaviour.

> **Common misconception 19.34 — “Data-only formats need no security review.”**  
> Parsers can exhaust resources or disagree; schemas can permit harmful values; downstream components can reinterpret strings; and old versions can bypass current invariants.
