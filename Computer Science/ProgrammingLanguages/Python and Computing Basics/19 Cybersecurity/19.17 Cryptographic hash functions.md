# 19.17 Cryptographic hash functions

A **cryptographic hash function** maps an arbitrary-length byte string to a fixed-length digest. Desired properties include resistance to:

- **preimage finding:** given a digest, finding an input producing it;
- **second-preimage finding:** given one input, finding a different input with the same digest;
- **collision finding:** finding any two distinct inputs with the same digest.

Because inputs are unbounded and digests finite, collisions must exist mathematically. Security means finding them is computationally infeasible under the model, not impossible.

~~~python
from hashlib import sha256
from pathlib import Path


def sha256_file(path: Path) -> str:
    digest = sha256()
    with path.open("rb") as stream:
        for chunk in iter(
            lambda: stream.read(1024 * 1024),
            b"",
        ):
            digest.update(chunk)
    return digest.hexdigest()
~~~

The function hashes file bytes incrementally and returns a hexadecimal representation. A published digest can detect accidental change only if the expected digest arrives through a trusted channel. If an attacker can replace both file and digest, the comparison supplies no authenticity.

Length-extension properties, collision attacks on obsolete algorithms, and encoding ambiguity affect protocol use. Hash structured data only after a canonical encoding or unambiguous framing. Hashing <code>a + b</code> without lengths can make distinct field pairs identical before the hash sees them.

### 19.17.1 Security level, collisions, and construction choice

For an ideal (n)-bit hash, generic preimage work is approximately (2^n), whereas collision search needs approximately (2^{n/2}) evaluations because of the birthday effect. These are asymptotic expectations, not guarantees for a particular function. Cryptanalytic weaknesses can lower them; output truncation deliberately lowers the bound. Choose algorithms and digest lengths from current protocol guidance, not from the fact that a name remains available in a library.

MD5 and SHA-1 have practical collision attacks and must not protect collision-sensitive security decisions. Legacy non-security checksums can remain appropriate for accidental-corruption detection under a non-adversarial model. Python’s `hash()` is a process-oriented hash-table mechanism with type-specific behaviour and randomisation; it is not a stable file digest or cryptographic protocol primitive.

Merkle trees hash leaves and internal nodes so one root commits to many items and membership can be proven with a logarithmic path. Leaf and node encodings need distinct prefixes or domain labels; otherwise a leaf representation might be confused with an internal node. Content-addressed storage similarly names bytes by digest but still needs provenance, access control, and collision policy.

~~~python
from hashlib import sha256


def leaf_digest(data: bytes) -> bytes:
    return sha256(b"leaf\x00" + len(data).to_bytes(8, "big") + data).digest()


def node_digest(left: bytes, right: bytes) -> bytes:
    if len(left) != 32 or len(right) != 32:
        raise ValueError("SHA-256 child digests required")
    return sha256(b"node\x00" + left + right).digest()
~~~

The labels separate leaf and node domains. This fragment does not define tree balancing, odd leaves, proof ordering, algorithm versioning, or trusted root distribution; those choices are part of the protocol.

### 19.17.2 Hashes in commitments and integrity checks

A digest obtained over an authenticated channel can identify a later artifact. A digest stored beside that artifact under the same attacker-controlled authority cannot detect deliberate replacement of both. Content-addressing supplies integrity relative to a trusted name; it does not supply origin authenticity by itself.

Plain `hash(secret || message)` and `hash(message || secret)` are not generic MAC designs. Some iterative hash constructions permit length-extension under one arrangement, and ad hoc layouts invite ambiguity. HMAC or a dedicated keyed hash has a reviewed security construction. Passwords require password hashing, not a fast unkeyed digest.

A hash used for deduplication can leak whether a known document exists: an observer hashes a candidate and compares identifiers. Convergent encryption, which derives encryption behaviour from content to preserve deduplication, leaks equality and enables confirmation attacks under many models. Storage optimisation therefore changes confidentiality claims.

> **Common misconception 19.44 — “A 256-bit hash has 256-bit collision security.”**  
> Generic collision work for an ideal 256-bit output is about (2^{128}), while preimage work is about (2^{256}). The properties are distinct.

> **Common misconception 19.45 — “Matching hashes prove two files came from the same publisher.”**  
> They support byte equality under collision assumptions. Publisher authenticity depends on how the expected digest or signed metadata was trusted.
