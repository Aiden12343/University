# 19.27 Defensive reconnaissance

**Reconnaissance** is information gathering about systems, identities, services, or exposures. Defensive reconnaissance inventories an explicitly authorised environment so unknown assets and configurations can be corrected.

Passive methods inspect owned records: asset inventories, certificate transparency entries for owned domains, DNS zones, cloud accounts, code repositories, dependency manifests, and configuration management. Active methods send requests or packets and can disrupt fragile services; they require scope, rate, maintenance windows, source identification, and stop conditions.

Python can validate an authorised inventory without scanning:

~~~python
from __future__ import annotations

from dataclasses import dataclass
from ipaddress import ip_address, ip_network


@dataclass(frozen=True)
class Asset:
    name: str
    address: str
    owner: str


def addresses_outside(
    assets: list[Asset],
    authorised_networks: list[str],
) -> list[Asset]:
    networks = [
        ip_network(value, strict=True)
        for value in authorised_networks
    ]
    outside: list[Asset] = []

    for asset in assets:
        address = ip_address(asset.address)
        if not any(address in network for network in networks):
            outside.append(asset)

    return outside
~~~

The function compares recorded addresses with authorised networks. It performs no network interaction. It supports the governance step that must precede any active testing: identify ownership and scope.

An assessment plan states:

- exact IP ranges, domains, accounts, and applications;
- excluded systems;
- permitted techniques;
- maximum request rate and concurrency;
- test source addresses;
- start/end time and time zone;
- data retention and encryption;
- emergency contact and stop signal;
- third-party constraints;
- report and remediation process.

### 19.27.1 Asset identity before reachability

An IP address is not a durable asset identity. Cloud instances, load balancers, shared hosting, network translation, and address reassignment mean that an address can be in scope at noon and owned by another party later. Link inventory records to provider account, resource identifier, owner, environment, data classification, service, repository, and lifecycle. Time-bound active targets from that authoritative inventory immediately before assessment.

External attack-surface management correlates DNS, certificates, routing, cloud resources, and observed services to find forgotten exposures. Each observation is evidence requiring ownership validation. A certificate name can remain after a service is retired; a shared address can host other organisations; a banner can be deceptive. Do not promote discovered infrastructure into testing scope automatically.

Passive sources reduce interaction but have their own legal, privacy, freshness, and attribution limits. Certificate-transparency logs reveal publicly issued names, not every deployed certificate. DNS history can be stale. Public code search can expose a secret that must be revoked without using it. Collection itself should be minimised and retained under policy.

### 19.27.2 Active validation under a safety envelope

Active discovery should begin with the smallest question: does the authorised endpoint accept a TCP connection, which protocol does it intentionally expose, or does configuration match inventory? Set connection deadlines, global and per-target rates, concurrency, retries, and maximum response bytes. Identify test traffic so operators can correlate it. Stop automatically on error-rate, latency, safety, or owner-defined thresholds.

Scanning changes systems. Authentication attempts can lock accounts; protocol probes can trigger vulnerable parsers; service detection can execute application routes; UDP can be spoofed or amplified; fragile industrial or embedded devices can fail under benign traffic. Exclusions and maintenance windows are engineering controls, not administrative decoration.

Results must distinguish observation from inference. “Port accepted a connection at time (t) from source (s)” is evidence. “The host is vulnerable because its banner resembles version (v)” is a hypothesis requiring vendor build information and controlled validation. Preserve raw minimal evidence and analysis provenance so another practitioner can reproduce the conclusion without repeating unnecessary traffic.

> **Common misconception 19.68 — “A passive reconnaissance source is necessarily harmless and accurate.”**  
> Passive collection can expose personal or sensitive data and produces stale or misattributed observations. It still needs purpose, validation, minimisation, and authority.
