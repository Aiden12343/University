# 19.8 Parsing is an adversarial boundary

A **parser** maps an external representation to internal structure under a grammar. Network messages, image files, archives, source code, and configuration are parser inputs. Untrusted inputs are chosen to exercise edge cases, not average cases.

Security requirements include:

- maximum total size;
- maximum nesting depth;
- maximum field count and length;
- canonical encoding;
- duplicate-field policy;
- numeric range;
- timeout or computational budget;
- rejection of trailing or ambiguous data;
- explicit error behaviour.

An algorithm linear in ordinary input can behave quadratically on a crafted case. Decompression can expand a tiny archive into enormous output. Recursive nesting can exhaust the call stack. Security cost analysis uses adversarial size and structure.

### Worked example 19.3 — Bounded JSON input

~~~python
from __future__ import annotations

import json
from typing import Any


def parse_small_json_object(
    payload: bytes,
    *,
    maximum_bytes: int = 16_384,
) -> dict[str, Any]:
    if len(payload) > maximum_bytes:
        raise ValueError("payload exceeds byte limit")

    try:
        text = payload.decode("utf-8", errors="strict")
        value = json.loads(text)
    except (UnicodeDecodeError, json.JSONDecodeError) as error:
        raise ValueError("invalid JSON document") from error

    if not isinstance(value, dict):
        raise ValueError("top-level JSON value must be an object")
    if len(value) > 100:
        raise ValueError("too many object members")
    return value
~~~

The byte limit precedes decoding and parsing. Strict UTF-8 avoids replacement that could collapse distinct invalid byte sequences. Structural validation follows syntax. The standard decoder does not impose every possible nesting or number-size limit, so a high-risk boundary may need streaming or specialised parsing under further constraints.

### 19.8.1 Grammar, framing, and parser differentials

A protocol needs both grammar and framing. Grammar states which sequences form values; framing states where one message ends. Reading until connection close, trusting an unchecked length, or accepting both length and delimiter rules can create ambiguity. When a proxy and application disagree about message boundaries, bytes belonging to one request can be interpreted as another.

A **parser differential** occurs when two consumers interpret the same representation differently. Causes include duplicate fields, invalid encodings, number overflow, case rules, comments, trailing data, non-canonical escapes, and error recovery. Security decisions must use the same parse result as the eventual action. Validating with a permissive library and executing with a stricter or differently permissive consumer is unsafe even when both are individually well tested.

~~~python
from __future__ import annotations

from dataclasses import dataclass, field


@dataclass
class BoundedFrames:
    maximum_frame: int = 65_536
    maximum_buffer: int = 131_076
    _buffer: bytearray = field(default_factory=bytearray)

    def feed(self, chunk: bytes) -> list[bytes]:
        self._buffer.extend(chunk)
        if len(self._buffer) > self.maximum_buffer:
            raise ValueError("buffer limit exceeded")

        frames: list[bytes] = []
        while len(self._buffer) >= 4:
            length = int.from_bytes(self._buffer[:4], "big")
            if length > self.maximum_frame:
                raise ValueError("frame limit exceeded")
            end = 4 + length
            if len(self._buffer) < end:
                break
            frames.append(bytes(self._buffer[4:end]))
            del self._buffer[:end]
        return frames
~~~

The decoder accepts arbitrary transport chunking, checks the declared length before waiting for its payload, and bounds accumulated incomplete state. Production framing must also specify zero-length messages, end-of-stream behaviour, message count, semantic schema, and whether processing partial output before a later error is safe.

### 19.8.2 Expansion, recursion, and composed formats

An archive is a container for names, metadata, links, and compressed bodies, not merely a list of files. Limits must cover entry count, path length, nesting, individual expanded size, total expanded size, compression ratio, sparse extents, links, special devices, metadata, and collisions. Nested archives multiply expansion and parser attack surface. Extract into a newly created restricted directory and publish results only after complete validation.

XML, YAML, regular expressions, fonts, office documents, images, and media formats can trigger entity expansion, object construction, catastrophic backtracking, decoder bombs, or native parser flaws. “Data-only” does not mean “computation-free”. Choose the least expressive format that meets the domain need, disable unnecessary features, and apply external process limits to complex parsers.

Streaming can bound resident memory but does not automatically bound total work or output. A streaming consumer can still accept an endless body. Maintain explicit counters and a deadline across the whole operation, including decompression and downstream writes. Rejecting after writing terabytes is not a successful input limit.

Unicode adds representation choices rather than a universal security normal form. Normalisation can make canonically equivalent strings compare alike, yet identifiers may remain visually confusable or meaningful distinctions may be lost. Define permitted scripts, case behaviour, normalisation form, length unit, and display rules for the particular identifier. Preserve original user text separately when required; never silently reinterpret security identifiers under locale-sensitive rules.

> **Common misconception 19.20 — “Valid syntax means safe input.”**  
> Syntax is only the first contract. Size, depth, domain semantics, authorisation, resource cost, and downstream interpretation remain.

> **Common misconception 19.21 — “Streaming removes denial-of-service risk.”**  
> It can reduce resident memory, but total bytes, time, expansion, output, connections, and downstream work still require bounds.

> **Common misconception 19.22 — “One Unicode normalisation step makes identifiers unambiguous.”**  
> Normalisation handles specified equivalences, not visual confusables, script policy, case semantics, or deceptive display.
