# 20.19 Network architecture

A network boundary restricts paths but does not replace application authentication. Typical controls include:

- private address spaces;
- subnets;
- routing tables;
- stateful firewall or security-group rules;
- stateless network access rules;
- egress controls;
- private service endpoints;
- load balancers;
- DNS zones.

An **ingress** path carries traffic into a service; **egress** carries traffic out. Egress restrictions limit data exfiltration and unexpected dependency access, but applications need explicit allowed destinations and DNS behaviour.

“Private” means not directly routed from a specified public network, not cryptographically confidential or inherently trustworthy. Internal traffic can traverse compromised hosts. Authenticate and encrypt according to threat model.

Infrastructure diagrams must correspond to enforced paths. A diagram arrow is not a firewall rule. Automated tests can attempt permitted and forbidden connections from representative identities.

### 20.19.1 Addressing, routing, and policy

An IP address identifies a network interface location within a routing context, not a human, workload, or application identity. Addresses can be reassigned, translated, shared, spoofed within some threat models, or represent a proxy. Use them for routing and coarse policy while authenticating the endpoint at a higher layer.

Classless inter-domain routing represents a prefix and length. An IPv4 prefix such as `10.24.0.0/16` fixes the first 16 bits and contains (2^{16}) addresses before platform reservations. Overlapping ranges complicate peering and migration because a router cannot distinguish identical destination addresses by organisational intent. Address planning is therefore an interface design problem, not clerical allocation.

A routing table chooses a next hop using the most specific matching prefix, subject to platform rules. A firewall then admits or rejects traffic based on fields and connection state. A stateful rule allowing outbound connections commonly permits related return packets; a stateless list needs both directions explicitly. Network address translation rewrites addresses or ports and can provide connectivity conservation, but it is not authentication or a complete firewall.

Separate management, service, storage, and public ingress paths where their trust and availability requirements differ. Segmentation limits lateral movement only when rules, identities, name resolution, and alternate paths are enforced. A publicly reachable administration endpoint protected by strong identity may be safer than a nominally private endpoint reachable by every compromised workstation; evaluate complete paths.

### 20.19.2 Name, channel, and endpoint identity

DNS maps names to records under caching and delegation. It does not by itself authenticate the application reached. TLS can authenticate a name under a certificate trust model and protect channel confidentiality and integrity; application authorisation still decides whether the authenticated peer may perform the operation.

Mutual TLS gives both endpoints certificate-based identity, but certificate issuance, name constraints, rotation, revocation, workload binding, and policy determine meaning. Encrypting all internal traffic without verifying the intended service name prevents passive reading but can still connect to an attacker-controlled endpoint with a valid but inappropriate certificate.

Network policy should include egress. A compromised parser that can reach instance metadata, internal control planes, arbitrary internet hosts, or data stores has a greater blast radius than one confined to its necessary dependencies. Domain-name-based egress controls must account for DNS changes, aliases, shared hosting, encrypted DNS, and direct IP use; they are useful policy mechanisms, not perfect semantic firewalls.

### 20.19.3 Failure domains and path behaviour

Regions, availability zones, racks, hosts, switches, power, DNS, certificate authorities, and control planes define different failure domains. Two replicas in different zones can still share a regional database or identity dependency. Draw dependency and authority edges, then test loss of each claimed domain.

Packets can be dropped, duplicated, reordered, fragmented, delayed, or delivered after a timeout. Maximum transmission unit mismatch can fail only larger messages. Connection establishment, TLS handshake, request transmission, server processing, response, and pool acquisition have distinct latency and failure. End-to-end deadlines must cover the complete user operation while phase metrics locate the constraint.

> **Common misconception 20.40 — “A private IP address identifies a trusted workload.”**  
> It identifies a routable location in a context. Workload identity, authenticated channel, and resource authorisation are separate properties.

> **Common misconception 20.41 — “Network redundancy means two network paths exist.”**  
> Paths that share power, control plane, DNS, certificate, provider, tunnel endpoint, or routing policy can fail together. Independence must be demonstrated at the relevant failure boundary.
