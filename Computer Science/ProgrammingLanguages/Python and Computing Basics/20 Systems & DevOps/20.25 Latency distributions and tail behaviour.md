# 20.25 Latency distributions and tail behaviour

Latency is a distribution, not one number. The **p99 latency** is a 99th percentile under a measurement procedure: 99% of measured eligible operations are at or below it. It is not the slowest request and does not mean any particular user experiences only one slow request per hundred.

Distributed fan-out amplifies tails. If a page waits for 20 independent backend calls and each has a 1% probability of being slow, the probability at least one is slow under the independence model is

\[
1-(0.99)^{20}\approx18.2\%.
\]

Independence may be false because shared load creates correlated slowness, often making incidents worse.

Histograms aggregate distributions across instances and time if bucket boundaries are designed in advance. Averaging p99 values from ten servers does not yield the fleet p99 because percentiles are not additive summaries.

### 20.25.1 Measurement points and omitted waiting

Latency must name start and end. A server handler timer omits DNS, connection pool wait, TCP/TLS establishment, proxy queues, network transit, client parsing, and retries. A user-perceived timer may include human-interface rendering and cache. Measure several phases, but retain one end-to-end indicator aligned with the user outcome.

**Coordinated omission** occurs when the measurement generator waits for one response before scheduling the next operation, thereby sending fewer requests during slowness and omitting the waiting that real fixed-rate demand would have experienced. An open-loop load generator schedules arrivals independently and records queueing or missed starts. Closed-loop tests remain useful for interactive populations whose users truly wait, but their workload model must be explicit.

Timeouts censor distributions: a request abandoned at five seconds is not a five-second success and should not disappear from the dataset. Record timeout as a bad event and, where useful, an interval-censored latency. Sampling only successful operations can make p99 improve during an outage because the slowest requests are now errors.

### 20.25.2 Quantiles and aggregation

For ordered observations (x_{(1)}\leq\cdots\leq x_{(n)}), a sample quantile requires a convention for mapping probability to rank and interpolation. Libraries use different conventions at small (n). Always name the implementation and avoid high quantiles from tiny samples: a per-minute p99 from 20 events has little resolution.

Histograms support aggregation by adding bucket counts when boundaries and semantics match. Bucket choice determines quantile error: if the desired 250 ms threshold lies inside a 100–500 ms bucket, the data cannot later reveal precisely how many met it. Design buckets around SLO thresholds and relevant orders of magnitude before collection.

Client-side percentiles cannot be averaged. To combine exact samples, merge observations; to combine histograms, sum compatible buckets; to combine mergeable sketches, use their specified merge operation and error bounds. “Average of p99” is a statistic, but not the p99 of the aggregate population.

### 20.25.3 Tail amplification and critical paths

For independent identically distributed branch completion probability (F(t)), a fan-out waiting for all (n) branches has

\[
P(\max(X_1,\ldots,X_n)\leq t)=F(t)^n.
\]

At (F(t)=0.99) and (n=20), only about (81.8\%) of compound operations finish by (t). Correlation, retries, shared queues, and unequal branches change the model, but the equation exposes why tails dominate fan-out.

Mitigations include reducing fan-out, caching, parallelising only independent work, coalescing duplicate requests, bounding optional branches, partitioning hot keys, precomputing, and setting sub-deadlines. Hedged requests can reduce tails but duplicate load and effects; use only for safe idempotent reads under a bounded hedge budget.

> **Common misconception 20.52 — “p99 is the experience of the worst one per cent of users.”**  
> It is a quantile of the measured event population. Frequent users, multi-request journeys, retries, and omitted failures alter which people experience tails.

> **Common misconception 20.53 — “More precise percentile calculation fixes poor latency data.”**  
> No estimator recovers waits, timeouts, biased sampling, wrong measurement boundaries, or dimensions never recorded.
