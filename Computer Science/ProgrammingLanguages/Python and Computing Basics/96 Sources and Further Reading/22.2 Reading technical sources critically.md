# 22.2 Reading technical sources critically

A citation supports only the claim for which it supplies evidence. Quoting a processor manual cannot establish a Python language guarantee; benchmarking one list length cannot prove an asymptotic bound; citing a machine-learning paper’s average result cannot establish suitability for a different population.

When evaluating a source, ask:

- What question does it answer?
- Which definitions and assumptions does it use?
- Is the statement normative, descriptive, pedagogical, or empirical?
- Which version, platform, workload, or population is in scope?
- What evidence could contradict it?
- Has a later standard, release, or replication revised the claim?
- Does the source have an incentive or selection mechanism affecting presentation?

The reader should maintain a **claim ledger**. Each important statement is labelled as definition, derivation, specification rule, implementation fact, empirical observation, modelling assumption, or substantive judgement. This practice prevents fluent prose from erasing epistemic boundaries.
