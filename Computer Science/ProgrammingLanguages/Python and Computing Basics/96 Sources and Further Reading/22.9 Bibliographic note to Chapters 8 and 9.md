# 22.9 Bibliographic note to Chapters 8 and 9

The Python data model, descriptor protocol, attribute access rules, and metaclass construction are governed by the language reference and versioned built-in documentation. Ramalho’s *Fluent Python* provides an extensive idiomatic treatment of protocols, functions, classes, concurrency, and the data model. Gamma, Helm, Johnson, and Vlissides catalogue object-oriented design patterns in a language context different from Python; patterns should be translated by intent, not copied mechanically.

Inheritance is one reuse mechanism, not the definition of object orientation. Liskov and Wing’s behavioural subtyping work supplies a stronger account of substitutability than sharing method names. Composition can localise responsibilities; protocols support polymorphism without requiring a common concrete base.

Metaclasses are a capstone because class creation itself is an object protocol. They should be selected only when class decorators, descriptors, <code>__init_subclass__</code>, or ordinary factories do not express the required invariant more directly.
