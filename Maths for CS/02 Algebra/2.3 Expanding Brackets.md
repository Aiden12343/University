## Introduction

In [[2.2 Simplifying Expressions]], you learned to combine like terms. Now you will learn the reverse kind of transformation — breaking brackets open by multiplying out.

When a number or expression sits **outside brackets**, it multiplies **every term inside**. Expanding brackets means removing the brackets by applying the distributive law.

A **single bracket** has one multiplier outside, like `3(x + 2)`. A **double bracket** has two bracketed expressions multiplied, like `(x + 2)(x + 3)`. The **area model** shows expansion as a rectangle split into parts. **Sign handling** is the careful management of positives and negatives during expansion.

> [!example] Everyday idea
> If 3 bags each contain 2 apples and 1 orange, you have 3 x 2 = 6 apples and 3 x 1 = 3 oranges. The outside number 3 was shared across everything inside each bag.

## New Words

- [[distributive law]] — the rule that a(b + c) = ab + ac, multiplying the outside term into each inside term.
- [[single bracket]] — one pair of brackets with one multiplier outside, such as 3(x + 2).
- [[double bracket]] — two bracketed expressions multiplied together, such as (x + 2)(x + 3).
- [[area model]] — a rectangle diagram that shows expansion as length x width split into sub-rectangles.
- [[sign handling]] — the careful use of positive and negative signs when multiplying terms.

## Breadcrumbs

### Breadcrumb 1: The Distributive Law

**Builds on:** [[1.4 Breadcrumb 1|Multiplication as Equal Groups]] (multiplying distributes over adding), [[1.4 Breadcrumb 3|Multiplication as Arrays]] (area model preview)

The [[distributive law]] connects multiplication and addition:

```text
a(b + c) = ab + ac
```

Example:

```text
3(x + 2) = 3x + 6
```

The 3 outside multiplies both `x` and `2`.

> [!important] Every inside term gets multiplied
> If there are three terms inside, the outside multiplier hits all three:

```text
2(x + 4 - 1) = 2x + 8 - 2
```

#### Chunked Example
Question: Expand `4(x + 5)`.

Step 1: Identify the outside multiplier — 4.

Step 2: Multiply 4 by each term inside the bracket.

```text
4 x x = 4x
4 x 5 = 20
```

Step 3: Write the result without brackets.

Answer: **4x + 20**.

### Breadcrumb 2: Expanding a Single Bracket

**Builds on:** [[2.3 Breadcrumb 1|The Distributive Law]] (direct application), [[2.2 Breadcrumb 4|Collecting Like Terms to Simplify]] (expand then simplify)

A [[single bracket]] has one multiplier outside one pair of brackets.

General pattern:

```text
k(ax + by + c) = kax + kby + kc
```

After expanding, you can often simplify.

```text
3(2x + 1) = 6x + 3
```

> [!tip] Arrow method
> Draw arrows from the outside number to each inside term. One arrow per multiplication.

```text
      3
     / \
  2x   1
  ↓    ↓
 6x   3
```

#### Chunked Example
Question: Expand and simplify `2(3x - 1) + 4`.

Step 1: Expand the bracket.

```text
2(3x - 1) = 6x - 2
```

Step 2: Add the remaining term.

```text
6x - 2 + 4
```

Step 3: Collect like terms.

```text
6x + 2
```

Answer: **6x + 2**.

### Breadcrumb 3: Sign Handling with Negatives

**Builds on:** [[1.8 Breadcrumb 6|Adding Negative Numbers]] (negative multiplier changes signs), [[2.3 Breadcrumb 2|Expanding a Single Bracket]] (same method, careful with signs)

[[sign handling]] is where most expansion errors happen.

When the multiplier is negative:

```text
-3(x + 2) = -3x - 6
```

The negative sign applies to **every** inside term:

```text
-(x - 4) = -x + 4
```

> [!warning] Common sign mistake
> Expanding `-(x - 4)` as `-x - 4` is wrong. The minus must flip **both** signs inside.

```text
-(x - 4) = -x + 4   ✓
-(x - 4) = -x - 4   ✗
```

#### Chunked Example
Question: Expand `-2(x - 5)`.

Step 1: Multiply -2 by the first inside term.

```text
-2 x x = -2x
```

Step 2: Multiply -2 by the second inside term.

```text
-2 x (-5) = +10
```

Step 3: Combine.

Answer: **-2x + 10**.

### Breadcrumb 4: The Area Model for Expansion

**Builds on:** [[1.4 Breadcrumb 3|Multiplication as Arrays]] (rows x columns = area), [[2.3 Breadcrumb 1|The Distributive Law]] (area model shows the same operation)

The [[area model]] treats multiplication as the area of a rectangle.

For `3(x + 2)`:

```text
        x        2
    +-------+-------+
  3 |  3x   |   6   |
    +-------+-------+
```

Total area = `3x + 6`, matching the distributive law.

For double-bracket expansion `(x + 2)(x + 3)`:

```text
           x          3
      +---------+---------+
  x   |   x²    |   3x    |
      +---------+---------+
  2   |   2x    |    6    |
      +---------+---------+
```

Total area: `x² + 3x + 2x + 6`.

Here `x²` means `x x x` — the variable multiplied by itself. This builds on [[1.4 Breadcrumb 1|Multiplication as Equal Groups]]: `x` copies of `x` equals `x²`.

> [!example] Why the area model works
> The rectangle's total width is `(x + 2)` and total height is `(x + 3)`. Splitting the rectangle into four smaller rectangles is exactly the same as multiplying each pair of parts.

#### Chunked Example
Question: Use the area model to expand `(x + 1)(x + 4)`.

Step 1: Draw a rectangle split into four regions.

```text
           x          4
      +---------+---------+
  x   |   x²    |   4x    |
      +---------+---------+
  1   |   x     |    4    |
      +---------+---------+
```

Step 2: Add the four areas.

```text
x² + 4x + x + 4
```

Step 3: Collect like terms.

Answer: **x² + 5x + 4**.

### Breadcrumb 5: Expanding Double Brackets

**Builds on:** [[2.3 Breadcrumb 4|The Area Model for Expansion]] (area model becomes the FOIL method), [[2.3 Breadcrumb 1|The Distributive Law]] (applied twice)

A [[double bracket]] means two bracketed expressions multiplied together.

Method: multiply **each term in the first bracket** by **each term in the second bracket**.

For `(x + 2)(x + 3)`:

```text
x x x = x²
x x 3 = 3x
2 x x = 2x
2 x 3 = 6
```

Result: `x² + 3x + 2x + 6 = x² + 5x + 6`.

This is sometimes called FOIL (First, Outer, Inner, Last) — a memory aid, not a separate rule.

> [!important] Four products, then simplify
> A double bracket with two terms each gives four products. Always collect like terms at the end.

#### Chunked Example
Question: Expand `(x + 3)(x - 2)`.

Step 1: Multiply First terms.

```text
x x x = x²
```

Step 2: Multiply Outer and Inner terms.

```text
x x (-2) = -2x
3 x x = 3x
```

Step 3: Multiply Last terms.

```text
3 x (-2) = -6
```

Step 4: Collect like terms.

```text
x² - 2x + 3x - 6 = x² + x - 6
```

Answer: **x² + x - 6**.

### Breadcrumb 6: Loop Unrolling in CS

**Builds on:** [[1.4 Breadcrumb 8|Nested Loops]] (compact loops vs explicit expansion), [[2.3 Breadcrumb 1|The Distributive Law]] (expanding a compact expression)

Expanding brackets is like **loop unrolling** in programming — replacing one compact loop with repeated explicit steps.

Compact form (brackets):

```python
total = k * (a + b + c)
```

Unrolled form (expanded):

```python
total = k * a + k * b + k * c
```

Both compute the same value. The expanded version makes each individual multiplication visible.

Compilers sometimes expand small loops for speed:

```python
# Before unrolling
for i in range(3):
    total += arr[i]

# After unrolling (conceptually)
total += arr[0]
total += arr[1]
total += arr[2]
```

> [!example] CS connection
> Symbolic maths tools expand expressions before further simplification. The distributive law is applied automatically — the same rule you use by hand.

#### Chunked Example
Question: Rewrite `k * (x + y + z)` as an expanded sum, like loop unrolling.

Step 1: Identify the outside multiplier — `k`.

Step 2: Apply the distributive law to each term.

```text
k x x = kx
k x y = ky
k x z = kz
```

Step 3: Write as a sum.

Answer: **kx + ky + kz**.

## Why This Works

The distributive law works because multiplication distributes over addition — you are counting equal groups.

If `3(x + 2)` means "3 copies of `(x + 2)`":

```text
(x + 2) + (x + 2) + (x + 2) = 3x + 6
```

This is the same repeated-addition idea from [[1.4 Breadcrumb 2|Multiplication as Repeated Addition]].

For double brackets, the area model shows that splitting a rectangle into parts does not change the total area.

Expanding and simplifying are opposite directions on the same expression. Expanding makes structure visible; simplifying makes it compact.

## Common Mistakes

- Multiplying only the first term inside: `3(x + 2) = 3x + 2` instead of **3x + 6**.
- Sign errors with negatives: `-2(x - 3) = -2x - 6` instead of **-2x + 6**.
- Forgetting to multiply the constant: `4(x + 1) = 4x + 1` instead of **4x + 4**.
- Missing a product in double brackets — there are always four for two-term brackets.
- Not collecting like terms after double-bracket expansion.

## Where This Shows Up in CS

The distributive law appears wherever code transforms compact expressions into explicit steps:

```python
# Compact
result = scale * (a + b + c)

# Expanded (same meaning)
result = scale * a + scale * b + scale * c
```

Uses include:

- compiler loop unrolling
- SIMD vectorisation (expanding operations across lanes)
- symbolic algebra in SymPy and Mathematica
- query planners expanding aggregate expressions

In SymPy:

```python
from sympy import symbols, expand
x = symbols('x')
expand(3*(x + 2))        # 3*x + 6
expand((x + 2)*(x + 3))  # x**2 + 5*x + 6
```
