## Introduction

An **inequality** compares two quantities using "greater than" or "less than" instead of equals. Where an equation asks "what value makes both sides the same?", an inequality asks "what values make this comparison true?" The answer is usually **many numbers**, not just one. You describe those numbers as a **solution set** and show them on a **number line interval**.

Four **inequality symbols** (`<`, `>`, `≤`, `≥`) express the comparison. **Strict vs inclusive** tells you whether the boundary value is allowed. Solving inequalities works like solving equations, with one extra rule: **flipping when multiplying by negatives**.

> [!example] Everyday idea
> "You must be at least 13 to use this app." That means age ≥ 13. Ages 13, 14, 100 all work; age 12 does not.

## New Words

- [[inequality symbols]] — the comparison signs `<`, `>`, `≤`, and `≥` that show order between quantities.
- [[solution set]] — all values of the variable that make an inequality true.
- [[number line interval]] — a shaded section of a number line showing which values belong to the solution set.
- [[strict vs inclusive]] — whether the boundary value is included (`≤`, `≥`) or excluded (`<`, `>`).
- [[flipping when multiplying by negatives]] — reversing the inequality sign when both sides are multiplied or divided by a negative number.

### Breadcrumb 1: Inequality Symbols

**Builds on:** [[1.1 Breadcrumb 8|Comparing Numbers]] (greater/less than comparisons), [[1.8 Breadcrumb 1|What Negative Numbers Are]] (number line extends left of zero)

[[inequality symbols]] compare two quantities:

```text
<   less than
>   greater than
≤   less than or equal to
≥   greater than or equal to
```

> [!tip] Reading the symbols
> The open side of `<` or `>` points toward the larger value.

#### Chunked Example
Question: Write "x is greater than 5" using a symbol.

Step 1: "Greater than" uses `>`.

Step 2: `x` is on the left, 5 on the right.

```text
x > 5
```

Answer: **x > 5**

### Breadcrumb 2: Strict vs Inclusive

**Builds on:** [[2.7 Breadcrumb 1|Inequality Symbols]] (understanding the symbols), [[1.1 Breadcrumb 1|Counting Numbers]] (inclusive/exclusive boundaries)

[[strict vs inclusive]] tells you whether the boundary number itself is allowed.

```text
x > 5    strict — 5 is NOT included
x ≥ 5    inclusive — 5 IS included
x < 3    strict — 3 is NOT included
x ≤ 3    inclusive — 3 IS included
```

On a number line:

- **Strict** (`<`, `>`): open circle at the boundary
- **Inclusive** (`≤`, `≥`): closed (filled) circle at the boundary

> [!important] "At least" means inclusive
> "At least 13" means 13 or more → `age ≥ 13`.

#### Chunked Example
Question: Describe the [[solution set]] of `x ≥ 4` in words.

Step 1: `≥` means "greater than or equal to" — inclusive.

Step 2: All numbers from 4 upward work.

Answer: **All numbers greater than or equal to 4**, including 4 itself.

### Breadcrumb 3: Solving Inequalities Like Equations

**Builds on:** [[2.7 Breadcrumb 1|Inequality Symbols]] (what we are solving for), [[2.5 Breadcrumb 4|Two-Step Equations]] (same inverse method), [[2.5 Breadcrumb 6|Always Check by Substitution]] (test values)

You solve many inequalities the same way as [[2.5 Solving Linear Equations]] — using balancing and [[inverse operations]] — except the answer is a range, not a single value.

```text
x + 3 > 7
x > 4
```

The [[solution set]] is all numbers greater than 4.

> [!warning] Show the inequality sign on every line
> Do not write `=` while solving an inequality unless you have changed the problem to an equation.

#### Chunked Example
Question: Solve `2x + 1 ≤ 9`.

Step 1: Subtract 1 from both sides.

```text
2x ≤ 8
```

Step 2: Divide both sides by 2.

```text
x ≤ 4
```

Step 3: Test a value in the set, e.g. `x = 4`.

```text
2(4) + 1 = 9 ≤ 9  ✓
```

Test outside: `x = 5` gives `11 ≤ 9` ✗

Answer: **x ≤ 4** (all numbers less than or equal to 4).

### Breadcrumb 4: Number Line Intervals

**Builds on:** [[2.7 Breadcrumb 2|Strict vs Inclusive]] (open vs closed circles), [[1.8 Breadcrumb 2|The Number Line Extended Left]] (negative values on number line)

A [[number line interval]] shows the [[solution set]] visually.

Rules:

- Shade the direction where values satisfy the inequality
- Open circle ○ for strict (`<`, `>`)
- Closed circle ● for inclusive (`≤`, `≥`)

```text
x > 2:

    ○----->=======>
    0   1   2   3   4   5
        shade right from open circle at 2
```

> [!example] Negative numbers on the line
> For `x < -1`, shade left from an open circle at -1. Negative solutions appear to the left of zero.

#### Chunked Example
Question: Represent `x ≤ 3` on a number line.

Step 1: Inclusive boundary at 3 — use a closed circle.

Step 2: `≤` means "less than or equal to" — shade left.

```text
<=======●
-2  -1   0   1   2   3   4
            closed circle at 3, shade left
```

Answer: Closed circle at **3**, shade **all numbers to the left**, including 3.

### Breadcrumb 5: Flipping When Multiplying by Negatives

**Builds on:** [[2.7 Breadcrumb 3|Solving Inequalities Like Equations]] (same steps, extra rule), [[1.8 Breadcrumb 5|Ordering Negative Numbers]] (negatives reverse order)

When you multiply or divide **both sides** of an inequality by a **negative number**, you must **flip** the sign. This is [[flipping when multiplying by negatives]].

```text
-x > 4
x < -4        (sign flipped)
```

Why? Multiplying by a negative reverses order on the number line. What was "greater" becomes "less" when viewed from the other direction.

> [!failure] Mistake pattern
> Forgetting to flip is the most common inequality error. `-2x > 6` gives `x < -3`, not `x > -3`.

#### Chunked Example
Question: Solve `-3x ≥ 12`.

Step 1: Divide both sides by -3.

Step 2: **Flip** the sign because you divided by a negative.

```text
x ≤ -4
```

Step 3: Test `x = -4`.

```text
-3(-4) = 12 ≥ 12  ✓
```

Test `x = -3` (should fail):

```text
-3(-3) = 9 ≥ 12  ✗
```

Answer: **x ≤ -4**

### Breadcrumb 6: Solution Sets and Bounds in CS

**Builds on:** [[2.7 Breadcrumb 3|Solving Inequalities Like Equations]] (finding the range), [[2.7 Breadcrumb 4|Number Line Intervals]] (visualising ranges)

The [[solution set]] is the complete collection of values that satisfy an inequality.

In computer science, inequalities describe **bounds** — limits on how large or small something can grow.

```text
n > 100        — input must exceed 100 for the rule to apply
time ≤ 2n      — runtime grows no faster than twice n
memory ≥ 1024  — at least 1024 bytes required
```

Program validation often uses inequalities:

```python
if age >= 13:
    allow_access()
if len(password) < 8:
    reject("too short")
```

> [!example] CS connection
> Big-O notation means runtime is **bounded above** by a linear function for large `n`. Inequalities are the language of those bounds.

#### Chunked Example
Question: A program requires `0 ≤ index < length`. If `length = 5`, list valid integer values of `index`.

Step 1: `≥ 0` means 0 is included.

Step 2: `< 5` means 5 is excluded.

Step 3: Valid integers: 0, 1, 2, 3, 4.

Answer: **{0, 1, 2, 3, 4}** — the same half-open interval pattern used for array bounds in many languages.

## Why This Works

Inequalities describe **order** on the number line, not just equality.

Most steps preserve order because balancing with addition, subtraction, and multiplication/division by **positive** numbers keeps the comparison direction the same.

Multiplying or dividing by a negative reverses order — a key idea from [[1.8 Negative Numbers]]. That is why the sign must flip.

If:

```text
-x > 4
```

then multiplying both sides by -1 gives:

```text
x < -4
```

The [[solution set]] changed form but the same numbers satisfy the original comparison.

This connects to [[2.5 Solving Linear Equations]] (same inverse steps) and to the bounding concepts used in [[10.1 Big O Theta and Omega]].

## Common Mistakes

- Forgetting to flip the sign when dividing or multiplying by a negative.
- Using an open circle when the boundary is inclusive (`≤`, `≥`).
- Shading the wrong direction on the number line.
- Treating `x > 5` as "x equals 5" — 5 is excluded in strict inequalities.
- Confusing `<` and `>` — test one value to verify your shading.
- Writing `x = 4` as the answer to `2x + 1 ≤ 9` — the answer is a **set** (`x ≤ 4`), not one number.

> [!failure] Mistake pattern
> `-2x > 6` → `x > -3` is wrong. Correct: divide by -2 and flip → `x < -3`.

## Where This Shows Up in CS

Inequalities appear everywhere programs make **range decisions**.

**Input validation:**

```python
if 0 <= score <= 100:
    save_score(score)
```

**Array bounds:**

```python
if 0 <= index < len(items):
    return items[index]
```

**Algorithm complexity:**

```text
If n > 1000, use the fast algorithm.
Runtime T(n) satisfies T(n) ≤ 5n + 10 for large n.
```

**Branch conditions:**

```python
if temperature < 0:
    print("freezing")
elif temperature >= 100:
    print("boiling")
```

**Pagination:**

```python
if offset >= total_count:
    return empty_page()
```

Every `if` comparing numbers is an inequality. Getting `<` vs `≤` wrong causes off-by-one bugs — the same class of error as array index mistakes.
