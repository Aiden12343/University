## Introduction

A **coordinate plane** is a flat grid where every point is named by two numbers: how far across and how far up. The **x-axis** runs horizontally, the **y-axis** runs vertically, and they cross at the **origin** `(0, 0)`. Every point has an ordered **coordinate pair** `(x, y)`. The axes divide the plane into four **quadrants**.

Coordinates turn "a bit to the right and a bit up" into exact numbers. That precision is what lets programs draw pixels, plot data, and move objects in game worlds.

> [!example] Everyday idea
> A chess board can be read as coordinates: column then row. The square at column 4, row 2 is not the same as column 2, row 4. Order matters — the same idea as `(x, y)`.

## New Words

- [[x-axis]] — the horizontal number line where the first coordinate is read.
- [[y-axis]] — the vertical number line where the second coordinate is read.
- [[origin]] — the point `(0, 0)` where the axes cross.
- [[coordinate pair]] — an ordered pair `(x, y)` naming one point.
- [[quadrant]] — one of the four regions of the plane, numbered I to IV.

## Breadcrumbs

### Breadcrumb 1: The Two Axes Form a Grid

**Builds on:** [[1.2 Breadcrumb 2|Number Lines]] (one-dimensional position), [[1.8 Breadcrumb 1|What Negative Numbers Are]] (values extend left)

The [[x-axis]] is the horizontal line. Positive x goes to the right; negative x goes to the left.

The [[y-axis]] is the vertical line. Positive y goes up; negative y goes down.

They cross at the [[origin]] `(0, 0)`.

The axes divide the plane into four regions:

| Quadrant | x sign | y sign |
|----------|--------|--------|
| I        | +      | +      |
| II       | −      | +      |
| III      | −      | −      |
| IV       | +      | −      |

This extends the number line into two dimensions. Every point needs **two** numbers, not one.

> [!important] Order is fixed
> In `(x, y)`, the **first** number is always horizontal (x) and the **second** is always vertical (y). `(3, 2)` and `(2, 3)` are different points.

#### Chunked Example
Question: Name the horizontal axis, the vertical axis, and the point where they meet.

Step 1: The horizontal axis is the **x-axis**.

Step 2: The vertical axis is the **y-axis**.

Step 3: Where they cross is the **origin** at `(0, 0)`.

Answer: **x-axis** (horizontal), **y-axis** (vertical), **origin** at `(0, 0)`.

### Breadcrumb 2: Reading a Coordinate Pair

**Builds on:** [[3.1 Breadcrumb 1|The Two Axes Form a Grid]] (you know the axes), [[1.2 Breadcrumb 3|Ordering Numbers]] (first then second)

A [[coordinate pair]] `(x, y)` tells you how to reach a point from the origin.

To plot `(4, 3)`:

Step 1: Start at the origin.

Step 2: Move **4** units along the x-axis (right, because x is positive).

Step 3: From there, move **3** units parallel to the y-axis (up, because y is positive).

```mermaid
xychart-beta
  x-axis "x" [0, 1, 2, 3, 4]
  y-axis "y" 0 --> 4
  line [0, 0, 0, 0, 0]
```

> [!warning] Common plotting mistake
> Do not swap the numbers. `(4, 3)` means x = 4 first, then y = 3. Swapping gives a different point.

#### Chunked Example
Question: Describe how to plot `(-2, 5)`.

Step 1: Start at the origin.

Step 2: Move **2** units **left** (x is negative).

Step 3: Move **5** units **up** (y is positive).

Answer: The point is in **Quadrant II** (left and up from the origin).

### Breadcrumb 3: Negative Coordinates

**Builds on:** [[3.1 Breadcrumb 2|Reading a Coordinate Pair]] (moving in both directions), [[1.8 Breadcrumb 2|The Number Line Extended Left]] (negatives go left/down)

Negative numbers now appear on **both** axes.

- Positive x → right; negative x → left.
- Positive y → up; negative y → down.

| Example    | Direction         | Quadrant |
|------------|-------------------|----------|
| `(3, -1)`  | right 3, down 1   | IV       |
| `(-4, -2)` | left 4, down 2    | III      |
| `(-1, 4)`  | left 1, up 4      | II       |
| `(2, 2)`   | right 2, up 2     | I        |

Points **on** an axis are not in any quadrant. `(0, 5)` is on the y-axis; `(3, 0)` is on the x-axis.

> [!example] CS connection
> Screen coordinates often use `(x, y)` for pixel position, but some graphics systems put the origin at the top-left and y increases **downward**. Always check which convention a system uses.

#### Chunked Example
Question: In which quadrant is `(-5, 1)`?

Step 1: x = −5 → negative → left of the y-axis.

Step 2: y = 1 → positive → above the x-axis.

Step 3: Negative x and positive y → **Quadrant II**.

Answer: **Quadrant II**.

### Breadcrumb 4: Finding Coordinates from a Point

**Builds on:** [[3.1 Breadcrumb 2|Reading a Coordinate Pair]] (reversing the process)

Reading coordinates from a graph is the reverse of plotting.

From a point on a grid:

Step 1: Draw a vertical line down to the x-axis. Read x.

Step 2: Draw a horizontal line across to the y-axis. Read y.

Step 3: Write `(x, y)`.

> [!important] Read x first, then y
> This matches the order in every [[coordinate pair]]. Consistency prevents swapped answers.

#### Chunked Example
Question: A point is 3 units right of the origin and 7 units up. Write its coordinates.

Step 1: Right 3 → x = 3.

Step 2: Up 7 → y = 7.

Answer: **`(3, 7)`**.

### Breadcrumb 5: Coordinates as Data Points

**Builds on:** [[3.1 Breadcrumb 1|The Two Axes Form a Grid]] (plotting points from data)

A list of coordinate pairs can represent measured data:

| Time (x) | Height (y) |
|----------|------------|
| 0        | 0          |
| 1        | 2          |
| 2        | 4          |
| 3        | 6          |

Each row is one [[coordinate pair]]. Plotting them reveals a pattern — here a straight line.

> [!example] CS connection
> In a scatter plot library, data is often stored as arrays of `(x, y)` pairs:

```python
points = [(0, 0), (1, 2), (2, 4), (3, 6)]
for x, y in points:
    draw_pixel(x, y)
```

The same structure appears in CSV files, sensor logs, and game entity positions.

#### Chunked Example
Question: List the coordinate pairs from the table above.

Answer: **(0, 0), (1, 2), (2, 4), (3, 6)**.

## Why This Works

Coordinates work because two independent number lines — built from [[1.2 Breadcrumb 2|Number Lines]] and [[1.8 Breadcrumb 2|The Number Line Extended Left]] — can describe any flat location uniquely.

The x value fixes horizontal position. The y value fixes vertical position. Together they pin down exactly one point. No other point shares the same `(x, y)`.

Question: A sprite is at pixel `(120, 80)` on a 1920×1080 screen. Is it in the top-left or bottom-right half?

Solution: x = 120 is near the left (of 1920). y = 80 is near the top (if y increases downward). The sprite is in the **top-left** region.

## Common Mistakes

- Swapping x and y: writing `(2, 5)` when the point is 5 across and 2 up.
- Forgetting that `(−3, 0)` is on the x-axis, not in a quadrant.
- Counting grid squares from 1 instead of from 0 when the origin is labelled 0.
- Assuming y always increases upward — graphics APIs may use y-down.
- Plotting only one coordinate and ignoring the other.

> [!failure] Mistake pattern
> If your point lands in the wrong quadrant, check the **signs** of x and y before redrawing.

## Where This Shows Up in CS

Coordinates appear in:

- **Pixel positions** — `(x, y)` on screens and images
- **Mouse and touch events** — click at `(340, 512)`
- **Game worlds** — entity positions and collision boxes
- **Graphs and charts** — plotting time series and benchmarks
- **GPS and maps** — latitude/longitude as ordered pairs
- **3D graphics** — `(x, y, z)` extends the same idea to depth

```python
rect_x, rect_y = 50, 100   # top-left corner
width, height = 200, 80
# corners: (50,100), (250,100), (250,180), (50,180)
```
