## Introduction

Some functions do not use one formula for all inputs. A **piecewise rule** gives different formulas on different **intervals** of the input. An **interval** is a continuous range of input values. **Step functions** stay constant on each interval and jump at the boundaries. The **floor function** ⌊x⌋ rounds down to the nearest integer; the **ceiling function** ⌈x⌉ rounds up.

> [!example] Everyday idea
> A taxi might charge £3 for the first mile and £2 for each mile after that. The price rule changes when the distance crosses 1 mile.

## New Words

- [[piecewise rule]] — a function defined by different formulas on different input intervals.
- [[interval]] — a continuous range of input values, often shown with inequality notation.
- [[step function]] — a piecewise constant function whose graph looks like steps.
- [[floor function]] — the greatest integer less than or equal to x, written ⌊x⌋.
- [[ceiling function]] — the smallest integer greater than or equal to x, written ⌈x⌉.

## Breadcrumbs

### Breadcrumb 1: Piecewise Notation

**Builds on:** [[3.2 Breadcrumb 1|What Is a Function]] (one input → one output), [[2.7 Breadcrumb 2|Inequality Notation]] (conditions on x)

A [[piecewise rule]] combines several formulas with conditions:

```text
f(x) = {  x + 1,    if x < 0
       {  x²,       if 0 ≤ x ≤ 2
       {  5,         if x > 2
```

Read: "choose the formula whose condition matches the input x."

> [!important] Exactly one rule must apply
> Every allowed input must match **exactly one** interval. Overlaps or gaps break the definition.

#### Chunked Example
Question: For the rule above, find f(-2), f(1), and f(4).

-2 < 0 → f(-2) = -2 + 1 = -1.
0 ≤ 1 ≤ 2 → f(1) = 1² = 1.
4 > 2 → f(4) = 5.

Answer: **f(-2) = -1, f(1) = 1, f(4) = 5**.

---

### Breadcrumb 2: Intervals and Endpoint Inclusion

**Builds on:** [[3.10 Breadcrumb 1|Piecewise Notation]] (conditions use intervals), [[2.7 Breadcrumb 3|Compound Double Inequalities]] (a ≤ x ≤ b form)

An [[interval]] is a range of inputs.

```text
a < x < b     open interval (a, b)       endpoints excluded
a ≤ x ≤ b     closed interval [a, b]     both endpoints included
a ≤ x < b     half-open [a, b)           left included, right excluded
```

On a graph: **closed** → filled dot (●); **open** → hollow dot (○).

> [!warning] Check ≤ vs <
> `x < 2` excludes 2. `x ≤ 2` includes 2. One wrong symbol changes the answer.

#### Chunked Example
Question: Which rule applies at x = 2?

```text
f(x) = {  2x,   if x < 2
       {  x + 3, if x ≥ 2
```

2 < 2 is false; 2 ≥ 2 is true → use second rule: f(2) = 2 + 3 = 5.

Answer: **f(2) = 5** using the second rule.

---

### Breadcrumb 3: Graphing Piecewise Functions

**Builds on:** [[3.10 Breadcrumb 2|Intervals and Endpoint Inclusion]] (open/closed dots), [[3.1 Breadcrumb 4|Plotting Points]] (each point gets plotted)

To graph a piecewise function:
1. Draw each piece separately on its interval.
2. Mark endpoints as open or closed.
3. Check that pieces meet or jump at boundaries.

> [!tip] Boundary checklist
> At every breakpoint, evaluate both neighbouring rules if the endpoint is included in either interval. A jump means a step; matching values mean the graph connects.

#### Chunked Example
Question: Sketch the key features of:

```text
f(x) = {  -1,  if x < 0
       {   x,  if 0 ≤ x < 2
       {   4,  if x ≥ 2
```

x < 0: constant -1 (horizontal line).

0 ≤ x < 2: y = x (segment from (0,0) to approaching (2,2)).

x ≥ 2: constant 4 starting at (2,4).

Endpoints: (0,0) closed, (2,2) open, (2,4) closed.

Answer: Graph has a step at **x = 2** from height 2 (open) to height 4 (closed).

### Breadcrumb 4: Step Functions

**Builds on:** [[3.10 Breadcrumb 3|Graphing Piecewise Functions]] (jumps at boundaries), [[3.10 Breadcrumb 2|Intervals and Endpoint Inclusion]] (flat on each interval)

A [[step function]] is constant on each interval and jumps at boundaries.

Example — postage tiers:

```text
cost(grams) = {  1.00,  if 0 ≤ g ≤ 100
              {  1.50,  if 100 < g ≤ 250
              {  2.00,  if g > 250
```

The graph looks like stairs: flat steps with vertical jumps.

> [!example] Flat then jump
> On each step, changing the input slightly does not change the output until you hit the next boundary.

#### Chunked Example
Question: A step function is f(x) = 3 for 0 ≤ x < 1, and f(x) = 5 for 1 ≤ x < 2. Find f(0.5), f(1), and f(1.5).

0.5 in [0,1) → f(0.5) = 3. 1 in [1,2) → f(1) = 5. 1.5 in [1,2) → f(1.5) = 5.

Answer: **f(0.5) = 3, f(1) = 5, f(1.5) = 5**.

---

### Breadcrumb 5: The Floor Function ⌊x⌋

**Builds on:** [[3.10 Breadcrumb 4|Step Functions]] (constant between integers, jumps at integers), [[1.1 Breadcrumb 2|Integers vs Non-Integers]] (identifying integers)

The [[floor function]] gives the greatest integer **less than or equal to** x.

```text
⌊3.7⌋ = 3
⌊3⌋ = 3
⌊-2.3⌋ = -3
```

Think: slide left on the number line until you hit an integer.

> [!warning] Floor of negatives
> ⌊-2.3⌋ = -3, not -2. "Greatest integer ≤ -2.3" means -3.

#### Chunked Example
Question: Evaluate ⌊4.9⌋, ⌊-1⌋, and ⌊-1.1⌋.

⌊4.9⌋ = 4 (greatest integer ≤ 4.9). ⌊-1⌋ = -1. ⌊-1.1⌋ = -2.

Answer: **4, -1, -2**.

---

### Breadcrumb 6: The Ceiling Function ⌈x⌉

**Builds on:** [[3.10 Breadcrumb 5|The Floor Function ⌊x⌋]] (opposite rounding direction), [[1.1 Breadcrumb 2|Integers vs Non-Integers]] (next integer up)

The [[ceiling function]] gives the smallest integer **greater than or equal to** x.

```text
⌈3.2⌉ = 4
⌈3⌉ = 3
⌈-2.3⌉ = -2
```

Think: slide right on the number line until you hit an integer.

Floor and ceiling are linked: ⌈x⌉ = -⌊-x⌋.

> [!important] Floor vs ceiling direction
> Floor rounds down; ceiling rounds up. For integers they agree; for non-integers they differ.

#### Chunked Example
Question: Evaluate ⌈2.01⌉, ⌈-2.01⌉, and ⌈5⌉.

⌈2.01⌉ = 3. ⌈-2.01⌉ = -2. ⌈5⌉ = 5.

Answer: **3, -2, 5**.

### Breadcrumb 7: Piecewise Functions in Code

**Builds on:** [[3.10 Breadcrumb 1|Piecewise Notation]] (conditions and formulas), [[2.7 Breadcrumb 5|Inequalities as Range Boundaries in CS]] (branch conditions)

In CS, [[piecewise rule]] logic is written as **if/else chains** or **switch** statements:

```python
def postage(grams):
    if grams <= 100:
        return 1.00
    elif grams <= 250:
        return 1.50
    else:
        return 2.00
```

Each branch is one interval's formula. Conditions must cover all valid inputs without overlap.

> [!example] Pricing tiers
> If usage ≤ 1000: charge = usage × 0.01. Else: charge = 10 + (usage - 1000) × 0.008.

#### Chunked Example
Question: Write a Python-style if/else chain for:

```text
f(x) = {  0,   if x < 0
       {  x,   if 0 ≤ x ≤ 10
       {  10,  if x > 10
```

```python
if x < 0:
    return 0
elif x <= 10:
    return x
else:
    return 10
```

### Breadcrumb 8: Floor and Ceiling in Programming

**Builds on:** [[3.10 Breadcrumb 6|The Ceiling Function ⌈x⌉]] (rounding up), [[3.10 Breadcrumb 5|The Floor Function ⌊x⌋]] (rounding down)

Most languages provide floor and ceiling:

```python
import math
math.floor(3.7)   # 3
math.ceil(3.7)    # 4
```

Integer division floors for non-negative numbers: `7 // 3 → 2`.

**Array indexing:** `index = floor(x / slot_width)`

**Memory allocation:** `pages = ceil(bytes / page_size)`

> [!warning] Negative division differs by language
> In Python `//` floors. In some languages integer division truncates toward zero.

#### Chunked Example
Question: A file is 5000 bytes. Each page holds 4096 bytes. How many pages are needed?

5000 / 4096 ≈ 1.22. ⌈5000 / 4096⌉ = 2.

Answer: **2 pages**.

## Why This Works

Piecewise functions partition the input domain into intervals and assign one formula per partition. [[2.7 Inequalities]] tell you which inputs belong where. [[3.2 Function Notation and Mapping]] ensures each input still maps to exactly one output.

Step functions are the special case where each formula is constant. Floor and ceiling are standard step functions defined on all real numbers.

The link to code is direct: an if/else chain is a piecewise definition.

Question: If f(x) = 2x for x < 1 and f(x) = 5 for x ≥ 1, find f(0.5) and f(3).

## Common Mistakes

- Using the wrong interval at a boundary (check ≤ vs <).
- Forgetting floor of negative goes more negative (⌊-1.1⌋ = -2).
- Confusing floor and ceiling (floor down, ceiling up).
- Leaving gaps or overlaps in piecewise definitions.
- Plotting the wrong endpoint open/closed at a jump.
- Writing if/else conditions in the wrong order in code.

> [!failure] Mistake pattern
> If f(2) disagrees with your graph, re-read both rules that touch x = 2. One symbol (< vs ≤) is usually the cause.

## Where This Shows Up in CS

**Pricing tiers** — Cloud storage, API calls, and phone plans charge different rates on different usage bands.

**Conditionals** — Every if/else chain implementing different behaviour on different input ranges is a piecewise function.

**Quantisation** — Mapping continuous sensor readings to discrete levels (low/medium/high).

**Floor and ceiling** — Math.floor, Math.ceil, integer division, array binning, pagination, memory page allocation.

**Graphics** — Piecewise linear interpolation between keyframes.
