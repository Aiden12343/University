## Introduction

A **function** is a rule that takes each allowed **input** and produces exactly one **output**. Function notation turns that idea into symbols like `f(x) = 2x + 1`. The same structure appears in programming: a function name, a parameter, and a return value.

The **domain** is the set of all allowed inputs. The **range** is the set of all possible outputs. Functions can be shown with formulas, tables, mapping diagrams, or graphs — but every representation must obey the one-input-one-output rule.

> [!example] Everyday idea
> A vending machine: you put in money (input), press a code, and get one snack (output). The same code with the same money should always give the same snack — one input, one output.

## New Words

- [[function]] — a rule that assigns exactly one output to each allowed input.
- [[input]] — the value you put into a function, often written as x.
- [[output]] — the value a function returns for a given input, often written as f(x) or y.
- [[domain]] — the set of all input values a function is allowed to accept.
- [[range]] — the set of all output values the function can actually produce.

## Breadcrumbs

### Breadcrumb 1: Functions as Input–Output Rules

**Builds on:** [[3.1 Breadcrumb 5|Coordinates as Data Points]] (pairs of values), [[2.1 Breadcrumb 1|What a Variable Is]] (x stands for a number)

A [[function]] is not just any formula. It is a rule with a strict contract:

- every allowed **input** gets exactly one **output**
- the same input always gives the same output

Think of a function as a machine:

```text
input x  --->  [ function rule ]  --->  output f(x)
```

Example rule: "double the input and add 1."

```text
x = 3  --->  2(3) + 1  --->  7
x = 5  --->  2(5) + 1  --->  11
```

> [!important] One input, one output
> If one input could give two different outputs, the rule is **not** a function. This is why "pick a square root of 9" fails as a function unless you restrict to positive roots only.

#### Chunked Example
Question: A rule says "add 4 to the input." Find the output when the input is 6.

Step 1: Identify the input — **6**.

Step 2: Apply the rule — add 4.

```text
6 + 4 = 10
```

Answer: Output = **10**.

### Breadcrumb 2: Function Notation f(x)

**Builds on:** [[3.2 Breadcrumb 1|Functions as Input–Output Rules]] (the rule needs a name), [[2.1 Breadcrumb 2|Expressions vs Equations]] (x is still a variable)

Instead of writing "the output when the input is x," we write **f(x)**.

If:

```text
f(x) = 2x + 1
```

then:

- `f` is the name of the function
- `x` is the input variable
- `f(x)` is the output when the input is `x`

> [!example] Reading f(x)
> `f(3)` means: substitute **3** for `x` in the rule for `f`.

```text
f(x) = 2x + 1
f(3) = 2(3) + 1 = 7
```

#### Chunked Example
Question: If `g(x) = x - 5`, find `g(12)`.

Step 1: Replace `x` with **12**.

```text
g(12) = 12 - 5
```

Step 2: Calculate.

```text
g(12) = 7
```

Answer: **g(12) = 7**.

### Breadcrumb 3: The Domain

**Builds on:** [[3.2 Breadcrumb 1|Functions as Input–Output Rules]] (inputs come from somewhere), [[2.11 Breadcrumb 1|Structure of an Algebraic Fraction]] (division restrictions)

The [[domain]] is the set of inputs the function is **allowed** to use.

Example:

```text
f(x) = 1/x
```

You cannot divide by zero, so **x = 0** is excluded.

Domain: all real numbers **except 0**.

> [!warning] Domain restrictions matter in code
> A function that divides by user input must check for zero before running. A missing domain check causes runtime errors.

#### Chunked Example
Question: `h(x) = 5x + 2` is defined for all real numbers. Is `x = -3` in the domain?

Step 1: Read the domain — all real numbers.

Step 2: Check whether `-3` is a real number — yes.

```text
h(-3) = 5(-3) + 2 = -13
```

Answer: **Yes**, `x = -3` is in the domain. **h(-3) = -13**.

---

### Breadcrumb 4: The Range

**Builds on:** [[3.2 Breadcrumb 3|The Domain]] (outputs depend on domain), [[3.1 Breadcrumb 3|Negative Coordinates]] (y-values can be negative)

The [[range]] is the set of outputs the function **can actually produce**.

For:

```text
f(x) = x^2
```

outputs are never negative (squaring gives 0 or positive).

Range: all real numbers **≥ 0**.

The domain tells you what you may put in. The range tells you what can come out.

> [!tip] Domain vs range
> **Domain** → inputs (horizontal thinking, x-values).
> **Range** → outputs (vertical thinking, y-values).

#### Chunked Example
Question: If `f(x) = 3x + 1`, can the output be 10?

Step 1: Set the output equal to 10.

```text
3x + 1 = 10
```

Step 2: Solve for x.

```text
3x = 9
x = 3
```

Step 3: Since x = 3 is a valid input, **10** is in the range.

Answer: **Yes**, the output **10** is possible when **x = 3**.

### Breadcrumb 5: Mapping Diagrams and Tables

**Builds on:** [[3.2 Breadcrumb 2|Function Notation f(x)]] (functions as pairs), [[3.1 Breadcrumb 5|Coordinates as Data Points]] (tables of values)

Functions can be shown without a formula.

**Table:**

| x  | f(x) |
|----|------|
| 1  | 3    |
| 2  | 5    |
| 3  | 7    |

Here the rule is "multiply by 2, add 1" — the same as `f(x) = 2x + 1`.

> [!failure] Not a function
> If one input appears with two different outputs, the table is **not** a function.

| x  | y  |
|----|----|
| 0  | 1  |
| 1  | 3  |
| 0  | 7  | ← x = 0 has two outputs

#### Chunked Example
Question: Does this table define a function?

| x  | y  |
|----|----|
| 2  | 4  |
| 3  | 6  |
| 4  | 8  |

Step 1: Check each input appears once.

Step 2: All inputs (2, 3, 4) are unique.

Answer: **Yes**, each input gives exactly one output.

### Breadcrumb 6: Functions and Graphs

**Builds on:** [[3.2 Breadcrumb 2|Function Notation f(x)]] (f(x) becomes y), [[3.1 Breadcrumb 5|Coordinates as Data Points]] (plotting (x, y) pairs)

Every function can be graphed on the coordinate plane:

- input → x-coordinate
- output → y-coordinate

For `f(x) = 2x + 1`:

```text
x = 0  →  (0, 1)
x = 1  →  (1, 3)
x = 2  →  (2, 5)
```

```mermaid
xychart-beta
  x-axis "x" [0, 1, 2]
  y-axis "y" 0 --> 6
  line [1, 3, 5]
```

> [!example] CS connection
> In Python, a function maps arguments to a return value:

```python
def f(x):
    return 2 * x + 1

f(3)  # returns 7, same as f(3) in maths
```

#### Chunked Example
Question: If `f(x) = x + 2`, write the coordinates for x = 0, 1, and 2.

Step 1: Evaluate each input.

```text
f(0) = 2   →  (0, 2)
f(1) = 3   →  (1, 3)
f(2) = 4   →  (2, 4)
```

Answer: **(0, 2), (1, 3), (2, 4)**.

## Why This Works

Functions work because they enforce a predictable relationship: given an input in the [[domain]], the rule produces exactly one output in the [[range]].

This is the same logical structure as [[2.1 Breadcrumb 1|What a Variable Is]] — a variable `x` stands for a number, and the function tells you what happens to that number. The difference is that a function names the whole rule (`f`) and separates **input** from **output** (`f(x)`).

## Worked Examples

For fully worked solutions, use [[3.2 Function Notation and Mapping - Worked Examples]].

### Example 1 - Evaluate f(x)
Question: If `f(x) = 3x - 4`, find `f(5)`.

Solution: `f(5) = 3(5) - 4 = 15 - 4 = 11`.

### Example 2 - Find an input
Question: If `g(x) = x + 7`, find x when `g(x) = 15`.

Solution: `x + 7 = 15`, so `x = 8`.

### Example 3 - Apply to CS
Question: What does `hash("hello")` represent in function language?

Solution: `"hello"` is the **input**; the digest string is the **output**; `hash` is the function name.

## Common Mistakes

- Treating `f(x)` as multiplication: `f(x)` does **not** mean `f × x`.
- Confusing domain and range: domain is inputs, range is outputs.
- Forgetting that one input must give only one output.
- Substituting incorrectly: in `f(x) = x^2 + 1`, `f(3)` means `3^2 + 1`, not `3x^2 + 1`.
- Using an input outside the domain, such as `x = 0` in `1/x`.
- Assuming every formula defines a function without checking for duplicate outputs.

> [!failure] Mistake pattern
> If `f(2)` gives two different answers, you do not have a function.

## Where This Shows Up in CS

Functions appear in:

- **Python / Java / C functions** — named rules with parameters and return values
- **API endpoints** — HTTP request maps to response
- **Hash functions** — data maps to fixed-size digest
- **Activation functions** — neuron input maps to output signal
- **Pure functions** — same input always yields same output (important for caching and testing)

```python
def apply_discount(price, rate):
    return price * (1 - rate)

apply_discount(100, 0.2)  # input (100, 0.2) → output 80.0
```
