## Introduction

A **logarithm** answers an exponent question. If `2³ = 8`, then `log₂(8) = 3`. Exponentials start with a power and produce a number; logarithms start with the number and ask which power produced it.

The **base** is the number being raised to a power. The **power** (or exponent) is what the log outputs. A logarithm is an **inverse operation** — it undoes exponentiation. The **log laws** are rules for simplifying logs of products, quotients, and powers.

> [!example] Everyday idea
> If a file doubles in size each backup round, a logarithm answers: "How many doublings did it take to get this large?"

## New Words

- [[logarithm]] — the inverse of exponentiation: the power needed to make a given number from a base.
- [[base]] — the number being raised to a power.
- [[power]] — the exponent that tells how many repeated multiplications are being used.
- [[inverse operation]] — an operation that undoes another operation.
- [[log laws]] — rules for simplifying logarithms of products, quotients, and powers.

## Breadcrumbs

### Breadcrumb 1: Logs Ask for the Power

**Builds on:** [[2.9 Breadcrumb 1|Repeated Multiplication as a Power]] (powers as repeated multiplication), [[3.6 Breadcrumb 1|Exponential Means the Input Is in the Power]] (bˣ form)

The basic conversion is:

```text
2³ = 8
log₂(8) = 3
```

Read it as: "What power of 2 gives 8?" Answer: 3.

> [!important] A logarithm is an answer to a power question
> The output of a log is usually an exponent, not the original number.

#### Chunked Example
Question: Evaluate `log₃(81)`.

Step 1: Translate: 3^? = 81.

Step 2: Powers of 3: 3¹=3, 3²=9, 3³=27, 3⁴=81.

Answer: **log₃(81) = 4**.

---

### Breadcrumb 2: Converting Between Log and Exponential Form

**Builds on:** [[3.7 Breadcrumb 1|Logs Ask for the Power]] (log definition), [[1.3 Breadcrumb 1|Undoing Addition]] (inverse operations undo)

Every logarithm can be rewritten as an exponential:

```text
log_b(a) = c   means   b^c = a
```

The [[base]] is b, the [[power]] is c, and the result is a.

> [!warning] Keep the base in the right place
> `log₂(32) = 5` means `2⁵ = 32`, not `32² = 5`.

#### Chunked Example
Question: Rewrite `log₅(125) = 3` in exponential form.

Base = 5, power = 3 → 5³ = 125.

Answer: **5³ = 125**.

---

### Breadcrumb 3: Logs Undo Exponentials

**Builds on:** [[3.7 Breadcrumb 2|Converting Between Log and Exponential Form]] (exponential → log), [[3.6 Breadcrumb 1|Exponential Means the Input Is in the Power]] (y = bˣ)

Logs and exponentials are [[inverse operation]]s.

If `y = 2ˣ`, then `x = log₂(y)`. So logarithms solve questions where the unknown is in the exponent.

> [!example] Doubling question
> If `2ˣ = 64`, a log asks how many doublings are needed to reach 64.

#### Chunked Example
Question: Solve `2ˣ = 32`.

Step 1: x = log₂(32). Step 2: 2⁵ = 32 → x = 5.

Answer: **x = 5**.

---

### Breadcrumb 4: Common Bases in CS

**Builds on:** [[3.7 Breadcrumb 1|Logs Ask for the Power]] (log evaluates powers), [[1.2 Breadcrumb 2|Decimal Place Value]] (powers of 10)

Different bases answer different scale questions.

- **Base 2** — `log₂(n)` counts doublings or halvings; appears in binary search and tree depth.
- **Base 10** — `log₁₀(n)` counts decimal place scale.
- **Base e** — `ln(n)` is the natural logarithm for calculus, probability, and continuous growth.

> [!important] The base tells you the unit of repeated multiplication

#### Chunked Example
Question: Interpret `log₂(1024) = 10` in CS language.

2¹⁰ = 1024, base 2 means doublings or binary choices.

Answer: **10 binary choices produce 1024 possibilities**; or **1024 is 10 doublings from 1**.

---

### Breadcrumb 5: Log Laws

**Builds on:** [[3.7 Breadcrumb 2|Converting Between Log and Exponential Form]] (b^c = a), [[2.9 Breadcrumb 3|Multiplying Powers With the Same Base]] (b^m × b^n = b^(m+n))

Product law: `log_b(xy) = log_b(x) + log_b(y)`

Quotient law: `log_b(x/y) = log_b(x) - log_b(y)`

Power law: `log_b(x^k) = k log_b(x)`

These work because multiplying powers with the same base adds exponents.

> [!warning] Logs do not distribute over addition
> `log(x + y)` is not `log(x) + log(y)`.

#### Chunked Example
Question: Simplify `log₂(8 * 4)`.

log₂(8) + log₂(4) = 3 + 2 = 5.

Answer: **log₂(8 * 4) = 5**.

---

### Breadcrumb 6: Solving Exponential Equations with Logs

**Builds on:** [[3.7 Breadcrumb 3|Logs Undo Exponentials]] (inverse operation), [[2.5 Breadcrumb 5|Solving With Inverse Operations on Both Sides]] (isolate unknown)

When the unknown is in the exponent and the answer is not obvious:

```text
3ˣ = 20   →   x = log₃(20)
```

> [!important] Exact log form is an answer
> `log₃(20)` exactly answers "what power of 3 gives 20?"

#### Chunked Example
Question: Solve `5ˣ = 70` exactly.

x = log₅(70).

Answer: **x = log₅(70)**.

---

### Breadcrumb 7: Logs Measure Repeated Halving

**Builds on:** [[3.7 Breadcrumb 4|Common Bases in CS]] (base 2 for halving), [[3.6 Breadcrumb 8|Exponentials in CS]] (doubling/halving)

Logarithms count how many times you can halve a problem.

Binary search halves the search range each step:

```text
1024 → 512 → 256 → ... → 1
```

Number of halvings: log₂(1024) = 10.

> [!example] Search depth
> A balanced binary tree with 1024 leaves has depth about 10.

```mermaid
xychart-beta
    title "y = log₂(x) — Repeated Halving"
    x-axis "x" [0.5, 1, 2, 4, 8, 16, 32, 64]
    y-axis "y" -1 --> 6
    line "log₂(x)" [-1, 0, 1, 2, 3, 4, 5, 6]
```

#### Chunked Example
Question: A sorted list has 256 items. About how many halving steps does binary search need?

log₂(256) = 8 (since 2⁸ = 256).

Answer: About **8 halving steps**.

---

### Breadcrumb 8: Logs Compress Scale

**Builds on:** [[3.7 Breadcrumb 5|Log Laws]] (product becomes sum), [[3.7 Breadcrumb 4|Common Bases in CS]] (scale measurement)

Logs turn multiplication into addition, compressing huge ranges.

10³ = 1000, 10⁶ = 1000000. Logs: log₁₀(1000) = 3, log₁₀(1000000) = 6.

This makes logs useful for charts, sound levels, and information theory.

This links forward to [[8.11 Information Theory]]: if there are 8 equally likely outcomes, log₂(8) = 3, so identifying one outcome takes 3 bits.

#### Chunked Example
Question: How many bits are needed to identify one item out of 16 equally likely choices?

bits = log₂(16) = 4 (since 2⁴ = 16).

Answer: **4 bits**.

## Why This Works

Logarithms work because they reverse exponentiation. [[3.6 Exponential Functions]] gives the forward rule `y = bˣ`; a logarithm asks for the hidden x.

The log laws work because index laws work. `b^m × b^n = b^(m+n)` means multiplying corresponds to adding powers.

## Common Mistakes

- Reading `log₂(8)` as 2 × 8 (it asks "what power of 2 gives 8?").
- Putting base and result in the wrong places (`log_b(a) = c` means `b^c = a`).
- Saying `log(x + y) = log(x) + log(y)` (product law is for multiplication).
- Forgetting logs only take positive inputs.
- Thinking logarithmic growth is fast (it is slow — it counts repeated halving).
- Rounding exact logs too early.

> [!failure] Mistake pattern
> If a log answer feels mysterious, convert it back to exponential form and check.

---

## Where This Shows Up in CS

Logarithms appear whenever a program repeatedly halves, doubles, or measures scale.

Binary search, balanced tree height, heap operations, entropy, compression, and many Big-O expressions use logs. `O(log n)` means work grows by one step when the input size doubles.
