## Introduction

Not all infinities are the same. A set is **countable** if you can list its elements in a sequence (even if the sequence never ends). The natural numbers {1, 2, 3, ...} are countable. Surprisingly, the integers and rational numbers are also countable. But the real numbers (all decimal numbers) are **uncountable** — there are too many to list. This was discovered by Georg Cantor and is the foundation of computability theory.

> [!example] Everyday idea
> Imagine a hotel with infinitely many rooms (Room 1, 2, 3, ...). If a new guest arrives, every guest moves to the next room, and the new guest takes Room 1. The hotel is always full but always has room for more. This is Hilbert's Hotel — it shows that infinite sets behave differently than finite ones.

## New Words

- [[countable]] — a set is countable if its elements can be paired with the natural numbers {1, 2, 3, ...}.
- [[uncountable]] — a set too large to be paired with ℕ (e.g., real numbers).
- [[aleph-null]] — the cardinality of ℕ, denoted ℵ₀; the smallest infinity.
- [[Cantor diagonal argument]] — a proof that ℝ is uncountable by constructing a number not in any proposed listing.
- [[bijection]] — a one-to-one correspondence between two sets; used to compare infinite sizes.

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: Finite vs Infinite

**Builds on:** [[5.1 Breadcrumb 6|Finite vs Infinite Sets]] (definition of infinite), [[1.1 Breadcrumb 1|Counting and Whole Numbers]] (one-to-one matching)

A set is **finite** if you can count its elements and stop. A set is **infinite** if it has no largest element.

Finite: {1, 2, 3} — count 1, 2, 3 and stop.
Infinite: {1, 2, 3, ...} — never stop.

> [!important] The defining test
> A set is infinite if you can remove some elements and still have the same size. Remove {1} from ℕ, get {2, 3, 4, ...}, which pairs with ℕ by n → n−1.

#### Chunked Example
Question: Is the set of even numbers {2, 4, 6, ...} the same size as ℕ?

Pair: 1→2, 2→4, 3→6, 4→8, ... Every natural maps to a unique even; every even has exactly one natural.

Answer: Yes, the even numbers have the same cardinality as ℕ. They seem "half as big" but are the same size.

### Breadcrumb 2: Countable Infinity

**Builds on:** [[5.4 Breadcrumb 1|Finite vs Infinite]] (pairing elements), [[5.1 Breadcrumb 5|Cardinality (Size of a Set)]] (comparing sizes via pairing)

A set is **countable** if you can list its elements as a sequence (a₁, a₂, a₃, ...) that eventually includes every element.

Countable sets:
- ℕ = {1, 2, 3, ...}
- ℤ = {..., −2, −1, 0, 1, 2, ...} — list as 0, 1, −1, 2, −2, 3, −3, ...
- ℚ = {p/q | p, q ∈ ℤ, q ≠ 0} — grid pattern along diagonals

> [!example] The rationals are countable
> Arrange fractions in a grid: row = numerator, column = denominator. Follow diagonals. Every rational appears exactly once.

#### Chunked Example
Question: Show the integers are countable by listing them.

Start with 0. Add 1, then −1, then 2, then −2.

Answer: 0, 1, −1, 2, −2, 3, −3, ... includes every integer exactly once.

### Breadcrumb 3: Uncountable Infinity and Cantor's Diagonal Argument

**Builds on:** [[5.4 Breadcrumb 2|Countable Infinity]] (assumption of countability), [[5.1 Breadcrumb 6|Finite vs Infinite Sets]] (properties of infinite sets)

The real numbers ℝ are **uncountable**. Cantor proved this by contradiction:

1. Suppose ℝ is countable and list all reals between 0 and 1.
2. Each is an infinite decimal: 0.d₁d₂d₃...
3. Construct a NEW number by taking the diagonal and changing each digit.
4. This new number differs from every number in the list (at position n, it differs from the n-th number's n-th digit).
5. Contradiction — the list was supposed to be complete. ∴ ℝ is uncountable.

```text
List:
1: 0.1 4 1 5 9 2 6 5 ...
2: 0.3 3 3 3 3 3 3 3 ...
3: 0.5 0 0 0 0 0 0 0 ...
4: 0.6 1 8 0 3 3 9 8 ...
5: 0.2 0 0 0 0 0 0 0 ...
6: 0.7 1 8 2 8 1 8 2 ...
...

Diagonal: 1, 3, 0, 0, 0, 1, ...
New: 0.2 4 1 1 1 2 ... (change each digit)
This new number is NOT in the list.
```

#### Chunked Example
Question: Why can't you just "add the new number to the list"?

If you add it, apply the diagonal argument again. You get ANOTHER missing number. The argument works for ANY proposed listing.

Answer: Because the argument proves no listing can be complete — it is not a flaw in any specific list.

---

### Breadcrumb 4: Comparing Infinities: ℵ₀, ℵ₁, ...

**Builds on:** [[5.4 Breadcrumb 3|Uncountable Infinity and Cantor's Diagonal Argument]] (ℝ > ℕ), [[5.1 Breadcrumb 5|Cardinality (Size of a Set)]] (cardinality comparison)

The cardinality of countable infinity is ℵ₀ (aleph-null). The cardinality of ℝ is 2^ℵ₀ (the continuum). Cantor proved 2^ℵ₀ > ℵ₀ — strictly more reals than naturals.

The **continuum hypothesis** states there is no infinity between ℵ₀ and 2^ℵ₀. It is independent of standard set theory (neither provable nor disprovable).

---

### Breadcrumb 5: Implications for Computer Science

**Builds on:** [[5.4 Breadcrumb 3|Uncountable Infinity and Cantor's Diagonal Argument]] (uncountably many functions), [[5.4 Breadcrumb 2|Countable Infinity]] (countably many programs)

Countability matters because:
- Programs are finite strings over a finite alphabet → countably many programs
- There are uncountably many functions from ℕ to {0, 1}
- Therefore, MOST functions cannot be computed by any program

> [!important] More functions than programs
> Since programs are countable and functions are uncountable, almost all functions are uncomputable. This is a mathematical fact, not a technology limitation.

#### Chunked Example
Question: Why does countability prove some problems have no algorithmic solution?

Programs are finite sequences of symbols → countably many. Decision problems (functions ℕ → {0,1}) are uncountable. More problems than programs → most have no program.

Answer: Countability shows uncountably many problems cannot be solved algorithmically.

## Worked Examples

### Example 1 — Showing the Integers Are Countable

Question: Give an explicit listing (a₁, a₂, a₃, ...) that proves ℤ = {..., −2, −1, 0, 1, 2, ...} is countable. What is the 10th term in your sequence?

Step 1: A bijection with ℕ must hit every integer exactly once. Start with 0. Then alternate positive and negative: 0, 1, −1, 2, −2, 3, −3, ...

Step 2: The sequence is: a₁=0, a₂=1, a₃=−1, a₄=2, a₅=−2, a₆=3, a₇=−3, a₈=4, a₉=−4, a₁₀=5.

Answer: The sequence **0, 1, −1, 2, −2, 3, −3, 4, −4, 5, ...** works. The 10th term is **5**.

### Example 2 — Same Cardinality via Bijection

Question: Show that the set of perfect squares S = {1, 4, 9, 16, 25, ...} has the same cardinality as ℕ = {1, 2, 3, ...}.

Step 1: Define a function f: ℕ → S by f(n) = n².

Step 2: f is one-to-one: if f(a) = f(b), then a² = b², so a = b (both positive).

Step 3: f is onto: every perfect square n² is f(n) for some n ∈ ℕ.

Step 4: Since a bijection exists, |ℕ| = |S|. An infinite set can have the same size as a proper subset of itself.

Answer: f(n) = **n²** gives a bijection, so |S| = |ℕ|.

### Example 3 — Cantor Diagonal Argument for a Specific Listing

Question: Suppose someone claims to have listed all real numbers between 0 and 1 as follows:
r₁ = 0.500000...
r₂ = 0.333333...
r₃ = 0.250000...
r₄ = 0.200000...
r₅ = 0.166666...
r₆ = 0.142857...
Construct a number not in this list using Cantor's diagonal argument.

Step 1: The diagonal digits (n-th digit of rₙ) are: r₁'s 1st digit = 5, r₂'s 2nd digit = 3, r₃'s 3rd digit = 0, r₄'s 4th digit = 0, r₅'s 5th digit = 6, r₆'s 6th digit = 7, ...

Step 2: Change each digit (e.g., add 1 mod 10, with 9→0): 5→6, 3→4, 0→1, 0→1, 6→7, 7→8, ...

Step 3: The new number d = 0.641178... differs from r₁ in digit 1, from r₂ in digit 2, from r₃ in digit 3, etc. It cannot be in the list.

Answer: The number **0.641178...** is not in the list, proving the listing is incomplete.

### Example 4 — Programs vs Functions

Question: Explain why there are uncountably many functions from ℕ to {0, 1} but only countably many computer programs. What does this imply?

Step 1: A function f: ℕ → {0, 1} can be represented as an infinite binary string (f(1), f(2), f(3), ...). This is like a binary decimal between 0 and 1. By Cantor's argument, the set of such functions is uncountable (same cardinality as ℝ).

Step 2: Each computer program is a finite string over a finite alphabet. There are countably many finite strings: list by length, then lexicographically. So programs are countable.

Step 3: Since there are more functions than programs, most functions cannot be computed by any program. This is a foundational result in computability theory — it proves undecidable problems exist.

Answer: There are **uncountably many** functions but only **countably many** programs, so most functions are **uncomputable**.

## Why This Works

Infinity is counterintuitive. "Size" for infinite sets means "can we pair elements?" rather than "how many?" If you can pair elements one-to-one, the sets are the same size — even if one is a proper subset of the other.

This connects to [[1.1 Counting and Number Sense]] — counting is one-to-one matching. Infinite counting just never stops.

## Common Mistakes

1. Thinking infinity is a number (it is a property of sets).
2. Saying "∞ + 1 > ∞" (ℵ₀ + 1 = ℵ₀).
3. Confusing "countable" with "finite" (countable includes infinite sets like ℕ).
4. Thinking the diagonal argument is a trick (it is a valid proof by contradiction).
5. Assuming all infinite sets are the same size (ℝ > ℕ).
6. Thinking uncountable means "cannot be counted in practice" (it means cannot be listed in principle).

> [!failure] Mistake pattern
> "There are infinitely many rationals and infinitely many reals, so they are the same size" — wrong! ℚ is countable, ℝ is uncountable. Strictly more reals.

## Where This Shows Up in CS

- **Computability theory**: some problems have no algorithm (halting problem is undecidable).
- **Programming languages**: countably many programs, uncountably many functions.
- **Complexity theory**: P vs NP deals with which problems are tractable.
- **Data types**: floating-point numbers are finite (countable), real numbers are infinite (uncountable).
- **Cryptography**: one-way functions exist because some functions are hard to invert.
