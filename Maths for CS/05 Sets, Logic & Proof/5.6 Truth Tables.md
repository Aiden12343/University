## Introduction

A truth table enumerates every possible assignment of truth values to atomic propositions and shows the result of a compound proposition under each assignment. It is the **exhaustive specification** of a logical expression: every possible input combination, every corresponding output.

For n atomic propositions, 2ⁿ rows are needed. This makes truth tables the most reliable method for verifying logical equivalence, identifying tautologies, and determining satisfiability — but also the method that grows fastest with n.

Truth tables are how CPUs compute Boolean expressions, how compilers optimise conditions, and how SAT solvers find satisfying assignments.

## New Words

- [[truth table]] — a table with one row per truth assignment; columns for atomic propositions, sub-expressions, and the final expression.
- [[row]] in a truth table — a single combination of truth values for the atomic propositions.
- [[column]] in a truth table — the computed truth values for a sub-expression.
- [[tautology]] — a proposition true in every row; column is all T.
- [[contradiction]] — a proposition false in every row; column is all F.
- [[contingency]] — a proposition true in some rows and false in others.
- [[satisfiable]] — there exists at least one row where the expression is true.
- [[logical equivalence]] — two propositions have identical result columns; written P ≡ Q.
- [[truth table size]] — 2ⁿ rows where n = number of atomic propositions.
- [[principle of explosion]] — a contradiction implies anything (from a false premise, any conclusion follows).

## Breadcrumbs

### Breadcrumb 1: Building a Truth Table

**Builds on:** [[5.5 Breadcrumb 5|Truth Tables for Complex Expressions]] (you have seen simple truth tables), [[5.5 Breadcrumb 2|Logical Connectives — NOT, AND, OR]] (tables for basic connectives)

A truth table is built systematically.

1. **Rows**: n atomic propositions → 2ⁿ rows. Count in binary from 0 to 2ⁿ−1 (T=1, F=0).
2. **Columns**: one per atomic proposition, one per sub-expression, one for the final result.
3. **Fill**: evaluate each column in order, using only previously filled columns.

```
P    Q    ¬P    ¬Q    ¬P ∨ ¬Q    P ∧ Q    ¬(P ∧ Q)
──────────────────────────────────────────────────────
T    T    F     F        F         T          F
T    F    F     T        T         F          T
F    T    T     F        T         F          T
F    F    T     T        T         F          T
```

» Columns ¬P ∨ ¬Q and ¬(P ∧ Q) are identical — De Morgan's law verified.

> [!tip] Binary counting for rows
> For 2 variables: TT, TF, FT, FF. For 3: TTT, TTF, TFT, TFF, FTT, FTF, FFT, FFF. Alternate T and F in the rightmost column fastest.

#### Chunked Example
Build truth table for `(P ∨ Q) ∧ ¬P`:

```
P    Q    P∨Q    ¬P    (P∨Q) ∧ ¬P
────────────────────────────────────
T    T     T      F          F
T    F     T      F          F
F    T     T      T          T
F    F     F      T          F
```

True only when P=F, Q=T.

### Breadcrumb 2: Tautologies and Contradictions

**Builds on:** [[5.6 Breadcrumb 1|Building a Truth Table]] (filling a column)

After filling the result column, classify the proposition:

| Result column | Classification |
|---------------|---------------|
| All T | Tautology — always true |
| All F | Contradiction — always false |
| Mixed | Contingency — depends on inputs |

**Tautology examples:**
- `P ∨ ¬P` — law of excluded middle
- `¬(P ∧ ¬P)` — law of non-contradiction
- `P → (Q → P)`
- `(P ∧ (P → Q)) → Q` — modus ponens

**Contradiction example:**
- `P ∧ ¬P`

> [!important] Why tautologies matter
> A tautology represents a reasoning pattern that is always valid. Tautologies can be used as axioms or inference rules in a formal proof system.

#### Chunked Example
Classify `(P → Q) ∨ (Q → P)` — build a truth table (5 rows):

```
P    Q    P→Q    Q→P    (P→Q) ∨ (Q→P)
───────────────────────────────────────
T    T     T      T           T
T    F     F      T           T
F    T     T      F           T
F    F     T      T           T
```

All T → tautology.

### Breadcrumb 3: Logical Equivalence via Truth Tables

**Builds on:** [[5.6 Breadcrumb 1|Building a Truth Table]] (comparing columns), [[5.5 Breadcrumb 6|Logical Equivalence]] (concept of equivalence)

Two propositions are logically equivalent if their truth table columns are identical.

**Verification process:**
1. List all atomic variables.
2. Build columns for both propositions.
3. Compare the final columns — if identical row for row, they are equivalent.

**Key equivalences to verify with truth tables:**
- `¬(P ∧ Q) ≡ ¬P ∨ ¬Q`
- `¬(P ∨ Q) ≡ ¬P ∧ ¬Q`
- `P → Q ≡ ¬P ∨ Q`
- `P → Q ≡ ¬Q → ¬P` (contrapositive)

> [!tip] Contrapositive
> `¬Q → ¬P` is equivalent to `P → Q`. This is the foundation of proof by contrapositive.

#### Chunked Example
Verify `P ∨ (Q ∧ R) ≡ (P ∨ Q) ∧ (P ∨ R)`:

```
P    Q    R    Q∧R    P∨(Q∧R)    P∨Q    P∨R    (P∨Q)∧(P∨R)
────────────────────────────────────────────────────────────
T    T    T     T        T         T       T         T
T    T    F     F        T         T       T         T
T    F    T     F        T         T       T         T
T    F    F     F        T         T       T         T
F    T    T     T        T         T       T         T
F    T    F     F        F         T       F         F
F    F    T     F        F         F       T         F
F    F    F     F        F         F       F         F
```

Columns P∨(Q∧R) and (P∨Q)∧(P∨R) are identical → disjunction distributes over conjunction.

### Breadcrumb 4: Satisfiability and Validity

**Builds on:** [[5.6 Breadcrumb 2|Tautologies and Contradictions]] (classifying propositions)

A proposition is **satisfiable** if there is at least one row where it is true.

- Tautology → satisfiable (true in all rows)
- Contingency → satisfiable (true in at least one row)
- Contradiction → **not** satisfiable (true in zero rows)

A proposition is **valid** (= a tautology) if it is true in every model (row). Validity is the strongest property.

> [!note] SAT problem
> The SAT problem asks: given a proposition, is it satisfiable? This is the first NP-complete problem. Modern SAT solvers handle millions of variables.

#### Chunked Example
P = "this algorithm runs in O(n log n)", Q = "the system has enough memory". Is `P ∧ ¬P` satisfiable?

No — a contradiction cannot be satisfied.

### Breadcrumb 5: Practical Limitation — 2ⁿ Growth

**Builds on:** [[5.6 Breadcrumb 1|Building a Truth Table]] (number of rows), [[1.1 Breadcrumb 5|Counting by Powers of 2]] (powers of two)

Truth tables are exhaustive and therefore expensive:

| n variables | 2ⁿ rows | Notes |
|------------|---------|-------|
| 1 | 2 | Trivial |
| 2 | 4 | Feasible by hand |
| 3 | 8 | Feasible by hand |
| 4 | 16 | Tedious |
| 5 | 32 | Error-prone |
| 10 | 1024 | Impractical by hand |
| 20 | ~1 million | Exhaustive search fails |
| 100 | ~10³⁰ | Larger than age of universe in nanoseconds |

For n > 4 or 5, use algebra (equivalence laws), SAT solvers, or BDDs instead.

**Coping strategies:**
- **Short-circuit evaluation**: don't compute sub-expressions when the result is already determined.
- **Partial evaluation**: substitute known values for some variables.
- **Symbolic methods**: rewrite using known equivalences rather than enumerating rows.

#### Chunked Example
How many rows for `(P ∨ Q ∨ R ∨ S) ∧ (T ∨ U ∨ V)`? 7 variables → 128 rows. Build it only if you must; equivalences are faster.

### Breadcrumb 6: Truth Tables in Programming

**Builds on:** [[5.6 Breadcrumb 1|Building a Truth Table]] (concept of exhaustive enumeration)

Every `if (condition)` in code evaluates a Boolean expression. Truth tables let you **exhaustively test** a condition.

```python
# Verify: can the user access the resource?
def can_access(is_admin, is_owner, is_banned):
    return (is_admin or is_owner) and not is_banned

# Truth table equivalent
for admin in [True, False]:
    for owner in [True, False]:
        for banned in [True, False]:
            result = (admin or owner) and not banned
            print(admin, owner, banned, "→", result)
```

This exhaustively covers all 8 cases. Every combination is a test case.

> [!tip] Branch coverage vs truth table coverage
> Branch coverage tests each `if` branch. Truth table coverage tests every combination of conditions — stronger but more expensive.

#### Chunked Example
Write a truth table for `(is_admin or is_owner) and not is_banned` and identify the access-allowed rows.

Answer: Allowed when not banned AND (admin OR owner). 3 of 8 rows.

## Worked Examples

### Example 1 — Building a Truth Table for a Three-Variable Expression

Question: Build a complete truth table for (P ∧ Q) ∨ (¬P ∧ R).

Step 1: Three atomic propositions → 2³ = 8 rows. List variables in binary order (TTT to FFF) with rightmost column alternating fastest.

Step 2: Compute intermediate columns: P∧Q, ¬P, ¬P∧R, then the final expression.

```
P  Q  R  P∧Q  ¬P  ¬P∧R  (P∧Q) ∨ (¬P∧R)
──────────────────────────────────────────
T  T  T   T    F    F          T
T  T  F   T    F    F          T
T  F  T   F    F    F          F
T  F  F   F    F    F          F
F  T  T   F    T    T          T
F  T  F   F    T    F          F
F  F  T   F    T    T          T
F  F  F   F    T    F          F
```

Answer: The final column is **T, T, F, F, T, F, T, F**.

### Example 2 — Classifying a Proposition

Question: Build a truth table for (P → Q) ∨ (Q → P) and classify it as tautology, contradiction, or contingency.

Step 1: Two variables → 4 rows. Compute P→Q, Q→P, then the disjunction.

```
P  Q  P→Q  Q→P  (P→Q) ∨ (Q→P)
──────────────────────────────────
T  T   T    T         T
T  F   F    T         T
F  T   T    F         T
F  F   T    T         T
```

Step 2: The result column is all T.

Answer: The proposition is a **tautology** (true under every assignment).

### Example 3 — Verifying Logical Equivalence

Question: Use a truth table to verify whether P ∨ (Q ∧ R) ≡ (P ∨ Q) ∧ (P ∨ R).

Step 1: Three variables → 8 rows. Compute both sides and compare.

```
P  Q  R  Q∧R  P∨(Q∧R)  P∨Q  P∨R  (P∨Q)∧(P∨R)
─────────────────────────────────────────────────
T  T  T   T      T       T     T        T
T  T  F   F      T       T     T        T
T  F  T   F      T       T     T        T
T  F  F   F      T       T     T        T
F  T  T   T      T       T     T        T
F  T  F   F      F       T     F        F
F  F  T   F      F       F     T        F
F  F  F   F      F       F     F        F
```

Step 2: Columns P∨(Q∧R) and (P∨Q)∧(P∨R) are identical on every row.

Answer: **Yes, they are logically equivalent**. This is the distributive law of ∨ over ∧.

### Example 4 — Truth Table for a Programming Condition

Question: A system grants access when: (is_admin ∨ is_owner) ∧ ¬is_banned. Build a truth table and find how many of the 8 possible combinations grant access.

Step 1: Three variables: A (admin), O (owner), B (banned). 8 rows.

```
A  O  B  A∨O  ¬B  (A∨O) ∧ ¬B
─────────────────────────────────
T  T  T   T    F        F
T  T  F   T    T        T
T  F  T   T    F        F
T  F  F   T    T        T
F  T  T   T    F        F
F  T  F   T    T        T
F  F  T   F    F        F
F  F  F   F    T        F
```

Step 2: Access is granted when (A or O is true) AND B is false. That is 3 rows: (T,T,F), (T,F,F), (F,T,F).

Answer: **3 out of 8** combinations grant access.

## Why This Works

Exhaustive enumeration over a finite set of possibilities is a complete method: if a property holds for every row, it holds in all possible worlds. This is the same principle underlying exhaustive search, brute-force algorithms, and case analysis.

For n variables, each row corresponds to a binary number from 0 to 2ⁿ−1. The truth table is a **lookup table** for the Boolean function — exactly how ROM (read-only memory) and FPGAs implement arbitrary logic in hardware.

## Common Mistakes

1. Inconsistent row ordering — always use binary counting (TT, TF, FT, FF).
2. Skipping intermediate columns — leads to errors in complex expressions.
3. Wrong column order — fill atomic propositions first, then sub-expressions, then result.
4. Misclassifying tautologies — all rows must be T; just "mostly true" is not enough.
5. Confusing satisfiability with validity — satisfiable ≠ tautology.
6. Assuming 2ⁿ scaling is practical — truth tables for n > 5 are rarely done by hand.
7. Forgetting that `P → Q` is not equivalent to `Q → P` (converse error).
8. Off-by-one in binary counting — the rightmost column alternates fastest.

---

## Where This Shows Up in CS

- **Test case generation**: exhaustive testing enumerates all input combinations. Truth tables produce test coverage that branch coverage alone cannot.
- **Hardware design**: logic gates realise truth tables in silicon. A full adder has 3 inputs → 8 rows.
- **SAT solvers**: determine satisfiability without full truth tables (which would be too large). Used for hardware verification, planning, package management.
- **Compiler optimisation**: constant folding, dead-code elimination, and branch prediction all reason about truth values.
- **FPGA programming**: lookup tables (LUTs) implement arbitrary Boolean functions by storing the result column in memory.
- **Database queries**: query optimisers reason about equivalence of WHERE clauses using truth-table-like reasoning.
