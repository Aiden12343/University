## Introduction

Implication (→) models "if P then Q" — the most important connective in mathematics. It is not the same as causality or temporal sequence. Implication is **truth-functional**: its meaning is entirely determined by the truth values of P and Q.

Equivalence (↔, iff) models "P if and only if Q" — two propositions that are true together and false together.

All mathematical theorems are implications (if premises hold, conclusion holds) or equivalences (conditions are interchangeable). Understanding → and ↔ is essential for reading and writing mathematical proofs.

## New Words

- [[implication]] (→, conditional, material implication) — P → Q is false only when P is true and Q is false.
- [[antecedent]] — the "if" part (P in P → Q).
- [[consequent]] — the "then" part (Q in P → Q).
- [[biconditional]] (↔, iff) — P ↔ Q is true when P and Q have the same truth value.
- [[converse]] — Q → P (the reverse of P → Q).
- [[inverse]] — ¬P → ¬Q.
- [[contrapositive]] — ¬Q → ¬P (equivalent to P → Q).
- [[sufficient condition]] — P is sufficient for Q if P → Q is true (P guarantees Q).
- [[necessary condition]] — Q is necessary for P if P → Q is true (Q must hold for P to hold).
- [[if and only if]] (iff) — another name for the biconditional.
- [[modus ponens]] — from P and P → Q, infer Q.
- [[modus tollens]] — from ¬Q and P → Q, infer ¬P.

> [!important] You pass this topic only when you can define all twelve terms without looking.

## Breadcrumbs

### Breadcrumb 1: The Truth Table for Implication

**Builds on:** [[5.5 Breadcrumb 2|Logical Connectives — NOT, AND, OR]] (truth tables for basic connectives), [[5.6 Breadcrumb 1|Building a Truth Table]] (reading a truth table)

```
P    Q    P → Q
────────────────
T    T      T
T    F      F
F    T      T
F    F      T
```

The only row where P → Q is false: P true, Q false. All other rows are true.

> [!warning] Counterintuitive cases
> "If the moon is cheese, then I'm a billionaire" → true (because the antecedent is false). This is **vacuously true**: when the premise is false, the implication is automatically true.

**Key equivalence:** `P → Q ≡ ¬P ∨ Q`. Verify this with a truth table.

> [!tip] Memory aid
> "The only way to break a promise is to keep the promise (P) but fail to deliver (Q)."

#### Chunked Example
P = "you study", Q = "you pass". Is `P → Q` true when you study and pass? Yes (T→T). When you study and fail? No (T→F). When you don't study and pass? Yes (F→T — lucky). When you don't study and fail? Yes (F→F — expected).

### Breadcrumb 2: Vacuously True — Why False Implies Anything

**Builds on:** [[5.7 Breadcrumb 1|The Truth Table for Implication]] (definition), [[5.5 Breadcrumb 6|Logical Equivalence]] (equivalence reasoning)

When P is false, P → Q is true **regardless** of Q. This is the **principle of explosion** (ex falso sequitur quodlibet — from falsehood, anything follows).

**Why?** Because P → Q is a **promise**: "if P holds, then Q holds." If P never holds, the promise is never tested — never broken.

Example: "If 1 = 0, then I am the Pope." True (vacuously). From a contradiction in mathematics, every statement becomes provable.

> [!warning] Common confusion
> Students often feel P → Q should be "false" or "undefined" when P is false. The truth table definition is a **convention** adopted because it makes the mathematics work (it makes → transitive, it makes modus ponens valid, it preserves the equivalence P → Q ≡ ¬P ∨ Q).

#### Chunked Example
"Every person in the empty room speaks French." Is this true? Vacuously yes. There are no persons in the room, so the statement cannot be contradicted.

### Breadcrumb 3: Converse, Inverse, Contrapositive

**Builds on:** [[5.7 Breadcrumb 1|The Truth Table for Implication]] (P → Q), [[5.6 Breadcrumb 3|Logical Equivalence via Truth Tables]] (comparing columns)

Given `P → Q`, three related statements:

| Name | Form | Equivalent to P → Q? |
|------|------|---------------------|
| Original | P → Q | — |
| Converse | Q → P | ❌ |
| Inverse | ¬P → ¬Q | ❌ |
| Contrapositive | ¬Q → ¬P | ✅ |

**Contrapositive proof** works because `P → Q ≡ ¬Q → ¬P`. If you want to prove "if it rains, the ground gets wet", you can instead prove "if the ground is dry, it did not rain."

```
P    Q    ¬P    ¬Q    P → Q    ¬Q → ¬P
─────────────────────────────────────────
T    T     F     F      T         T
T    F     F     T      F         F
F    T     T     F      T         T
F    F     T     T      T         T
```

P → Q and ¬Q → ¬P are identical columns → equivalent.

> [!warning] Converse error
> P → Q does NOT imply Q → P. "If you are a CS student, you take this course" ≠ "If you take this course, you are a CS student."

#### Chunked Example
Statement: "If a shape is a square, then it has four sides." Converse: "If a shape has four sides, then it is a square" (false — rectangles also have four sides). Contrapositive: "If a shape does not have four sides, then it is not a square" (true).

### Breadcrumb 4: Necessary and Sufficient Conditions

**Builds on:** [[5.7 Breadcrumb 1|The Truth Table for Implication]] (P → Q)

P → Q means:
- P is **sufficient** for Q: P guarantees Q. If P holds, Q must hold.
- Q is **necessary** for P: Q must hold for P to hold. If Q fails, P fails.

| Implication | Means |
|-------------|-------|
| P → Q | P is sufficient for Q |
| (¬Q → ¬P) | Q is necessary for P |
| P ↔ Q | P is necessary and sufficient for Q |

> [!example]
> "If you are 18 or older, you can vote." Being 18+ is sufficient to vote. Being able to vote does NOT mean you are 18+ (you could be 18+ in another district). Voting-eligibility is necessary for being 18+? No — you can be 20 and not registered. The logic: 18+ → canVote means 18+ is sufficient for canVote; canVote is necessary for 18+.

#### Chunked Example
"Passing the exam is necessary for passing the course." Translation: coursePass → examPass (if you pass the course, you must have passed the exam). Or equivalently: ¬examPass → ¬coursePass.

### Breadcrumb 5: Modus Ponens and Modus Tollens

**Builds on:** [[5.7 Breadcrumb 1|The Truth Table for Implication]] (definition), [[5.7 Breadcrumb 3|Converse, Inverse, Contrapositive]] (contrapositive)

These are the two fundamental inference rules for implication.

**Modus ponens** (mode that affirms): If P is true and P → Q is true, then Q must be true.
- Premises: P, P → Q → Conclusion: Q

**Modus tollens** (mode that denies): If Q is false and P → Q is true, then P must be false.
- Premises: ¬Q, P → Q → Conclusion: ¬P

> [!tip] Modus tollens = contrapositive + modus ponens
> From P → Q and ¬Q, the contrapositive gives ¬Q → ¬P. Apply modus ponens: ¬Q and ¬Q → ¬P gives ¬P.

**Fallacies to avoid:**
- **Affirming the consequent**: P → Q and Q, therefore P. ❌ (Converse error.)
- **Denying the antecedent**: P → Q and ¬P, therefore ¬Q. ❌

| Rule | Valid? | Premises | Conclusion |
|------|--------|----------|------------|
| Modus ponens | ✅ | P, P→Q | Q |
| Modus tollens | ✅ | ¬Q, P→Q | ¬P |
| Affirming consequent | ❌ | Q, P→Q | P |
| Denying antecedent | ❌ | ¬P, P→Q | ¬Q |

#### Chunked Example
Premises: "If it's raining, the ground is wet." "The ground is dry." Valid conclusion:

Apply modus tollens: ¬wet (dry) and rain → wet ⇒ ¬rain (it is NOT raining). Valid.

### Breadcrumb 6: The Biconditional (Iff)

**Builds on:** [[5.7 Breadcrumb 1|The Truth Table for Implication]] (P → Q), [[5.7 Breadcrumb 3|Converse, Inverse, Contrapositive]] (converse)

P ↔ Q (P iff Q) means P → Q AND Q → P.

```
P    Q    P → Q    Q → P    (P → Q) ∧ (Q → P)    P ↔ Q
──────────────────────────────────────────────────────────
T    T      T        T             T                T
T    F      F        T             F                F
F    T      T        F             F                F
F    F      T        T             T                T
```

P ↔ Q is true exactly when P and Q have the same truth value.

**Equivalence:** `P ↔ Q ≡ (P → Q) ∧ (Q → P)`

> [!example]
> "A number is even iff it is divisible by 2." The → direction: if divisible by 2, then even. The ← direction: if even, then divisible by 2. Both hold, so it's an iff.

#### Chunked Example
"x > 0 iff x is positive." This is true by definition in ℕ. In ℤ, it's also true. In ℂ, it's false (complex numbers have no positivity ordering). The biconditional depends on the domain.

### Breadcrumb 7: Logical Implication vs Causality vs Temporal Sequence

**Builds on:** [[5.7 Breadcrumb 1|The Truth Table for Implication]] (truth-functional definition)

Implication (→) is **truth-functional**: it cares only about truth values, not about meaning, causality, or time.

| Type | Example | Logical? | Notes |
|------|---------|----------|-------|
| Causal | If you drop the glass, it will break. | Model as → | But causality has a mechanism; → just tracks truth |
| Temporal | If you finish eating, then you may have dessert. | Model as → | Time order is implicit, not required by → |
| Definitional | If a number is even, it is divisible by 2. | → | Necessary connection: being even ≡ divisible by 2 |
| Promise | If you pass, I'll buy you a pizza. | → | Broken only when you pass and I don't buy |

Logical implication captures only the truth pattern, not the reason.

> [!tip] When to use → correctly
> Use → when you mean: "whenever P is true, Q is also true." Do NOT use → to mean "therefore" or "causes."

#### Chunked Example
"The sun rises because the Earth rotates" — this is causal, not truth-functional. In logic we write: `earthRotates → sunRises`, but this does not capture the causal mechanism.

## Worked Examples

### Example 1 — Truth Table and Classification for Implication

Question: Build a truth table for (P → Q) ∧ (Q → P) and classify it.

Step 1: Two variables → 4 rows. Compute P→Q, Q→P, then the conjunction.

```
P  Q  P→Q  Q→P  (P→Q) ∧ (Q→P)
──────────────────────────────────
T  T   T     T         T
T  F   F     T         F
F  T   T     F         F
F  F   T     T         T
```

Step 2: The result is true when P and Q have the same truth value.

Answer: This is the **biconditional** P ↔ Q. It is a **contingency** (true in 2 rows, false in 2 rows). Its truth table matches (P ∧ Q) ∨ (¬P ∧ ¬Q).

### Example 2 — Contrapositive Conversion

Question: State the converse, inverse, and contrapositive of: "If it is raining, then the ground is wet." Which are equivalent to the original?

Step 1: Original: Raining → Wet.

Step 2: Converse: Wet → Raining. (Swap antecedent and consequent.) **Not equivalent**.

Step 3: Inverse: ¬Raining → ¬Wet. (Negate both.) **Not equivalent**.

Step 4: Contrapositive: ¬Wet → ¬Raining. (Swap AND negate.) **Equivalent**.

Answer: Converse: "If the ground is wet, then it is raining." Inverse: "If it is not raining, then the ground is not wet." Contrapositive: "If the ground is not wet, then it is not raining." Only the **contrapositive** is equivalent.

### Example 3 — Necessary and Sufficient Conditions

Question: Consider the statement: "If a number is divisible by 6, then it is divisible by 3."
(a) Is being divisible by 6 sufficient for being divisible by 3?
(b) Is being divisible by 3 necessary for being divisible by 6?
(c) Is the converse true?

Step 1: (a) Divisible by 6 → Divisible by 3. The antecedent guarantees the consequent. Yes, **divisible by 6 is sufficient** for divisible by 3.

Step 2: (b) If a number is divisible by 6, it must be divisible by 3. So divisible by 3 is a requirement. Yes, **divisible by 3 is necessary** for divisible by 6.

Step 3: (c) Converse: "If divisible by 3, then divisible by 6." Counterexample: 9 is divisible by 3 but not by 6. The converse is **false**.

Answer: (a) **Yes**, (b) **Yes**, (c) **No** — the converse is false.

### Example 4 — Modus Ponens and Modus Tollens

Question: Given the premises "If the database is connected, then the query succeeds" and "The query did not succeed", what can you conclude? State which rule you used.

Step 1: Let C = "database is connected", Q = "query succeeds". Premises: C → Q and ¬Q.

Step 2: By modus tollens: from C → Q and ¬Q, conclude ¬C.

Step 3: Therefore, the database is not connected.

Answer: The database is **not connected** (modus tollens).

## Why This Works

Implication is defined as ¬P ∨ Q because this definition:
1. Makes modus ponens valid (the only thing we truly need from implication).
2. Makes implication transitive (if P→Q and Q→R, then P→R).
3. Preserves the equivalence P→Q ≡ ¬Q→¬P (contrapositive).
4. Matches mathematical practice: a theorem "if P then Q" is false only when P holds and Q does not.

The biconditional is simply equality of truth values. In Boolean algebra, P ↔ Q can be rewritten as (P ∧ Q) ∨ (¬P ∧ ¬Q) or as ¬(P ⊕ Q) where ⊕ is XOR.

## Common Mistakes

1. Confusing converse with contrapositive — Q→P is the converse (not equivalent), ¬Q→¬P is the contrapositive (equivalent).
2. Believing "false → anything" is wrong — it is the vacuously true basis of all logical deduction.
3. Affirming the consequent — "If P then Q, Q, therefore P" is a fallacy.
4. Denying the antecedent — "If P then Q, not P, therefore not Q" is a fallacy.
5. Confusing necessary with sufficient — necessary = Q must hold, sufficient = P guarantees Q.
6. Thinking → means causality — it does not; it is truth-functional only.
7. Forgetting that ↔ requires both → directions — must prove P→Q AND Q→P separately.
8. Using "if" when you mean "iff" — in mathematical writing, "if" alone does not imply "only if."

## Where This Shows Up in CS

- **Type systems**: `x: T` means "if x has a value, then that value is of type T" — an implication.
- **Program verification**: Hoare logic `{P} code {Q}` means "if P holds before code, Q holds after."
- **Database constraints**: foreign key constraints are implications: "if a record references id X, then X must exist."
- **Contract programming**: preconditions → postconditions. "If input is valid, output is correct."
- **Logic programming**: Prolog rules are Horn clauses: `q :- p.` means p → q.
- **Boolean search**: "cats NOT dogs" translates to `cats ∧ ¬dogs`.
- **SAT/SMT solvers**: implications are used for constraint propagation: `(P → Q)` and `(P)` gives `Q`.
- **Access control**: "if user is admin, then access is granted" → admin → access.
