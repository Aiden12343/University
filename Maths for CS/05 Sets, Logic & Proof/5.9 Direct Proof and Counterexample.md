## Introduction

Proof is the mechanism by which mathematics establishes truth with certainty. A **direct proof** starts from known facts and moves step-by-step to a conclusion. A **counterexample** demonstrates a statement is false by producing a single case that violates it. Together, these are the most fundamental tools in any mathematician's or computer scientist's reasoning toolkit.

Direct proof builds up from premises to conclusion using valid inferences. Counterexample tears down universal claims by showing one exception. Every programmer uses both: proving a loop invariant holds, or finding a test case that breaks a function.

## New Words

- [[theorem]] — a mathematical statement that has been proved true.
- [[proof]] — a logical argument demonstrating the truth of a statement.
- [[counterexample]] — a single example that disproves a universal statement.
- [[lemma]] — a smaller result used as a stepping stone in a larger proof.
- [[conjecture]] — a statement believed to be true but not yet proved.

## Breadcrumbs

### Breadcrumb 1: What Is a Proof?

**Builds on:** [[5.5 Breadcrumb 1|What Is a Proposition?]] (propositions as building blocks), [[5.7 Breadcrumb 1|The Truth Table for Implication]] (P → Q as theorem shape)

A **proof** is a sequence of logical steps from assumptions (premises) to a conclusion. Each step must be justified.

Structure of a direct proof:
1. State the theorem: "If P, then Q."
2. Assume P is true.
3. Use definitions, axioms, and known results to derive Q.
4. Conclude: If P, then Q.

> [!important] Proof is not experimentation
> Testing 1000 examples does not prove a theorem. Proof requires logical reasoning that covers ALL cases.

### Chunked Example
Question: Prove that the sum of two even numbers is even.

Step 1: Let a and b be even numbers.
Step 2: By definition, a = 2m and b = 2n for some integers m, n.
Step 3: a + b = 2m + 2n = 2(m + n).
Step 4: m + n is an integer, so 2(m + n) is even by definition.

Answer: The sum of two even numbers is **even**. ✓

### Breadcrumb 2: Direct Proof Structure

**Builds on:** [[5.9 Breadcrumb 1|What Is a Proof?]] (general concept), [[5.7 Breadcrumb 1|The Truth Table for Implication]] (P → Q form)
A direct proof of "If P, then Q" follows this template:

```text
Theorem: P → Q
Proof:
  1. Assume P.
  2. From P, derive step S₁ (justify: definition of P).
  3. From S₁, derive S₂ (justify: known fact).
  4. ...
  5. From Sₙ₋₁, derive Q (justify: definition of Q).
  6. Therefore, P → Q. QED.
```

### Chunked Example
Question: Prove that if n is odd, then n² is odd.

Step 1: Assume n is odd → n = 2k + 1 for some integer k.
Step 2: n² = (2k + 1)² = 4k² + 4k + 1 = 2(2k² + 2k) + 1.
Step 3: 2(2k² + 2k) is even, so 2(2k² + 2k) + 1 is odd.

Answer: If n is odd, then n² is **odd**. ✓

### Breadcrumb 3: Proving Universal Statements

**Builds on:** [[5.9 Breadcrumb 2|Direct Proof Structure]] (following the template), [[5.1 Breadcrumb 1|What Is a Set?]] (universal quantifier over a set)

"All integers with property P also have property Q."

To prove: choose an **arbitrary** element with property P (do not pick a specific one) and show it has property Q.

### Chunked Example
Question: Prove that for any integer n, if 3 divides n, then 3 divides n².

Step 1: Assume 3 | n (3 divides n). Then n = 3k for some integer k.
Step 2: n² = (3k)² = 9k² = 3(3k²).
Step 3: 3(3k²) is divisible by 3.

Answer: If 3 | n, then **3 | n²**. ✓

### Breadcrumb 4: Disproving with Counterexample

**Builds on:** [[5.9 Breadcrumb 3|Proving Universal Statements]] (universal statements are the target), [[5.1 Breadcrumb 3|Subsets]] (counterexample shows subset relation fails)

To show "All P are Q" is false, find one P that is NOT Q.

> [!warning] One counterexample is enough
> A single counterexample disproves a universal statement completely. You do not need to find all counterexamples.

### Chunked Example
Question: Is it true that "all prime numbers are odd"? Disprove if false.

Step 1: Consider the prime number 2.
Step 2: 2 is even, not odd.
Step 3: This is a counterexample.

Answer: The statement is **false**. 2 is a prime number that is even.

### Breadcrumb 5: Proving Existential Statements

**Builds on:** [[5.9 Breadcrumb 4|Disproving with Counterexample]] (one example suffices for existence), [[5.1 Breadcrumb 2|Elements and Membership]] (finding an element in a set)

"Some P has property Q" — to prove this, find one example.

### Chunked Example
Question: Prove there exists an integer n such that n² = 144.

Step 1: Try n = 12. 12² = 144. ✓
Step 2: (Also n = -12 works: (-12)² = 144.)

Answer: n = **12** (or -12) satisfies the property.

### Breadcrumb 6: Common Proof Techniques

**Builds on:** [[5.9 Breadcrumb 2|Direct Proof Structure]] (all techniques produce direct proofs), [[5.7 Breadcrumb 5|Modus Ponens and Modus Tollens]] (inference rules)
- **Exhaustion**: Check all cases (works for finite domains).
- **Generalising from generic particular**: Pick an arbitrary element, prove for it.
- **Using definitions**: Always start by writing the definition of each term.
- **Forward-backward method**: Work forward from assumptions and backward from goal until they meet.

### Chunked Example
Question: Prove that the product of two consecutive integers is even.

Step 1: Let integers be n and n + 1.
Step 2: Case 1: n is even → n = 2k → product = 2k(n+1) → even.
Step 3: Case 2: n is odd → n = 2k+1 → n+1 = 2k+2 = 2(k+1) → product = n × 2(k+1) → even.
Step 4: In both cases, the product is even.

Answer: The product of two consecutive integers is **always even**. ✓

## Worked Examples

### Example 1 — Direct Proof: Sum of Two Odd Numbers

Question: Prove that the sum of any two odd integers is even.

Step 1: Let the two odd integers be a and b. By definition of odd, a = 2m + 1 and b = 2n + 1 for some integers m, n.

Step 2: a + b = (2m + 1) + (2n + 1) = 2m + 2n + 2 = 2(m + n + 1).

Step 3: Since m + n + 1 is an integer, a + b = 2 × (integer), which is even by definition.

Answer: The sum of any two odd integers is **even** ✓.

### Example 2 — Direct Proof: Square of an Even Number

Question: Prove that if n is an even integer, then n² is divisible by 4.

Step 1: Assume n is even. Then n = 2k for some integer k.

Step 2: n² = (2k)² = 4k².

Step 3: 4k² = 4 × k², which is clearly divisible by 4.

Answer: If n is even, then **n² is divisible by 4** ✓.

### Example 3 — Disproving with Counterexample

Question: Determine whether the following statement is true or false: "For all integers n, n² + n + 41 is prime." If false, provide a counterexample.

Step 1: This is Euler's polynomial. It produces primes for n = 0, 1, 2, ..., 39. Test n = 40.

Step 2: n² + n + 41 = 40² + 40 + 41 = 1600 + 40 + 41 = 1681.

Step 3: 1681 = 41 × 41. It is not prime (it has factors 1, 41, 1681).

Step 4: n = 40 is a counterexample. (Also n = 41 works: 41² + 41 + 41 = 41(41 + 1 + 1) = 41 × 43.)

Answer: The statement is **false**. Counterexample: n = **40** gives 1681 = 41 × 41, which is composite.

### Example 4 — Proving an Existential Statement

Question: Prove that there exist three consecutive integers whose sum is 30.

Step 1: Let the three consecutive integers be n, n+1, n+2.

Step 2: Their sum = n + (n+1) + (n+2) = 3n + 3.

Step 3: Set 3n + 3 = 30 → 3n = 27 → n = 9.

Step 4: The three integers are 9, 10, 11. Their sum is 9 + 10 + 11 = 30. ✓

Answer: **9, 10, 11** are three consecutive integers whose sum is 30.

## Why This Works
Proofs work because each step preserves truth. If the assumptions are true and each step uses a valid logical rule, the conclusion must be true. This connects back to [[1.1 Counting and Number Sense]] — each step follows from the previous one — and to [[5.1 Set Theory Basics]] — a theorem asserts a property about all elements of a set, and a counterexample finds an element that fails it.

## Common Mistakes
1. Using an example as a proof (one example proves nothing for universal statements).
2. Proving the converse instead of the original statement.
3. Assuming what you want to prove (circular reasoning).
4. Making an unjustified leap between steps.
5. Forgetting to consider all cases.
6. Not stating the domain (integers, reals, etc.).

> [!failure] Mistake pattern
> "I checked 20 numbers and they all worked, so it must be true" — this is NOT a proof. Testing examples suggests truth but does not prove it.

## Where This Shows Up in CS
- **Algorithm correctness**: proving that a sorting algorithm always sorts.
- **Type systems**: proving that well-typed programs do not have runtime type errors.
- **Formal verification**: using proof assistants (Coq, Lean) to verify software.
- **Cryptography**: proving that breaking a cipher is as hard as factoring.
- **Data structures**: proving that a hash table has O(1) average-case lookup.
