> [!tip] How to study this note

## Plain-English Idea

A **relation** is a connection between elements of two sets. "Alice is friends with Bob", "5 is greater than 3", "Paris is the capital of France" — these are all relations.

A **function** is a special kind of relation where each input has exactly one output. f(x) = x² is a function: every x gives exactly one x².

> [!example] Everyday idea
> A relation is like "is the parent of" — a child can have two parents, so it is a relation but not a function. A function is like "has a social security number" — each person has exactly one SSN, and no two people share it.

## New Words

- **[[binary relation]]** - a subset of A × B: the set of all pairs (a,b) where a is related to b.
- **[[function]]** - a relation where each input (domain element) is paired with exactly one output (codomain element).
- **[[domain]]** - the set of all possible inputs to a function or the first elements of a relation.
- **[[codomain]]** - the set of all possible outputs (every function output is in the codomain).
- **[[injective, surjective, bijective]]** - one-to-one (injective), onto (surjective), both (bijective).

You pass this topic only when you can define all five terms without looking.

## Concept 1 - Binary Relations

A binary relation R from set A to set B is a subset of A × B:

```text
R ⊆ A × B = {(a,b) | a ∈ A, b ∈ B, a is related to b}
```

If (a,b) ∈ R, we write aRb (a is related to b).

### Chunked Example

Question: A = {1, 2, 3}, B = {a, b}. R = {(1,a), (2,a), (2,b), (3,b)}. Is 1Rb? Is 2Rb?

Step 1: Check if (1,b) is in R: it is not. So 1Rb is false.

Step 2: Check if (2,b) is in R: it is. So 2Rb is true.

Answer: **1Rb: No. 2Rb: Yes**.

```text
Arrow diagram:
A    B
1 → a
2 → a
2 → b
3 → b
```

## Concept 2 - Properties of Relations on a Single Set

A relation R on a set A (R ⊆ A × A) can have special properties:

### Reflexive
Every element is related to itself: aRa for all a ∈ A.

### Symmetric
If a is related to b, then b is related to a: aRb ⇒ bRa.

### Transitive
If a is related to b and b is related to c, then a is related to c: aRb ∧ bRc ⇒ aRc.

### Equivalence Relation
A relation that is reflexive, symmetric, AND transitive.

### Chunked Example

Question: On A = {1, 2, 3}, is R = {(1,1), (2,2), (3,3), (1,2), (2,1)} an equivalence relation?

Step 1: Check reflexive: (1,1), (2,2), (3,3) are all present. ✓

Step 2: Check symmetric: (1,2) has (2,1). (2,1) has (1,2). Pairs (1,1),(2,2),(3,3) are self-symmetric. ✓

Step 3: Check transitive: (1,2) and (2,1) ⇒ need (1,1) ✓. (2,1) and (1,2) ⇒ need (2,2) ✓. No other violations. ✓

Answer: **Yes, R is an equivalence relation**.

> [!example] CS connection
> Equality (=) is an equivalence relation. "Same hash code" is an equivalence relation (all items in the same hash bucket). Database keys define equivalence on rows.

## Concept 3 - Functions as Special Relations

A function f: A → B from A to B is a relation with the extra rule:

**Each a ∈ A appears in exactly one ordered pair (a, f(a)).**

In other words: every input has exactly one output.

### Chunked Example

Question: Which of these is a function from {1,2,3} to {a,b}?

```text
R₁ = {(1,a), (2,a), (3,a)}   → each input has exactly one output → FUNCTION
R₂ = {(1,a), (2,a)}          → 3 has no output → NOT a function (partial)
R₃ = {(1,a), (1,b), (2,a)}   → 1 has two outputs → NOT a function
```

Answer: **Only R₁ is a function**.

## Concept 4 - Injective, Surjective, Bijective

### Injective (One-to-One)
Each output has at most one input. If f(a) = f(b) then a = b.
```text
Think: different inputs map to different outputs.
```

### Surjective (Onto)
Every element of the codomain has at least one input mapping to it.
```text
Think: the range equals the codomain.
```

### Bijective
Both injective AND surjective. A perfect matching — each input pairs with exactly one output, covering all outputs.

### Chunked Example

Question: f: {1,2,3} → {a,b,c}, f(1)=a, f(2)=b, f(3)=c. Is it injective? Surjective? Bijective?

Step 1: Injective: all outputs a,b,c are different → yes, injective.

Step 2: Surjective: {a,b,c} all mapped to, codomain is {a,b,c}. Range = codomain → yes, surjective.

Answer: **Injective ✓, Surjective ✓, Bijective ✓**.

### Chunked Example

Question: f: {1,2,3} → {a,b}, f(1)=a, f(2)=b, f(3)=b. Injective? Surjective?

Step 1: Injective: 2 and 3 both map to b → NOT injective.

Step 2: Surjective: {a,b} both appear, codomain is {a,b} → surjective.

Answer: **Surjective but not injective**.

## Concept 5 - Composition of Functions

Given f: A → B and g: B → C, the composition g∘f: A → C is:

```text
(g∘f)(x) = g(f(x))
```

First apply f, then apply g.

### Chunked Example

Question: f(x) = x+1, g(x) = x². Find (g∘f)(3) and (f∘g)(3).

Step 1: (g∘f)(3) = g(f(3)) = g(3+1) = g(4) = 4² = 16.

Step 2: (f∘g)(3) = f(g(3)) = f(9) = 9+1 = 10.

Step 3: Note: g∘f ≠ f∘g (composition is not commutative).

Answer: **(g∘f)(3)=16, (f∘g)(3)=10**.

> [!example] CS connection
> Function composition is fundamental in functional programming. filter ∘ map ∘ reduce is a common pipeline pattern.

## Why This Works

Relations are the mathematical generalisation of "connection". Any time you say "X is related to Y", you are defining a relation. Functions are relations with the extra constraint that each X has exactly one Y — this constraint makes functions predictable and composable, which is why programming relies on them.

The properties of relations (reflexive, symmetric, transitive) mirror properties of equality — which is why equivalence relations are so useful: they partition sets into groups of "equivalent" elements.

## Worked Examples

### Example 1 - Identifying Properties

Question: On ℤ (integers), the relation aRb if a ≤ b. Is it reflexive? Symmetric? Transitive?

Step 1: Reflexive: a ≤ a for all integers? Yes. ✓

Step 2: Symmetric: if a ≤ b, does b ≤ a? No (3 ≤ 5 but 5 ≤ 3 is false). ✗

Step 3: Transitive: if a ≤ b and b ≤ c, does a ≤ c? Yes (3 ≤ 5 and 5 ≤ 7, so 3 ≤ 7). ✓

Answer: **Reflexive ✓, Symmetric ✗, Transitive ✓. This is a partial order**.

### Example 2 - Counting Functions

Question: How many functions are there from A={1,2,3} to B={a,b}?

Step 1: Each element of A (3 elements) can map to any of 2 elements of B.

Step 2: 2³ = 8 functions.

Answer: **8 functions**.

### Example 3 - CS Application: Database Relations

Question: A database table "Students" and "Courses" with a relation "Enrolled" linking them. What type of relation is it?

Step 1: A student can be enrolled in multiple courses (one-to-many). A course can have multiple students (many-to-many).

Step 2: Many-to-many = general relation (not a function).

Answer: **A general relation (many-to-many), not a function**.

### Example 4 - Injective Function Count

Question: How many injective functions from A={1,2,3} to B={a,b,c,d}?

Step 1: Element 1 can map to 4 elements. Element 2 can map to 3 remaining. Element 3 maps to 2 remaining.

Step 2: 4 × 3 × 2 = 24.

Answer: **24 injective functions** (which is P(4,3)).

## Common Mistakes

> [!failure] Mistake pattern: Confusing domain and codomain
> Domain = inputs that actually exist. Codomain = all possible outputs. The range (actual outputs) is a subset of the codomain.

> [!failure] Mistake pattern: Thinking all relations are functions
> A relation can have one input with multiple outputs. A function cannot. Every function is a relation, but not every relation is a function.

> [!failure] Mistake pattern: Assuming composition is commutative
> f∘g is almost never the same as g∘f. Order matters: f∘g means "first g, then f".

> [!failure] Mistake pattern: Confusing injective with surjective
> Injective: each output has ≤1 input (horizontal line test). Surjective: all outputs are used. Memorise: injective = "one-to-one", surjective = "onto".

## Where This Shows Up in CS

### Database Theory
Tables are relations (in the mathematical sense). SQL queries are relational algebra operations.

### Functional Programming
```haskell
-- Map applies a function to every element in a list
map :: (a -> b) -> [a] -> [b]

-- Filter keeps elements where predicate is true
filter :: (a -> Bool) -> [a] -> [a]
```

### Type Systems
Types are sets. Functions are type transformations: add :: (Int, Int) → Int.

### Other applications
- **Graph theory**: edges are a binary relation on vertices
- **Machine learning**: models are functions from features to predictions
- **Cryptography**: encryption is a bijective function (must be invertible)
- **Automata theory**: transition function δ: Q×Σ → Q
