## Plain-English Idea

An **automaton** (plural: automata) is an abstract machine with a finite number of states. It reads input one symbol at a time and transitions between states. Some states are accepting — if the machine ends in an accepting state, the input is accepted.

A **formal language** is a set of strings over an alphabet. Automata recognise languages — they answer "is this string in the language?"

> [!example] Everyday idea
> A vending machine is a finite automaton. States: "waiting for money", "has enough money", "dispensing", "out of stock". Inserting a coin is a transition. If you end in "dispensing" state, you get a drink. In CS, every regex (regular expression) is compiled into an automaton that checks if a string matches the pattern.

## New Words

- **[[finite automaton]]** - a machine with finitely many states that reads input and decides accept/reject.
- **[[state]]** - a configuration of the automaton at a point in time.
- **[[transition]]** - moving from one state to another based on input symbol.
- **[[accepting state]]** - a state indicating the input string is accepted (usually drawn as a double circle).
- **[[regular language]]** - languages that can be recognised by a finite automaton.

You pass this topic only when you can define all five terms without looking.

## Concept 1 - Deterministic Finite Automaton (DFA)

A DFA is defined by a 5-tuple (Q, Σ, δ, q₀, F):

```text
Q  = finite set of states
Σ  = alphabet (finite set of input symbols)
δ  = transition function: Q × Σ → Q
q₀ = start state (q₀ ∈ Q)
F  = set of accepting states (F ⊆ Q)
```

A DFA reads input one symbol at a time. For each symbol, it follows the transition from the current state. At the end, if the current state is in F, the string is accepted.

### Chunked Example

Question: DFA for strings over {0,1} that end with 1.

```text
States: Q = {q₀, q₁}
Alphabet: Σ = {0, 1}
Start: q₀
Accept: F = {q₁}
Transitions:
  q₀ with 0 → q₀
  q₀ with 1 → q₁
  q₁ with 0 → q₀
  q₁ with 1 → q₁

Diagram:
      0
  ┌──────┐
  ↓      │     1
> q₀ ────→ q₁
  ↑       │
  └───0───┘
  (1 loop on q₁ not shown)
```

Test string: 0101

```text
Start at q₀.
Read 0: q₀→q₀
Read 1: q₀→q₁
Read 0: q₁→q₀
Read 1: q₀→q₁
End at q₁ (accepting) → ACCEPTED (string ends with 1).
```

Test string: 0100

```text
Start q₀ → 0(q₀) → 1(q₁) → 0(q₀) → 0(q₀).
End at q₀ (not accepting) → REJECTED (string ends with 0).
```

## Concept 2 - Regular Expressions (Regex)

Regular expressions describe patterns in strings. They are equivalent in power to finite automata — every regex can be converted to a DFA and vice versa.

### Basic Operations

```text
a       → matches the symbol 'a'
ε       → matches the empty string
ab      → a followed by b (concatenation)
a|b     → a OR b (union)
a*      → zero or more a's (Kleene star)
a+      → one or more a's
a?      → zero or one a
(a|b)c  → ac or bc (grouping)
```

### Chunked Example

Question: Write a regex for strings over {0,1} ending with 1.

Step 1: Any string ending with 1 = (something) followed by 1.

Step 2: The "something" can be any string of 0s and 1s = (0|1)*.

Answer: **(0|1)*1**.

> [!example] CS connection
> Every time you use `grep`, `sed`, or `re.match`, you are using a regex that gets compiled into a finite automaton internally.

## Concept 3 - Non-Deterministic Finite Automaton (NFA)

An NFA is like a DFA but with a key difference: from a given state and symbol, there can be **multiple possible transitions** (including zero). An NFA accepts if ANY path leads to an accepting state.

NFAs are easier to write, but every NFA can be converted to an equivalent DFA (the subset construction).

### Chunked Example

Question: NFA for strings over {0,1} ending with 1.

```text
States: q₀, q₁
Transitions:
  q₀ with 0 → q₀
  q₀ with 1 → q₀ (stay) OR q₁ (guess this is the last 1)
  q₁ with 0 → (none)
  q₁ with 1 → (none)
Accept: q₁
```

For input "101":
```text
Possible paths:
q₀ -1→ q₁ (accept)    → ACCEPTED
q₀ -1→ q₀ -0→ q₀ -1→ q₁ (accept) → also accepted
```

The NFA "guesses" the right path. The equivalent DFA tracks all possible states simultaneously.

## Concept 4 - Regular Languages and the Pumping Lemma

A language is **regular** if it can be recognised by a finite automaton (or described by a regex).

### Chunked Example

Question: Is L = {0ⁿ1ⁿ | n ≥ 0} (strings with n zeros followed by n ones) regular?

Step 1: This language needs to "count" — you need to remember how many zeros you saw to match with the same number of ones.

Step 2: A finite automaton has a fixed number of states. For large n, you would run out of states to remember the count.

Step 3: The **Pumping Lemma** formally proves that L is not regular.

Answer: **L = {0ⁿ1ⁿ} is NOT regular** (requires more power than a DFA).

## Concept 5 - Context-Free Grammars

Context-free grammars (CFGs) extend regular languages. They are powerful enough to describe programming language syntax.

A CFG has production rules: A → α where A is a non-terminal and α is a string of terminals and non-terminals.

### Chunked Example

Question: Grammar for balanced parentheses: S → (S) | SS | ε.

Step 1: S can become (S) (parentheses around something), or SS (two parts), or nothing.

Step 2: Derive "(())()":

```text
S → SS → (S)S → ((S))S → (())S → (())(S) → (())()
```

Answer: **(())() is generated by the grammar**.

> [!example] CS connection
> Programming language syntax is defined by CFGs. Every compiler uses a parser that checks if source code matches the grammar.

## Why This Works

Automata theory formalises "what can a computer do?" by studying increasingly powerful machines.

The Chomsky hierarchy organises languages by the power needed to recognise them:

```text
Regular (DFA/NFA/regex)   ← weakest, fastest
Context-Free (PDA/CFG)     ← programming languages
Context-Sensitive (LBA)    ← more complex patterns
Recursively Enumerable (TM) ← Turing machines = general computers
```

Each level adds power: a finite automaton cannot count, a pushdown automaton can (using a stack), and a Turing machine can do everything a real computer can.

## Worked Examples

### Example 1 - Design a DFA

Question: Design a DFA over {0,1} that accepts strings where the number of 1s is even.

Step 1: Two states: q_even (even 1s, start, accept) and q_odd (odd 1s).

```text
Transitions:
q_even with 0 → q_even (0 doesn't change count)
q_even with 1 → q_odd
q_odd  with 0 → q_odd
q_odd  with 1 → q_even
```

Step 2: Test "1011":
```text
q_even -1→ q_odd -0→ q_odd -1→ q_even -1→ q_odd
End at q_odd → REJECTED
```

Answer: **See DFA above**.

### Example 2 - Regex Equivalence

Question: Write a regex for the DFA above (even number of 1s).

Step 1: Strings with an even number of 1s can have any number of 0s.

Step 2: Pattern: (0*10*10*)* — groups of exactly two 1s with any zeros.

Step 3: Simplified: (0*10*10*)*, with option for trailing 0s: (0*10*10*)*0*.

Answer: **(0*10*10*)*0* (or equivalently, (0*10*1)*0*)**.

### Example 3 - NFA to DFA Conversion

Question: Convert the NFA where q₀ with 1 goes to {q₀, q₁} to a DFA.

Step 1: The NFA state set is {q₀, q₁}. The DFA states are subsets: {}, {q₀}, {q₁}, {q₀,q₁}.

Step 2: Start state = ε-closure(q₀) = {q₀}.

Step 3: Compute transitions:

```text
{q₀} with 1 → {q₀, q₁} (all states reachable from q₀ with 1)
{q₀} with 0 → {q₀}
{q₀, q₁} with 1 → {q₀, q₁} (q₀→q₀ and q₀→q₁)
{q₀, q₁} with 0 → {q₀} (only q₀ has a 0 transition)
```

Answer: **DFA with 3 reachable states: {q₀} and {q₀, q₁} (accepting since it contains q₁)**.

### Example 4 - Grammar Derivation

Question: Grammar: S → aSb | ε. Derive "aaabbb".

Step 1: S → aSb → aaSbb → aaaSbbb → aaabbb.

Answer: **aaabbb is generated** (matches a³b³ pattern).

## Common Mistakes

> [!failure] Mistake pattern: Forgetting that DFA transitions must be defined for every symbol
> Every DFA state must have exactly one transition for each symbol in Σ. If a transition is missing, it is an NFA, not a DFA.

> [!failure] Mistake pattern: Confusing DFA acceptance with NFA acceptance
> DFA: if the final state is accepting → accept. NFA: if ANY path leads to an accepting state → accept. NFAs can have multiple active paths.

> [!failure] Mistake pattern: Thinking regex can match anything
> Regex (regular languages) cannot count or match nested structures. Parsing HTML with regex famously fails because HTML is context-free, not regular.

## Where This Shows Up in CS

### Compilers
```text
Lexer:   regex → DFA → tokeniser
Parser:  CFG → parser → AST
```

### Text Processing
Every programming language has regex libraries. `grep`, `sed`, `awk`, JavaScript `RegExp`, Python `re` all use automata theory.

### Network Protocols
Finite state machines model protocols (TCP, HTTP, etc.). Each state represents a stage, each packet triggers a transition.

### Other applications
- **Pattern matching**: DNA sequence matching, intrusion detection
- **Game AI**: finite state machines for character behaviour
- **Hardware design**: circuit state machines
- **Natural language processing**: regular languages for tokenisation
