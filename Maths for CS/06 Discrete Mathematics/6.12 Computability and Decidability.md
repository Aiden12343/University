## Plain-English Idea

Some problems can be solved by computers — these are **decidable**. Some problems cannot be solved by any computer, no matter how fast or how much memory — these are **undecidable**.

The most famous undecidable problem is the **Halting Problem**: "Given a program and its input, will it eventually stop or run forever?" In 1936, Alan Turing proved that no algorithm can decide this for all possible programs.

> [!example] Everyday idea
> You write a program with a while-loop. You think it always terminates, but you are not sure. You wish you could write a "halting checker" that looks at any program and says "yes, it will stop" or "no, it will loop forever". Turing proved this is impossible — there will always be programs where you cannot tell without running them.

## New Words

- **[[decision problem]]** - a yes/no question about an input (e.g., "Is this number prime?").
- **[[decidable]]** - a problem for which an algorithm exists that always gives the correct yes/no answer.
- **[[undecidable]]** - a problem for which no algorithm can ever exist.
- **[[Halting Problem]]** - the problem of determining whether an arbitrary program halts or runs forever.
- **[[reduction]]** - proving a problem is undecidable by showing that solving it would let you solve the Halting Problem.

You pass this topic only when you can define all five terms without looking.

## Concept 1 - Decidable Problems

A problem is **decidable** if there is an algorithm that:

1. Always halts (terminates).
2. Always gives the correct answer (yes or no).

Many problems are decidable:
```text
Is this number prime?         → Yes (trial division works)
Is this string in the DFA?    → Yes (simulate the DFA)
Is this boolean formula true? → Yes (truth table, but slow)
Are these two grammars equal? → No! (undecidable for CFGs)
```

### Chunked Example

Question: Is "Is the first element of this array equal to 5?" decidable?

Step 1: Algorithm: read the first element, compare to 5, output yes/no, halt.

Step 2: This always works in a finite number of steps.

Answer: **Yes, this is decidable**.

## Concept 2 - The Halting Problem

The Halting Problem asks: Given a program P and an input I, does P(I) halt or run forever?

Turing's proof shows that no program H(P, I) can decide this correctly for all P and I.

### The Proof (by contradiction)

Assume such a program H exists:

```text
H(P, I):
  if P(I) halts:  return "halts"
  if P(I) loops:  return "loops"
```

Now construct a "contradiction program" Q:

```python
def Q(P):
    if H(P, P) == "halts":
        while True: pass   # loop forever
    else:
        return             # halt
```

Now ask: What happens when Q runs on itself? Q(Q)?

```text
Case 1: H(Q, Q) says "halts".
  Then Q(Q) enters the while-loop → it does NOT halt.
  Contradiction: H said halts, but Q does not halt.

Case 2: H(Q, Q) says "loops".
  Then Q(Q) returns immediately → it DOES halt.
  Contradiction: H said loops, but Q halts.
```

Both cases lead to contradiction. Therefore H cannot exist.

> [!tip] Why this matters
> This proof shows there is a fundamental limit to computation. No matter how powerful computers become, the Halting Problem will always be unsolvable.

## Concept 3 - Implications of Undecidability

Once you have one undecidable problem (the Halting Problem), you can prove many others are undecidable by **reduction**.

If problem X can be solved, then the Halting Problem can be solved. Since the Halting Problem is unsolvable, X must also be unsolvable.

### Classic Undecidable Problems

```text
1. Halting Problem: Will this program halt?
2. Rice's Theorem: ANY non-trivial property of program behaviour is undecidable.
   - "Does this program ever output 42?" → undecidable.
   - "Does this program ever crash?" → undecidable.
   - "Are these two programs equivalent?" → undecidable.
3. Post Correspondence Problem: matching sequences of tiles.
4. Hilbert's Tenth Problem: solving Diophantine equations.
5. The Entscheidungsproblem: deciding if a first-order logic formula is valid.
```

### Chunked Example

Question: Is "Does this program ever print 'Hello'?" decidable?

Step 1: If you could decide this, you could solve the Halting Problem.

Step 2: Modify any program to print "Hello" just before halting. If it halts, it prints "Hello". If it loops, it never prints "Hello".

Step 3: A "prints Hello?" checker would tell you whether the program halts. Since halting is undecidable, "prints Hello?" is also undecidable.

Answer: **No, it is undecidable (by Rice's Theorem)**.

> [!example] CS connection
> This means that no compiler can ever warn you about all infinite loops. No static analyser can perfectly detect all bugs. All useful static analysis is necessarily approximate.

## Concept 4 - Decidable vs Undecidable (Practical Guide)

Most problems you encounter are decidable:

```text
DECIDABLE:
  Sorting, searching, pathfinding
  Checking if a number is prime
  Checking if a grammar generates a specific string
  Linear programming optimisation
  Boolean satisfiability (SAT) — decidable but hard (NP-complete)

UNDECIDABLE:
  Halting problem
  Program equivalence
  Any non-trivial property of program behaviour (Rice)
  Whether a CFG is ambiguous
  Whether two context-free grammars generate the same language
  Whether a given Turing machine halts on all inputs
```

## Concept 5 - Turing Machines and the Church-Turing Thesis

A **Turing machine** is the mathematical model of a general-purpose computer. It has:

- An infinite tape (memory).
- A read/write head.
- A finite set of states and transition rules.

**Church-Turing Thesis**: Any function that can be computed by any physical computer can be computed by some Turing machine. This is a thesis (not a theorem), but it is universally accepted.

### Chunked Example

Question: What is the difference between a DFA and a Turing machine?

Step 1: A DFA only reads input once left-to-right and has no memory besides its state.

Step 2: A Turing machine can read AND write on the tape, move left and right, and has unlimited memory.

Step 3: Turing machines can simulate any DFA (but not vice versa). DFAs recognise regular languages; Turing machines recognise recursively enumerable languages.

Answer: **Turing machines are strictly more powerful (can write, unlimited memory)**.

## Why This Works

Computability theory draws a line between what can and cannot be computed. The line is not about our current technology — it is a mathematical impossibility.

The proof works because programs are just strings that can be analysed by other programs (like compilers). The self-referential trick (running Q on Q) is similar to the liar paradox: "This statement is false."

Just as [[5.8 Propositional Logic]] and [[5.9 Predicate Logic]] formalise what can be proven, computability theory formalises what can be computed.

## Worked Examples

### Example 1 - Classifying Problems

Question: Classify as decidable or undecidable:
(a) Given a DFA and a string, does the DFA accept the string?
(b) Given two DFAs, do they accept the same language?
(c) Given a program, does it ever use more than 1GB of memory?

Step 1: (a) Yes, simulate the DFA → decidable.

Step 2: (b) Yes, minimise both DFAs and compare (DFA equivalence is decidable) → decidable.

Step 3: (c) If you could decide this, you could solve the Halting Problem (replace "use 1GB" with "halt") → undecidable.

Answer: **(a) Decidable, (b) Decidable, (c) Undecidable**.

### Example 2 - A Decidable Non-Obvious Problem

Question: Is the language of a DFA infinite? Decidable?

Step 1: If a DFA accepts arbitrarily long strings, its language is infinite.

Step 2: On a DFA with n states, if it accepts any string of length ≥ n, it accepts infinitely many (pumping lemma).

Step 3: Algorithm: check all strings of length from n to 2n-1. If any is accepted, language is infinite. Finite check → decidable.

Answer: **Decidable (bounded search)**.

### Example 3 - Reduction in Practice

Question: Show that "Does this program output 'Hello'?" is undecidable by reduction from the Halting Problem.

Step 1: Suppose we have a program H that decides "Does P output 'Hello'?".

Step 2: Given any program P and input I, construct P' that behaves like P but prints "Hello" at each step.

Step 3: P halts on I ↔ P' outputs 'Hello' (finitely many times). If H says yes, P halts.

Step 4: Since halting is undecidable, H cannot exist.

Answer: **Undecidable (as proven by reduction)**.

### Example 4 - The Busy Beaver Problem

Question: The Busy Beaver problem asks: what is the maximum number of 1s an n-state Turing machine can print before halting? Is this decidable?

Step 1: If you could compute BB(n) for all n, you could solve the Halting Problem (run a machine for BB(n) steps; if it hasn't halted, it never will).

Step 2: BB(n) grows faster than any computable function.

Step 3: BB(1)=1, BB(2)=4, BB(3)=6, BB(4)=13, BB(5)≥4098, BB(6) is astronomically large (unknown).

Answer: **Undecidable in general (though small values are known by exhaustive search)**.

## Common Mistakes

> [!failure] Mistake pattern: Confusing "hard" with "undecidable"
> Travelling Salesman Problem (NP-hard) is decidable — it just takes exponential time. Undecidable means NO algorithm exists, not even a slow one.

> [!failure] Mistake pattern: Thinking the Halting Problem is a practical problem
> For most programs you actually write, you CAN tell whether they halt. The Halting Problem says no single algorithm works for ALL programs. The hard cases are self-referential.

> [!failure] Mistake pattern: Misapplying Rice's Theorem
> Rice's Theorem applies to non-trivial SEMANTIC properties of programs — properties about what the program DOES, not how it is WRITTEN. "Does the program have 50 lines?" is decidable (trivial syntactic property). "Does the program compute the square root?" is undecidable.

## Where This Shows Up in CS

### Compiler Optimisation
No compiler can perfectly detect all dead code (code that never executes) — this is undecidable by Rice's Theorem.

### Static Analysis
Tools like linters, type checkers, and bug finders are always incomplete. They can find some bugs but cannot find all.

### Software Verification
Proving a program correct for all inputs is undecidable in general. This is why formal verification ([[11.2 Formal Verification Model Checking]]) focuses on restricted models (e.g., finite-state systems).

### Other applications
- **AI**: deciding if a general AI will behave safely is undecidable
- **Programming languages**: type inference for advanced type systems may be undecidable
- **Theorem proving**: no algorithm can decide if an arbitrary mathematical statement is true
- **Viruses**: detecting a perfect virus (one that infects all programs) is undecidable
