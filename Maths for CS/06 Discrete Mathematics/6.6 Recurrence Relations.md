## Introduction

A **recurrence relation** defines a sequence where each term depends on previous terms. Fibonacci: `F₀ = 0, F₁ = 1, Fₙ = Fₙ₋₁ + Fₙ₋₂`. Merge sort: `T(n) = 2T(n/2) + n`.

Recurrences are the mathematical modelling tool for recursive algorithms. Every recursive function has a corresponding recurrence describing its running time. Solving recurrences — finding closed forms or complexity classes — is essential for understanding whether an algorithm is fast enough for a given input size.

The two key methods: **iteration** (expand and look for a pattern) and the **Master Theorem** (a formula for divide-and-conquer recurrences).

## New Words

- [[recurrence relation]] — an equation defining a sequence term using previous terms.
- [[base case]] — the starting value(s) that stop the recursion (e.g., T(1)=1).
- [[closed form]] — a direct formula for the n-th term that does not reference earlier terms.
- [[iteration method]] — expanding the recurrence repeatedly to find a pattern.
- [[Master Theorem]] — a formula for solving recurrences of the form T(n) = aT(n/b) + f(n).

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: What Is a Recurrence?

**Builds on:** [[6.1 Sequences and Series]] (sequences defined by position), [[5.11 Proof by Induction]] (base case + inductive step)

A recurrence has two parts:

1. **Base case(s)**: defined directly (no recursion).
2. **Recurrence step**: defines a term using earlier terms.

### Chunked Example

Question: Given T(1)=1, T(n)=T(n-1)+n for n>1, find T(4).

Step 1: Start from the base and build up.

```text
T(1) = 1
T(2) = T(1) + 2 = 1 + 2 = 3
T(3) = T(2) + 3 = 3 + 3 = 6
T(4) = T(3) + 4 = 6 + 4 = 10
```

Answer: **T(4) = 10**.

> [!tip] Building up vs recursing down
> You can start from the base case and work up (as above) or start from T(n) and substitute down until you hit the base case. Both give the same answer.

### Breadcrumb 2: The Iteration Method

**Builds on:** [[6.6 Recurrence Relations]] (recurrence structure), [[6.2 Summation and Product Notation]] (summing the pattern)

Expand the recurrence repeatedly, look for a pattern, then write a closed form.

### Chunked Example: Arithmetic Recurrence

Question: T(1)=1, T(n)=T(n-1)+2. Find closed form.

Step 1: Expand:

```text
T(n) = T(n-1)+2
T(n-1) = T(n-2)+2, so T(n) = T(n-2) + 2 + 2
T(n-2) = T(n-3)+2, so T(n) = T(n-3) + 2 + 2 + 2
```

Step 2: After k steps: T(n) = T(n-k) + 2k.

Step 3: When n-k=1, k=n-1: T(n) = T(1) + 2(n-1) = 1 + 2n - 2 = 2n - 1.

Answer: **T(n) = 2n - 1**.

Check: T(1)=1, T(2)=3, T(3)=5, T(4)=7. ✓

### Chunked Example: Geometric Recurrence

Question: T(1)=1, T(n)=2T(n-1). Find closed form.

Step 1: Expand:

```text
T(n) = 2T(n-1) = 2(2T(n-2)) = 2²T(n-2) = 2³T(n-3) = ...
```

Step 2: After k steps: T(n) = 2ᵏT(n-k).

Step 3: When n-k=1, k=n-1: T(n) = 2ⁿ⁻¹ × T(1) = 2ⁿ⁻¹ × 1 = 2ⁿ⁻¹.

Answer: **T(n) = 2ⁿ⁻¹**.

Check: T(1)=1=2⁰, T(2)=2=2¹, T(3)=4=2². ✓

### Breadcrumb 3: Divide-and-Conquer Recurrences

**Builds on:** [[6.6 Recurrence Relations]] (iteration method), [[2.9 Indices and Powers]] (logarithms for split factor b)

These model recursive algorithms that split the input.

```text
T(n) = aT(n/b) + f(n)
```

where:
- a = number of subproblems
- n/b = size of each subproblem
- f(n) = cost to split and combine

### Chunked Example: Merge Sort

Question: Merge sort: T(n) = 2T(n/2) + n, T(1)=1. What is its complexity?

Step 1: Visualise the recursion tree.

```text
Level 0: 1 problem of size n, cost = n
Level 1: 2 problems of size n/2, cost = 2 × n/2 = n
Level 2: 4 problems of size n/4, cost = 4 × n/4 = n
...
```

Step 2: There are log₂(n)+1 levels, each costing n.

Step 3: Total cost = n × (log₂n + 1) = n log₂n + n.

Answer: **T(n) = n log₂n + n, which is O(n log n)**.

### Breadcrumb 4: The Master Theorem

**Builds on:** [[6.6 Recurrence Relations]] (divide-and-conquer form), [[3.7 Logarithms]] (log_b a as comparison baseline)

For recurrences T(n) = aT(n/b) + f(n), compare f(n) to n^(log_b a).

```text
Case 1: f(n) = O(n^(log_b a - ε))   → T(n) = Θ(n^(log_b a))
Case 2: f(n) = Θ(n^(log_b a))        → T(n) = Θ(n^(log_b a) × log n)
Case 3: f(n) = Ω(n^(log_b a + ε))    → T(n) = Θ(f(n))
```

### Chunked Example

Question: T(n) = 9T(n/3) + n. Solve with Master Theorem.

Step 1: a=9, b=3, f(n)=n. Compute log_b a = log₃9 = 2.

Step 2: n^(log_b a) = n². Compare f(n)=n to n².

```text
n = O(n²⁻¹)  → Case 1 with ε=1.
```

Step 3: T(n) = Θ(n²).

Answer: **Θ(n²)**.

### Chunked Example

Question: T(n) = 2T(n/2) + n. (Merge sort).

Step 1: a=2, b=2, f(n)=n. log₂2=1. n¹=n.

Step 2: f(n) = n = Θ(n^log_b a) → Case 2.

Step 3: T(n) = Θ(n log n).

Answer: **Θ(n log n)**.

> [!warning] When the Master Theorem does not apply
> The Master Theorem only applies when a ≥ 1, b > 1, and f(n) is asymptotically positive. If T(n) = T(n-1) + n (not divide-and-conquer), use iteration instead.

### Breadcrumb 5: Fibonacci Numbers

**Builds on:** [[6.6 Recurrence Relations]] (recurrence structure), [[6.1 Sequences and Series]] (building terms step by step)

The Fibonacci sequence is defined by:

```text
F₀ = 0, F₁ = 1, Fₙ = Fₙ₋₁ + Fₙ₋₂
```

### Chunked Example

Question: Compute F₇.

Step 1: Build up from F₀, F₁.

```text
F₀ = 0
F₁ = 1
F₂ = 0+1 = 1
F₃ = 1+1 = 2
F₄ = 1+2 = 3
F₅ = 2+3 = 5
F₆ = 3+5 = 8
F₇ = 5+8 = 13
```

Answer: **F₇ = 13**.

> [!example] CS connection
> Computing Fibonacci with naive recursion takes T(n) = T(n-1) + T(n-2) + O(1) which is O(2ⁿ) — exponential! Dynamic programming reduces this to O(n) by storing computed values.

## Worked Examples

### Example 1 — Iteration Method: Linear Recurrence

Question: Given T(1) = 5, T(n) = T(n−1) + 3n for n > 1, find T(4).

Step 1: Build up from the base case.
T(1) = 5.

Step 2: Apply the recurrence.
T(2) = T(1) + 3×2 = 5 + 6 = 11.
T(3) = T(2) + 3×3 = 11 + 9 = 20.
T(4) = T(3) + 3×4 = 20 + 12 = 32.

Answer: **T(4) = 32**.

### Example 2 — Iteration Method: Geometric Recurrence (Closed Form)

Question: Given T(1) = 2, T(n) = 4T(n−1) for n > 1, find a closed form.

Step 1: Expand the recurrence.
T(n) = 4T(n−1) = 4 × 4T(n−2) = 4²T(n−2) = 4³T(n−3).

Step 2: After k steps: T(n) = 4ᵏT(n−k).

Step 3: Stop when n−k = 1, so k = n−1.
T(n) = 4ⁿ⁻¹ × T(1) = 4ⁿ⁻¹ × 2 = 2 × 4ⁿ⁻¹.

Step 4: Check: T(1)=2, T(2)=8, T(3)=32, T(4)=128. ✓

Answer: **T(n) = 2 × 4ⁿ⁻¹**.

### Example 3 — Master Theorem

Question: T(n) = 4T(n/2) + n. Solve using the Master Theorem.

Step 1: Identify parameters.
a = 4, b = 2, f(n) = n.

Step 2: Compute log_b a = log₂4 = 2.
n^(log_b a) = n².

Step 3: Compare f(n) = n to n².
n = O(n²⁻¹) with ε = 1, so this is Case 1.

Step 4: Apply Case 1: T(n) = Θ(n^(log_b a)) = Θ(n²).

Answer: **Θ(n²)**.

### Example 4 — Fibonacci Numbers

Question: Compute F₁₀ where F₀ = 0, F₁ = 1, Fₙ = Fₙ₋₁ + Fₙ₋₂.

Step 1: Build up from the base cases.
F₀ = 0
F₁ = 1
F₂ = 0 + 1 = 1
F₃ = 1 + 1 = 2
F₄ = 1 + 2 = 3
F₅ = 2 + 3 = 5
F₆ = 3 + 5 = 8
F₇ = 5 + 8 = 13
F₈ = 8 + 13 = 21
F₉ = 13 + 21 = 34
F₁₀ = 21 + 34 = 55

Answer: **F₁₀ = 55**.

## Why This Works

Recurrences are the mathematical version of recursion. The base case is the `if` that stops recursion; the recurrence step is the recursive call. Just as [[5.11 Proof by Induction]] proves P(k) → P(k+1), recurrences define T(n) in terms of T(n-1) or T(n/b). The iteration method expands until the base case is reached; the Master Theorem provides a shortcut for divide-and-conquer patterns.

The recursion tree visualisation (level 0: one problem of size n, level 1: a problems of size n/b, ...) makes the total cost visible as a geometric series.

## Common Mistakes

> [!failure] Mistake pattern: Forgetting base cases
> T(n) = T(n-1) + n without specifying T(1) is incomplete. Every recurrence needs at least one base case.

> [!failure] Mistake pattern: Applying Master Theorem to non-divide-and-conquer recurrences
> T(n) = T(n-1) + n does NOT fit the form T(n) = aT(n/b) + f(n). Use iteration instead.

> [!failure] Mistake pattern: Off-by-one in Fibonacci indexing
> Some sources start F₁=1, F₂=1. Others start F₀=0, F₁=1. Always check which indexing is used.

> [!failure] Mistake pattern: Confusing n for n/2
> In Master Theorem, b is the factor the input is divided by. T(n)=2T(n/2)+n has b=2. If the recurrence were T(n)=2T(n-2)+n, that is not divide-and-conquer.

## Where This Shows Up in CS

### Merge Sort Recursion Tree
```text
T(n) = 2T(n/2) + n  →  Θ(n log n)
```

### Binary Search
```text
T(n) = T(n/2) + 1  →  Θ(log n)
```

### Recursive Fibonacci
```text
T(n) = T(n-1) + T(n-2) + 1  →  Θ(2ⁿ)  (exponential — impractical!)
```

### Other applications
- **Dynamic programming**: any DP algorithm solves subproblems defined by a recurrence
- **Divide-and-conquer algorithms**: most have T(n) = aT(n/b) + f(n)
- **Data structures**: tree height, balance conditions
- **Recursive graph algorithms**: DFS, topological sort
