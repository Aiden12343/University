## Plain-English Idea

A **tree** is a connected graph with no cycles. It is the simplest structure that can connect many vertices without redundancy. Trees model hierarchies:

```text
File system:      root → folders → files
HTML DOM:         html → head, body → divs
Organisation:     CEO → directors → managers → staff
Binary search:    root → left (smaller), right (larger)
```

**Traversal** is the order in which you visit every node in a tree.

> [!example] Everyday idea
> A family tree is a tree. Each person has parents (ancestors), which branches further up. A traversal would be listing all relatives in a specific order. In computing, every folder and file in your hard drive forms a tree.

## New Words

- **[[tree]]** - a connected, acyclic graph. |E| = |V| - 1.
- **[[root]]** - the topmost node in a rooted tree (no parent).
- **[[leaf]]** - a node with no children (degree 1 in a rooted tree).
- **[[depth]]** - the number of edges from the root to a given node.
- **[[traversal]]** - visiting nodes in a specific order (preorder, inorder, postorder).

You pass this topic only when you can define all five terms without looking.

## Concept 1 - Tree Properties

A tree is the simplest connected graph. Key properties:

```text
1. Connected: there is a path between any two vertices.
2. Acyclic: there is no cycle (no way to return to a vertex).
3. |E| = |V| - 1 (for a tree with n vertices, there are n-1 edges).
```

### Chunked Example

Question: A tree has 12 vertices. How many edges?

Step 1: For any tree, |E| = |V| - 1.

```text
|E| = 12 - 1 = 11
```

Answer: **11 edges**.

### Chunked Example

Question: Is a graph with 6 vertices and 5 edges necessarily a tree?

Step 1: |E| = |V|-1 = 5. Condition met.

Step 2: But it also must be connected and acyclic. If it is disconnected or has a cycle, it is not a tree.

Answer: **It could be a tree IF connected and acyclic. The edge count alone is not enough**.

## Concept 2 - Rooted Trees

In a **rooted tree**, one vertex is designated as the root. Every edge points away from the root.

Terminology:
- **Root**: the top node (no parent).
- **Parent**: a node's immediate predecessor toward the root.
- **Child**: a node's immediate successor away from the root.
- **Leaf**: a node with no children.

```text
        A  ← root
       / \
      B   C  ← children of A
     / \   \
    D   E   F  ← leaves (D, E, F have no children)
```

### Chunked Example

Question: In the tree above, what are the parents of D and F? What are the leaves?

Step 1: D's parent is B. F's parent is C.

Step 2: Leaves have no children: D, E, F.

Answer: **Parent(D)=B, Parent(F)=C. Leaves={D, E, F}**.

## Concept 3 - Binary Trees

A **binary tree** is a rooted tree where each node has at most 2 children (left and right).

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

### Full Binary Tree
Every node has 0 or 2 children. (D, E, F are leaves → OK. B has 2 children → OK. C has 1 child → NOT a full binary tree.)

### Complete Binary Tree
All levels are filled except possibly the last, which is filled from left to right.

## Concept 4 - Tree Traversal Orders

Traversal visits every node exactly once. Three standard orders for binary trees:

### Preorder (Root, Left, Right)
```text
Visit root → traverse left subtree → traverse right subtree
```

### Inorder (Left, Root, Right)
```text
Traverse left subtree → visit root → traverse right subtree
```

### Postorder (Left, Right, Root)
```text
Traverse left subtree → traverse right subtree → visit root
```

### Chunked Example

Question: For the tree:
```text
    A
   / \
  B   C
 / \
D   E
```

List nodes in preorder, inorder, and postorder.

Step 1: Preorder (Root, Left, Right):
```text
Visit A. Then left subtree (B). Then right subtree (C).
Left of B: D, E in preorder → B, D, E → C.
Total: A, B, D, E, C
```

Step 2: Inorder (Left, Root, Right):
```text
Left of A → traverse B's left (D), visit B, visit B's right (E). Visit A.
Right of A: C.
Total: D, B, E, A, C
```

Step 3: Postorder (Left, Right, Root):
```text
Left of A → traverse B's left (D), right (E), visit B.
Right of A: C.
Visit A.
Total: D, E, B, C, A
```

Answer:
```text
Preorder:  A, B, D, E, C
Inorder:   D, B, E, A, C
Postorder: D, E, B, C, A
```

> [!tip] Mnemonic
> Pre = root first. Post = root last. In = root in the middle.

## Concept 5 - Tree Height and Depth

**Height** of a node: the number of edges on the longest path from that node to a leaf.
**Depth** of a node: the number of edges from the root to that node.
**Height of the tree**: height of the root.

### Chunked Example

Question: In the tree:
```text
    A
   / \
  B   C
 / \
D   E
```

Find depth of E and height of the tree.

Step 1: Depth of E: A→B→E = 2 edges. Depth=2.

Step 2: Height of tree: longest path root-to-leaf. Paths: A-B-D (2 edges), A-B-E (2 edges), A-C (1 edge). Max=2.

Answer: **Depth(E)=2, tree height=2**.

## Why This Works

A tree is the minimal connected graph. Adding one edge to a tree creates exactly one cycle. Removing any edge disconnects the tree. This makes trees ideal for hierarchies (file systems, organisational charts, search structures) where you want exactly one path between any two nodes.

Every tree is a graph (satisfies all graph definitions from [[6.7 Graph Theory Basics]]), but not every graph is a tree. The extra constraints (connected, acyclic) make trees simpler and more structured.

## Worked Examples

### Example 1 - Tree Identification

Question: A graph has 7 vertices and 6 edges, is connected, and has no cycles. Is it a tree?

Step 1: Check |E| = |V|-1: 6 = 7-1. ✓

Step 2: Connected and acyclic given.

Answer: **Yes, it is a tree**.

### Example 2 - Preorder Traversal

Question: Traverse in preorder:
```text
    A
   / \
  B   C
 /   / \
D   E   F
```

Step 1: Root A. Then left subtree (B). Then right subtree (C).

Step 2: In B's subtree: Visit B, then left D. B has no right child.

Step 3: In C's subtree: Visit C, left E, right F.

Answer: **A, B, D, C, E, F**.

### Example 3 - Inorder Traversal of BST

Question: Inorder traverse a Binary Search Tree with keys: 50 (root), 30 (left), 70 (right), 20 (left of 30), 40 (right of 30), 60 (left of 70), 80 (right of 70).

Step 1: Draw the tree:
```text
        50
       /  \
     30    70
    /  \   / \
  20   40 60  80
```

Step 2: Inorder (left, root, right):
```text
Traverse left of 50: 20, 30, 40.
Visit 50.
Traverse right of 50: 60, 70, 80.
```

Answer: **20, 30, 40, 50, 60, 70, 80** (sorted order!).

> [!example] CS connection
> Inorder traversal of a BST visits nodes in sorted order. This is why BSTs are used for ordered data.

### Example 4 - Postorder for Expression Trees

Question: Postorder traverse the expression tree for (A+B)×(C-D):
```text
    ×
   / \
  +   -
 / \ / \
A  B C  D
```

Step 1: Postorder (left, right, root): left sub (A, B, +), right sub (C, D, -), root (×).

Answer: **A, B, +, C, D, -, ×** (Reverse Polish Notation — used in stack-based calculators).

## Common Mistakes

> [!failure] Mistake pattern: Confusing preorder and postorder
> Preorder: root first (pre = before children). Postorder: root last (post = after children). Think "pre = process before children, post = process after children."

> [!failure] Mistake pattern: Forgetting that a tree must be connected
> A graph with |E| = |V|-1 that is disconnected is a FOREST (several trees), not a tree.

> [!failure] Mistake pattern: Treating all trees as binary
> A general tree node can have any number of children, not just 0, 1, or 2.

```text
/ (root)
├── home
│   ├── user

├── etc
└── var
```
