## Introduction

Computers cannot represent real numbers exactly. They use **floating-point approximation** — like 3.14159265358979 instead of π. These tiny rounding errors (about 1 part in 10¹⁶ for double precision) can grow during calculations, making answers completely wrong.

From [[7.11 Matrix Decompositions LU QR SVD]], you know that different algorithms for the same problem can give different results. The difference is numerical stability: an algorithm that controls rounding error is stable; one that lets errors explode is unstable.

The key concept is the **condition number** — a property of the problem itself (not the algorithm). An **ill-conditioned** problem is one where small input changes cause huge output changes. No algorithm can fix that.

## New Words

- **[[numerical stability]]** — an algorithm whose output is not overly sensitive to rounding errors.
- **[[condition number]]** — κ(A) = ||A||·||A⁻¹||, a measure of how sensitive the problem is.
- **[[ill-conditioned]]** — a problem with large κ(A) (small errors cause large output changes).
- **[[machine epsilon]]** — ε_mach, about 2×10⁻¹⁶ for double precision, the rounding unit.
- **[[backward stability]]** — an algorithm gives the exact answer for a slightly perturbed input.

## Breadcrumbs

### Breadcrumb 1: Floating-Point Arithmetic

**Builds on:** [[7.6 Solving Linear Systems with Matrices]] (matrix computations), [[1.13 Estimation and Error Checking]] (approximation, significant figures)

Computers store numbers in binary with limited precision:
- **Single precision (float32)**: about 7 decimal digits, ε ≈ 1.2×10⁻⁷.
- **Double precision (float64)**: about 16 decimal digits, ε ≈ 2.2×10⁻¹⁶.

Every floating-point operation introduces a relative error of about ε. These errors are usually harmless, but they can accumulate catastrophically in certain situations.

Floating-point arithmetic does not follow exact mathematical rules:
- (a + b) + c ≠ a + (b + c) in general (associativity fails).
- a × (b + c) ≠ a×b + a×c in general (distributivity fails).

#### Chunked Example

Question: In double precision, compute 1 + 10⁻¹⁷ - 1.

Step 1: 1 + 10⁻¹⁷ = 1.00000000000000001. But double precision only stores ≈ 16 decimal digits.

Step 2: 10⁻¹⁷ is below ε × 1 ≈ 2×10⁻¹⁶, so 1 + 10⁻¹⁷ rounds to exactly 1.

Step 3: 1 - 1 = 0. The result is 0, not 10⁻¹⁷.

Answer: **The small number was lost to rounding. This is called "catastrophic cancellation"**.

### Breadcrumb 2: Condition Number

**Builds on:** [[7.4 Identity and Inverse Matrices]] (A⁻¹), [[7.11 Matrix Decompositions LU QR SVD]] (SVD reveals singular values)

The **condition number** κ(A) measures how sensitive the solution of Ax = b is to changes in A or b:

```
κ(A) = ||A|| × ||A⁻¹||
```

In terms of SVD singular values:
```
κ(A) = σ_max / σ_min
```

A rule of thumb: you lose about log₁₀(κ) decimal digits of accuracy.

| κ(A) | Classification | What Happens |
|------|---------------|--------------|
| 1 | Perfectly conditioned | No error amplification |
| 10² | Well-conditioned | Lose about 2 digits |
| 10⁸ | Ill-conditioned | Lose about 8 digits |
| ∞ (σ_min = 0) | Singular | Matrix not invertible |

#### Chunked Example

Question: The Hilbert matrix Hₙ has entries Hᵢⱼ = 1/(i+j-1). For n = 10, κ ≈ 10¹³. How many decimal digits of accuracy do you lose?

Step 1: log₁₀(10¹³) = 13.

Step 2: Double precision gives ≈ 16 digits. Lose 13 → only 3 digits of accuracy remain.

Answer: **You lose 13 decimal digits. The answer may only have 3 correct digits**.

### Breadcrumb 3: Ill-Conditioned vs Well-Conditioned

**Builds on:** Breadcrumb 2

A problem is **ill-conditioned** if small changes in the input cause large changes in the output. This is a property of the problem, not the algorithm.

```
Ill-conditioned:    small Δb → large Δx
Well-conditioned:   small Δb → small Δx
```

Geometrically: when A has a small singular value, there is a direction where A almost collapses space. Solving Ax = b in that direction requires huge amplification, making the solution sensitive to any error in b.

#### Chunked Example

Question: A = [[1, 2], [2, 4.0001]]. Is this system well-conditioned?

Step 1: Singular values: σ_max ≈ 5, σ_min ≈ 0.00002. κ ≈ 250,000.

Step 2: Changing b by 0.1% could change x by ≈ 250,000 × 0.1% = 250×.

Answer: **No. κ ≈ 250,000 — extremely ill-conditioned. The two rows are nearly linearly dependent**.

### Breadcrumb 4: Numerical Stability of Algorithms

**Builds on:** [[7.11 Matrix Decompositions LU QR SVD]], Breadcrumbs 1-3

An algorithm is **numerically stable** if it produces the exact answer for a problem that is close to the original input. Different algorithms for the same mathematical problem can have very different stability:

| Algorithm | Stability | Why |
|-----------|-----------|-----|
| Gaussian elimination (no pivoting) | Unstable | Small pivots amplify errors |
| Gaussian elimination (partial pivoting) | Stable | Pivoting avoids small divisors |
| Normal equation (AᵀAx = Aᵀb) | Can be unstable | Squares the condition number |
| QR for least squares | Stable | Avoids squaring the condition number |
| SVD for least squares | Most stable | Handles rank-deficient cases directly |

#### Chunked Example

Question: Why is the normal equation (AᵀA)x = Aᵀb less stable than QR for least squares?

Step 1: The condition number of AᵀA is κ(AᵀA) = κ(A)².

Step 2: If κ(A) = 10⁶, then κ(AᵀA) = 10¹² — losing 12 digits instead of 6.

Step 3: QR solves the problem without forming AᵀA, so κ(A) stays as κ(A).

Answer: **The normal equation squares the condition number. QR is preferred for ill-conditioned least squares**.

### Breadcrumb 5: Practical Guidelines

**Builds on:** All previous breadcrumbs

#### When to Use Each Algorithm

1. **Ax = b, well-conditioned**: Gaussian elimination with partial pivoting (or LU).
2. **Ax = b, ill-conditioned**: Use SVD — set very small singular values to zero.
3. **Least squares, well-conditioned**: QR decomposition.
4. **Least squares, ill-conditioned**: SVD — it handles rank-deficient problems naturally.
5. **Any problem with κ(A) > 10¹⁰**: Switch to higher precision (if available) or reconsider the problem.

#### Warning Signs of Numerical Trouble

- The determinant is very small (but not zero).
- The matrix has entries with very different magnitudes.
- The inverse has entries much larger than the original matrix.
- Computing A⁻¹b gives very different answers for slightly different b.

#### Chunked Example

Question: You solve Ax = b and get x. Then you compute r = b - Ax. The residual r is tiny, but x seems wrong. What is happening?

Step 1: If κ(A) is large, even a tiny residual does not guarantee an accurate solution.

Step 2: This is called the "small residual, large error" phenomenon — characteristic of ill-conditioned problems.

Answer: **The problem is ill-conditioned. The small residual only means Ax ≈ b, but x may be far from the true solution**.

## Worked Examples

### Example 1 — Catastrophic Cancellation

Question: In double precision (ε ≈ 2.2×10⁻¹⁶), compute (1 + 10⁻¹⁶) - 1.

Step 1: 10⁻¹⁶ is less than ε × |1| ≈ 2.2×10⁻¹⁶. When added to 1, the result rounds to exactly 1 because the small number is below machine precision relative to 1.

Step 2: 1 - 1 = 0. The expected answer is 10⁻¹⁶, but the computed answer is 0.

Answer: **The result is 0, not 10⁻¹⁶. The small number is lost to rounding — an example of catastrophic cancellation**.

### Example 2 — Estimating Accuracy Loss from Condition Number

Question: A matrix has σ_max = 500 and σ_min = 0.05. What is κ(A)? How many decimal digits of accuracy are lost?

Step 1: κ(A) = σ_max / σ_min = 500 / 0.05 = 10,000.

Step 2: Digits lost ≈ log₁₀(κ) = log₁₀(10,000) = 4.

Step 3: Double precision has about 16 decimal digits. After solving Ax = b with this matrix, only about 16 - 4 = 12 digits of accuracy remain.

Answer: **κ = 10,000. About 4 decimal digits are lost. Expect ≈ 12 correct digits**.

### Example 3 — Detecting an Ill-Conditioned Matrix

Question: A = [[1, 1], [1, 1.00001]]. Classify this problem as well-conditioned or ill-conditioned.

Step 1: Compute det = 1×1.00001 - 1×1 = 0.00001. The matrix is nearly singular.

Step 2: The two rows are almost identical — small changes in b will cause large changes in x.

Step 3: σ_max ≈ 2, σ_min ≈ 0.000005. κ ≈ 400,000. log₁₀(κ) ≈ 5.6, so about 5-6 digits are lost.

Answer: **Extremely ill-conditioned (κ ≈ 400,000). The rows are nearly linearly dependent. Only about 10 of 16 digits will be accurate**.

### Example 4 — Normal Equation vs QR for Least Squares

Question: For a least squares problem with κ(A) = 10⁸, compare the expected accuracy of the normal equation versus QR decomposition.

Step 1: Normal equation (AᵀA)x = Aᵀb squares the condition number: κ(AᵀA) = κ(A)² = 10¹⁶.

Step 2: log₁₀(10¹⁶) = 16. All 16 decimal digits of double precision are lost — the result would be meaningless.

Step 3: QR decomposition does not square κ(A). κ(A) stays at 10⁸, losing about 8 digits. About 8 correct digits remain.

Answer: **Normal equation loses all 16 digits (useless). QR loses 8 digits, giving about 8 correct digits. QR is strongly preferred**.

## Why This Works

Numerical analysis is the study of how to compute reliably with floating-point numbers. The condition number separates the unavoidable (problem sensitivity) from the preventable (algorithm stability).

A good rule: always check the condition number before trusting a computed solution. If κ(A) is large, the problem itself is the issue, not the algorithm.

## Common Mistakes

> [!failure] Mistake pattern: Blaming the algorithm for an ill-conditioned problem
> If κ(A) = 10¹², no algorithm can give an accurate answer in double precision. The problem itself is the issue.

> [!failure] Mistake pattern: Trusting a tiny residual as proof of accuracy
> A tiny residual ||Ax - b|| does not guarantee a tiny error ||x - x_true|| when the problem is ill-conditioned.

> [!failure] Mistake pattern: Using the normal equation for ill-conditioned problems
> The normal equation squares the condition number. Use QR or SVD instead.

> [!failure] Mistake pattern: Forgetting to scale variables
> Mixing variables with very different scales (meters and nanometers) produces ill-conditioned matrices. Normalise first.
