## Introduction

**Bayesian inference** is the application of Bayes Theorem to parameter estimation. Instead of giving a single "best guess" (like frequentist statistics), Bayesian methods produce a **posterior distribution** — a full probability distribution over possible parameter values.

From [[8.3 Bayes Theorem]], you know P(A|B) = P(B|A)P(A)/P(B). In Bayesian inference:
- P(A) becomes the **prior** P(θ) — belief about parameter θ before seeing data
- P(B|A) becomes the **likelihood** P(data|θ) — how probable the data is given θ
- P(A|B) becomes the **posterior** P(θ|data) — updated belief after seeing data

Why is Bayesian inference so important in CS? It provides a principled framework for learning from data that naturally handles uncertainty, incorporates prior knowledge, and supports sequential learning. It is the foundation of:
- **Regularisation** in machine learning (L2 regularisation = Gaussian prior)
- **Thompson sampling** for exploration-exploitation in reinforcement learning
- **Bayesian A/B testing** which gives direct probabilities like "P(B is better than A) = 0.95"
- **Gaussian processes** for regression with uncertainty estimates
- **Probabilistic programming** (PyMC, Stan, TensorFlow Probability)

The Bayesian approach contrasts with frequentist statistics: instead of asking "what is the best estimate?", it asks "what is the full distribution of plausible values?"

## New Words

- **[[prior distribution]]** — P(θ), initial belief about parameter θ before data.
- **[[likelihood]]** — P(data|θ), the probability of the data given the parameter.
- **[[posterior distribution]]** — P(θ|data), updated belief after seeing data.
- **[[conjugate prior]]** — a prior that produces a posterior in the same distribution family (e.g., Beta prior + Binomial likelihood = Beta posterior).
- **[[credible interval]]** — Bayesian analogue of confidence interval: P(a ≤ θ ≤ b | data) = 0.95.
- **[[maximum a posteriori (MAP)]]** — the parameter value that maximises the posterior distribution.
- **[[Bayesian updating]]** — sequential process: posterior becomes prior for the next observation.

## Breadcrumbs

### Breadcrumb 1: From Bayes Theorem to Bayesian Inference

**Builds on:** [[8.3 Bayes Theorem]] (formula), [[8.4 Random Variables and Expected Value]] (θ as a random variable)

Bayesian inference treats the unknown parameter θ as a random variable with a distribution. The key equation:

```
P(θ | data) ∝ P(data | θ) × P(θ)
                 ↑            ↑
              likelihood    prior
```

The denominator P(data) is a normalising constant that ensures the posterior integrates to 1. For many problems, we only need the proportional relationship: P(θ|data) ∝ P(data|θ) × P(θ).

#### Chunked Example — Coin Bias Estimation

Question: You want to estimate the probability θ that a coin lands heads. Before flipping, you believe all values of θ are equally likely (uniform prior: P(θ) = 1 for 0 ≤ θ ≤ 1). You flip heads 3 times out of 5. What is the posterior?

Step 1: Likelihood: P(3 heads in 5 | θ) ∝ θ³(1-θ)² (Binomial, ignoring constant).

Step 2: Posterior ∝ prior × likelihood = 1 × θ³(1-θ)² = θ³(1-θ)².

This is a Beta(4, 3) distribution. The Beta distribution is the natural conjugate prior for the Binomial likelihood.

Answer: **Posterior is Beta(4, 3). The mode is at θ = (4-1)/(4+3-2) = 3/5 = 0.6**.

### Breadcrumb 2: Conjugate Priors

**Builds on:** Breadcrumb 1

A conjugate prior makes Bayesian updating algebraically simple: the posterior is in the same distribution family as the prior.

| Likelihood | Conjugate Prior | Posterior |
|---|---|---|
| Binomial(n, θ) | Beta(α, β) | Beta(α + successes, β + failures) |
| Poisson(θ) | Gamma(α, β) | Gamma(α + sum, β + n) |
| Normal(θ, σ²) | Normal(μ₀, σ₀²) | Normal(μ_post, σ_post²) |

The conjugate prior acts like "pseudo-data": α and β in the Beta prior can be interpreted as having seen α-1 successes and β-1 failures before the actual data.

#### Chunked Example — Beta-Binomial

Question: Coin flips. Prior: Beta(2, 2) (a weak prior centred at 0.5). You flip 10 heads and 5 tails. What is the posterior?

Step 1: Prior parameters: α=2, β=2. Data: successes=10, failures=5.

Step 2: Posterior: Beta(2+10, 2+5) = Beta(12, 7).

Step 3: Mode of posterior = (12-1)/(12+7-2) = 11/17 ≈ 0.647.

Answer: **Posterior is Beta(12, 7). Mode ≈ 0.647. The prior pull (= 0.5) and data (= 10/15 ≈ 0.667) are combined**.

Notice how the posterior mode (0.647) is between the prior mode (0.5) and the data proportion (0.667). This "shrinkage" effect is natural Bayesian regularisation.

### Breadcrumb 3: Bayesian Updating — Sequential Learning

**Builds on:** Breadcrumb 1, [[8.3 Bayes Theorem]] (sequential updating)

Bayesian inference is naturally sequential: the posterior from today's data becomes the prior for tomorrow's data.

```
P(θ | data₁, data₂) ∝ P(data₂ | θ) × P(θ | data₁)
                         ↑                 ↑
                    today's data       yesterday's posterior
```

This means the order of updating does not matter — you get the same final posterior whether you process data all at once or one observation at a time.

#### Chunked Example — Sequential Coin Flips

Question: Coin with Beta(2, 2) prior. Day 1: 3 heads, 2 tails → Beta(5, 4). Day 2: 7 heads, 3 tails. What is the final posterior?

Step 1: Using sequential updating: Day 1 posterior = Beta(5, 4). This becomes Day 2 prior.

Step 2: Day 2: successes=7, failures=3. Posterior = Beta(5+7, 4+3) = Beta(12, 7).

Step 3: Using all-at-once: Prior Beta(2, 2), total data = 10 heads, 5 tails. Posterior Beta(2+10, 2+5) = Beta(12, 7).

Answer: **Both methods give Beta(12, 7). Sequential = all-at-once**.

### Breadcrumb 4: MAP Estimation

**Builds on:** Breadcrumb 1

The **Maximum A Posteriori (MAP)** estimate is the θ that maximises the posterior distribution. For a uniform prior, this equals the Maximum Likelihood Estimate (MLE).

```
θ_MAP = argmax P(θ | data) = argmax P(data | θ) × P(θ)
```

For Beta-Binomial: θ_MAP = (α + successes - 1) / (α + β + n - 2).

#### Chunked Example

Question: Beta(2, 2) prior, 10 heads, 5 tails. Find θ_MAP.

Step 1: α_post = 12, β_post = 7.

Step 2: θ_MAP = (12 - 1) / (12 + 7 - 2) = 11 / 17 ≈ 0.647.

Answer: **θ_MAP ≈ 0.647**.

Compare to MLE (no prior): θ_MLE = 10/15 = 0.667. The MAP is slightly pulled toward the prior (0.5).

### Breadcrumb 5: Credible Intervals

**Builds on:** [[8.6 Continuous Distributions]] (z-scores, area under curve), Breadcrumb 1

A **95% credible interval** [a, b] satisfies P(a ≤ θ ≤ b | data) = 0.95. Unlike a frequentist confidence interval, this IS a probability statement about θ.

For the Beta(12, 7) posterior, the 95% credible interval is approximately [0.44, 0.83] (computed from Beta quantiles — can be looked up in a Beta table or approximated using the normal distribution for large α, β).

The interpretation is intuitive: "There is a 95% probability that the true bias θ lies between 0.44 and 0.83." This is exactly what most people (incorrectly) think a confidence interval means — the credible interval actually delivers that interpretation.

## Worked Examples

### Example 1 — Bayesian A/B Testing

Question: Variant A: 120 conversions out of 1000 visitors. Variant B: 150 conversions out of 1000 visitors. Using Beta(1, 1) prior for both, what is P(B > A)?

Step 1: Posterior for A: Beta(1+120, 1+880) = Beta(121, 881).
Posterior for B: Beta(1+150, 1+850) = Beta(151, 851).

Step 2: The mean of Beta(α, β) is α/(α+β). Meanₐ = 121/1002 ≈ 0.1208. Meanᵦ = 151/1002 ≈ 0.1507.

Step 3: P(B > A) can be computed via numerical integration or simulation. Draw 10,000 samples from each posterior, count how often B > A. Approximately 0.975.

Answer: **P(B > A | data) ≈ 0.975**. This is more interpretable than a frequentist p-value.

### Example 2 — Prior Strength

Question: Two analysts study the same coin. Analyst A uses a strong prior Beta(100, 100) (believes coin is fair). Analyst B uses a weak prior Beta(1, 1) (uniform). After 20 heads and 10 tails, what are their posteriors? What are their MAP estimates?

Step 1 (A): Posterior = Beta(100+20, 100+10) = Beta(120, 110). MAP = (120-1)/(120+110-2) = 119/228 ≈ 0.522.

Step 2 (B): Posterior = Beta(1+20, 1+10) = Beta(21, 11). MAP = (21-1)/(21+11-2) = 20/30 ≈ 0.667.

Answer: **Analyst A: MAP ≈ 0.522 (strong prior dominates). Analyst B: MAP ≈ 0.667 (data dominates)**. Both are valid — the choice depends on how confident you are in your prior.

### Example 3 — Bayesian Updating for Click-through Rate

Question: An ad campaign starts with no prior information (Beta(1, 1)). After day 1: 50 clicks, 950 no-clicks. After day 2: 30 clicks, 970 no-clicks. What is the posterior after each day? After both days?

Step 1: After day 1: Beta(1+50, 1+950) = Beta(51, 951). MAP = 50/1000 = 0.05.

Step 2: After day 2 (sequential): Beta(51+30, 951+970) = Beta(81, 1921). MAP = 80/2000 = 0.04.

Step 3 (all at once): Beta(1+80, 1+1920) = Beta(81, 1921). Same result.

Answer: **After day 1: Beta(51, 951), MAP = 5%. After both days: Beta(81, 1921), MAP = 4%**. The estimate converges as more data arrives.

## Why This Works

Bayesian inference is philosophically straightforward: uncertain quantities get probability distributions. The prior encodes what you know before seeing data, and Bayes Theorem provides a principled way to update that knowledge.

This is especially powerful when:
- Data is limited (the prior provides regularisation)
- You want sequential learning (online algorithms)
- You need full uncertainty quantification (not just point estimates)

The conjugate prior framework makes Bayesian updating tractable: instead of complex numerical integration, you simply update the parameters of a known distribution.

## Common Mistakes

> [!failure] Mistake pattern: Using a flat (uniform) prior and thinking it means "no prior"
> A flat prior is still a prior — it represents the belief that all values are equally likely. For some parameters (like variance), a flat prior can be improper (does not integrate to 1).

> [!failure] Mistake pattern: Interpreting credible intervals like confidence intervals
> A 95% credible interval means P(θ in [a,b] | data) = 0.95. A 95% confidence interval means 95% of intervals from repeated sampling contain the true θ — not the same thing.

> [!failure] Mistake pattern: Forgetting to update the evidence term P(data)
> When computing posterior ∝ likelihood × prior, the constant P(data) must be computed for exact inference. For MAP estimation, you can ignore it.

> [!failure] Mistake pattern: Choosing a prior that is too strong
> A very strong prior (e.g., Beta(1000, 1000)) can overwhelm the data. It takes a lot of evidence to move such a prior, which can be inappropriate for exploratory analysis.
