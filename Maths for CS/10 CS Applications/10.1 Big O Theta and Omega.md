## Introduction

**Big O notation** classifies how fast a function grows as n→∞. It ignores constants and lower-order terms to focus on the dominant behaviour. This is the language used to compare algorithm efficiency.

The central question: how does the runtime (or memory) of an algorithm scale as the input size grows?

From [[6.1 Combinatorics Basics]], you know about counting and combinatorial growth. From [[2.1 Variables and Expressions]], you understand how to work with algebraic expressions. Big O formalises the idea that some functions grow much faster than others — and when n is large, only the fastest-growing term matters.

There are three main symbols:
- **O (Big O)**: upper bound (≤). f(n) = O(g(n)) means f grows no faster than g.
- **Ω (Big Omega)**: lower bound (≥). f grows at least as fast as g.
- **Θ (Big Theta)**: tight bound (=). f grows exactly as fast as g.

Why does this matter? An O(n²) algorithm on n=10⁶ inputs takes ≈10¹² operations — hours of compute. An O(n log n) algorithm on the same input takes ≈20×10⁶ operations — milliseconds. Big O lets you predict this before writing a single line of code.

## New Words

- **[[Big O]]** — f(n) = O(g(n)) if ∃c,n₀: 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀ (upper bound).
- **[[Big Theta]]** — f(n) = Θ(g(n)) if f = O(g) and f = Ω(g) (tight bound).
- **[[Big Omega]]** — f(n) = Ω(g(n)) if ∃c,n₀: 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀ (lower bound).
- **[[asymptotic growth]]** — behaviour of a function as the input approaches infinity.
- **[[dominant term]]** — the term that grows fastest as n→∞ (e.g., n² in 3n²+5n+2).

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: Common Growth Rates — Ranked from Best to Worst

**Builds on:** [[6.1 Combinatorics Basics]] (factorials, combinations, permutations), [[2.1 Variables and Expressions]] (polynomial expressions)

Here are the growth rates you will encounter most often:

```
O(1)       constant     array access arr[i], hash table lookup
O(log n)   logarithmic  binary search, balanced BST operations
O(n)       linear       scanning a list once
O(n log n) linearithmic merge sort, heapsort
O(n²)      quadratic    bubble sort worst case, nested loops
O(n³)      cubic        matrix multiplication (naive)
O(2ⁿ)      exponential  subset generation, naive Fibonacci
O(n!)      factorial    permutation generation, travelling salesman (naive)
```

#### Chunked Example — Ranking Growth Rates

Question: Rank these from slowest to fastest growth: n, n², n log n, 2ⁿ, log n, n!.

Step 1: Start with the slowest: constant is not listed, so log n is slowest.

Step 2: Next is n (linear), then n log n, then n².

Step 3: Exponential 2ⁿ grows faster than n². Factorial n! grows faster than 2ⁿ.

Answer: **log n ≪ n ≪ n log n ≪ n² ≪ 2ⁿ ≪ n!**

### Breadcrumb 2: Formal Definition of Big O

**Builds on:** Breadcrumb 1

f(n) = O(g(n)) means: ∃ positive constants c, n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀.

In plain English: beyond some threshold n₀, f(n) is bounded above by a constant multiple of g(n).

The **n₀** says: we only care about large inputs (small inputs are trivial). The **c** says: constant factors are irrelevant — x² and 1000x² are both O(x²).

#### Chunked Example — Proving 3n+7 is O(n)

Question: Show f(n) = 3n+7 = O(n) using the formal definition.

Step 1: Find c and n₀. For n ≥ 7: 3n+7 ≤ 3n+n = 4n.

Step 2: Choose c = 4, n₀ = 7. Then 3n+7 ≤ 4n for all n ≥ 7.

Step 3: This satisfies the definition: f(n) ≤ c·n for all n ≥ n₀.

Answer: **3n+7 = O(n) with c=4, n₀=7**.

#### Chunked Example — Proving 100n²+50n+10 is O(n²)

Question: Show f(n) = 100n²+50n+10 = O(n²).

Step 1: For n ≥ 1: 50n ≤ 50n², 10 ≤ 10n².

Step 2: So 100n²+50n+10 ≤ 100n²+50n²+10n² = 160n².

Step 3: Choose c = 160, n₀ = 1. Then f(n) ≤ 160n² for all n ≥ 1.

Answer: **100n²+50n+10 = O(n²) with c=160, n₀=1**. (A tighter bound exists — the point is one exists.)

### Breadcrumb 3: Big Omega — The Lower Bound

**Builds on:** Breadcrumb 1

Ω gives a lower bound: f grows at least as fast as g.
f(n) = Ω(g(n)) means: ∃c,n₀ > 0 such that f(n) ≥ c·g(n) for all n ≥ n₀.

#### Chunked Example — Proving n²-100n is Ω(n²)

Question: Show f(n) = n²-100n = Ω(n²).

Step 1: For n ≥ 200: n²-100n ≥ n² - ½·n² = ½·n².

Step 2: Choose c = ½, n₀ = 200.

Step 3: Then f(n) ≥ ½·n² for all n ≥ 200. ✓

Answer: **f(n) = Ω(n²) with c=½, n₀=200**.

### Breadcrumb 4: Big Theta — The Tight Bound

**Builds on:** Breadcrumbs 2 and 3

Θ means f is bounded both above and below by g: f grows at exactly the same rate as g.

f(n) = Θ(g(n)) iff f(n) = O(g(n)) AND f(n) = Ω(g(n)).

#### Chunked Example — Proving n²+1000n is Θ(n²)

Question: Show f(n) = n²+1000n = Θ(n²).

Step 1: Upper bound (Big O): For n ≥ 1000: n²+1000n ≤ n²+n² = 2n² → O(n²) with c=2, n₀=1000.

Step 2: Lower bound (Big Omega): For n ≥ 1: n²+1000n ≥ n² → Ω(n²) with c=1, n₀=1.

Step 3: Since f = O(n²) and f = Ω(n²), we have f = Θ(n²).

Answer: **f(n) = Θ(n²)**.

## Worked Examples

### Example 1 — Verifying Big O for a Quadratic

Question: Is f(n) = n²+1000n O(n³)?

Step 1: For n ≥ 1000: n²+1000n ≤ n²+n² = 2n² ≤ 2n³.

Step 2: Choose c=2, n₀=1000. f(n) ≤ 2n³ for all n ≥ 1000.

Step 3: Yes, f = O(n³). But note: Θ(n²) is the tight bound — O(n³) is a loose upper bound.

Answer: **Yes, but Θ(n²) is the tight bound**.

### Example 2 — Loop Analysis

Question: What is the runtime of this nested loop?

```python
for i in range(n):
    for j in range(i):
        print(i, j)
```

Step 1: Outer loop runs n times. Inner loop runs i times for each i.

Step 2: Total iterations = 0+1+2+...+(n-1) = n(n-1)/2.

Step 3: n(n-1)/2 = (n²-n)/2. Dominant term: n²/2. Drop constant: O(n²).

Answer: **O(n²)**.

### Example 3 — Binary Search Analysis

Question: Prove binary search is O(log n).

Step 1: Each iteration halves the search space. After k iterations: n → n/2 → n/4 → ... → n/2^k.

Step 2: Algorithm stops when n/2^k ≤ 1 → 2^k ≥ n → k ≥ log₂ n.

Step 3: Number of iterations ≤ log₂ n + 1 = O(log n).

Step 4: Lower bound is also Ω(log n) (you must halve at least log₂ n times). So it is Θ(log n).

Answer: **Binary search is Θ(log n)**.

### Example 4 — CS Application: Real-World Impact

Question: n = 10⁶. Compare O(n²) vs O(n log n).

Step 1: O(n²) ≈ 10¹² operations. At 10⁹ ops/sec (1 GHz CPU, one op per cycle): 10¹²/10⁹ = 1000 seconds ≈ 17 minutes.

Step 2: O(n log n) ≈ 10⁶ × 20 ≈ 20×10⁶ operations. At 10⁹ ops/sec: 20×10⁶/10⁹ = 0.02 seconds.

Step 3: Difference: 0.02 seconds vs 17 minutes. This is why algorithm choice matters.

Answer: **O(n²): 17 minutes. O(n log n): 0.02 seconds**.

## Why This Works

Constants and lower-order terms become irrelevant as n→∞. 1000n²+5000n+9000 is still O(n²) because for large n, n² dwarfs n and the constants. This lets us compare algorithms without worrying about hardware differences.

Big O is a **set** of functions, not a single value. Saying "f = O(g)" means "f belongs to the set of functions bounded above by g." This is why we can write 3n+7 = O(n) and 100n² = O(n²) — both functions belong to their respective sets.

The three symbols (O, Ω, Θ) give a complete picture: O says "no worse than," Ω says "no better than," and Θ says "exactly as." For a complete analysis, we want Θ (when achievable).

## Common Mistakes

> [!failure] Mistake pattern: Dropping constants incorrectly
> O(3n²+5n) = O(n²). O(3) = O(1). Constants are dropped in Big O.

> [!failure] Mistake pattern: Confusing Big O with worst case
> Big O is an UPPER BOUND on growth rate, not a synonym for "worst case." You can have O(n²) worst case, O(n) best case, and O(1) average case. They are orthogonal concepts.

> [!failure] Mistake pattern: Writing f(n)=O(g(n)) as an equation
> O(g(n)) is a SET. The correct reading: "f is in O(g(n))." But writing f=O(g) is conventional.

> [!failure] Mistake pattern: Forgetting the "for all n ≥ n₀" condition
> The inequality only needs to hold beyond some threshold. Small n does not matter — we care about scalability.

## Where This Shows Up in CS

### Algorithm Design
```text
- Sorting: O(n log n) for merge/quick/heap, O(n²) for bubble/selection
- Search: O(log n) binary, O(n) linear
- Graph: O(V+E) DFS/BFS, O(E log V) Dijkstra
- Data structures: O(1) hash table, O(log n) BST
```

### System Design — Scalability Analysis
```python
# Database indexing:
# Sequential scan: O(n) — full table scan
# B-tree index: O(log n) — fast lookup
# Hash index: O(1) — fastest but no range queries
```

### Real-World Impact
```text
- n=10⁶: O(n²) ≈ 10¹² ops (hours). O(n log n) ≈ 20×10⁶ ops (milliseconds)
- This is WHY algorithm choice matters at scale
- Big O guides framework and database selection
```

### Compiler Optimisation
```text
- Loop analysis: detects O(n²) patterns and suggests optimisations
- Vectorisation: transforms scalar loops to SIMD (O(n) with better constant)
```
