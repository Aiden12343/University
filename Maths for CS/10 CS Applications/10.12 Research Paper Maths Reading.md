## Introduction

A research paper is not a textbook. It assumes background, skips steps, and combines notation freely. Your job is to extract the key idea: what problem does it solve, what technique does it use, and how is it evaluated?

From modules [[10.1 Big O Theta and Omega]] through [[10.11 Type Theory and Program Logic Intro]], you have learned the mathematical foundations that appear in CS research papers. From [[5.10 Proof Techniques]], you know how to construct and follow proofs. Now we apply these skills to reading research.

The **three-pass strategy** is the standard approach:
1. **First pass** (5 minutes): title, abstract, intro, conclusions, figures. Decide if relevant.
2. **Second pass** (1 hour): read carefully but skip proofs. Understand definitions, theorems, experimental setup.
3. **Third pass** (3-5 hours): read proofs in detail, implement key algorithms, reconstruct derivations.

Most papers only deserve a first or second pass. Only the papers you build on need a third pass.

## New Words

- **[[abstract]]** — one-paragraph summary of the paper (problem, method, result, contribution).
- **[[theorem statement]]** — the main mathematical result, usually in a box or bold text.
- **[[proof sketch]]** — high-level overview of a proof, omitting tedious details.
- **[[notation dictionary]]** — the set of symbols defined in Section 2 or "Preliminaries."
- **[[contribution]]** — what new knowledge the paper adds to the field.

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: The Three-Pass Reading Strategy

**Builds on:** [[5.10 Proof Techniques]] (understanding proof structure)

**First pass (5 minutes)**: read title, abstract, introduction, conclusions, and scan figures. Answer: Is this relevant to my work? What problem does it solve? What is the main result?

**Second pass (1 hour)**: read carefully but skip proofs. Understand all definitions, theorem statements, and the experimental setup. Mark sections to revisit.

**Third pass (3-5 hours)**: reconstruct proofs, implement key algorithms, fill in skipped steps. Only for papers you need to build on.

#### Chunked Example

Question: You have 20 papers to read for a literature review. Strategy?

Step 1: First pass all 20 (≈2 hours total). Reject 12 as irrelevant.

Step 2: Second pass on the 8 relevant papers (≈8 hours total).

Step 3: Third pass on the 2-3 most important papers (≈10 hours total).

Answer: **3-pass: screen (20→8) → understand (8→3) → deep dive (3)**.

### Breadcrumb 2: Reading a Theorem Statement

**Builds on:** [[5.10 Proof Techniques]] (theorem structure: assumptions → conclusion)

A theorem has: assumptions, conclusion, quantifiers. Identify each part. Ask: what does this mean intuitively?

#### Chunked Example

Question: "Theorem 1. For any ε > 0, algorithm A achieves regret R_T ≤ O(√T log(1/ε)) with probability ≥ 1-ε." Interpret.

Step 1: Assumptions: ε > 0 (confidence parameter, small = high confidence).

Step 2: Conclusion: regret R_T grows as √T (sublinear in T).

Step 3: Probability statement: the bound holds with high probability (1-ε).

Step 4: Meaning: as T grows, average regret per step → 0. The algorithm learns over time.

Answer: **Sublinear regret with high probability → the algorithm converges to optimal**.

### Breadcrumb 3: Building a Notation Dictionary

**Builds on:** [[10.1 Big O Theta and Omega]] through [[10.11 Type Theory]] (various notations)

Every paper has its own notation. Create a **notation dictionary** as you read — a table mapping symbols to meanings. Most papers define symbols in Section 2 ("Preliminaries" or "Background").

#### Chunked Example

Question: Paper defines: x_i ∈ ℝ^d (input), y_i ∈ {±1} (label), w ∈ ℝ^d (weights). In "margin = y_i(w·x_i+b)." What does margin measure?

Step 1: w·x_i+b is the signed distance from the decision boundary (from SVM theory).

Step 2: Multiply by y_i: positive if classification is correct, negative if wrong.

Step 3: Larger absolute value = more confident prediction.

```text
Notation Dictionary:
  x_i ∈ ℝ^d      = input feature vector
  y_i ∈ {±1}     = true label (+1 or -1)
  w ∈ ℝ^d        = weight vector (learned)
  b ∈ ℝ           = bias term
  margin = y_i(w·x_i+b) = signed confidence
```

Answer: **Margin = signed confidence: >0 = correct, higher = more confident**.

### Breadcrumb 4: Reconstructing a Skipped Derivation

**Builds on:** [[9.9 Gradient Descent and Optimisation]], [[9.8 Multivariable Functions]]

Papers often say "by standard analysis" and skip steps. Reconstructing these steps builds understanding and verifies the claim.

#### Chunked Example

Question: Paper says "By standard gradient descent analysis, we have f(w_t) - f(w*) ≤ L||w₀-w*||²/(2ηt)." Reconstruct.

Step 1: For convex f with L-Lipschitz gradient: f(y) ≤ f(x) + ∇f(x)ᵀ(y-x) + (L/2)||y-x||².

Step 2: With update w_{t+1} = w_t - η∇f(w_t), substitute into inequality.

Step 3: f(w_{t+1}) ≤ f(w_t) - η||∇f(w_t)||² + (Lη²/2)||∇f(w_t)||².

Step 4: For η ≤ 1/L: f(w_{t+1}) ≤ f(w_t) - (η/2)||∇f(w_t)||².

Step 5: After telescoping: f(w_t) - f(w*) ≤ ||w₀-w*||²/(2ηt).

Answer: **Standard GD convergence: O(1/t) for smooth convex functions**.

## Worked Examples

### Example 1 — Analysing a Theorem Statement

Question: Consider the following theorem: "Theorem 3.1. Let f : ℝᵈ → ℝ be a convex function with L-Lipschitz gradient. For any starting point w₀ ∈ ℝᵈ, gradient descent with step size η = 1/L satisfies f(w_T) - f(w*) ≤ L||w₀ - w*||² / (2T)." Identify the assumptions, the conclusion, and explain the intuitive meaning.

Step 1: Assumptions: (1) f is convex, (2) f has an L-Lipschitz gradient (gradient changes at rate at most L), (3) step size is η = 1/L, (4) any starting point w₀ is allowed.

Step 2: Conclusion: after T iterations, the gap f(w_T) - f(w*) between the current value and the optimal value is at most L||w₀ - w*||² / (2T).

Step 3: Intuitive meaning: the error decreases as O(1/T). Doubling the number of iterations halves the upper bound on the error.

Step 4: The constants depend on the smoothness L and the squared distance from the start to the optimum.

Answer: **Assumptions: convexity, L-smoothness, η = 1/L. Conclusion: O(1/T) convergence. Intuition: error halves when iterations double**.

### Example 2 — Building a Notation Dictionary

Question: A paper defines: "Let G = (V, E) be a graph with adjacency matrix A ∈ ℝⁿˣⁿ and diagonal degree matrix D = diag(d₁, ..., dₙ). Node features X ∈ ℝⁿˣᵈ. The graph convolution layer computes Z = D^{-1/2} A D^{-1/2} X Θ, where Θ ∈ ℝᵈˣᵏ are learnable weights." Build a notation dictionary and explain what one layer computes.

Step 1: Notation dictionary: n = |V| = number of nodes. Aᵢⱼ = 1 if edge (i,j) exists, 0 otherwise. dᵢ = Σⱼ Aᵢⱼ (degree of node i). D^{-1/2} scales by 1/√dᵢ. X stacks d-dimensional feature vectors row-wise. Θ transforms features from d to k dimensions.

Step 2: The normalised adjacency D^{-1/2} A D^{-1/2} has entries Aᵢⱼ / √(dᵢ dⱼ) — symmetric normalisation preventing degree bias.

Step 3: Multiplying X by this matrix aggregates neighbour features: each node's new representation is a weighted average of its neighbours' features.

Step 4: Multiplying by Θ applies a linear transformation, projecting from d-dimensional to k-dimensional feature space.

Answer: **Notation: A (adjacency), D (degree matrix), X (node features), Θ (weights). One layer = normalised neighbour feature aggregation + linear projection**.

### Example 3 — Reconstructing a Skipped Derivation

Question: A paper claims: "From the L-smoothness inequality f(y) ≤ f(x) + ∇f(x)ᵀ(y - x) + (L/2)||y - x||² and the gradient descent update w_{t+1} = w_t - η∇f(w_t), one obtains f(w_{t+1}) ≤ f(w_t) - (η/2)||∇f(w_t)||² when η ≤ 1/L." Reconstruct the missing steps.

Step 1: Substitute y = w_{t+1} = w_t - η∇f(w_t) and x = w_t into the smoothness inequality: f(w_{t+1}) ≤ f(w_t) + ∇f(w_t)ᵀ(-η∇f(w_t)) + (L/2)||-η∇f(w_t)||².

Step 2: Simplify: ∇f(w_t)ᵀ(-η∇f(w_t)) = -η||∇f(w_t)||². The norm term: ||-η∇f(w_t)||² = η²||∇f(w_t)||².

Step 3: Combine: f(w_{t+1}) ≤ f(w_t) - η||∇f(w_t)||² + (Lη²/2)||∇f(w_t)||² = f(w_t) - η(1 - Lη/2)||∇f(w_t)||².

Step 4: When η ≤ 1/L, we have 1 - Lη/2 ≥ 1/2. Therefore f(w_{t+1}) ≤ f(w_t) - (η/2)||∇f(w_t)||².

Answer: **Substitute the GD update into the smoothness inequality, collect ||∇f(w_t)||² terms, and use η ≤ 1/L to obtain the coefficient -(η/2)**.

## Why This Works

Research papers are written for experts who already understand the context. The three-pass strategy matches this reality: first pass filters, second pass extracts the key ideas without getting lost in technicalities, third pass fills gaps for papers you build on.

Building a notation dictionary is essential because every paper has its own conventions. The same symbol can mean different things in different papers (e.g., ||x|| can be L2 norm, L1 norm, or matrix norm depending on context).

Reconstructing derivations is how you truly understand a paper. Reading the paper's derivation gives you the claim; reconstructing it yourself verifies the claim and builds deeper understanding.

## Common Mistakes

> [!failure] Mistake pattern: Reading papers linearly like textbooks
> Do not start at the beginning and read through. Use the three-pass strategy. You will waste hours on irrelevant details otherwise.

> [!failure] Mistake pattern: Skipping the abstract
> The abstract is the most important paragraph. If it does not interest you, the paper is probably not relevant.

> [!failure] Mistake pattern: Getting stuck on notation
> Every paper has its own notation. Build a notation dictionary as you read. Refer back to it. Most papers have a "Preliminaries" section.

> [!failure] Mistake pattern: Not checking related work
> If a paper is confusing, find a survey paper on the same topic. Surveys explain the context and compare approaches.

## Where This Shows Up in CS

### Literature Review
```text
1. Search: Google Scholar, arXiv, DBLP, Semantic Scholar
2. Filter: read title + abstract → decide relevance
3. Read: second pass on ~8-10 papers
4. Deep dive: third pass on ~2-3 key papers
5. Organise: Zotero/Mendeley with tags, notes, annotations
```

### Conference Reviewing
```text
- Reviewers typically spend 1-2 hours per paper
- First pass: abstract + intro + figures (10 min)
- Second pass: full paper check (60 min)
- Decision: accept/revision/reject
```

### Reproducibility
```text
- Most papers have code repositories (GitHub)
- Use the code to verify mathematical claims
- Running code often clarifies ambiguous notation
- Papers without code: implement yourself to verify
```
