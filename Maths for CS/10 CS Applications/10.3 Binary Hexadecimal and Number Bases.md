## Introduction

Number bases are different ways to write the same quantity. Decimal uses powers of 10 (base-10): 342₁₀ = 3×10² + 4×10¹ + 2×10⁰. Binary uses powers of 2 (base-2): 101011₂ = 1×2⁵ + 0×2⁴ + 1×2³ + 0×2² + 1×2¹ + 1×2⁰.

From [[1.1 Counting and Number Sense]] and [[1.2 Place Value and Expanded Form]], you already understand place value in decimal. The same concept applies to any base — only the base changes.

Computers use binary because transistors have two states (on/off). Every piece of data — numbers, text, images, sound — is ultimately stored as binary bits.

Hexadecimal (base-16) is a compact way to write binary: one hex digit = 4 binary bits. Programmers use hex constantly — colour codes (#FF0000 = red), memory addresses (0x7FFF...), and binary protocols.

## New Words

- **[[binary]]** — base-2 number system using digits 0, 1.
- **[[hexadecimal]]** — base-16 system using digits 0-9 and A-F (A=10, B=11, C=12, D=13, E=14, F=15).
- **[[bit]]** — binary digit (0 or 1), the smallest unit of data.
- **[[byte]]** — 8 bits, range 0-255 (hex 0x00-0xFF).
- **[[two's complement]]** — signed integer representation: for -k, invert bits of k and add 1.

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: Binary to Decimal Conversion

**Builds on:** [[1.2 Place Value and Expanded Form]] (place values), [[1.1 Counting and Number Sense]]

Each bit position i contributes bit_i × 2ⁱ. The rightmost bit is position 0 (2⁰ = 1).

#### Chunked Example

Question: Convert binary 101101 to decimal.

Step 1: Write bit positions from right to left:
```
1  0  1  1  0  1
2⁵ 2⁴ 2³ 2² 2¹ 2⁰
```

Step 2: Compute: 1×32 + 0×16 + 1×8 + 1×4 + 0×2 + 1×1.

Step 3: 32+0+8+4+0+1 = 45.

Answer: **101101₂ = 45₁₀**.

#### Chunked Example

Question: Convert binary 11001 to decimal.

Step 1: 1×16 + 1×8 + 0×4 + 0×2 + 1×1 = 16+8+0+0+1 = 25.

Answer: **11001₂ = 25₁₀**.

### Breadcrumb 2: Decimal to Binary Conversion

**Builds on:** Breadcrumb 1

Method: repeatedly divide by 2, read remainders from last to first.

#### Chunked Example

Question: Convert 37 to binary.

Step 1: 
```
37 ÷ 2 = 18 remainder 1
18 ÷ 2 = 9  remainder 0
9 ÷ 2  = 4  remainder 1
4 ÷ 2  = 2  remainder 0
2 ÷ 2  = 1  remainder 0
1 ÷ 2  = 0  remainder 1
```

Step 2: Read remainders from bottom to top: 100101.

Answer: **37₁₀ = 100101₂**.

#### Chunked Example

Question: Convert 100 to binary.

Step 1: 100÷2=50r0, 50÷2=25r0, 25÷2=12r1, 12÷2=6r0, 6÷2=3r0, 3÷2=1r1, 1÷2=0r1.

Step 2: Read remainders bottom→top: 1100100.

Answer: **100₁₀ = 1100100₂**.

### Breadcrumb 3: Hexadecimal

**Builds on:** Breadcrumbs 1 and 2

Base 16: digits 0-9 (0-9), A (10), B (11), C (12), D (13), E (14), F (15). Each hex digit represents exactly 4 binary bits.

Why hex is useful: binary numbers are long (e.g., 32 bits). Hex compresses 4 bits into one character. 32-bit binary = 8 hex digits.

#### Chunked Example — Binary to Hex

Question: Convert binary 11011010 to hex.

Step 1: Split into groups of 4 from the right: 1101 1010.

Step 2: 1101₂ = 1×8+1×4+0×2+1×1 = 13 = D. 1010₂ = 1×8+0×4+1×2+0×1 = 10 = A.

Step 3: Concatenate: 0xDA (the 0x prefix means hex in many programming languages).

Answer: **11011010₂ = 0xDA**.

#### Chunked Example — Hex to Decimal

Question: Convert 0x3F to decimal.

Step 1: 3×16¹ + F×16⁰ = 3×16 + 15×1 = 48 + 15 = 63.

Answer: **0x3F = 63₁₀**.

### Breadcrumb 4: Two's Complement — Signed Integers

**Builds on:** Breadcrumbs 1 and 2

Two's complement represents negative integers in binary. The key property: addition and subtraction work the same as for unsigned (same hardware).

To compute -k in n-bit two's complement:
1. Write k in n-bit binary.
2. Invert all bits (0→1, 1→0).
3. Add 1.

#### Chunked Example — Computing -5 in 8 Bits

Question: Represent -5 in 8-bit two's complement.

Step 1: 5 in 8-bit binary: 00000101.

Step 2: Invert: 11111010.

Step 3: Add 1: 11111011.

Answer: **-5 in 8-bit two's complement = 11111011**.

#### Chunked Example — Detecting Sign

Question: What is the value of 11111011 (two's complement, 8 bits)?

Step 1: The leftmost bit is 1 → negative number.

Step 2: Subtract 1: 11111010. Invert: 00000101 = 5.

Step 3: Value = -5.

Answer: **11111011₂ = -5₁₀** (in 8-bit two's complement).

## Worked Examples

### Example 1 — Binary Addition

Question: Add binary 1011₂ + 1101₂.

Step 1: Align right and add column by column:
```
  1 0 1 1
+ 1 1 0 1
---------
```

Step 2: Rightmost column: 1+1=0 carry 1.
Column 2: 1+0+carry=0 carry 1.
Column 3: 0+1+carry=0 carry 1.
Column 4: 1+1+carry=1 carry 1.

Step 3: Result: 11000₂ (24₁₀).

Answer: **1011₂ + 1101₂ = 11000₂**.

### Example 2 — Bitwise Operations

Question: Compute 0xFF & 0x0F and 0xFF | 0x0F.

Step 1: 0xFF = 11111111 (all 8 bits set). 0x0F = 00001111 (lower 4 bits set).

Step 2: AND: 11111111 & 00001111 = 00001111 = 0x0F.
OR: 11111111 | 00001111 = 11111111 = 0xFF.

Answer: **AND: 0x0F, OR: 0xFF**.

### Example 3 — CS Application: IP Address

Question: IP address 192.168.1.1 — convert to 32-bit binary and hex.

Step 1: 192 = 11000000, 168 = 10101000, 1 = 00000001, 1 = 00000001.

Step 2: Concatenate: 11000000 10101000 00000001 00000001.

Step 3: Hex groups: 1100=C, 0000=0, 1010=A, 1000=8, 0000=0, 0001=1, 0000=0, 0001=1 → 0xC0A80101.

Answer: **192.168.1.1 = 0xC0A80101**.

### Example 4 — CS Application: Colour Codes

Question: RGB colour #FF8800 — what colour is this? How is it stored?

Step 1: #RRGGBB: FF (red) = 255, 88 (green) = 136, 00 (blue) = 0.

Step 2: This is orange (full red, medium green, no blue).

Step 3: In memory: 24 bits, or 3 bytes: 0xFF, 0x88, 0x00.

Answer: **Orange. Stored as bytes: [255, 136, 0]**.

## Why This Works

Any base b represents numbers as sum of digits × b^k. Binary (b=2) uses fewest digits per value but many bits. Hexadecimal (b=16) is convenient because 16 = 2⁴, making conversion trivial — each hex digit maps to exactly 4 bits.

Two's complement works because the highest bit has a negative place value. In 8-bit: the leftmost bit contributes -2⁷ = -128. So 11111111 = -128+127 = -1. This makes addition/subtraction work with the same hardware circuits as unsigned addition — no special "subtract" circuitry needed.

## Common Mistakes

> [!failure] Mistake pattern: Confusing hex letters
> A=10, B=11, C=12, D=13, E=14, F=15. NOT A=1, B=2, etc. Mnemonic: A comes after 9.

> [!failure] Mistake pattern: Grouping binary to hex from the wrong side
> Always group from the RIGHT. Binary 1101 = D, but 1101 grouped from left would give incorrect results for bit counts not divisible by 4.

> [!failure] Mistake pattern: Forgetting two's complement sign extension
> When extending a negative number to more bits, fill with 1s: -5 (8-bit) = 11111011 → -5 (16-bit) = 1111111111111011.

> [!failure] Mistake pattern: Confusing bits and bytes
> 1 byte = 8 bits. A 32-bit integer = 4 bytes. A 64-bit integer = 8 bytes. Easy to mix up.

## Where This Shows Up in CS

### Low-Level Programming
```python
# Bit manipulation in Python
x = 0b1101     # binary literal (13)
y = 0xFF       # hex literal (255)
masked = x & y # bitwise AND (13)
shifted = x << 2  # left shift = 13×4 = 52
```

### Networking
```text
- IPv4 addresses: 32-bit numbers, often in dotted decimal
- MAC addresses: 48-bit hex (e.g., 00:1A:2B:3C:4D:5E)
- Subnet masks: binary AND with IP
```

### Graphics
```text
- Colour codes: #FF0000 = red (hex RGB)
- Image data: pixel values as bytes
- Memory-mapped I/O: hardware registers as bitfields
```

### Cryptography
```text
- All operations on binary blocks (AES: 128-bit blocks)
- Hash outputs: SHA-256 produces 256 bits = 64 hex digits
- Private keys: shown as hex strings
```
