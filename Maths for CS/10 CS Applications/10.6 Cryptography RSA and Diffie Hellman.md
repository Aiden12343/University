## Introduction

**Public-key cryptography** solves a fundamental problem: how can two people communicate securely without having shared a secret key beforehand?

From [[6.2 Modular Arithmetic]], you know about modular arithmetic and inverses. From [[6.12 Number Theory Basics]], you know about prime numbers and Euler's theorem. These deceptively simple ideas — modular multiplication, exponentiation, and the difficulty of factoring — are the foundation of all internet security.

Two breakthrough algorithms from the 1970s:
- **Diffie-Hellman key exchange**: two parties agree on a shared secret over an insecure channel.
- **RSA encryption**: a public key (n, e) encrypts, a private key (d) decrypts.

Every time you visit an HTTPS website, your browser uses one or both of these algorithms. Every SSH login, every encrypted email, every blockchain transaction depends on the maths of modular exponentiation.

## New Words

- **[[public-key cryptography]]** — encryption using public/private key pairs.
- **[[RSA]]** — Rivest-Shamir-Adleman: encryption via modular exponentiation m^e mod n.
- **[[Diffie-Hellman key exchange]]** — protocol to share a secret key over an insecure channel.
- **[[trapdoor function]]** — easy to compute one way, hard to invert without secret info (e.g., factoring n = p×q is easy, but factoring n back to p,q is hard).
- **[[discrete logarithm]]** — given g^x mod p, finding x is computationally hard for large primes.

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: Modular Exponentiation — The Building Block

**Builds on:** [[6.2 Modular Arithmetic]] (mod multiplication, exponentiation), [[10.3 Binary Hexadecimal]]

Both RSA and DH rely on computing a^b mod m efficiently. **Repeated squaring** makes this O(log b) instead of O(b).

#### Chunked Example — Repeated Squaring

Question: Compute 3⁵ mod 7 using repeated squaring.

Step 1: Write exponent 5 in binary: 5 = 101₂ = 4 + 1.

Step 2: Compute powers: 3¹ mod 7 = 3. 3² mod 7 = 2. 3⁴ mod 7 = 4.

Step 3: 3⁵ = 3⁴ × 3¹ ≡ 4 × 3 ≡ 12 ≡ 5 mod 7.

Answer: **3⁵ mod 7 = 5** (using 2 multiplications instead of 4).

### Breadcrumb 2: Diffie-Hellman Key Exchange

**Builds on:** Breadcrumb 1

1. Alice and Bob agree on a large prime p and a generator g (both public).
2. Alice picks secret a, sends A = g^a mod p.
3. Bob picks secret b, sends B = g^b mod p.
4. Alice computes s = B^a mod p. Bob computes s = A^b mod p.
5. Both get s = g^(ab) mod p — the shared secret.

An eavesdropper sees p, g, A, B but cannot compute s without finding a or b (the discrete log problem).

#### Chunked Example

Question: p = 23, g = 5. Alice's secret a = 6, Bob's secret b = 15. Compute the shared secret.

Step 1: Alice sends A = 5⁶ mod 23 = 15625 mod 23 = 8.

Step 2: Bob sends B = 5¹⁵ mod 23. Compute: 5¹⁵ = 5⁸ × 5⁴ × 5² × 5¹. 5²=2, 5⁴=4, 5⁸=16. 16×4×2×5=640 mod 23 = 19. So B = 19.

Step 3: Alice: s = 19⁶ mod 23. 19²=361 mod 23=16. 19⁴=16²=256 mod 23=3. 19⁶=19⁴×19²=3×16=48 mod 23=2.

Step 4: Bob: s = 8¹⁵ mod 23 = 2 (same computation structure, same result).

Answer: **Shared secret = 2**.

### Breadcrumb 3: RSA Key Generation

**Builds on:** [[6.12 Number Theory Basics]] (Euler's totient φ(n) = (p-1)(q-1)), [[6.2 Modular Arithmetic]] (modular inverse)

RSA key generation:
1. Choose two large primes p, q.
2. Compute n = p × q.
3. Compute φ(n) = (p-1)(q-1).
4. Choose e (public exponent) coprime with φ(n) (typically e = 65537).
5. Compute d = e⁻¹ mod φ(n) (the private exponent, using extended Euclidean algorithm).
6. Public key: (n, e). Private key: d.

#### Chunked Example

Question: Generate RSA keys with p = 5, q = 11.

Step 1: n = 5 × 11 = 55. φ(n) = (5-1)(11-1) = 4 × 10 = 40.

Step 2: Choose e = 3 (gcd(3,40) = 1, so they are coprime). Public key: (55, 3).

Step 3: Find d such that 3d ≡ 1 mod 40. 3 × 27 = 81 ≡ 1 mod 40. So d = 27.

Answer: **Public key: (55, 3). Private key: d = 27**.

### Breadcrumb 4: RSA Encryption and Decryption

**Builds on:** Breadcrumb 3

Encryption: c = m^e mod n (anyone with public key can do this).
Decryption: m = c^d mod n (only the holder of private key d can do this).

The correctness follows from Euler's theorem: m^(ed) ≡ m mod n when ed ≡ 1 mod φ(n).

#### Chunked Example

Question: Encrypt m = 7 using public key (55, 3). Then decrypt.

Step 1: Encrypt: c = 7³ mod 55 = 343 mod 55 = 343 - 6×55 = 343-330 = 13.

Step 2: Decrypt: m = 13²⁷ mod 55. Using repeated squaring:
13¹=13, 13²=169 mod 55=4, 13⁴=16, 13⁸=256 mod 55=36, 13¹⁶=36²=1296 mod 55=31.
13²⁷ = 13¹⁶×13⁸×13²×13¹ = 31×36×4×13 mod 55.
31×36=1116 mod 55=16. 16×4=64 mod 55=9. 9×13=117 mod 55=7.

Step 3: Decrypted: m = 7. ✓ Matches original.

Answer: **Encrypt: 7 → 13. Decrypt: 13 → 7**.

## Worked Examples

### Example 1 — RSA Encryption

Question: Given RSA primes p = 11, q = 13 and public exponent e = 7, encrypt the message m = 5. Compute the ciphertext c = m^e mod n using repeated squaring.

Step 1: Compute n = p × q = 11 × 13 = 143.

Step 2: Compute c = 5⁷ mod 143. Write exponent in binary: 7 = 4 + 2 + 1 (111₂).

Step 3: Compute successive squares: 5² = 25 mod 143 = 25. 5⁴ = 25² = 625 mod 143 = 625 - 4×143 = 625 - 572 = 53.

Step 4: Combine: 5⁷ = 5⁴ × 5² × 5¹ = 53 × 25 × 5 = 53 × 125 = 6625 mod 143. 143 × 46 = 6578. 6625 - 6578 = 47.

Answer: **c = 47**.

### Example 2 — Diffie-Hellman Key Exchange

Question: Alice and Bob agree on p = 11 and g = 2. Alice picks secret a = 4, Bob picks secret b = 7. Compute A = g^a mod p, B = g^b mod p, and the shared secret s = g^{ab} mod p.

Step 1: A = 2⁴ mod 11 = 16 mod 11 = 5.

Step 2: B = 2⁷ mod 11 = 128 mod 11 = 128 - 11×11 = 128 - 121 = 7.

Step 3: Alice computes s = B^a mod p = 7⁴ mod 11. 7² = 49 mod 11 = 5. 7⁴ = 5² = 25 mod 11 = 3.

Step 4: Bob computes s = A^b mod p = 5⁷ mod 11. 5² = 25 mod 11 = 3. 5⁴ = 3² = 9. 5⁷ = 5⁴ × 5² × 5 = 9 × 3 × 5 = 135 mod 11 = 135 - 12×11 = 135 - 132 = 3.

Answer: **A = 5, B = 7, shared secret s = 3**.

### Example 3 — RSA Decryption

Question: Given RSA primes p = 7, q = 13 and public exponent e = 5, find the private key d. Then decrypt ciphertext c = 33 to recover the original message m.

Step 1: n = 7 × 13 = 91. φ(n) = (7 - 1)(13 - 1) = 6 × 12 = 72.

Step 2: Find d = e⁻¹ mod φ(n) = 5⁻¹ mod 72. Using extended Euclidean: 72 = 14×5 + 2, 5 = 2×2 + 1. Back-substitute: 1 = 5 - 2×2 = 5 - 2(72 - 14×5) = 29×5 - 2×72. So d ≡ 29 mod 72.

Step 3: Decrypt: m = c^d mod n = 33²⁹ mod 91. Write 29 = 16 + 8 + 4 + 1. Compute: 33² = 1089 mod 91 = 1089 - 11×91 = 1089 - 1001 = 88. 33⁴ = 88² = 7744 mod 91 = 7744 - 85×91 = 7744 - 7735 = 9. 33⁸ = 9² = 81. 33¹⁶ = 81² = 6561 mod 91 = 6561 - 72×91 = 6561 - 6552 = 9.

Step 4: m = 33¹⁶ × 33⁸ × 33⁴ × 33¹ mod 91 = 9 × 81 × 9 × 33 mod 91. 9×81 = 729 mod 91 = 729 - 8×91 = 729 - 728 = 1. 1×9 = 9. 9×33 = 297 mod 91 = 297 - 3×91 = 297 - 273 = 24. So m = 24.

Step 5: Verify: 24⁵ mod 91 should equal c = 33. 24² = 576 mod 91 = 576 - 6×91 = 576 - 546 = 30. 24⁴ = 30² = 900 mod 91 = 900 - 9×91 = 900 - 819 = 81. 24⁵ = 24⁴ × 24 = 81 × 24 = 1944 mod 91 = 1944 - 21×91 = 1944 - 1911 = 33. ✓

Answer: **d = 29, m = 24**.

## Why This Works

Modular exponentiation (a^b mod n) can be computed in O(log b) steps using repeated squaring. This is fast — computing a^b mod n for 2048-bit numbers takes milliseconds.

Reversing it — finding b from g^b mod p — is the **discrete log problem**. The fastest known algorithms take sub-exponential time. For 2048-bit primes, this is computationally infeasible even with massive resources.

RSA's security relies on the same asymmetry: given n = p×q, computing the private key d requires φ(n) = (p-1)(q-1), which requires factoring n. Factoring large semiprimes (products of two primes) is also infeasible.

This asymmetry — easy one way, hard the other without a trapdoor — is the foundation of all public-key cryptography.

## Common Mistakes

> [!failure] Mistake pattern: Confusing RSA with Diffie-Hellman
> RSA is for encryption/signing. DH is for key agreement. TLS often uses both for different purposes.

> [!failure] Mistake pattern: Using small primes
> p and q must be large (~150+ digits for RSA-1024). Textbook examples use tiny primes for illustration only — these are NOT secure.

> [!failure] Mistake pattern: Textbook RSA without padding
> Direct RSA (m^e mod n) is deterministic and vulnerable. Real RSA uses OAEP padding.

> [!failure] Mistake pattern: Thinking DH provides authentication
> DH alone is vulnerable to man-in-the-middle attacks. Without signatures or certificates, you do not know who you are exchanging keys with.

## Where This Shows Up in CS

### Real-World Usage
```python
from Crypto.PublicKey import RSA
key = RSA.generate(2048)
public_key = key.publickey()
ciphertext = public_key.encrypt(message, None)
```

### Protocols
```text
- TLS/SSL: DH (or ECDHE) + RSA (or ECDSA)
- SSH: Diffie-Hellman key exchange
- PGP/GPG: RSA for signing + encryption
- Bitcoin: ECDSA (elliptic curve variant)
```

- Lattice-based: resistant to quantum attacks
