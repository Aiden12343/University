## Introduction

**Error-correcting codes** add extra bits to data so that even if part of the message is damaged, the original can be recovered. Like saying "Roger, over and out" on a noisy radio — the redundancy lets you recognise the message even when some words are garbled.

From [[10.3 Binary Hexadecimal and Number Bases]], you understand binary data representation. Error correction operates at the bit/symbol level — the sender produces a longer sequence, and the receiver reconstructs the original even if some bits flipped.

The fundamental trade-off: more redundancy = more error tolerance = less data capacity. A QR code can be set to L (7% recovery), M (15%), Q (25%), or H (30%). Higher recovery means fewer data characters can be stored.

## New Words

- **[[error-correcting code]]** — encoding that adds redundancy to detect and fix errors.
- **[[Reed-Solomon code]]** — block code that adds 2t parity symbols to correct t errors (works on symbols, not bits).
- **[[Hamming distance]]** — number of differing bits between two equal-length binary strings.
- **[[minimum distance]]** — smallest Hamming distance between any two codewords in a code.
- **[[parity bit]]** — extra bit set so the total number of 1s is even (even parity) or odd (odd parity).

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: Hamming Distance

**Builds on:** [[10.3 Binary Hexadecimal and Number Bases]] (binary representation)

The **Hamming distance** d(x,y) is the number of positions where two equal-length strings differ.

#### Chunked Example

Question: Compute the Hamming distance between 10110 and 10011.

Step 1: Compare bit by bit:
```
10110
10011
^ ^  → positions 2 and 4 differ
```

Step 2: There are 2 positions where the bits are different.

Answer: **Hamming distance = 2**.

#### Chunked Example

Question: Hamming distance between 000000 and 111111?

Step 1: Every position differs. Six positions → d = 6.

Answer: **d = 6**.

### Breadcrumb 2: Minimum Distance and Correction Capacity

**Builds on:** Breadcrumb 1

If a code's minimum distance is d_min, then:
- **Error detection**: up to d_min - 1 errors can be detected.
- **Error correction**: up to t = ⌊(d_min - 1)/2⌋ errors can be corrected.

Why? Think of codewords as points in space. Each codeword has a "ball" of radius t around it containing all strings at distance ≤ t. If the balls do not overlap, any corrupted string falls into exactly one ball and maps back to the correct codeword.

#### Chunked Example

Question: A code has d_min = 5. How many errors can it detect? How many can it correct?

Step 1: Detection: d_min - 1 = 4 errors.

Step 2: Correction: t = ⌊(5-1)/2⌋ = ⌊4/2⌋ = 2 errors.

Answer: **Detects up to 4 errors, corrects up to 2 errors**.

### Breadcrumb 3: Simple Parity — Detection Only

**Builds on:** Breadcrumb 1

A **parity bit** adds a single bit to make the total number of 1s even (even parity) or odd (odd parity). This can detect any odd number of bit flips, but cannot correct them (and cannot detect even numbers of flips).

#### Chunked Example

Question: Add even parity to 1011. What happens if a single bit flips?

Step 1: 1011 has three 1s (odd). Even parity: add bit = 1 to make four 1s. Codeword: 10111.

Step 2: If no errors: 4 ones → even → no error detected. ✓

Step 3: If single bit flips (e.g., 10011): 3 ones → odd → error detected! (But cannot locate which bit.)

Step 4: If two bits flip (e.g., 10001): 2 ones → even → error NOT detected. ✗

Answer: **Codeword: 10111. Detects odd number of errors. Cannot detect even errors**.

### Breadcrumb 4: Reed-Solomon Codes

**Builds on:** Breadcrumb 2

Reed-Solomon is a block code that works on **symbols** (typically bytes = 8 bits), not individual bits. It adds 2t parity symbols to correct t symbol errors.

Key properties:
- Works on symbol level — a symbol error corrupts all bits in that symbol.
- Excellent at correcting burst errors (consecutive corrupted symbols).
- Used in QR codes, CDs/DVDs, deep-space communication, RAID 6.

#### Chunked Example — QR Code Error Correction

Question: QR code version 5 has 108 data symbols and 26 error correction symbols. How many errors can it correct?

Step 1: Reed-Solomon with 2t parity symbols corrects t symbol errors.

Step 2: 2t = 26 → t = 13 symbol errors.

Step 3: Each symbol = 8 bits → can correct up to 13 bytes = 104 bits (if errors are concentrated in few symbols).

Answer: **Corrects up to 13 symbol errors**.

## Worked Examples

### Example 1 — Repetition Code (Majority Vote)

Question: Send each bit 3 times. Receiver gets 101 for a single bit. What was the original?

Step 1: Send 0 as 000, 1 as 111.

Step 2: Received: 101. Count: two 1s, one 0 → majority vote = 1.

Step 3: Corrects 1 error per group of 3 bits. Cost: 3× data size.

Answer: **Original bit = 1. Corrects 1 error, but triples data**.

### Example 2 — Hamming Code (Corrects 1 Error)

Question: A Hamming code has d_min = 3. What is its correction capacity?

Step 1: t = ⌊(3-1)/2⌋ = 1 error corrected.

Step 2: Detection: d_min - 1 = 2 errors can be detected (but not corrected).

Step 3: Uses parity bits at positions 1, 2, 4, 8, ... to locate the error.

Answer: **Corrects 1 error, detects 2 errors**.

### Example 3 — CS Application: QR Code Structure

Question: How does a QR code actually work?

Step 1: Data encoded as Reed-Solomon blocks. Four error correction levels: L (7%), M (15%), Q (25%), H (30%).

Step 2: Finder patterns (three large squares in corners) locate the code and determine orientation.

Step 3: Timing patterns (alternating black/white) determine the grid size.

Step 4: Masking patterns break up large black/white areas for reliable scanning.

```text
QR Version 40 (177×177 modules):
- Up to 4296 alphanumeric characters
- H-level EC: corrects up to 30% damage
- Reed-Solomon across multiple blocks
```

Answer: **Finder patterns + Reed-Solomon EC + masking + timing patterns**.

### Example 4 — CS Application: ECC Memory

```text
- ECC RAM: SECDED (Single Error Correct, Double Error Detect)
- Uses Hamming code with extra parity bit
- Essential for servers, scientific computing, critical systems
- Standard in most server-grade hardware
```

## Why This Works

Error correction works by creating **distance** between valid codewords. If no two codewords are too close (minimum distance is large), then a small number of errors cannot transform one valid codeword into another.

Think of it geometrically: valid codewords are points in an n-dimensional space. Errors move a point away from its original position. If the minimum distance between any two codewords is d_min, then a sphere of radius t = ⌊(d_min-1)/2⌋ around each codeword contains only strings that are closest to that codeword.

Reed-Solomon achieves this by treating symbols as coefficients of a polynomial. The 2t parity symbols encode evaluation of that polynomial at extra points. If some evaluations are corrupted, polynomial reconstruction (via Lagrange interpolation or Berlekamp-Massey) recovers the original data.

## Common Mistakes

> [!failure] Mistake pattern: Confusing error detection with correction
> Parity detects single errors but cannot correct them. Hamming code (d_min=3) can correct 1 error. Always know which your system needs.

> [!failure] Mistake pattern: Assuming all codes work on bits directly
> Reed-Solomon works on symbols (bytes), not individual bits. A "symbol error" affects all bits in that symbol. This is actually good for burst errors.

> [!failure] Mistake pattern: Overestimating correction capacity
> A code with d_min=5 corrects 2 errors. It does NOT correct 3 errors (would need d_min ≥ 7). Always compute t = ⌊(d_min-1)/2⌋.

## Where This Shows Up in CS

### QR Codes
```text
- Used in: payments, URLs, ticketing, passports
- Version 40 (177×177 modules): up to 4296 alphanumeric characters
- Error correction H (30%): readable with up to 30% damage
```

### Storage
```text
- CDs/DVDs: Reed-Solomon + cross-interleaving (CIRC)
- RAID: parity for disk failure recovery (RAID 5/6)
- ECC memory: SECDED (single error correct, double error detect)
```

### Communication
```text
- WiFi (802.11): convolutional codes, LDPC
- 5G: polar codes
- Deep space: Reed-Solomon + convolutional (NASA Voyager)
- Satellite TV: turbo codes
```
