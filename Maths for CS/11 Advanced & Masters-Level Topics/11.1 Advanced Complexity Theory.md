## Introduction

**Complexity theory** asks: what can computers feasibly compute? Beyond the raw runtime analysis of individual algorithms ([[10.1 Big O Theta and Omega]]), complexity theory studies the inherent difficulty of computational problems themselves — regardless of which algorithm you use.

The big ideas:

- **P** (Polynomial Time): problems solvable in O(nᵏ) time — "efficiently solvable".
- **NP** (Nondeterministic Polynomial Time): problems whose solutions can be verified in polynomial time — "efficiently checkable".
- **NP-complete**: the hardest problems in NP — if any one of them has a polynomial-time algorithm, then all of NP does (P = NP).
- **Reductions**: a way to compare problem difficulty. If problem A can be transformed into problem B in polynomial time (A ≤_p B), then A is no harder than B.

From [[10.1 Big O Theta and Omega]], you know how to measure algorithm running time asymptotically. From [[5.11 Proof by Induction]], you can reason about recursive algorithms. From [[5.5 Propositional Logic]], you understand Boolean formulas — essential for SAT, the canonical NP-complete problem.

The central open question — does P = NP? — is one of the seven Millennium Prize Problems, with a \$1M reward. Most computer scientists believe P ≠ NP, but no one has proven it.

## New Words

- **[[P]]** — class of problems solvable in deterministic polynomial time O(nᵏ).
- **[[NP]]** — class of problems verifiable in nondeterministic polynomial time (given a solution, check it in polynomial time).
- **[[NP-complete]]** — a problem that is (1) in NP and (2) NP-hard (all NP problems reduce to it).
- **[[NP-hard]]** — a problem that all NP problems reduce to (may not be in NP itself).
- **[[reduction]]** — a polynomial-time transformation of one problem into another, A ≤_p B.
- **[[polynomial hierarchy]]** — the layered complexity classes: P ⊆ NP ⊆ PSPACE ⊆ EXPTIME.
- **[[co-NP]]** — problems whose complement is in NP (e.g., TAUTOLOGY: is φ true for all assignments?).
- **[[PSPACE]]** — problems solvable using polynomial space (may use exponential time).

> [!important] You pass this topic only when you can define all eight terms without looking.

## Breadcrumbs

### Breadcrumb 1: P vs NP — The Central Question

**Builds on:** [[10.1 Big O Theta and Omega]] (polynomial time), [[5.5 Propositional Logic]] (Boolean formulas)

**P** is the set of problems solvable by a deterministic Turing machine in polynomial time O(nᵏ). In practice: problems we can solve efficiently.

**NP** is the set of problems whose solutions can be verified by a deterministic Turing machine in polynomial time. In practice: problems where checking a candidate answer is easy, even if finding one may be hard.

Every problem in P is also in NP (if you can solve it, you can certainly verify a solution). So P ⊆ NP. But does NP ⊆ P? That is, can every problem whose solution is easy to check also be solved efficiently?

#### Chunked Example — Sorting vs Travelling Salesman

Question: Classify Sorting and TSP as P, NP, or both.

Step 1: Sorting n numbers: O(n log n) algorithm exists → sorting ∈ P.

Step 2: TSP: given n cities and distances, find the shortest tour visiting each city once. No known polynomial algorithm.

Step 3: But given a proposed tour, verify it visits all cities and compute total distance in O(n). So TSP ∈ NP.

Answer: **Sorting ∈ P. TSP ∈ NP (but not known to be in P)**. This asymmetry — easy to check, possibly hard to find — is the essence of the P vs NP question.

#### Chunked Example — Factoring as an NP Problem

Question: Why is integer factoring believed to be outside P?

Step 1: Given n = 1,234,567,891,011,121, find its prime factors. No known polynomial algorithm.

Step 2: But given candidate factors p and q, verify p × q = n in O(log² n) using multiplication.

Step 3: Factoring ∈ NP. Not known to be in P. However, factoring is not believed to be NP-complete either (it's in NP ∩ co-NP).

Answer: **Factoring ∈ NP, probably not NP-complete, probably not in P.** This "sweet spot" is what RSA cryptography relies on.

### Breadcrumb 2: Reductions — Comparing Problem Difficulty

**Builds on:** Breadcrumb 1, [[5.5 Propositional Logic]] (logical implication and transformations)

A **reduction** A ≤_p B is a polynomial-time algorithm that transforms any instance of problem A into an instance of problem B, such that solving B gives the answer for A.

```
Instance of A ---[reduce]--- Instance of B ---[solve]--- Answer for B = Answer for A
```

Properties:
- If A ≤_p B and B ∈ P, then A ∈ P.
- If A ≤_p B and A is NP-hard, then B is NP-hard.
- Reductions compose: A ≤_p B and B ≤_p C implies A ≤_p C.

The direction is critical: A ≤_p B means A is **no harder** than B. To show a problem is hard, you reduce a known hard problem to it.

#### Chunked Example — SAT ≤_p 3SAT

Question: Show that any SAT instance can be reduced to a 3SAT instance.

Step 1: SAT allows clauses of any length. 3SAT requires exactly three literals per clause.

Step 2: Replace a clause (x₁ ∨ x₂) with (x₁ ∨ x₂ ∨ y)(x₁ ∨ x₂ ∨ ¬y) where y is a fresh variable.

Step 3: Replace a clause (x₁ ∨ x₂ ∨ x₃ ∨ x₄) with (x₁ ∨ x₂ ∨ y)(¬y ∨ x₃ ∨ x₄).

Step 4: Each replacement preserves satisfiability. The new formula is satisfiable iff the original was.

Answer: **SAT ≤_p 3SAT**. This shows 3SAT is at least as hard as SAT — so 3SAT is NP-complete.

#### Chunked Example — 3SAT ≤_p Independent Set

Question: Show 3SAT reduces to the Independent Set problem (find k vertices with no edges between them).

Step 1: Given a 3SAT formula φ with m clauses, construct a graph with 3m vertices (one per literal in each clause).

Step 2: Add edges between every pair of vertices in the same clause (they cannot all be true simultaneously).

Step 3: Add edges between contradictory literals (x and ¬x).

Step 4: Set k = m. φ is satisfiable iff the graph has an independent set of size m.

Answer: **3SAT ≤_p Independent Set**. This is how NP-completeness propagates through the problem space.

### Breadcrumb 3: NP-Completeness — The Hardest Problems in NP

**Builds on:** Breadcrumbs 1, 2

A problem is **NP-complete** if:
1. It is in NP (solutions verifiable in polynomial time).
2. It is NP-hard (every problem in NP reduces to it).

The first NP-complete problem: **SAT** (Cook-Levin Theorem, 1971). Cook showed that any NP computation can be encoded as a Boolean formula — the accepting computation of a nondeterministic Turing machine maps to a satisfying assignment.

Once SAT is known to be NP-complete, we can prove others NP-complete by reduction: A is NP-complete if SAT ≤_p A (or any known NP-complete problem ≤_p A).

#### Chunked Example — Proving Vertex Cover is NP-complete

Question: Show Vertex Cover (does G have a set of ≤ k vertices covering all edges?) is NP-complete.

Step 1: VC ∈ NP: given a set of k vertices, check each edge has an endpoint in the set — O(m).

Step 2: NP-hardness: reduce from 3SAT. Create a vertex for each literal. Add edges connecting literals within clauses (triangle for 3 clauses), plus edges between x and ¬x.

Step 3: A vertex cover of size 2m (where m = number of clauses) forces picking one literal per clause that is "true" and all complement pairs fully covered.

Step 4: The satisfying assignment selects literals not in the vertex cover as true.

Answer: **Vertex Cover is NP-complete** via 3SAT ≤_p VC.

## Why This Works

Reductions form a directed graph of problem difficulty. If A ≤_p B, then A is no harder than B. The NP-complete problems form a "hardness club" — all NP problems reduce to them, but they reduce to each other.

```
P: easy to solve
    ↓
NP: easy to verify (includes P)
    ↓
NP-complete: hardest in NP (SAT, 3SAT, VC, TSP, Clique, Subset Sum)
    ↓
NP-hard: at least as hard as NP (may not be in NP — e.g., TSP optimisation)
    ↓
PSPACE: polynomial space (includes NP)
```

The P vs NP question asks: does P = NP? If so, every problem with an efficient verifier also has an efficient solver — breaking most cryptography and revolutionising optimisation. If not (as widely believed), there are inherently hard problems that require approximation or heuristics.

## Worked Examples

### Example 1 — Constructing a Reduction (VERTEX-COVER ≤ₚ CLIQUE)

Question: Given G = (V,E) with V = {1,2,3,4,5} and E = {(1,2),(1,3),(2,4),(3,5),(4,5),(2,5)}, and k = 2. Reduce the VERTEX-COVER instance (G,k) to a CLIQUE instance (Ḡ,k') using the complement reduction. Does G have a vertex cover of size ≤ 2?

Step 1: The complement Ḡ has edges for all vertex pairs not in E. Pairs not in E: (1,4),(1,5),(2,3),(3,4). So Ḡ = (V, Ē) with Ē = {(1,4),(1,5),(2,3),(3,4)}.

Step 2: The reduction sets k' = |V| − k = 5 − 2 = 3. The CLIQUE instance asks: does Ḡ contain a clique of size 3?

Step 3: Check Ḡ for a 3-clique. Vertex 1 connects to 4 and 5, but 4 and 5 are not adjacent in Ḡ. Vertex 3 connects to 2 and 4, but 2 and 4 are not adjacent. No vertex has degree ≥ 2 with its neighbours also mutually connected — no 3-clique exists.

Step 4: Since Ḡ has no 3-clique, G does NOT have a vertex cover of size ≤ 2. The minimum vertex cover of G is {1,2,5} of size 3.

Answer: **Ḡ has no 3-clique → G has no vertex cover of size ≤ 2. Minimum vertex cover = 3.**

### Example 2 — Applying a Reduction (3SAT ≤ₚ Independent Set)

Question: Given φ = (x₁ ∨ ¬x₂ ∨ x₃) ∧ (¬x₁ ∨ x₂ ∨ ¬x₃), construct the graph for the 3SAT ≤ₚ Independent Set reduction. What is the maximum independent set size, and is φ satisfiable?

Step 1: Create 3 vertices per clause (one per literal). Clause 1: (1,1)=x₁, (1,2)=¬x₂, (1,3)=x₃. Clause 2: (2,1)=¬x₁, (2,2)=x₂, (2,3)=¬x₃.

Step 2: Add intra-clause edges (triangles): (1,1)-(1,2), (1,1)-(1,3), (1,2)-(1,3) for clause 1; similarly (2,1)-(2,2), (2,1)-(2,3), (2,2)-(2,3) for clause 2.

Step 3: Add inter-clause edges between contradictory literals: (1,1)-(2,1) (x₁ and ¬x₁), (1,2)-(2,2) (¬x₂ and x₂), (1,3)-(2,3) (x₃ and ¬x₃).

Step 4: Set k = 2 (number of clauses). An independent set of size 2 exists: pick (1,1)=x₁ and (2,2)=x₂ — they are not in the same clause and not contradictory. This corresponds to assignment x₁ = T, x₂ = T. Since we can pick one vertex from each clause, φ is satisfiable.

Answer: **Max independent set = 2 = m, so φ is satisfiable (e.g., x₁ = T, x₂ = T, x₃ arbitrary).**

### Example 3 — NP-Completeness: Concrete SUBSET SUM Instance

Question: Given S = {3, 5, 7, 11, 13} and target T = 20: (a) Show that SUBSET SUM ∈ NP by verifying a candidate subset. (b) Find a subset that sums to 20, or prove none exists.

Step 1: (a) Given a candidate subset, say {3, 7, 11}, verify by summing: 3 + 7 + 11 = 21 ≠ 20. This candidate fails, but verification takes O(|S|) = O(5) time — polynomial.

Step 2: (b) Check subsets systematically. {7, 13}: 7 + 13 = 20. This subset sums to exactly 20.

Step 3: With the candidate {7, 13}, the verifier sums the elements (2 additions) and compares to T — O(n) verification.

Step 4: SUBSET SUM is NP-complete (reduction from VERTEX COVER). Finding such a subset without being given one requires searching exponentially many candidates in the worst case.

Answer: **{7, 13} sums to 20. Verification is O(|S|). SUBSET SUM ∈ NP; NP-complete means no polynomial algorithm unless P = NP.**

### Example 4 — Polynomial Hierarchy Classification

Question: Consider the decision problem EXACT-CLIQUE: given a graph G and integer k, does the largest clique in G have size exactly k? Classify this problem in the polynomial hierarchy.

Step 1: The property "clique size ≥ k" is in NP: guess k vertices and verify they form a clique.

Step 2: The property "clique size ≤ k" is in co-NP: verifying that no (k+1)-clique exists requires a universal quantifier over all subsets of size k+1.

Step 3: EXACT-CLIQUE requires both: (∃ clique of size ≥ k) ∧ (∀ subsets of size k+1, not a clique). This is a conjunction of an NP statement and a co-NP statement — placing it in DP = NP ∩ co-NP.

Step 4: DP is a level in the polynomial hierarchy (specifically, the second level). Problems in DP are believed harder than NP or co-NP alone.

Answer: **EXACT-CLIQUE ∈ DP (difference of NP and co-NP), a class in the second level of the polynomial hierarchy.**

## Common Mistakes

> [!failure] Mistake pattern: Confusing "NP" with "exponential"
> NP does NOT mean "non-polynomial." It means "nondeterministic polynomial" — verifiable in polynomial time. Many NP problems have exponential worst-case algorithms, but some NP problems (those in P) have polynomial algorithms.

> [!failure] Mistake pattern: Reversing the reduction direction
> A ≤_p B means A reduces TO B (solve A by solving B). If you want to prove problem X is NP-hard, reduce a KNOWN NP-hard problem TO X, not X to the known problem. Common error: "SAT ≤_p X" proves X is hard; "X ≤_p SAT" just proves X is not harder than SAT.

> [!failure] Mistake pattern: NP-completeness is worst-case
> A problem being NP-complete means there exist hard instances. Average instances might be easy. Modern SAT solvers (CDCL) handle many industrial instances with millions of variables — the worst-case instances are carefully constructed.

> [!failure] Mistake pattern: PSPACE vs EXPTIME
> PSPACE allows exponential time but only polynomial space. EXPTIME requires exponential time regardless of space. Some PSPACE-complete problems (like QBF — quantified Boolean formulas) can run for exponential time but need only polynomial memory.

## Where This Shows Up in CS

### Algorithm Design
```text
- Proving NP-completeness → stop seeking polynomial exact algorithm
- Switch to approximation, heuristics, parameterised complexity, or exact exponential with pruning
- SAT solvers (CDCL, resolution): solve real-world SAT instances with millions of clauses
```

### Cryptography
```text
- Security assumes hard NP problems (factoring, discrete log, lattice problems)
- Quantum computing breaks factoring (Shor's algorithm) but not NP-complete problems generally
- Post-quantum cryptography uses lattice problems (worst-case hardness connects to NP)
```

### Optimisation
```text
- TSP solved for n=10⁶ using heuristics, exact for n≈10⁴ using branch-and-cut
- Scheduling, resource allocation, packing — all NP-hard; industry uses MILP solvers
- Approximation algorithms with provable guarantees (2-approximation for Vertex Cover)
```

### Complexity Zoo
```text
P ⊆ NP ⊆ PSPACE ⊆ EXPTIME ⊆ NEXPTIME ⊆ EXPSPACE
L (log space) ⊆ NL ⊆ P
BPP (randomised polynomial) — believed equal to P
BQP (quantum polynomial) — contains factoring, not known to contain NP-complete
```
