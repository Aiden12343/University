## Introduction

**Category theory** is "the mathematics of mathematics" — it studies patterns that recur across different mathematical domains. For computer science, it provides the language for functional programming, type theory, and semantics.

From [[10.11 Type Theory and Program Logic Intro]], you understand types as sets of values and functions as transformations. From [[5.9 Direct Proof and Counterexample]] and [[5.10 Proof by Contradiction and Contrapositive]], you can reason rigorously about mathematical structures.

The core concepts:
- **Category**: objects + morphisms (arrows) satisfying composition (associative) and identity.
- **Functor**: a structure-preserving mapping between categories.
- **Natural transformation**: a family of morphisms between functors, commuting with all morphisms in the source category.
- **Monad**: an endofunctor T with η: X → T(X) (unit) and μ: T(T(X)) → T(X) (join), structuring computational effects.
- **Universal property**: defining an object uniquely (up to isomorphism) by its relationship to other objects.

The mantra: **"good mathematics is about structure, and structure is about relationships, not objects."**

## New Words

- **[[category]]** — a collection of objects and morphisms (arrows) with composition (associative) and identity morphisms.
- **[[functor]]** — a mapping F: C → D that sends objects to objects and morphisms to morphisms, preserving identity and composition.
- **[[natural transformation]]** — a family of morphisms η_X: F(X) → G(X) such that for every f: X → Y, η_Y ∘ F(f) = G(f) ∘ η_X.
- **[[monad]]** — an endofunctor T: C → C with natural transformations η: Id → T (unit) and μ: T² → T (join) satisfying associativity and identity laws.
- **[[universal property]]** — a definition of an object up to unique isomorphism by specifying its relationship (via morphisms) to all other objects.

> [!important] You pass this topic only when you can define all five terms without looking.

## Breadcrumbs

### Breadcrumb 1: The Category Set — Objects and Morphisms

**Builds on:** [[10.11 Type Theory and Program Logic Intro]] (types and functions), [[5.9 Direct Proof and Counterexample]] (function composition)

A **category** C consists of:
- Objects: ob(C)
- Morphisms (arrows): for each pair (A, B), a set Hom(A, B) of morphisms f: A → B.
- Composition: g ∘ f: A → C for f: A → B, g: B → C (associative).
- Identity: id_A: A → A (unit for composition).

The prototypical category: **Set** — objects are sets, morphisms are functions.

#### Chunked Example — Composition in Set

Question: In Set, f: A → B, g: B → C. What is g ∘ f and what are its properties?

Step 1: g ∘ f: A → C. (g ∘ f)(x) = g(f(x)) for all x ∈ A.

Step 2: Associativity: h ∘ (g ∘ f) = (h ∘ g) ∘ f for h: C → D.

Step 3: Identity: id_A(x) = x. f ∘ id_A = f, id_B ∘ f = f.

Answer: **Composition of functions is associative with identity — Set satisfies all category axioms.**

### Breadcrumb 2: Functors — Structure-Preserving Maps

**Builds on:** Breadcrumb 1, [[5.9 Direct Proof and Counterexample]] (preserving properties)

A **functor** F: C → D maps each object X ∈ C to F(X) ∈ D and each morphism f: X → Y to F(f): F(X) → F(Y), preserving:
- Identity: F(id_X) = id_{F(X)}.
- Composition: F(g ∘ f) = F(g) ∘ F(f).

#### Chunked Example — List Functor in Haskell

Question: Show that Haskell's List type constructor is a functor.

Step 1: Object mapping: type a → [a] (list of a).

Step 2: Morphism mapping: fmap f [x, y, z] = [f x, f y, f z].

Step 3: Preserves identity: fmap id [x, y, z] = [x, y, z] = id [x, y, z].

Step 4: Preserves composition: fmap (g ∘ f) = fmap g ∘ fmap f.

Answer: **List is a functor: fmap applies a function to each list element, preserving structure.**

### Breadcrumb 3: Natural Transformations and Monads

**Builds on:** Breadcrumb 2, [[5.10 Proof by Contradiction and Contrapositive]] (commuting diagrams)

A **natural transformation** η: F → G is a family of morphisms η_X: F(X) → G(X) such that for every f: X → Y:

```
η_Y ∘ F(f) = G(f) ∘ η_X    (the naturality square commutes)
```

A **monad** is an endofunctor T: C → C with:
- η: Id → T (unit/return)
- μ: T² → T (join/flatten)
- Laws: μ ∘ Tμ = μ ∘ μT (associativity), μ ∘ Tη = μ ∘ ηT = id (unit laws).

#### Chunked Example — Maybe Monad

Question: Show that Maybe in Haskell forms a monad.

Step 1: Maybe a = Nothing | Just a. T maps a → Maybe a, f → fmap f.

Step 2: η (return): X → Maybe X, return x = Just x.

Step 3: μ (join): Maybe(Maybe a) → Maybe a. Nothing → Nothing, Just Nothing → Nothing, Just (Just x) → Just x.

Step 4: Bind: (>>=) = μ ∘ fmap f. Nothing >>= _ = Nothing, Just x >>= f = f x.

Answer: **Maybe monad: encapsulates optionality. η = Just, μ = flatten. Used for null-safe chaining.**

## Why This Works

Category theory unifies seemingly different concepts:

```
Set theory                Category theory
---------                ----------------
Sets                      Objects
Functions                 Morphisms
Injective                 Monomorphism
Surjective                Epimorphism
Bijection                 Isomorphism
Image factorisation       (Epi, Mono) factorisation
```

In computer science:
- **Functors** = generic container types (List, Maybe, Tree, Promise).
- **Natural transformations** = polymorphic functions (head :: [a] → Maybe a).
- **Monads** = computational effects (IO, State, Maybe, Either, Reader, Writer).
- **Products** = pair types, **Coproducts** = sum types (Either).
- **Kleisli category** = composition of effectful functions (monadic do-notation).

## Worked Examples

### Example 1 — Verifying the Naturality Square for head

Question: Let f: {1, 2, 3} → {a, b} be defined by f(1) = a, f(2) = a, f(3) = b. Verify that the naturality square commutes for head: [X] → Maybe X where head([]) = Nothing and head(x:_) = Just x, applied to the list [1, 2, 3].

Step 1: Compute the left side fmap f ∘ head. head([1, 2, 3]) = Just 1. fmap f (Just 1) = Just (f(1)) = Just a.

Step 2: Compute the right side head ∘ fmap f. fmap f [1, 2, 3] = [f(1), f(2), f(3)] = [a, a, b]. head([a, a, b]) = Just a.

Step 3: Both sides evaluate to Just a. The naturality square commutes for this input. ✓

Answer: **fmap f (head [1,2,3]) = Just a = head (fmap f [1,2,3]). Naturality holds for this case.**

### Example 2 — Verifying the List Functor Preserves Composition

Question: Let f: {1, 2} → {a, b} with f(1) = a, f(2) = b and g: {a, b} → {x, y} with g(a) = x, g(b) = y. Verify that the List functor preserves composition on the list [1, 2].

Step 1: Compute fmap (g ∘ f) [1, 2] = [g(f(1)), g(f(2))] = [g(a), g(b)] = [x, y].

Step 2: Compute (fmap g ∘ fmap f) [1, 2] = fmap g (fmap f [1, 2]) = fmap g [a, b] = [x, y].

Step 3: Both equal [x, y]. The functor law F(g ∘ f) = F(g) ∘ F(f) holds. ✓

Answer: **fmap (g ∘ f) [1, 2] = [x, y] = (fmap g ∘ fmap f) [1, 2]. List preserves composition.**

### Example 3 — Universal Property of the Product

Question: Let A = {a, b} and B = {1, 2} in the category Set. Show that A × B = {(a,1), (a,2), (b,1), (b,2)} with projections π₁(x, y) = x, π₂(x, y) = y satisfies the universal property for the object C = {*} with f(*) = a, g(*) = 1.

Step 1: Universal property requires a unique h: C → A × B such that π₁ ∘ h = f and π₂ ∘ h = g.

Step 2: Define h(*) = (a, 1). Check: π₁(h(*)) = π₁(a, 1) = a = f(*). ✓. π₂(h(*)) = π₂(a, 1) = 1 = g(*). ✓.

Step 3: Uniqueness: any h' with π₁ ∘ h' = f must satisfy h'(*) = (a, _). Then π₂ ∘ h' = g forces the second component to be 1. Thus h(*) = (a, 1) is the unique mediating morphism.

Answer: **h(*) = (a, 1) is the unique morphism satisfying the product universal property.**

### Example 4 — Verifying the Maybe Monad Left Unit Law

Question: For the Maybe monad with unit η(x) = Just x and join μ(Nothing) = Nothing, μ(Just Nothing) = Nothing, μ(Just (Just x)) = Just x, verify the left unit law μ ∘ Tη = id_T on the inputs Nothing and Just 5.

Step 1: Tη (fmap η) maps Nothing → Nothing, Just x → Just (η x) = Just (Just x).

Step 2: For input Nothing: (μ ∘ Tη)(Nothing) = μ(fmap η Nothing) = μ(Nothing) = Nothing = id_T(Nothing). ✓

Step 3: For input Just 5: (μ ∘ Tη)(Just 5) = μ(fmap η (Just 5)) = μ(Just (η 5)) = μ(Just (Just 5)) = Just 5 = id_T(Just 5). ✓

Answer: **μ ∘ Tη = id_T holds for both cases: (μ ∘ Tη)(Nothing) = Nothing, (μ ∘ Tη)(Just 5) = Just 5.**

## Common Mistakes

> [!failure] Mistake pattern: Overcomplicating category theory
> Category theory is abstract by design. Always ground concepts in concrete categories: Set (sets+functions), Hask (Haskell types+functions), Vect (vector spaces+linear maps), Grp (groups+homomorphisms).

> [!failure] Mistake pattern: Ignoring naturality
> A natural transformation must commute with ALL morphisms. If the naturality square does not commute for some f, it is not natural — it is merely a family of morphisms.

> [!failure] Mistake pattern: Confusing monad with monoid
> "A monad is a monoid in the category of endofunctors" is a precise technical statement. In practice: monad = endofunctor + unit + join satisfying three laws.

## Where This Shows Up in CS

### Functional Programming
```haskell
-- Functor, Applicative, Monad hierarchy
fmap  :: (a → b) → f a → f b       -- Functor
(<*>) :: f (a → b) → f a → f b     -- Applicative
(>>=) :: m a → (a → m b) → m b     -- Monad
```

### Common Monads
```text
- Maybe: optionality / null safety
- List: nondeterminism (multiple results)
- Either: error handling with messages
- IO: side effects (Haskell)
- State: mutable state
- Reader/Writer: dependency injection / logging
```

### Design Patterns
```text
- Functor = mappable (map in C#, .Select in LINQ)
- Monad = composable effectful computation
- Natural transformation = polymorphic function (∀a. F a → G a)
- Category = composable interface (e.g., Monoid as a single-object category)
```

### Formal Methods and PL Research
```text
- Initial algebra semantics: recursive types as fixed points of functors
- Cartesian closed categories: models of typed λ-calculus
- Fibrations: indexed types, dependent types
- Categorical quantum mechanics: quantum protocols
```
