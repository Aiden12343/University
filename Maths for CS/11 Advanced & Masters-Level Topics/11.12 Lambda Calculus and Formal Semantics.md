## Introduction

**Lambda calculus** (λ-calculus) is the theoretical foundation of functional programming languages and a model of computation equivalent to Turing machines (Church-Turing thesis). It is both a programming language and a logical system.

From [[11.11 Category Theory for CS Intro]], you understand structure-preserving maps and composition — which appear in typed λ-calculus as Cartesian closed categories. From [[10.11 Type Theory and Program Logic Intro]], you know how types classify terms and prevent runtime errors. From [[5.9 Direct Proof and Counterexample]] and [[5.10 Proof by Contradiction and Contrapositive]], you can reason about rewriting and normalisation.

The three constructs:
- **Variable**: x — a named placeholder for a value.
- **Abstraction**: λx.M — "given x, produce M" (function creation).
- **Application**: M N — "apply function M to argument N" (function call).

Everything else (numbers, booleans, data structures, recursion) is encoded using these three constructs.

## New Words

- **[[λ-term]]** — M ::= x | λx.M | M N (variable, abstraction, application).
- **[[β-reduction]]** — (λx.M)N →_β M[x:=N] where M[x:=N] is substitution with α-conversion to avoid capture.
- **[[Church-Rosser property]]** — (confluence) if M →* N₁ and M →* N₂, then there exists L such that N₁ →* L and N₂ →* L.
- **[[simply typed lambda calculus]]** — λ-calculus with type annotations: x:τ, λx:τ.M: τ→σ, application requires matching types.
- **[[Curry-Howard correspondence]]** — types correspond to logical propositions; terms correspond to proofs; β-reduction corresponds to proof normalisation.
- **[[α-conversion]]** — renaming bound variables: λx.x =_α λy.y (bound variable names are irrelevant).

> [!important] You pass this topic only when you can define all six terms without looking.

## Breadcrumbs

### Breadcrumb 1: Beta Reduction — The Essence of Computation

**Builds on:** [[10.11 Type Theory and Program Logic Intro]] (function application, substitution)

**β-reduction** is the single computational rule of λ-calculus:

```
(λx.M)N →_β M[x:=N]
```

The term (λx.M) is called a **redex** (reducible expression). M[x:=N] means "replace every free occurrence of x in M with N", performing α-conversion first to avoid variable capture.

#### Chunked Example — Reducing a Simple Term

Question: Reduce (λx.λy. x + y) 3 4.

Step 1: (λx.λy. x + y) 3 → λy. 3 + y (substitute 3 for x).

Step 2: (λy. 3 + y) 4 → 3 + 4 (substitute 4 for y).

Step 3: 3 + 4 → 7.

Answer: **7. Functional application via sequential β-reduction.**

#### Chunked Example — Alpha Conversion to Avoid Capture

Question: Reduce (λx.λy.x) y. Why is α-conversion needed?

Step 1: If we naively substitute: (λx.λy.x) y → λy.y. But this changes meaning — the free y gets captured!

Step 2: α-convert first: (λx.λz.x) y → λz.y (bound variable renamed to z).

Step 3: Now substitute correctly: λz.y — y stays free.

Answer: **α-conversion prevents variable capture: (λx.λy.x)y =_α (λx.λz.x)y →_β λz.y.**

### Breadcrumb 2: Church Numerals — Encoding Numbers

**Builds on:** Breadcrumb 1, [[5.9 Direct Proof and Counterexample]] (recursive definitions)

Church numerals encode natural numbers as functions:

```
0 := λf.λx.x
1 := λf.λx.f x
2 := λf.λx.f (f x)
3 := λf.λx.f (f (f x))
```

The numeral n applies f to x exactly n times.

#### Chunked Example — Addition via Church Numerals

Question: Define addition and compute 2 + 3.

Step 1: PLUS := λm.λn.λf.λx. m f (n f x).

Step 2: PLUS 2 3 = λf.λx. 2 f (3 f x).

Step 3: 3 f x = f(f(f x)). 2 f (result) = f(f(f(f(f x)))).

Step 4: Result: λf.λx.f⁵(x) = 5.

Answer: **PLUS encodes addition by applying m and then n to the same f. 2 + 3 = 5.**

### Breadcrumb 3: Church-Rosser and Normalisation

**Builds on:** Breadcrumb 1, [[5.10 Proof by Contradiction and Contrapositive]] (uniqueness proofs)

The **Church-Rosser property** (confluence): if M reduces to both N₁ and N₂, there exists L such that both reduce to L. This guarantees:
- **Uniqueness of normal forms**: a λ-term can have at most one normal form.
- **Reduction strategy does not affect final result** (if one exists).

However, some terms may not have a normal form:

```
Ω := (λx.x x)(λx.x x) →_β (λx.x x)(λx.x x) →_β Ω (loops forever!)
```

#### Chunked Example — Reduction Strategy Matters for Termination

Question: (λy.z) Ω. Does this term have a normal form?

Step 1: Normal-order (leftmost, outermost): reduce the outer redex first. (λy.z) Ω →_β z. Terminates!

Step 2: Applicative-order (rightmost, innermost): evaluate Ω first. Ω loops forever. Never terminates.

Step 3: Church-Rosser guarantees: if a term has a normal form, normal-order reduction finds it.

Answer: **Yes — normalisation depends on reduction strategy. Normal-order finds normal form if it exists.**

## Why This Works

λ-calculus is the simplest model of computation that is Turing-complete. The key theorems:

- **Church-Rosser**: reduction is confluent — the order of reductions does not affect the final result (if one exists).
- **Church-Turing thesis**: λ-calculus can compute any function computable by a Turing machine (and vice versa).
- **Curry-Howard**: the simply typed λ-calculus corresponds to natural deduction (intuitionistic logic). A term M of type τ is a proof of proposition τ. β-reduction corresponds to proof normalisation (cut elimination).
- **Strong normalisation**: every well-typed term in the simply typed λ-calculus terminates — no infinite reductions. This means the simply typed λ-calculus is NOT Turing-complete (no recursion).

Recursion is regained via **fixed-point combinators** (Y combinator) in the untyped λ-calculus, or via explicit recursion in typed settings (general recursive types).

## Worked Examples

### Example 1 — β-Reduction of Nested Abstractions

Question: Apply β-reduction to (λx.λy.x)(a)(b), showing each step and the final result.

Step 1: The outermost redex is (λx.λy.x)(a). Substitute a for x in λy.x: (λx.λy.x)(a) → λy.a.

Step 2: Now reduce (λy.a)(b). Substitute b for y in a: (λy.a)(b) → a. The body a contains no free y, so the bound variable is discarded.

Step 3: Final result: a.

Answer: **(λx.λy.x)(a)(b) →_β a.**

### Example 2 — The Ω Term: One-Step Reduction

Question: Reduce Ω = (λx.xx)(λx.xx) by one step of β-reduction. Does Ω have a normal form?

Step 1: Identify the redex: (λx.M)N with M = xx and N = λx.xx.

Step 2: Substitute N for every free occurrence of x in M: xx[x := λx.xx] = (λx.xx)(λx.xx).

Step 3: After one step: Ω →_β Ω. The term reduces to itself. It never reaches a normal form — it diverges.

Answer: **(λx.xx)(λx.xx) →_β (λx.xx)(λx.xx). Ω has no normal form (non-terminating).**

### Example 3 — Church Numerals: Computing SUCC 1

Question: Church numeral 1 = λf.λx.f x and SUCC = λn.λf.λx.f (n f x). Compute SUCC 1 and verify it equals Church numeral 2 = λf.λx.f (f x).

Step 1: SUCC 1 = (λn.λf.λx.f (n f x)) (λf.λx.f x). Apply β-reduction: substitute 1 for n → λf.λx.f ((λf.λx.f x) f x).

Step 2: Reduce the inner application (λf.λx.f x) f x. First substitute f for f: → (λx.f x) x. Then substitute x for x: → f x.

Step 3: So SUCC 1 = λf.λx.f (f x) = Church numeral 2. ✓

Answer: **SUCC 1 = λf.λx.f (f x) = 2.**

### Example 4 — Type Inference in Simply Typed Lambda Calculus

Question: Find the type of the term λf.λx.f (f (x)) in the simply typed lambda calculus with a base type ι.

Step 1: Let f: α → β and x: γ. For f(x) to type-check, x must have type α. So γ = α and f(x): β.

Step 2: For f(f(x)) to type-check, the argument f(x) must have type α. So β = α and f: α → α.

Step 3: Then f(f(x)): α. Abstracting x gives λx.f(f(x)): α → α. Abstracting f gives λf.λx.f(f(x)): (α → α) → α → α.

Step 4: With base type ι: the term has type (ι → ι) → ι → ι.

Answer: **λf.λx.f(f(x)) : (ι → ι) → ι → ι.**

## Common Mistakes

> [!failure] Mistake pattern: Substituting without α-conversion
> (λx.λy.x) y: naive substitution gives λy.y (capture!). Always α-convert bound variables first: (λx.λz.x)y → λz.y.

> [!failure] Mistake pattern: Confusing abstraction with application
> λx.x y means λx.(x y) — an abstraction whose body is x y. NOT (λx.x) y — which is an application.

> [!failure] Mistake pattern: Thinking λ-calculus is only theoretical
> Python lambdas, JavaScript arrow functions, and functional languages all directly implement λ-calculus. Closures are λ-abstractions with captured environments.

## Where This Shows Up in CS

### Functional Programming Languages
```haskell
-- λ-calculus in Haskell
id = \x -> x                        -- λx.x
apply = \f x -> f x                 -- λf.λx.f x
compose = \f g x -> f (g x)         -- λf.λg.λx.f(g x)
```

### Type Systems
```text
- Simply typed λ-calculus: base of ML, Haskell, OCaml
- System F: polymorphic λ-calculus (∀a. a→a)
- Dependent types: λ-calculus with terms in types (Coq, Agda, Idris)
- Linear types: each variable used exactly once (Rust borrow checker)
```

### Formal Semantics
```text
- Operational semantics: how programs execute (β-reduction)
- Denotational semantics: meaning as mathematical objects
- Axiomatic semantics: Hoare logic (pre/post conditions)
- All use λ-calculus as the core language
```

### Proof Assistants
```text
- Coq, Lean, Isabelle: based on typed λ-calculus
- Curry-Howard: writing programs = writing proofs
- Extraction: Coq programs → OCaml/Haskell/λ-calculus
```
