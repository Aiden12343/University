## Introduction

**Elliptic curve cryptography** (ECC) is public-key cryptography based on the algebraic structure of elliptic curves over finite fields. It achieves equivalent security to RSA with much smaller keys — 256-bit ECC ≈ 3072-bit RSA — making it the standard for modern TLS, Bitcoin, and Signal.

From [[11.13 Finite Fields and Polynomial Arithmetic]], you understand the field arithmetic that underlies curve operations. From [[10.6 Cryptography RSA and Diffie Hellman]], you know the basics of public-key cryptography (key pairs, encryption, signatures). From [[6.3 Modular Arithmetic]], you can compute modular inverses needed for point addition.

The central concepts:
- **Elliptic curve**: set of points (x, y) satisfying y² = x³ + ax + b over a field, plus a point at infinity O.
- **Point addition**: the group operation — P + Q = R, defined geometrically (line through P and Q intersects curve at −R).
- **Scalar multiplication**: kP = P + P + ... + P (k times), computed via double-and-add.
- **ECDLP** (Elliptic Curve Discrete Log Problem): given P and Q = kP, find k. This is the hardness assumption underlying ECC security.

## New Words

- **[[elliptic curve]]** — the set of points (x, y) satisfying y² = x³ + ax + b (with Δ ≠ 0), plus the point at infinity O; forms an abelian group.
- **[[point addition]]** — the group operation P + Q = R; defined by intersecting the line through P and Q with the curve and reflecting the third point over the x-axis.
- **[[point doubling]]** — P + P = 2P; uses the tangent line at P instead of the secant line.
- **[[scalar multiplication]]** — kP = P + P + ... + P (k additions); computed efficiently via the double-and-add algorithm.
- **[[ECDLP]]** — Elliptic Curve Discrete Logarithm Problem: given P and kP, find k (the base-2 logarithm of k relative to generator P).

## Breadcrumbs

### Breadcrumb 1: The Group Law — Point Addition

**Builds on:** [[11.13 Finite Fields and Polynomial Arithmetic]] (field arithmetic, inverses)

Points on an elliptic curve form an abelian group with the point at infinity O as identity.

**Geometric addition**: P + Q = R where the line through P and Q intersects the curve at −R, then reflect over x-axis to get R.

**Algebraic addition** (over any field):
- Slope: m = (y_Q − y_P) / (x_Q − x_P)
- x_R = m² − x_P − x_Q
- y_R = m(x_P − x_R) − y_P

Special cases: P + O = P, P + (−P) = O, P + P uses doubling (tangent line).

#### Chunked Example — Point Addition Over ℝ

Question: E: y² = x³ − 2x + 1. P = (0, 1), Q = (2, 1). Find P + Q.

Step 1: m = (1 − 1)/(2 − 0) = 0 (horizontal line). Line: y = 1.

Step 2: Intersection: x³ − 2x + 1 = 1 → x³ − 2x = 0 → x(x² − 2) = 0. Roots: x = 0, x = 2, x = −√2.

Step 3: −R = (−√2, 1). Reflect: R = (−√2, −1).

Answer: **P + Q = (−√2, −1).**

### Breadcrumb 2: Scalar Multiplication — Double-and-Add

**Builds on:** Breadcrumb 1, [[6.3 Modular Arithmetic]] (binary representation)

Scalar multiplication kP computes P added to itself k times. Use the binary expansion of k:

```
k = 13 = 1101₂
Start: R = O
Bit 0 (LSB, 1): R = P
Double: P → 2P
Bit 1 (0): skip
Double: 2P → 4P
Bit 2 (1): R = P + 4P = 5P
Double: 4P → 8P
Bit 3 (1): R = 5P + 8P = 13P
```

Total: 3 doubles + 2 adds = O(log k) operations.

#### Chunked Example — Computing 5P

Question: Compute 5P using double-and-add.

Step 1: k = 5 = 101₂. Start R = O. Process bits from LSB to MSB.

Step 2: Bit 0 (1): R = P. Double P → 2P.

Step 3: Bit 1 (0): skip. Double 2P → 4P.

Step 4: Bit 2 (1): R = P + 4P = 5P.

Answer: **5P = double-and-add: 2 doubles + 1 add (3 group operations total).**

## Why This Works

ECC's security relies on the ECDLP: given P and kP, find k. The best classical algorithms (Pollard rho) take O(√n) time where n is the order of the group. For a 256-bit curve (n ≈ 2²⁵⁶), this is 2¹²⁸ operations — infeasible.

Key advantages over RSA:
- **Smaller keys**: 256-bit ECC ≈ 3072-bit RSA for equivalent security.
- **Faster operations**: ECC scalar multiplication ≈ 2-10× faster than RSA modular exponentiation.
- **Forward secrecy**: ECDHE (ephemeral Diffie-Hellman) generates fresh keys per session.

However, quantum computing threatens ECC: Shor's algorithm solves ECDLP in polynomial time. Post-quantum cryptography (lattice-based) is the long-term replacement.

## Worked Examples

### Example 1 — Point Addition Over GF(7)

Question: E: y² = x³ + x + 1 over GF(7). P = (0, 1), Q = (2, 2). Compute P + Q.

First verify both points are on the curve:
- P = (0,1): y² = 1. x³ + x + 1 = 0 + 0 + 1 = 1. ✓
- Q = (2,2): y² = 4. x³ + x + 1 = 8 + 2 + 1 = 11 ≡ 4. ✓

Step 1: Compute slope m = (y_Q − y_P) / (x_Q − x_P) = (2 − 1) / (2 − 0) = 1/2 mod 7.
2⁻¹ mod 7 = 4 (since 2×4 = 8 ≡ 1). m = 1 × 4 = 4.

Step 2: x_R = m² − x_P − x_Q = 4² − 0 − 2 = 16 − 2 = 14 ≡ 0 mod 7.

Step 3: y_R = m(x_P − x_R) − y_P = 4(0 − 0) − 1 = −1 ≡ 6 mod 7.

Step 4: R = (0, 6). Verify on curve: y² = 36 ≡ 1. x³ + x + 1 = 0 + 0 + 1 = 1. ✓

Answer: **P + Q = (0, 6)**. Verify: y² = 36 ≡ 1, x³ + x + 1 = 0 + 0 + 1 = 1. ✓ The result is on the curve.

### Example 2 — Curve25519 / X25519

Question: What makes Curve25519 efficient?

Step 1: Curve25519: y² = x³ + 486662x² + x over GF(2²⁵⁵ − 19).

Step 2: Montgomery form enables x-coordinate-only scalar multiplication (no y needed).

Step 3: The prime p = 2²⁵⁵ − 19 simplifies modular reduction (like 2²⁵⁵ ≡ 19 mod p).

Step 4: Constant-time implementation prevents side-channel attacks. ≈2.5M cycles for key exchange.

Answer: **X25519: fast (Montgomery ladder, special prime), constant-time, no patent encumbrances.**

### Example 3 — ECDSA Signatures

Question: How does ECDSA sign and verify?

Step 1: Key generation: private key d, public key Q = dG (G = generator).

Step 2: Sign (message m): pick random k, compute R = kG = (x₁, y₁), r = x₁ mod n, s = k⁻¹(H(m) + r·d) mod n. Signature = (r, s).

Step 3: Verify: compute u₁ = H(m)·s⁻¹ mod n, u₂ = r·s⁻¹ mod n, point = u₁G + u₂Q. Valid if r ≡ x-coordinate of point mod n.

Step 4: Security: forging a signature requires solving ECDLP.

Answer: **ECDSA: sign with d, verify with Q = dG. Nonce k must be unique and random.**

### Example 4 — Pairing-Based Cryptography

Question: What are pairings and what do they enable?

Step 1: A pairing e: G₁ × G₂ → G_T is bilinear: e(aP, bQ) = e(P, Q)^{ab}.

Step 2: Enables: BLS signatures (one group element), identity-based encryption, tripartite Diffie-Hellman.

Step 3: BLS signature: σ = H(m)ᵈ. Verify: e(σ, g) = e(H(m), dG).

Step 4: Pairings are computed using the Tate/Weil pairing on special curves (BN curves, BLS curves).

Answer: **Pairings: e(aP, bQ) = e(P, Q)^{ab}. Enable BLS signatures, IBE, and more.**

## Common Mistakes

> [!failure] Mistake pattern: Using composite-order curves
> Always verify the curve order has a large prime factor. Small factors enable Pohlig-Hellman attack (solve ECDLP in each subgroup).

> [!failure] Mistake pattern: Missing special cases in point addition
> P + O = P, P + (−P) = O, P + P uses doubling formula. Missing these causes crashes or incorrect results.

> [!failure] Mistake pattern: Reusing nonce k in ECDSA
> Two signatures with same k leak the private key: d = (s₁ − s₂)⁻¹(k·s₁ − H(m₁)) mod n. This broke PlayStation 3 ECDSA.

> [!failure] Mistake pattern: Invalid curve attacks
> If the curve equation is not verified, attacker can supply points on a weak curve. Always check that received points satisfy the curve equation.

## Where This Shows Up in CS

### Standard Curves (2026)
```text
- NIST P-256 (secp256r1): TLS, code signing
- Curve25519/X25519: modern TLS 1.3, SSH, Signal
- Curve448: higher security margin
- secp256k1: Bitcoin, Ethereum
- BN curves/BLS curves: pairing-friendly
```

### Implementation
```python
from cryptography.hazmat.primitives.asymmetric import ec

private_key = ec.generate_private_key(ec.SECP256R1())
signature = private_key.sign(message, ec.ECDSA(hashes.SHA256()))
shared_key = private_key.exchange(ec.ECDH(), peer_public_key)
```

### Security Levels
```text
- 256-bit ECC ≈ 3072-bit RSA ≈ 128-bit symmetric
- 384-bit ECC ≈ 7680-bit RSA ≈ 192-bit symmetric
- 521-bit ECC ≈ 15360-bit RSA ≈ 256-bit symmetric
- Quantum: Shor breaks all ECC and RSA — post-quantum replacement needed
```

### Applications
```text
- TLS 1.3: ECDHE mandatory key exchange
- Bitcoin: ECDSA for transaction signatures
- Signal: X25519 + ECDHE for forward secrecy
- Zero-knowledge proofs: SNARKs over elliptic curves
```
