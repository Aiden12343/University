## Introduction

**Advanced optimisation** studies algorithms that converge provably faster and handle non-convex, stochastic, and constrained problems. This is the engine behind modern ML.

From [[9.9 Gradient Descent and Optimisation]], you know basic GD and its convergence for convex functions. From [[9.10 Convex Optimisation Basics]], you understand convex sets, convex functions, and the importance of convexity. From [[11.2 Randomised Algorithms]], you have seen how randomness enables efficient algorithms — now randomness enters optimisation via SGD.

Key concepts:
- **Convergence rates**: sublinear O(1/k) vs linear O(exp(−k)) vs quadratic O(exp(−2ᵏ)).
- **Strong convexity**: the function curves upward at least as fast as a quadratic — guarantees linear convergence.
- **Second-order methods**: Newton's method uses curvature (Hessian) for faster convergence.
- **Adaptive methods**: Adam, RMSProp tune per-parameter learning rates.
- **Stochastic methods**: SGD, SVRG, handle large data via gradient estimates.
- **Duality**: every optimisation problem has a dual — sometimes easier to solve.

## New Words

- **[[strong convexity]]** — f(y) ≥ f(x) + ∇f(x)ᵀ(y−x) + (μ/2)||y−x||²; guarantees linear convergence of GD.
- **[[Nesterov acceleration]]** — momentum with lookahead: v_{t+1} = x_t − η∇f(x_t + γv_t).
- **[[Adam optimiser]]** — Adaptive Moment Estimation: per-parameter learning rates computed from first and second gradient moments.
- **[[duality]]** — every primal optimisation problem has a dual; weak duality: dual ≤ primal; strong duality: dual = primal under constraint qualifications.
- **[[KKT conditions]]** — Karush-Kuhn-Tucker: necessary conditions for optimality in constrained optimisation (stationarity, primal/dual feasibility, complementary slackness).
- **[[variance reduction]]** — techniques (SVRG, SAGA) that reduce gradient noise to achieve linear convergence in stochastic optimisation.

> [!important] You pass this topic only when you can define all six terms without looking.

## Breadcrumbs

### Breadcrumb 1: Convergence Rates and Strong Convexity

**Builds on:** [[9.9 Gradient Descent and Optimisation]] (GD update, convergence for convex functions)

Convergence rates classify how fast optimisation algorithms approach the optimum:

```
Convex + Lipschitz gradient:      f(x_k) − f(x*) = O(1/√k)
Convex + smooth:                  f(x_k) − f(x*) = O(1/k)
Strongly convex + smooth:         f(x_k) − f(x*) = O(exp(−μk/L))
```

#### Chunked Example — Exponential Speedup from Strong Convexity

Question: For ε = 10⁻⁶, how many iterations for convex smooth vs strongly convex?

Step 1: Convex smooth: O(1/k) → need k ≈ 1/ε = 10⁶ iterations.

Step 2: Strongly convex: O(exp(−μk/L)) → need k ≈ (L/μ) ln(1/ε) ≈ 2 × 13.8 = 28 iterations (assuming L/μ = 2).

Answer: **Strong convexity: ~28 iterations vs 1,000,000 for convex smooth — exponential speedup.**

### Breadcrumb 2: Adaptive Methods — Adam

**Builds on:** Breadcrumb 1, [[9.9 Gradient Descent and Optimisation]] (learning rates, momentum)

Adam maintains per-parameter learning rates based on gradient moments:

```
m_k = β₁·m_{k−1} + (1−β₁)·g_k          # first moment (mean)
v_k = β₂·v_{k−1} + (1−β₂)·g_k²         # second moment (uncentred variance)
m̂_k = m_k / (1−β₁ᵏ)                      # bias correction
v̂_k = v_k / (1−β₂ᵏ)
w_{k+1} = w_k − η·m̂_k / (√v̂_k + ε)
```

#### Chunked Example — Adam Update Step

Question: Gradient g = [3, 0.1]. β₁=0.9, β₂=0.999, η=0.001. First Adam step?

Step 1: m₁ = 0.9·0 + 0.1·[3, 0.1] = [0.3, 0.01]. v₁ = 0.999·0 + 0.001·[9, 0.01] = [0.009, 0.00001].

Step 2: Bias-correct: m̂₁ = [0.333, 0.011]; v̂₁ = [0.00901, 0.00001001].

Step 3: Update: w₁ = [0,0] − 0.001·[0.333/√0.00901, 0.011/√0.00001] ≈ [−0.0035, −0.0035].

Step 4: Both coordinates receive similar update magnitudes despite very different gradient sizes.

Answer: **Adam normalises per-coordinate step sizes by gradient magnitude.**

### Breadcrumb 3: Second-Order Methods — Newton

**Builds on:** [[9.3 Differentiation Rules]] (derivatives), Breadcrumb 1

Newton's method uses the Hessian (matrix of second derivatives):

```
w_{k+1} = w_k − [∇²f(w_k)]⁻¹ ∇f(w_k)
```

- Quadratic functions: one step to exact optimum.
- General functions: quadratic convergence near smooth minimum.

#### Chunked Example — Newton on Quadratic

Question: f(w) = ½wᵀAw − bᵀw. Newton update?

Step 1: ∇f = Aw − b. ∇²f = A (constant Hessian).

Step 2: w₁ = w₀ − A⁻¹(Aw₀ − b) = A⁻¹b. One step reaches exact minimum.

Answer: **Newton converges in 1 step for quadratics; quadratic convergence (doubling precision digits) for general smooth functions near optimum.**

## Why This Works

Strong convexity provides a quadratic lower bound on the function, which GD exploits for linear convergence. Adaptive methods handle ill-conditioned problems (different curvatures in different directions). Newton's method uses curvature information to take more informed steps.

The convergence speed hierarchy:
```
Sublinear (O(1/√k)) ← Linear (O(exp(−k))) ← Quadratic (O(exp(−2ᵏ)))
     SGD (no noise reduction)    GD (convex)    GD (strongly convex)   Newton
```

For large-scale ML, stochastic methods dominate. Variance reduction (SVRG) bridges the gap between SGD and GD — achieving linear convergence at SGD's per-iteration cost.

## Worked Examples

### Example 1 — Nesterov Accelerated Gradient Step

Question: Apply one step of Nesterov accelerated gradient to f(x) = x² with momentum γ = 0.9, learning rate η = 0.1, starting at x₀ = 5, v₀ = 0. Compute x₁ and v₁. Then compare x₂ with standard GD.

Step 1: Nesterov lookahead: ỹ₀ = x₀ − γv₀ = 5 − 0.9 × 0 = 5. Gradient at lookahead: ∇f(5) = 2 × 5 = 10.

Step 2: Velocity update: v₁ = γv₀ + η∇f(ỹ₀) = 0.9 × 0 + 0.1 × 10 = 1. Parameter update: x₁ = x₀ − v₁ = 5 − 1 = 4.

Step 3: Step 2: ỹ₁ = x₁ − γv₁ = 4 − 0.9 × 1 = 3.1. ∇f(3.1) = 6.2. v₂ = 0.9 × 1 + 0.1 × 6.2 = 1.52. x₂ = 4 − 1.52 = 2.48.

Step 4: Standard GD at η = 0.1: x₁ = 4, x₂ = 4 − 0.1 × 8 = 3.2. Nesterov reaches 2.48 vs GD 3.2 — acceleration emerges as momentum builds.

Answer: **x₁ = 4, v₁ = 1. x₂ = 2.48 (Nesterov) vs 3.2 (GD). Nesterov accelerates convergence.**

### Example 2 — Strong Convexity and Convergence Rate

Question: Determine the strong convexity parameter μ for f(x) = x². If the gradient Lipschitz constant L = 2, how many GD iterations are needed to reach ε = 10⁻⁶ from x₀ = 5? Compare to a convex (non-strongly) smooth function requiring O(1/k) rate.

Step 1: f(y) = x² + 2x(y−x) + (y−x)². Strong convexity requires f(y) ≥ f(x) + ∇f(x)ᵀ(y−x) + (μ/2)||y−x||². So (y−x)² ≥ (μ/2)(y−x)² → μ = 2. (Verified by f''(x) = 2.)

Step 2: For strongly convex smooth GD: f(x_k) − f(x*) ≤ exp(−μk/L)(f(x₀) − f(x*)). Here f(x₀) = 25, f(x*) = 0.

Step 3: Set exp(−2k/2) ≤ 10⁻⁶/25 = 4 × 10⁻⁸. So e⁻ᵏ ≤ 4 × 10⁻⁸ → k ≥ −ln(4 × 10⁻⁸) ≈ 17.

Step 4: Convex (non-strongly) smooth GD rate: O(1/k). To reach f(x_k) − f(x*) ≤ ε, need k ≈ 25/ε = 2.5 × 10⁷ iterations — dramatically worse.

Answer: **μ = 2. Strongly convex GD: ~17 iterations. Non-strongly convex GD: ~25 million iterations.**

### Example 3 — KKT Conditions for Constrained Optimisation

Question: Minimise f(x) = x² subject to the constraint x ≥ 2. Write the Lagrangian, apply the KKT conditions, and find the optimal solution.

Step 1: Lagrangian: L(x, λ) = x² − λ(x − 2), with dual feasibility λ ≥ 0.

Step 2: Stationarity: ∂L/∂x = 2x − λ = 0 → λ = 2x.

Step 3: Complementary slackness: λ·(x − 2) = 0. Case λ > 0: then x = 2, λ = 4 (λ ≥ 0 ✓). Case λ = 0: then x = 0, but g(0) = −2 < 0 violates primal feasibility.

Step 4: Primal feasibility: x ≥ 2. x* = 2 satisfies this. Optimal value: f(2) = 4.

Answer: **x* = 2, λ* = 4, f(x*) = 4. The constraint is active (binding) at the optimum.**

### Example 4 — Adam Optimiser: First Update Step

Question: At step k = 1, gradient g = [2, −3]. Given β₁ = 0.9, β₂ = 0.999, η = 0.001, ε = 10⁻⁸, and initial parameters w₀ = [0, 0] (with m₀ = [0,0], v₀ = [0,0]), compute the first Adam update w₁. Compare with standard SGD at the same learning rate.

Step 1: Compute biased moments: m₁ = β₁·0 + (1−β₁)·g = 0.1 × [2, −3] = [0.2, −0.3]. v₁ = β₂·0 + (1−β₂)·g² = 0.001 × [4, 9] = [0.004, 0.009].

Step 2: Bias correction: m̂₁ = m₁/(1−β₁) = [0.2, −0.3]/0.1 = [2, −3]. v̂₁ = v₁/(1−β₂) = [0.004, 0.009]/0.001 = [4, 9].

Step 3: Adam update: w₁ = [0,0] − η·m̂₁/(√v̂₁ + ε) = [0,0] − 0.001 × [2/(√4 + 10⁻⁸), −3/(√9 + 10⁻⁸)] ≈ [0,0] − 0.001 × [2/2, −3/3] = [−0.001, 0.001].

Step 4: Standard SGD: w₁ = [0,0] − 0.001 × [2, −3] = [−0.002, 0.003]. Adam normalises per-coordinate step sizes: both coordinates move by 0.001 despite different gradient magnitudes (2 vs 3).

Answer: **Adam: w₁ = [−0.001, 0.001]. SGD: w₁ = [−0.002, 0.003]. Adam adapts per-parameter learning rates.**

## Common Mistakes

> [!failure] Mistake pattern: Using Newton on non-convex functions without care
> The Hessian may be indefinite. Fix: add λI (Levenberg-Marquardt), use trust region methods, or stick to first-order methods.

> [!failure] Mistake pattern: Assuming Adam always converges
> Adam can fail to converge for some simple convex functions (Reddi et al., 2018). AMSGrad and AdamW fix known issues.

> [!failure] Mistake pattern: Neglecting strong convexity condition
> Linear convergence requires μ > 0. Many ML problems have μ ≈ 0 near the optimum. Add L2 regularisation to ensure strong convexity.

## Where This Shows Up in CS

### Deep Learning Frameworks
```text
- PyTorch optimisers: SGD, Adam, AdamW, RMSProp
- Learning rate schedules: cosine annealing, warm restarts
- Gradient clipping: prevent exploding gradients
- Mixed precision: half-precision gradients for speed
```

### Convergence Diagnostics
```text
- Training/validation loss curves
- Gradient norm ||∇L|| → 0
- Learning rate tuning via LR finder
- Early stopping based on validation plateau
```

### Reinforcement Learning
```text
- Policy gradient: REINFORCE, PPO (trust region)
- Natural gradient: TRPO constrains policy update
- Q-learning: fixed-point iteration, not gradient descent
```
