# 1.13 Estimation and Error Checking - Worked Examples

Theory note: [[1.13 Estimation and Error Checking]]

Use these before attempting [[1.13 Estimation and Error Checking - Practice Questions]].

> [!tip] Worked example routine
> Estimate, calculate, inverse-check, unit-check. Use that order until it becomes automatic.

## Example 1 - Estimating a Sum
Question: Estimate and calculate `398 + 607`.

### Step 1 - Estimate first

```text
398 -> 400
607 -> 600
400 + 600 = 1000
```

### Step 2 - Calculate exactly

```text
398 + 607 = 1005
```

### Step 3 - Compare
1005 is close to 1000.

Answer: The exact answer is **1005**, and it is reasonable.

## Example 2 - Estimating a Product
Question: Estimate and calculate `52 x 19`.

### Step 1 - Estimate

```text
52 -> 50
19 -> 20
50 x 20 = 1000
```

### Step 2 - Calculate

```text
52 x 19 = 988
```

### Step 3 - Compare
988 is close to 1000.

Answer: The exact answer is **988**, and it is reasonable.

## Example 3 - Catching a Percentage Error
Question: A learner says 20% of 50 is 100. Is this reasonable?

### Step 1 - Use a mental check
20% is less than 100%.

### Step 2 - Compare with the whole
20% of 50 must be less than 50.

### Step 3 - Decide
100 is greater than 50.

Answer: Not reasonable. Correct answer:

```text
20% of 50 = 10
```

## Example 4 - Inverse Check
Question: Check `72 - 38 = 34`.

### Step 1 - Use the inverse operation
Subtraction is checked with addition.

```text
34 + 38
```

### Step 2 - Calculate

```text
34 + 38 = 72
```

Answer: The subtraction is correct.

## Example 5 - Unit Rate Check
Question: A service handles 1500 requests in 30 seconds. Find the rate and check units.

### Step 1 - Divide requests by seconds

```text
1500 / 30 = 50
```

### Step 2 - Attach units

```text
50 requests/second
```

Answer: The rate is **50 requests/second**.

## Example 6 - Unit Conversion Bug
Question: A program says 2 seconds equals 200 milliseconds. What is wrong?

### Step 1 - Recall the conversion

```text
1 second = 1000 milliseconds
```

### Step 2 - Convert

```text
2 seconds = 2000 milliseconds
```

Answer: The program is wrong by a factor of 10. It likely used 100 instead of 1000.

## Example 7 - Magnitude Check
Question: A calculator output says `997 x 102 = 10,169,400`. Is that reasonable?

### Step 1 - Estimate

```text
997 -> 1000
102 -> 100
1000 x 100 = 100,000
```

### Step 2 - Compare
The output is over 10 million, much larger than 100,000.

Answer: Not reasonable. The true answer should be near 100,000.

## Example 8 - Debugging a Benchmark
Question: A benchmark processes 120,000 records in 2 seconds but reports 60 records/second. What is the likely issue?

### Step 1 - Estimate the rate

```text
120,000 / 2 = 60,000
```

### Step 2 - Compare with reported value
Reported:

```text
60 records/second
```

Expected:

```text
60,000 records/second
```

Answer: The result is too small by a factor of 1000. This may be a unit conversion or scaling bug.

## Self-Check
You understand these examples when you can:

- estimate before exact calculation
- compare exact answers to estimates
- use mental checks for percentages
- check subtraction with addition
- attach correct units to rates
- spot magnitude errors in program output
