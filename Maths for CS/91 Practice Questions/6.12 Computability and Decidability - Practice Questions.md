# 6.12 Computability and Decidability - Practice Questions

Theory note: [[6.12 Computability and Decidability]]

Do these on paper first. Check [[6.12 Computability and Decidability - Answers]] only after making a serious attempt.

## Vocabulary
1. Define algorithm.
2. Define decidable.
3. Define undecidable.
4. Write one sentence explaining the difference between two of the new words.

## Core Skill
5. Classify each problem as decidable or undecidable, and explain why.
   (a) Given a DFA and a string w, does the DFA accept w?
   (b) Given a program P, does P ever divide by zero?
   (c) Given two DFAs, do they accept the same language?

6. Outline Turing's proof that the Halting Problem is undecidable. Write the contradiction program Q that uses H(P, I) as a subroutine, and explain the contradiction that arises when evaluating Q(Q).

7. Use reduction from the Halting Problem to show that "Does this program ever divide by zero?" is undecidable. (Hint: given a program P and input I, construct a new program P' that performs a division by zero exactly when P(I) halts.)

8. State Rice's Theorem. Give one example of a non-trivial semantic property of programs that is undecidable, and one example of a syntactic property that is decidable.

## Error Checking
9. A student claims: "The Halting Problem is undecidable in theory, but we can write a program that correctly determines whether most real programs halt, so it is actually decidable in practice." Identify the mistake in this reasoning.

10. According to the topic's decidable/undecidable table, is "whether a context-free grammar is ambiguous" decidable or undecidable? Check your answer against the theory note.

## CS Transfer
11. Rice's Theorem states that any non-trivial semantic property of programs is undecidable. Explain why this means no compiler can perfectly detect all infinite loops or all dead code. Why are static analysis tools still useful despite this limitation?

12. Explain the key difference between a problem being NP-hard (like the Travelling Salesman Problem) and being undecidable (like the Halting Problem). Give one example of each type and explain why the distinction matters for software engineers.

Pass target: 85%. Definitions must be perfect.
